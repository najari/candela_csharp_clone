## 사용자와 제품 가치

진단 설계자는 DID·서비스·변형을 정의한다. ECU 개발자는 데이터 배치와 값 변환을 확인한다. 검토자는 오류 위치·변경 영향·교환 결과를 확인한다. 사용자 계정·권한 서버는 두지 않는다. 읽기 전용 표시는 파일 상태·미지원 의미·동시 열기에 대한 편집 제약이다.

첫 출시의 성공은 하나의 검증된 진단 부분집합을 생성/가져오기 → 편집 → SQLite 저장 → 재열기 → ODX 출력 → 외부 의미 대조까지 완료하는 것이다. 실무 CANdelaStudio 전체 대체를 첫 출시 조건으로 두지 않는다.

## 범위 구분

P1: Snapshot/Extended Data, 가변 길이·Multiplexer·Iteration, 추가 UDS 서비스, PDX, 비교, XLSX, HTML 사양서.

P2: CDD/CDDT 쓰기, 템플릿 편집기, AUTOSAR DEXT, 요구사항 동기화, 번역/TMX, 외부 도구 연계.

실제 ECU 통신과 플래싱은 현재 로드맵에 없다. SQLite 공유 폴더 다중 작성, 계정 서버, 클라우드 동기화도 MVP 범위가 아니다. UI는 한국어, qualifier·기술 식별자는 ASCII 규칙, 내용 텍스트는 Unicode로 한다.

## 출시 조건

모든 P0 연결 테스트 통과, 지원 의미의 저장·재열기 일치, 차단 오류 없는 ODX 출력, 지정 외부 도구의 재열기·의미 대조, 설치·복구 실증이 필요하다. 성능 목표 미달은 측정 결과와 해결 작업을 남기며 무조건 Rust 도입으로 처리하지 않는다.
