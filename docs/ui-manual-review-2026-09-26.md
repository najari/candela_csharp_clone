# UI 개선 검토 — CANdelaStudio 13 도움말 대비 상호작용 (2026-09-26)

[화면 명세](backup/04-ui-specification.md) · [이전 화면 검토(U1~U6)](backup/ui-candela13-screen-review-2026-09-26.md) · **목업: [ui-manual-review-2026-09-26.html](ui-manual-review-2026-09-26.html)**

상태: 제안(미구현). 이 검토에서는 앱 코드를 바꾸지 않았다.

## 근거

- **도움말**: 사용자가 준 CANdelaStudio 13 도움말(CHM에서 뽑은 764쪽). 이 문서에는 쪽 이름과 FeatureID만 적는다. 도움말 파일은 저장소에 넣지 않는다.
  - 주로 본 쪽: Basic User Interface Rules, Keyboard Shortcuts, Search Dialog, Ribbon Navigation Area, Object Paths, Output Window, Status Bar, Docking Windows, Open Page, Ribbon Tab File(Recent), Options(General·Display·Edit·Confirmation), DTCs, Available DTCs, DTC Property Page(General), How to Edit DTCs Efficiently, Qualifier, Qualifier Overview, Recreate Qualifier, Value, Data Objects, Graphical Telegram Table, Services, Diagnostic Instance, Replace Data Type, Variant Wizard, Compare View, Dependencies.
  - 인용한 FeatureID는 모두 도움말 본문에서 다시 찾아 확인했다. ID가 없는 규칙은 쪽 이름으로 적는다.
- **DiagAuthor 지금 상태**: 23차 작업본 코드를 읽어 확인했다. `ui.py`(`create_actions`, `tree_selected`, `show_page`, `fit_columns`, `table_menu`, `selection_changed`, `find_document_dialog`, `go_path`, `bulk_edit`, `copy_table`), `dialogs.py`(`BaseDialog`, `ObjectDialog`, `DtcAttributeEditor`), `layout_view.py`, `presentation.byte_grid`, `pages.WorkLog`, `overviews.py`, `application.py`(`execute_command`, `query_objects`, `resolve_name_path`, `_common`).
- **앞선 문서와의 관계**: [이전 화면 검토](backup/ui-candela13-screen-review-2026-09-26.md)는 실제 화면으로 노드·페이지 **구성**을 맞췄다(U1~U6, 22차 구현). 23차는 사용자 화면 피드백 4건(선택 객체 창을 목록 아래로, Qualifier 열 맨 뒤, DTC 속성 편집 등)을 반영했다. 이 문서는 도움말의 **상호작용 규칙**(편집·선택·찾기·키보드·출력 창·대화상자)을 기준으로 남은 차이를 본다.
- **목업**: 검토한 부분을 HTML 한 파일로 만들었다(9개 화면, 가상 데이터, 네트워크 없이 브라우저로 연다). Chromium에서 9개 화면이 1920×1080·1440×900 두 크기에서 콘솔 오류 없이 열리고, 주요 동작 112개를 스크립트로 눌러 확인했다.

## 1. 결론

1. **구성은 거의 맞았고, 남은 차이는 상호작용이다.** CANdela는 목록에서 바로 고치고(F2, Tab), 여러 행에 한 번에 넣고, 필터·찾기·출력 창 링크로 옮겨 다닌다. DiagAuthor는 거의 모든 수정이 대화상자를 거친다. F2도 셀 편집이 아니라 편집 대화상자다. [화면 명세](backup/04-ui-specification.md)의 "표와 속성 편집 계약"은 이미 셀 편집(Enter·Esc·F2)을 정해 두었지만 아직 구현되지 않았다.
2. **1단계로 9개를 권한다**(매일 쓰는 편집 흐름): 셀 편집(M1-1), 여러 행 입력·값 복사(M1-2), 필터 규칙(M1-3), 노드 진입 규칙(M1-4), 새 번호(M1-5), Qualifier 자동 생성(M2-1), 찾기 대화상자(M3-1), 키보드(M3-3), 바이트 격자(M5-1).
3. **결함에 가까운 것 3건**:
   - 바이트 격자가 64바이트에서 잘려 그 뒤 필드가 격자에 없다(`byte_grid(limit=64)`). 도움말은 긴 필드를 줄여 보이되 마지막 바이트까지 보인다([DOUIG-R210]). → M5-1
   - 표 복사(Ctrl+C) 머리 줄에 화면 열 이름 대신 내부 키(`name`, `qualifier`, `attr:cdd.…`)가 들어간다. [LIST-R100]은 "보이는 그대로"다. → M3-3
   - 오른쪽 버튼으로 행을 누르면 여러 행 선택이 그 행 하나로 줄고, 선택 신호를 막아 두어 선택 객체 창은 이전 객체를 그대로 보인다. 빈 곳에서는 메뉴가 없다([UI-R350-Element]·[UI-R350-Empty]). → M1-2
4. **CDD·ODX 의미는 바꾸지 않는다.** 모든 항목은 화면과 명령 수준이다. 도메인에 닿는 것은 따로 표시했다: 여러 DTC에 레코드 항목 넣기(M1-2, 묶음 명령), 데이터 타입 바꾸기(M6-3, 새 명령), 변형 마법사(M6-4, 새 명령), 비교의 속성·다른 언어 차이(M6-6, 비교 엔진 확장).
5. **먼저 정할 것이 7가지다**(6절). 특히 F2의 뜻(D1), 필터 단어 규칙(D2), 한글 이름의 Qualifier(D3), 목록 페이지 나눔(D4)은 1단계 전에 정해야 한다.

## 4. 항목별 검토

### M1 목록

#### M1-1 셀에서 바로 고치기 — P1 · 중간

- **근거**: [LIST-R410] F2(또는 천천히 두 번 클릭)로 목록에서 바로 편집. [UI-R300] 편집 중 Tab/Shift+Tab은 다음·이전 편집 칸으로 옮겨 다시 편집하고, [UI-R300-TABLast] 마지막 행 마지막 칸의 Tab은 새 요소를 만들어 첫 편집 칸을 편집한다. Keyboard Shortcuts: 셀 편집에서 ENTER 확정, ESC 취소. [CM-R120] 안 되는 이유가 드러나지 않는 명령은 눌렀을 때 이유를 알린다.
- **지금**: 표가 `NoEditTriggers`이고 F2와 두 번 클릭 모두 편집 대화상자(`edit_object`)를 연다. 이름 한 글자를 고쳐도 대화상자를 거친다.
- **바꿀 것**: DTC 목록(코드·이름·레코드 항목)과 DID 목록(이름)부터 셀 편집을 켠다. 열거형 레코드 항목은 콤보. Enter 확정, Esc 취소, Tab/Shift+Tab 이동, 마지막 칸 Tab은 새 행. 글자를 치면 그 글자로 편집을 시작한다. 편집할 수 없는 열에서 F2를 누르면 상태 줄과 출력 창에 이유를 쓴다. 속성 대화상자는 두 번 클릭·Alt+Enter·선택 객체 창의 `속성…` 버튼으로 연다(결정 D1).
- **구현 메모**: `ObjectModel.flags`·`setData`와 `QStyledItemDelegate`(QLineEdit·QComboBox). 확정하면 기존 명령(`update_dtc`의 `code`·`name`·`attributes`, `update_did`·`update_common`의 `name`)을 `expected_revision`과 함께 보낸다. 거부되면 입력을 셀에 남기고 오류를 보인다. 한 셀 = 한 명령 = Undo 한 번. 04 명세의 셀 편집 계약과 같다.
- **목업**: [주 화면](ui-manual-review-2026-09-26.html#main) — Set condition 칸에서 F2, 입력, Tab.

#### M1-2 여러 행 입력·값 복사·오른쪽 버튼 규칙 — P1 · 큼

- **근거**: [LIST-R420] 여러 행을 고르고, 바꿀 열에서 마지막 행을 누른 뒤 F2 → 입력(열거는 선택 목록) → Enter면 모든 선택 행에 넣는다. [DTCUI-R035]·[DTCOP-R035] "Copy Value into Selected DTCs": 마지막으로 고른 DTC의 그 열 값을 다른 선택 DTC에 복사한다. 여러 DTC를 고르고, 사용자 정의 열(코드·이름이 아닌 열)이고, 중복을 허용하는 열일 때만 켜진다. [UI-R350-Element] 오른쪽 버튼은 누른 요소로 포커스를 옮기고 그 요소의 메뉴를 보인다. [UI-R350-Empty] 빈 곳의 오른쪽 버튼은 선택 없는 특별 메뉴.
- **지금**: `선택 행 일괄 편집…`은 `name`·`description` 두 필드만 입력 상자로 넣는다. 레코드 항목은 DTC마다 대화상자에서 고친다. 값 복사가 없다. 오른쪽 버튼은 누른 행 하나만 남기고(여러 행 선택이 풀림) 선택 신호를 막아 선택 객체 창이 갱신되지 않는다. 빈 곳에서는 메뉴가 뜨지 않는다.
- **바꿀 것**: 여러 행 F2 입력, 오른쪽 버튼 메뉴 `선택한 DTC에 이 값 복사`. 이미 선택된 행 위의 오른쪽 버튼은 선택을 유지하고, 새로 누른 행으로 선택이 바뀌면 선택 객체 창도 바꾼다. 빈 곳 오른쪽 버튼은 `새로 만들기…` 메뉴.
- **구현 메모**: 레코드 항목을 여러 DTC에 한 명령으로 넣는 묶음 명령이 필요하다(`update_dtc`의 `attributes`를 여러 id에 적용). 필수 항목·템플릿 열거 값 검사는 23차 `_set_dtc_attributes` 규칙을 그대로 쓴다. 이름·설명은 기존 `bulk_edit`를 쓴다. 공유 DTC는 모든 사용 변형에 반영된다는 안내를 지금 일괄 편집처럼 보인다.
- **목업**: 주 화면 — Ctrl+클릭으로 DTC 셋, 마지막에 Corrective action 칸, 오른쪽 버튼 → 이 값 복사.

#### M1-3 필터 규칙 — P1 · 작음

- **근거**: [LIST-R500] 대소문자를 가리지 않는다. 띄어 쓴 단어는 **하나라도** 맞으면 보이고, 큰따옴표 안은 그대로 찾는다. Available DTCs "Filter": 필터 오른쪽 버튼으로 지운다. [UI-R100-Filter] 노드에 들어가면 초기화, [UI-R340-Filter] 수정 뒤 유지.

### M2 속성 편집

#### M2-1 Qualifier를 이름에서 자동으로 — P1 · 중간

- **근거**: [QUAL-R010] 새 객체는 이름에서 Qualifier를 만든다. [QUAL-R020] 이름을 바꾸면, Qualifier가 아직 이름에서 만든 값과 같을 때만 따라 바꾼다. [QUAL-R050] 만드는 법: 로마자로 바꾸기(ä → ae), 바꿀 수 없는 글자는 `_`, 연속 `_`는 하나, 끝의 `_` 제거, 숫자로 시작하면 앞에 `_`, 길이 제한, 대소문자 옵션. [QUAL-R120] 0-9 A-Z a-z _만 쓰고 숫자로 시작하지 않는다. [QUAL-R130] 비어 있으면 안 되고 최대 128자.
- **지금**: 추가 대화상자의 Qualifier 칸이 비어 있어 직접 채워야 한다(비우면 형식 오류). 이름을 바꿔도 Qualifier는 그대로다. 128자 제한이 없다. 변형·데이터 타입·상태만 중복 Qualifier를 거부한다(`_common`).
- **바꿀 것**: 위 규칙으로 만들고 이름을 따라가게 한다. 사용자가 Qualifier를 직접 고치면 따라가기를 멈추고, `이름에서 다시 만들기`로 되돌린다. Qualifier 줄은 접어 둔다(사용자 요청: Qualifier는 평소 볼 필요가 없다).
- **구현 메모**: 생성 함수는 `domain.py`의 `qualifier()` 검사 옆에 두고 대화상자·셀 편집·새 번호 흐름에서 같이 쓴다. 한글만 있는 이름은 빈 값이 되므로 규칙이 필요하다(결정 D3). 같은 이름이면 같은 Qualifier가 나오며, 번호를 자동으로 붙이지 않는다(도움말 근거 없음). 중복 거부는 지금 규칙 그대로다. 가져온 CDD의 Qualifier는 바꾸지 않는다.
- **목업**: [속성 대화상자](ui-manual-review-2026-09-26.html#dialog) — DTC 이름 바꾸기, 식별 이름 줄을 펼쳐 직접 고치기, `이름에서 다시 만들기`, 한글 이름.

#### M3-2 경로 입력 — P2 · 중간

- **목업**: [데이터 타입 바꾸기](ui-manual-review-2026-09-26.html#replace-type) — 새 타입 `UInt8 ×1 bar`, `UInt32 ×0.001 bar`.

### 1단계 — P1 9개
