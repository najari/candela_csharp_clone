Compare View

Opening

[CMP-R001] You open the dialog opened with...

  • two input objects: “left” and “right”, from same or different document.
  • the mode whether data transfer is possible or not

Non-Modal Use

[CMP-R200]

  • When you...
    • delete compared object and
    • switch back to Compare View,
  • then CANdelaStudio...
    • shows a message box indicating that one of the compared objects is does not exist any more,
    • and disables the transfer and reload operations.

Handling of References

[CMP-R005]

  • for directed references S => T in the data model,
  • if there are differences in T,
  • then CompareView...
    • shows only one line like “Differences in referenced object” at S;
    • it does not show difference details of T at S.
    • it shows a special icon that indicates the difference is at a referenced object.
  • This applies to:
    • Data Object / Bitfield => Datatype
    • DTC => DTC in DTC Pool
    • Container/DTC => Vehicle System Group
    • NRC at Service

Example:

  • in Compare View for a document where only one datatype description has been changed,
  • at each data object that references the datatype,
  • Compare View does not show the description difference detail lines, e.g. “OLD”,
  • but only one line for the datatype, e.g. “Bcd (2 Byte)”.

Note: this does not apply to referenced Diagnostic Instances (these are not directed references S => T).

[CMP-R007] - for directed references S => T in the data model, - if there are differences in T, - Compare View allows to navigate to the differences of T * context menu “Go to difference details”). - Note: not for NRCs.

[CMP-R010]: Compare View supports filters via toolbar buttons: show/hide differences of type…

  • object exists only in left side (default: show)
  • object exists in both sides with modifications (default: show)
  • object exists only in right side (default: show)
  • referenced objects (default: show). Uses the icon of [CMP-R005].

[CMP-R012]: Compare View support additional filters via Ribbon menu items:

  • differences of record items (e.g. “Fault memory columns”) (default: show)
  • differences of TextIDs (default: show)
  • differences of OIDs (default: show):
    • Note: Requires activating OIDs in Options menu.
  • differences of state transitions (default: show)
  • differences of attribute values (default: show)
  • differences in languages other than the shown one (default: not shows)

[CMP-R016]: button "Reset filter (show all)" resets all filters.

[CMP-R018]: for an inner node in the difference tree,

  • if all its child nodes are hidden due to filters,
  • then Compare View also hides the inner node.
  • It applies this rule recursively up the tree.
  • If no difference node is left at all, it displays an explanatory text, like “No differences are left to show.”

  • expanding the entire tree and
  • collapsing the tree to:
    • Variants

[CMP-R030]: Compare View shows a details window for extra information about the selected tree node (on bottom of comparison view / details pane at the right which shows multi-line text also).

[CMP-R035]: in the tree, Compare View show differences in other languages than the one currently shown, and lists the languages in which there are differences (terms as in File|Properties) (may also be filtered).

[CMP-R050]: if the dialog has been opened in a context where data transfer is possible (cf. [CMP-R001] above), Compare View provides a toggle "Switch to Transfer Mode".

a) If the button is on,

  • Compare View displays a checkbox in a separate column between tree and left/right columns;
  • Compare View preserves the checkbox value when user switches transfer mode off, then on again
  • Compare View shows tree nodes that cannot be updated on their own (e.g. save number) in a special way (e.g. gray, or in italics, or checkbox grayed out);
  • Compare View shows tree nodes that have the checkbox checked in a special way that improves visualization of the checked nodes (e.g. background color like selection, or strong font)

b) If off, Compare View hides the checkbox, hides the panel, and restores standard tree display (fonts, colors etc.)

c) Data transfer is not possible: in View/ViewX edition, in pre document update (cf. [CMP-R140]).

d) If transfer mode was enabled the last time the dialog was opened in a context where data transfer is possible (even across CANdelaStudio sessions), switch to transfer mode on dialog entry. Default: disabled.

[CMP-R055]: After “Transfer”, Compare View restores tree expansion state and currently selected element. If the previously selected element does no more exist in the difference tree, it selects the lowest still existing ancestor element.

[CMP-R070]: Compare View mentions the CDD (with revision), CDDT (with revision) and object (path) used by each document in the difference view.

[CMP-R080]: Compare View explains what the colors used in the difference view mean (e.g. using a legend, or by showing the colors on a filter button).

[CMP-R100]: Compare View provides a way to navigate in the document(s) compared: navigate to left object, navigate to right object. Bring the document to the front of the MDI stack. Keep difference view open.

[CMP-R110]: Compare View shows the difference objects in the order shown in the document navigator tree (e.g. show variants before datatypes).

Export of Differences

[CMP-R131-DiffExport] Compare View allows to export the computed difference in the formats

  • Text,
  • XML,
  • XHTML.

Diff Export

[CMP-R131-Filters] Compare View does not apply GUI filters to the diff export.

See also Compare via Command Line.

XML Diff Export Structure

There are few tags which carry general information about the diff and which exist only once in the exported XML:

  • <candeladiff> Encloses the whole exported diff.
    • Note: as of v12, the opening tag is not exported (CDS-71858).
  • <sourcefile> Left file of comparison.
  • <targetfile> Right file of comparison.

Each difference is represented by one of the following tags:

  • <modify> Objects exist in source and target, there is a differences between source and target.
  • <add> Object is missing in source, it only exists in target.
  • <delete> Object is missing in target, it only exists in source.

Properties

  • each difference has a unique id beginning with an underscore (e.g. <modify id='_5'>).
  • Contents of <modify>:
    • <qpath> The qpath to the entity in source and target, if the path is the same, else:
      • <qpathsrc> The qpath to the entity in the source document, if it is different from the target one, and…
      • <qpathtgt> ... vice versa
    • <valuesrc> The value of the different object in source, and
    • <valuetgt> ... in target.
  • Contents of <add> and <delete> differences:
    • no <qpath> but only <qpathtgt> or <qpathsrc>
    • no <valuesrc> and <valuetgt>

Example: a DID is missing in target

<delete id='_19'>
<qpathsrc>qpath:/Base_Variant/[DID]DID_0xF414</qpathsrc>
</delete>
