Editing Protocol Services

  • In standard view, the chapter "Protocol services" is read-only.
  • In Expert View, you can edit directly in the list, and create new and edit existing Protocol Services.

Editing Protocol Services

Note: Some of the editing actions described below require an update of all DiagClassTemplates and DiagInstances of the document (e.g. after adding/removing service components).

Default Components for a Protocol Service

New protocol services must be created with a default set of components, depending on the primitive type:

  • Request:

    • ConstComp (spec = “serviceId”, name = “SID-RQ”, qualifier = “SID_RQ”, value = defined by user).

  • PosResponse:

    • ConstComp (spec = “serviceId”, name = “SID-PR”, qualifier = “SID_PR” value = value of Request + 0x40).

  • NegResponse:

    • ConstComp (spec = “serviceId”, name = “SID-NR”, qualifier = “SID_NR”, value = 0x7F),
    • ConstComp (spec = “serviceId”, name = “SID-RQ-NR”, qualifier = “SID_RQ_NR” value = value of Request),
    • SimpleProxyComp (destiny = “resCode”, name = “RESPONSE CODE”, qualifier = “RESPONSE_CODE”).

The Request primitive is always present, whereas primitives PosResponse and NegResponse must be selected on creation of a new protocol service.

Adding Protocol Service Components

Protocol service components must be added in the table of a primitive. On creation of a new protocol service component, a dialog appears which provides a selection of protocol service components (see below). Special cases are:

  1. MuxComp and NumeratorIterComp must have a selector (a SimpleProxyComp) which is to the left of the component. It must be possible to choose the selector from a list of proxy components in the selection dialog, since there is no means to set the selector to another proxy component after creation. If there is no proxy component in the primitive at all, then CANdelaStudio must create a new one first (before creating the MuxComp).

  2. StatusOfDtcProxyComp and GroupOfDtcProxyComp can only be added, if all necessary data types are available. Both classes inherit properties from SimpleProxyComp and can be created by selecting the appropriate specification in the selection dialog.

  3. EndMarkerIterComp needs an “end marker selector”. The default is always the very first component inside the EndMarkerIterComp.

The combo box “Specification” contains the items

  • “Any”,
  • “Data “,
  • “DTC”,
  • “OBD-DTC”,
  • “Environment Data” (only for option “Multiplexer”),
  • “Response Code” (only for option “Proxy”),
  • “Group of DTC” (only for option “Proxy”) and
  • “DTC Status” (only for option “Proxy”).

The combo box “Selector” contains...

  • all SimpleProxyComps which will be to the left of the new MuxComp after creation, or
  • “None (create new proxy)” if there are no proxy components at all.

After adding the component, the following must be done:

  • ConstComp: nothing. DiagClassTemplates and instances remain unchanged.

  • Variable Value (StaticComp): all DiagClassTemplates using the protocol service must be updated by adding a new unshared static component. This unshared static component must then be shared with already existing shared static components.

    To avoid problems with different bit lengths of shared static components, the overall bit length must be computed before creating the new StaticComp.

  • ProxyComp, IterComp: all DiagClassTemplates using the protocol service must be updated by adding appropriate unshared proxy components.

Removing Protocol Service Components

After removing the component, the following must be done:

  • ConstComp: nothing. DiagClassTemplates and instances remain unchanged.

  • StaticComp: all DiagClassTemplates using the protocol service must be updated by removing the static component from shared static components.

  • ProxyComp, IterComp: all DiagClassTemplates using the protocol service must be updated by removing the proxy component from shared proxy components.

Modifying Protocol Service Components

Protocol service components may only be modified if the following restrictions are met:

ConstComp: no restrictions. Length and specification can be edited at any time.

StaticComp: if the protocol service is already in use, then editing of the bit length must be prohibited.

ProxyComp: editing of the destiny must be prohibited. It must be set on creation of the Protocol service component and cannot be modified afterwards.

Editing the bit length of a proxy component is possible if...

  • the proxy component is not shared,
  • and if the maximum length of all data objects created in the diagnostic instance using the proxy component/protocol service is less than the maximum length entered by the user (CDS-3673).

Special cases are:

  1. MuxComp, NumeratorIterComp: selector cannot be modified.

  2. StatusOfDtcProxyComp, GroupOfDtcProxyComp: data type describing bit length cannot be modified afterwards.

  3. EndMarkerIterComp: one of the components lying inside this component must be specified as “end marker”. All components lying before the “end marker” must have fix bit length, and the “end marker” itself must not be greater than 4 bytes.

Creating a Protocol Service

Specify name, qualifier and service identifier of the protocol service.

Specify whether the protocol service has primitives Positive Response and/or Negative Response.

Specify whether primitives Request and (optionally) Positive Response contain a constant or variable value used to hold an identifier or the number of a sub function.

Specify data components of primitive Request.

Specify data components of primitive Positive Response.

Select a subset of negative response codes from a list.

Page "New Component"

For a Variable Value component (CDS-8032 R020):

  1. show a combo box for selecting the text table data type below option “Variable value”.

  2. fill the combo box with text table data types only, show an error message if there is no suitable text table data type if user clicks on [OK].

Property Page for Components

Controls “Name” and “Qualifier” are edit controls.

Depending on the selected type of protocol service component, the list “Specification” contains items for

  • Constants [PS-R300-Specification] or
  • Variable Values [PS-R400-Specification].

“Value” is a numeric edit control. It additionally provides a selection box to change the input format. It is disabled if the component is a Variable Value.

The controls are always visible.

Property Page for Data

Specify whether the protocol service transports data objects in its primitives Request and Positive Response.

Controls “Component”, “Name” and “Qualifier” do not change (i.e. they may be edited but they do not disappear or will be disabled).

All controls beneath control “Qualifier” are changing depending on the selection made in control “Component”:

  • “Constant”: one combo box for the specification, two edit controls for bit length and value.
  • “Proxy”: one combo box for the specification, two edit controls for min bit length and max bit length (see picture).
  • “Mux”: controls for specifying the data selector (name, qualifier, specification, min/max bit length)
  • “Iterator (n)”
  • “Iterator (End)”
  • “Iterator (Marker)”

Property Page for Negative Response Codes

Select one or several of the codes.
