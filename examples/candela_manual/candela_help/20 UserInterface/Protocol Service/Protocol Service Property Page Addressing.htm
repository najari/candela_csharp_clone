Support the "Suppress Positive Response Message Indication Bit (SPRMIB)"

[PSUI-R710] The read-only checkbox shows whether the services support the SPRMIB [PS-R710].

  • [PSUI-R710-nonUDS] For non-UDS, the checkbox is not shown.
  • [PSUI-R710-NoPR] If no positive response exists,
    • the checkbox is un-checked and insensitive.
  • [PSUI-R710-PR] if a positive response exists,
    • the checkbox is insensitive and shows the value from the subfunction component in the request
    • because the SPRMIB is actually transported on the line as part of the subfunction byte.

Bottom Part: Default Settings for New Services

Dialog Variations

There are variations of the bottom dialog part:

  • Dialog Variation with SPRMIB not Supported
  • Dialog Variation with SPRMIB Supported

CANdelaStudio shows one of the dialog variations, depending on...

  • the Protocol Standard of the template
  • for Protocol Standard UDS: whether the Protocol Service supports the Suppress Positive Response Message Indication Bit (SPRMIB) (shown by a checkbox in the top part of the page)

Dialog Behavior

  • [PSUI-R705] CANdelaStudio applies changes...
    • at once for all existing services, when you leave the underlying Protocol Service dialog with OK,
    • as a default for new services created in the future.
  • Physical and functional requests are controlled by separate settings.
  • For details about the settings, see the Protocol Service Addressing Feature.
  • For UDS, the dialog does not show data model properties that are fixed in UDS,
    • e.g. "ECU sends a response".
    • See the property descriptions in [PS-R760]ff. (CDS-39671 v11)
  • The sensivity of the controls is based on the Valid Combinations of Addressing Properties of a Protocol Service in the description of the addressing feature.
  • Dialog defaults: see the description of the addressing feature [PS-R740]ff.

Dialog Variation with SPRMIB not Supported

Protocol Service Property Page "Addressing" for Protocol Service with SPRMIB not set

If SPRMIB is not supported, ...

  • [PSUI-R740-NoSPRMIB] there are not controls to specify "Test system sends physical request..." [PS-R740],
  • [PSUI-R750-NoSPRMIB] the checkbox "ECU sends a response" [PS-R760] is shown.
    • [PSUI-R750-NoPR] If the Protocol Services does not have a positive response, “ECU sends a response...” is un-checked and insensitive.

Dialog Variation with SPRMIB Supported

Protocol Service Property Page "Addressing" for Protocol Service with SPRMIB set

If SPRMIB is supported,...

  • [PSUI-R740-SPRMIB] the property "Test system sends..." [PS-R740] can be specified,
  • [PSUI-R750-SPRMIB] "ECU sends a response" [PS-R760] is fixed by UDS and represented by a text.
  • If “Test system sends...” is not checked, ...
    • [PSUI-R750-NotSends] “ECU sends a response...” is un-checked and insensitive
    • [PSUI-R760-NotSends] the radio buttons "The test system shall set the SPRMIB..." have "user-defined" selected and are insensitive.
  • In constellations [PS-R770] where the property "Test system shall set the SPRMIB..." is fixed,
    • the radio buttons "The test system shall set the SPRMIB..." are insensitive.
