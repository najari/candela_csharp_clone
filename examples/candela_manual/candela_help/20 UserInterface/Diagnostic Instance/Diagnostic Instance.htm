Diagnostic Instance

See also the Diagnostic Instance Feature.

Right Side of a Diagnostic Instance in Tree

Name

You can enter the name of the diagnostic instance in the Name entry field. The name has to be unique within the diagnostic class or variant.

Properties

The properties button to the right of the "Name" entry field opens the properties dialog of the diagnostic instance.

Description

The Description entry field is read-only. To edit the description, open the properties dialog (see above).

Identifier, Type...

Diagnostic Instance Identifier

In diagnostic instances that may occur more than once, the dialog shows an entry field e.g. for the Identifier of the diagnostic instance, below the "Description" entry field.

If all Used ProtocolServices of the diagnostic class reference the same text table, then the edit control allows selection by text from the text table (CDS-8032 R030).

Name of the Property

Actually, the name of the entry field depends on the diagnostic class as defined in the template: it may be "Identifier", "Address", "Subfunction", "Type" etc. The meaning in the diagnostic protocol is different, but the role for the data model is the same: the value distinguishes multiple diagnostic instances within a diagnostic class.

Suppress Positive Response Message Indication Bit

If the service supports the Suppress Positive Response Message Indication Bit (SPRMIB), the value specified is a place-holder only - its highest bit does not matter:

  • you may e.g. specify 0x01 or 0x81 at authoring time in the document.
  • when the user of a test system at runtime sends a service of the diagnostic instance, he can decide at that time to send either 0x01 or 0x81 (i.e. set the highest bit or not), independent of the value in the document.

Associated Data Type

The properties button to the right of the entry field opens the property dialog of the associated data type. The data type describes the allowed values of the identifier etc.

Write-Protection for DIDs

In a diagnostic instance corresponding (as of D214 in spec of CDS-37944) with a DID, CANdelaStudio shall set the Identifier write-protected (CDS-39293 8.5).

Services

Under "Service":, you can create or delete services for the diagnostic instances. See the detailed description about the Services list.

Telegram Tables

[DIUI-R300] The telegram tables (data object lists) show and edit the data transported for the respective combined component.

E.g. for a UDS Protocol Service 0x22, typically a telegram table "Data (zz)" defines the data to be transported in the positive response at the "zz" abbreviation in the response sequence 62 01 12 zz.

  • CANdelaStudio shows "DID" on the tab header of the telegram:

"DID" on the Telegram Table Hedaer

Showing DID Contents in Diagnostic Instance (CDS-40405, CDS-69423, 9.1)

[DIUI-R310]

  • In...
    • a telegram table with "DID Data Reference" semantics set [DID-R050-DIDDataReference] (CDS-40405 9.1; = telegram header shows "DID", see previous chapter),
    • or in a diagnostic class that is DID Enabled [DCL-D001],
  • if the telegram contains a DID Data Reference [DID-R160] as the single data object in a telegram [DCL-D001-b2] (CDS-69423 9.1),
  • CANdelaStudio...
  • [DIUI-R310-content] shows the content of the referenced DID in the telegram table
  • [DIUI-R310-goto] shows a context menu item "Goto DID" (above Go To Data Type)
  • [DIUI-R310-properties] shows a context menu item "Properties of DID Data Reference" (above "Properties of Data Type...") to open the properties dialog of the DID Data Reference (modifiable)
  • [DIUI-R310-hide] does not show the context menu entries:
    • New DID Data Reference
    • New DID Reference
    • Move to New DID
  • [DIUI-R310-operations] applies all operations to the DID contents
  • [DIUI-R310-context] otherwise uses the context menu and behaviour/restrictions of the DID context for this telegram table
  • [DIUI-R310-confirm] Shows the confirmation "You are about to modify a shared diagnostic instance" also for a modification of the DID contents.
    • If confirmed, CANdelaStudio unshares (replaces by a copy) the diagnostic instance and the DID (CDS-70579 v10).
  • [DIUI-R310-notSharedConfirm] When the diagnostic instance is not shared, but the DID is shared, CANdelaStudio prompts to unshare the DID (CDS-70579 v10).

Note - not covered: "Change DID" in context menu which lets the user choose a new DID for this instance.

Negative Response Codes

Negative Response Codes at a Service

[DIUI-R410] The right side for a diagnostic instance lists the Negative Response Codes of each service.

[DIUI-R420] If a service is blocked [STTR-R020-no] in some state of a state group, the list automatically shows the NRC associated with that state group [NRC-R050].

  • [DIUI-R420-Icon] The NRC is shown with a special icon .

You can show and hide the list of negative response codes with the buttons << and >> at the right end of the services list, or by clicking the rc hyperlinks.

The format of the list is the same as in the Available Negative Response Codes (NRC Pool) page.

Override the NRC description: select the description cell, then press F2, or click again.

See the Negative Response Codes at a Service feature.
