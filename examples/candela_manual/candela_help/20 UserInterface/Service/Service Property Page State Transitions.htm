Service Property Page "State Transitions"

The page shows one separate sub-page for each state group.

Sub-Page for one State Group

Each sub-page offers two Views, which you can select by the following buttons:

  • Shows a table in which you can edit the transitions for the service
  • Shows a graph of the transitions for the service (see below)

Editing (Tabular)

Service Property Page "State Transitions"

Service/Job is relevant for ...

This is un-checked if all cells (transitions) read "(yes)", i.e. the service is not relevant for the state group.

As soon as you set a cell value to non "(yes)", CANdelaStudio automatically check the checkbox.

To reset all cells to "(yes)", just un-check the checkbox.

This check-box is GUI convenience only; actually the “relevance” information is derived from the state transitions, there is no separate “relevance” info.

Impact of "Link Target Group to State" for "Service/Job is relevant for..."

With the Link Target Group to State feature,

  • changes to the state transitions of the service...
  • can be coupled with changes to the relevance of the service for a target group.
  • Note: this applies to services only, not for jobs.

[SVCUI-D200] This may lead to a situation where you cannot check "is relevant..." because the respective modification of the target group relevance is not allowed:

  • to unset "is relevant" for State Group "Authorization" means: set all state transitions to "(yes)".
  • For states linked with target groups,
    • when setting the state transitions to "(yes)",
    • CANdelaStudio must automatically set the linked target groups to be "relevant" (checked) at the service.
  • But if a target group is "not relevant" (un-checked) at the diagnostic instance,
    • it must also be "not relevant" at the service.
    • This is a CANdelaStudio consistency condition.
  • Therefore, setting "relevant" at the service is not allowed for target groups which are "not relevant" at the diagnostic instance.
  • Therefore, unsetting "is relevant" for the State Group is not allowed in this situation.

Table

Each page contains a table with one row.

The second and further columns represent the states of the state group.

The cells represent the behaviour of the ECU in the given state (column) when it receives a request of the given service. The values have the same meaning as in the State Dependency chapter.

For write-protection of columns, see Editing of State Transitions.
