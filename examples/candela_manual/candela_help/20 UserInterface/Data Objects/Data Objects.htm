Data Objects (Telegram Table)

See the Data Objects Feature.

CANdelaStudio Telegram Table Showing Various Kinds of Data Objects

A telegram table displays data objects in a list.

Columns

Byte No., Bit Pos.

The "Byte No." and "Bit Pos." columns contain the start position of a data object within the telegram.

  • The "Byte No." is relative within the telegram table and therefore always starts with zero.
  • If the data object is on top-level (directly in the list), the "Bit Pos." is empty.
  • Only byte-sized data starting at byte positions can be positioned directly in the list. Other data must be put into a bit-field.
  • If the data object is within a bitfield, the "Byte No." is empty, and "Bit Pos." denotes the relative position within the bitfield.
  • "Bit Pos." normally starts with zero, but CANdelaStudio supports starting with the most significant bit, see Bitfield Display Variation.

CANdelaStudio calculates the values in these columns automatically from the lengths of the data objects, you cannot modify them directly.

Name

The "Name" column contains the name of the data object.

For reserved objects, the name is typically "(reserved)".

Data Type

[DOUI-R200]

  • [DOUI-R200-DataObject] For a data object, CANdelaStudio shows the name of the referenced data type [DO-R100].

  • [DOUI-R200-Bitfield] For a bitfield, CANdelaStudio shows the name of the referenced data type [BF-R100].

  • [DOUI-R200-Reserved] For a reserved object [DO-R200 Reserved], CANdelaStudio shows "reserved (n bytes)" (the number "n" must be > 0).
  • [DOUI-R200-DIDDataReference] For a DID Data Reference [DID-R160] in a telegram table, CANdelaStudio shows in the "Data Type" column (CDS-38517)...
    • the DID identifier (hexadecimal, leading "0x", zero filled to 2 bytes)
    • a blank
    • the DID name
    • Example: "0x100 Braking".

  • [DOUI-R200-DIDReference] For a DID Reference [DID-R180] in a telegram table, CANdelaStudio shows in the "Data Type" column the same info as for a DID Data Reference (see above).

Default

The "Default" value is typically used when a test system constructs a request, but may be changed by the user of the test system.

How the value is displayed depends on the display format set up in the data type.

Constant

The "Constant" value describes a value known to be fix in the ECU implementation, e.g. a version number. A test system (like the Vector CANoe diagnostic console) may hide the constant value when asking the user for input of request data.

The "Constant" value described at a data object is not directly used to identify the ECU variant - a test system typically uses a separate description in the variant identification.

Description

The "Description" column contains the description of the data object.

Multiple lines are shown in the list as one line, separated by a blank. To comfortably edit a description that contains multiple lines, the property dialog provides a large edit control.

Attributes

[DOUI-R700] The telegram table shows data object attributes that have the "visible in separate table column" flag [ATTR-R090-DataObj] set.

Properties of Self-Referencing Multiplexer (CDS-40502 8.5 SP2)

  • [DOUI-R800 Self-Referencing Mux] for a data object that references an identity data type [DTMUX-R800-Identity] which represents a self-referencing Mux, ...
    • [DOUI-R800-a] CANdelaStudio shall additionally provide a context menu item "Properties of Self-Referencing Multiplexer" below "Properties of Data Type".
    • [DOUI-R800-b] if the user selects the context menu item, CANdelaStudio shall open the data type property dialog for the referenced Mux data type.

Note: for a data object that does not represent a self-referencing Mux, CANdelaStudio shall not show the context menu item.

Using Keyboard (CDS-71870 v13)

  • [DOUI-R810] TAB leaves editing and navigates to the next cell.
  • [DOUI-R815] Shift-TAB leaves editing and navigates to the previous cell.
  • [DOUI-R820] ESC leaves editing, discarding changes.
  • [DOUI-R830] In the description control (multi-line):
    • [DOUI-R830-ENTER] ENTER inserts a line-break in the text.
    • [DOUI-R830-CtrlENTER] Ctrl-ENTER leaves editing, accepting changes.
    • [DOUI-R830-Focus] after leaving editing (with a key above, button OK or Cancel), a cell has focus,
      • such that e.g. pressing key Cursor-left navigates to the previous cell, F2 edits a cell.
