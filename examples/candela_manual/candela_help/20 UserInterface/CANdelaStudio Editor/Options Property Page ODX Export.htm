File | Options | ODX Export

Ribbon Tab File | Options, Page "ODX Export"

The dialog represents the ODX Export Options [ODXE-R200], ...

  • stored in the INI file
  • possibly overridden by a Special Attribute
    • with the qualifier equal to the name of the INI option;
    • the dialog does not visualize such an override (cf. CDS-35047).
  • The dialog can be write-protected.

General

Format the ODX file

Check this option if you want the ODX file to be output in formatted form (i.e. including indentations).

See [ODXE-R300].

Store log messages within ODX file

Check this option if you would like to export output messages in the ODX file.

CANdelaStudio stores the messages in an XML comment at the beginning of the ODX file.

See [ODXE-R1030-Log].

Abort on warnings

[OPT-R240] Check this option if you would like the export to abort if warnings occur.

If the option is not checked, the export ignores warnings (but still stops if errors occur).

See [ODXE-R1001-Warnings].

Always use local ODX export installation

[OPT-R245] Check this option if you...

  • have installed a newer version of the ODX export as an independent application, but
  • want to use the older built-in version (stored locally to the CANdelaStudio installation)

For details, see [DXEXE-R110].

Layers/Categories

One separate file per DIAG-LAYER

Check this option if you would like to export every DIAG-LAYER in a separate file.

See [ODXE-R1050-Files].

PROTOCOL layer for supported interfaces

Check this option if you would like to export a protocol layer for each supported interface.

See [ODXE-R1040-ComParam].

COMPARAM-SPEC

Check this option if you would like to export COMPARAM-SPECS.

See [ODXE-R1040-ComParam].

Only necessary COMPARAM-REFs

[OPT-R360] Check this option if you would like to export a COMPARAM-REF only if the value of the corresponding communication parameter of the CANdela document differs from the value of the COMPARAM-SPEC.

See [ODXE-R1040-ComParam].

ISO COMPARAM-SPECs

Check this option if you would like to export ISO COMPARAM-SPECs.

See [ODXE-R1040-ComParam].

VEHICLE-INFO-SPEC

Check this option if you would like to export VEHICLE-INFO-SPEC.

See [ODXE-R1130].

Contained ECU-SHARED-DATA

Check this option if you would like to export contained ECU-SHARED-DATA.

See [ODXE-R1120].

Available DTCs as ECU-SHARED-DATA

Check this option if you would like the DTC pool ("Available DTCs") to be exported as ECU-SHARED-DATA. The DTCs of the DTC pool will be referenced by the BASE-VARIANT and the ECU-VARIANTs by using DTC-REFs.

See [ODXE-R1040-ComParam].

TMX file (multi-language ODX)

[OPT-R350] Check this option if you would like to create a TMX file (Translation Memory eXchange) while exporting.

  • You can have multiple languages in a CANdela document and translate using the Translation View (in Pro / Admin edition).
  • Then you can let ODX export create a TMX file, which contains the translations of the multi-language document.
  • By this, you will have the ODX file for diagnostics, and the TMX file for translations.

See ODX Export [ODXE-R1160].

Optimizations

Export only referenced data types

This option excludes unused data types.

See [ODXE-R310].

Export only Java-Jobs

Check this option if you would like to export Java jobs only, not jobs of other types.

See [ODXE-R1090-Jobs].

Export two PARAMs for a bitfield only if necessary

Check this option if you would like to export bit fields in two PARAMs. This is necessary if bit fields are used as identifying features.

See [ODXE-R1100-PhysBitfield].

Reuse DTCs

Check this option if you would like identical DTCs to be reused by using DTC-REFs.

See [ODXE-R1100-ReuseDTCs].

Reuse identical environment data

Check this option if you would like identical environment (snapshot) data to be reused.

see [ODXE-R1000-EnvData].

Specific properties

DESCRIPTION

Check this option if you would like to export DESCRIPTIONs.

  • formatted: Check this option if you want the DESCRIPTIONs to be output with formattings (bold, italic, etc.).

  • with attachments: Check this option if you want to export attachments contained in description fields.

See [ODXE-R320].

SDG at DTC-DOP

Check this option if you would like to export SDGs to the DTC-DOP.

See [ODXE-R1100-FaultMem].

CANdela service information

Check this option if you would like to export CANdela specific service information.

See [ODXE-R1080-ExportService].

Object ID (OID)

Check this option if you would like to export Object IDs.

See [ODXE-R1020-OID].

Make ECU-VARIANT.SHORT-NAMEs unique

Check this option if you would like to export unique ECU-VARIANT.SHORT-NAMEs.

See [ODXE-R1050-Unique].

ODX-ID: Use ECU qualifier as prefix

Check this option if you would like to use the ECU qualifier as a prefix for ODX-IDs.

See [ODXE-R1020-ID].

Create MATCHING-REQUEST-PARAM in response

Check this option if you would like to export parameters of type MATCHING-REQUEST-PARAM within positive responses (ODX: POS-RESPONSE)

See [ODXE-R1080-Matching].

Use POS-RESPONSE-SUPPRESSABLE (ODX 2.2.0)

This option is relevant for ODX 2.2.0 only.

Check this option if you would like to export elements of type POS-RESPONSE-SUPPRESSABLE for those services having the suppress positive response message indication bit set with setting "User defined". In doing so, the POS-RESPONSE-SUPPRESSABLE elements are pointing to a parameter in the request which is used to decide whether the service responds with a positive response or whether the response is suppressed.

See [ODXE-R1080-DiagClass].
