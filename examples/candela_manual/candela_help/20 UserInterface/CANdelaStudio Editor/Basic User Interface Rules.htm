Navigation to a Right Side

[UI-R100] When the user enters a tree node with a list to the right,

  • [UI-R100-Focus] the list shall have focus,
  • [UI-R100-Selection] the first list element (if one exists) shall be selected,
  • [UI-R100-Sort] the list shall be sorted ascending by the identifying property (e.g. the Identifier of a DID).
  • [UI-R100-Filter] the filter shall be reset. Preserve the filter within the CANdelaStudio session!

When the user navigates to a specific element (e.g. via a menu item "Go to..." or via path):

  • [UI-R100-NavSelection] that element shall be selected,
  • [UI-R100-NavFilter] if the element is excluded by the filter, CANdelaStudio shall reset the filter so that the element becomes visible.

Prompt for Modifying Operations

[UI-R320]

  • if...
    • the user starts a modifying operation for which CANdelaStudio usually prompts for confirmation (e.g. deletion of an object).
    • but the operation is not allowed in the given data constellation,
  • then...
    • CANdelaStudio shall inform the user at once,
    • i.e. it shall not prompt for confirmation and only after "yes", inform the user that the operation is not possible.

Lists of Objects

[LIST-D100 Lists of Objects]

Copying

  • [LIST-R100] Copy data from a list to the Windows clipboard (e.g. for use in a spreadsheet):
    • select the list rows,
    • then press Ctrl-C.
  • This copies "what you see" in the list to the clipboard (CDS-6703, CDS-11314, 6.0).

List Sorting

  • [LIST-R200] sort by one column:
    • left click on the table header of the column
    • [LIST-R250] The table indicates the sort order.
  • [LIST-R210] sort by multiple columns:
    • left click on the table header of the first column,
    • then hold the Ctrl key and left click on the table header of one or more other columns
    • [LIST-R250] The table indicates the sort order.
  • [LIST-R220] reverse the sort order:
    • left click the table header again
    • [LIST-R250] The table indicates the sort order.
  • [LIST-R230] On first dialog entry within a CANdelaStudio session,
    • as a default, a list is sorted ascending by the contents of the first column.
    • There may be exceptions for lists with specific columns.
    • [LIST-R250] The table indicates the sort order.
  • [LIST-R240] On a subsequent dialog entry within a CANdelaStudio session,
    • a list is sorted as left in the former dialog entry.
    • [LIST-R250] The table indicates the sort order.
  • [LIST-R250] For each column used for sorting, the table header shows a symbol that indicates the sort order
    • up arrow: sort ascending
    • down arrow: sort descending

List Columns

  • [LIST-R700] The width of a column can be adapted by moving its right border in the table header.
  • [LIST-R710] On first entry of a dialog in a CANdelaStudio session, column are so wide that the contents of all rows is visible.
    • There may be exceptions for specific lists.
  • [LIST-R720] On subsequent entry of a dialog in a CANdelaStudio session, column are as left before.

List Selection

  • [LIST-R600] On entry of a dialog, a non-empty list has a selection. [LIST-R600-Default] Default: the first list element.

Navigating between List Cells

[UI-R300] If an edit control is active in a list cell ("edit mode"), then...

  • [UI-R300-TAB] TAB (on the non-last modifiable cell)...
    • quits edit mode in that cell,
    • [LIST-R300] navigates to the next modifiable cell and
    • enters edit mode there
  • [UI-R300-ShTAB] Shift TAB (on the non-first modifiable cell)...
    • quits edit mode in that cell,
    • [LIST-R310] navigates to the previous modifiable cell and
    • enters edit mode there
  • [UI-R300-TABLast] TAB on the last modifiable cell of the list...
    • creates a new element and
    • enters edit mode in its first modifiable cell.

Selecting Multiple Objects in a List

[LIST-R110]

  • [LIST-R110-Range] Select a range of multiple objects at once:
    • left click the first object row,
      • hold the Shift key and left click the last object row.
  • [LIST-R110-Values] Select multiple values (not a range) at once:
    • left click the first row,
      • hold the Ctrl key and left click any further desired rows.
  • [LIST-R110-Ranges] Select multiple ranges at once:
    • left click the first row,
      • hold the Shift key and left click the last row of the range,
    • hold the Ctrl key and left click the first row of the additional range,
      • hold the Shift and Ctrl keys and left click the last row of the additional range
    • repeat for further ranges.

List Property Editing (old style before v12)

Example: the Telegram Table.

  • [LIST-R400] You can Edit properties of a diagnostic object in a Property dialog:
    • [LIST-R400-Menu] use the "Properties" menu item in the context menu (right mouse).
    • [LIST-R400-DblClick] Most often, a double-click will work, too (a double click means "Open" which for some objects just navigates in the tree).
  • [LIST-R410] Edit directly in the list:
    • press key "F2"
    • (or left click twice, slowly)
    • (= [UI-R360-EditMode])
  • [LIST-R420] Edit multiple objects at once:
    • Note: not all lists in CANdelaStudio support this feature.
    • Select the objects [LIST-R110];
    • be sure to left click the last object row in the column you want to set,
    • press F2. CANdelaStudio shows...
      • an edit control (for text properties), or
      • a selection list (for an enumeration property);
    • enter or select the value to assign,
    • press ENTER.
      • CANdelaStudio assigns the value in all selected rows.
    • (= [LIST-R430], [LIST-R440])

List Property Editing (new style since v12)

Example: the Events list [EVUI-R005].

  • [LIST-R1400] You can Edit properties of a selected diagnostic object in a Property sheet to the right.
  • [LIST-R1420] Edit multiple objects at once:
    • select the objects [LIST-R110];
    • modify properties in the property sheet.

List Filter Handling

[LIST-R500] If you enter text in a "filter" edit control for a list of objects, the list shows only "matching" lines: - The match is case insensitive * e.g. filter text A matches a line containing a. - If the filter text contains blank separated words, a line matches if it contains at least one of the words. * e.g. filter text A B matches a line containing A and a line containing B. - If the filter text contains sub-text enclosed by double quotes, a line matches if it literally contains that sub-text. * e.g. filter text "A B" does not match a line containing A, but one containing A B.

Note: not all lists in CANdelaStudio support this feature.

List Insertion Position (General Case)

  • [UI-R330-MagicLine] an element inserted via the magic line shall be placed in the data model at the end of the list (not in the middle, in order to allow creating multiple elements conveniently)
  • [UI-R330-Insert] otherwise an element inserted shall be placed in the data model before the currently selected element in the list (i.e. the rest of the list including the selection is shown "pushed down")

Identifying Number and List Insertion Position

[UI-R335] If the objects shown in the list have a number as an identifying property,

  • and the list is typically sorted by that number,
  • e.g. DTC code, DID identifier, Snapshot Record Number
  • CANdelaStudio sets the number and hence the visible insertion position as follows.

[UI-R335-Add]: CANdelaStudio creates the new object based on a "reference" object R (for DIDs: CDS-68394 9.1):

  • if there is no Reference object, CANdelaStudio takes
    • the first valid number,
  • otherwise,
    • for the number, it uses the minimum unused valid number starting at <number of R> + 1 (increasing values),
    • if none exists, it uses the maximum unused valid number starting at <number of R> - 1 (decreasing values),
    • if none exists, it fails.

[UI-R335-Reference] Reference Object R

  • if the list is empty, there is no Reference Object;
  • if the visible list is empty (due to a filter), take R := the object with maximum identifier;
  • if you press a toolbar button or use a context menu:
    • if the first visible object is selected, take it for R
    • otherwise (i.e. a second or later object is selected), take for R the object shown above the first selected object.
  • if you press the magic line below the list:
    • take the last visible object for R.

List Display after Modifying Operations

[UI-R340] After a modifying operation, ...

  • [UI-R340-Focus] the list shall have focus,
  • [UI-R340-Sort] the sort-order of the list shall be preserved,
  • [UI-R340-Filter] the filter shall be preserved,
  • [UI-R340-SortIns] inserted elements shall be shown in the position according with the list sort order
  • [UI-R340-SelIns] inserted elements (New, Paste, magic line...) shall be selected
  • [UI-R340-SelMod] after a modification of elements,
    • they shall still be selected
  • [UI-R340-SelDel] after deleting elements, ...
    • if any of the previously selected elements still exist (i.e. could not be deleted), they shall still be selected;
    • otherwise the element at the first previously selected position (if it exists), or
    • the last element shall be selected.

Right Click in List

[UI-R350]

  • [UI-R350-Element] a right click on an element shall...
    • ... pull focus to the element
    • ... show the context menu for that element (not the previously focussed one)
    • firing a menu item in the context menu shall trigger the operation on that element (not the previously focussed one).
  • [UI-R350-Empty] a right click on the empty list area shall...
    • remove focus from the previously focussed list element
    • ... show a special context menu that has no items for a concrete selected element.

Controls for Optional Properties and Mass Operations

Context: Optional Properties

Some data model properties are optional.

Example: in the context of Events, you may specify that a counter...

  • is volatile, or
  • is nonvolatile, or
  • you don't care, or don't want to decide yet.

[UI-D400] CANdelaStudio shows the third state as "undefined".

  • Motivation: this is consistent with the special value "undefined" in enumerations, which has the same semantics.
  • Source code may typically represent it by a "null" value.
  • The following are synonym:
    • not having a value
    • having value "undefined"
    • having value "null"
    • being empty.

The user interface presents the "undefined" state in a special way.

Multi-Selection in Property Sheet

[UI-D410] When you...

  • select multiple objects in a list, and
  • the objects have different values for a given property,
  • the property sheet that represents all selected objects shows and handles these different values in a special way, as described in the following.

Boolean

Controls for Boolean Properties and Mass Operations

[UI-R400] The user interface represents a Boolean property by a checkbox.

  • [UI-R400-single] with a single selection, the checkbox toggles between checked and un-checked for each click
  • [UI-R400-multi] dito with a multi-selection:
    • in the case the selected objects have different values for the Boolean, the user interface shows the checkbox as "indifferent" ("tri-state", grayed);
    • additionally, a text label gives a hint that there are "different values"
    • on click, the indifferent checkbox gets checked (= sets the property to true at all selected objects)
    • a further click un-checks the checkbox
    • a further click again checks the checkbox - in the user interface, there is no way back to the initial state where the objects had different values.

Optional Boolean

An optional Boolean property has the values true, false and undefined (as of [UI-D400]).

Controls for Optional Boolean Properties and Mass Operations

[UI-R410] The user interface represents an optional Boolean property by 3 radio buttons.

  • Motivation: using radio buttons makes the "undefined" state explicit, and avoids confusion with the "indifferent" state of a multi-selection.
  • [UI-R410-multi] for a multi-selection of an optional Boolean,
    • in case the selected objects have different values (true/false/undefined) for the optional Boolean, the user interface shows no radio button selected,
    • additionally, a text label gives a hint that there are "different values"
    • any click on one of the radio buttons sets the property to the respective value at all selected objects.
    • in the user interface, there is no way back to the initial state where the objects had different values.

Integer

Controls for Integer Properties and Mass Operations

[UI-R450] The user interface represents an Integer property by an edit field.

  • the edit field restricts input to the allowed character set,
    • e.g. digits only for an unsigned integer
  • depending on the context and possible values, the edit field may additionally have...
    • buttons to increment/decrement the value, or
    • a selection list for predefined values
  • [UI-R450-single] with a single selection, the edit field always contains a numeric value
    • there is no "empty" state of the edit field
    • initially, CANdelaStudio sets the value to some default.
  • [UI-R450-multi] with a multi-selection:
    • in case the selected objects have different values for the integer, the user interface shows the input control empty and sensitive
    • additionally, a text label gives a hint that there are "different values"
    • if you enter a value, CANdelaStudio assigns that value to the property at all selected objects
    • in the user interface, there is no way back to the initial state where the objects had different values.

Optional Integer

An optional Integer property has numeric values and undefined (as of [UI-D400]).

Controls for Optional Integer Properties and Mass Operations

[UI-R460] The user interface represents an optional Integer property by...

  • an edit field for the integer value, and

  • a button to reset the value to "undefined".

  • [UI-R460-single] with a single selection, the controls represent...
    • either "undefined": the edit field shows a placeholder "(undefined)" and is sensitive, the button is insensitive
      • entering an integer value assigns that value to the integer property
    • or an integer value: edit field is sensitive and contains a value, the button is sensitive
      • initially, CANdelaStudio sets the value to some default
      • pressing the button sets the value to undefined
  • [UI-R460-multi] with a multi-selection of an optional integer:
    • in case the selected objects all have undefined,
      • the user interface shows the edit field sensitive, the button is insensitive
      • if you enter a value, CANdelaStudio assigns that value to all selected objects
    • in case the selected objects have different integer values, or some have undefined, while others actually have an integer value,
      • the user interface shows the edit field empty and sensitive, the button is sensitive
      • additionally, a text label gives a hint that there are "different values"
      • if you enter a value, CANdelaStudio assigns that value to the property at all selected objects
      • if you press the button, CANdelaStudio sets the value to undefined at all selected objects
      • in the user interface, there is no way back to the initial state where the objects had different values.

Dialogs

[UI-D1000 Dialogs]

Modal Dialog Behavior

  • [UI-R1100] A modal dialog is not shown in the Windows task list
    • (= which is shown by Alt-TAB, and at the bottom of the screen)
  • [UI-R1110] When a modal dialog is open, a click into the CANdelaStudio application window does not bring the application window to the foreground.
  • [UI-R1120] A dialog is resizable at the corners and at the edges (cf. CDS-39825 U004)
    • [UI-R1120-Flow] resizing moves controls in a reasonable way:
      • which elements are fixed
      • minimum size of variable-size elements
      • relation of multiple variable-size elements
    • [UI-R1120-Gripper] The bottom right corner has a visual indication that the dialog is resizable.
    • [UI-R1120-Min] At the minimum dialog size, it is still possible to use and leave the dialog.
  • [UI-R1130] On entry, the first control at top-left has focus
    • i.e. typing enters data into that control

Dialog Layout

  • [UI-R1200] The visual order corresponds with some logical order (workflow, importance, …).
  • [UI-R1210] Controls are aligned meaningfully:
    • Related controls are aligned where reasonable.
    • Similar things look similar.
  • [UI-R1240] Distances
    • [UI-R1240-Controls] Distances between controls are identical
    • [UI-R1240-Related] Except: related things are positioned closer to each other than others
    • cf. the Gestalt principles
      • [UI-R1240-Border] Distances between controls and the border are identical.
  • [UI-R1220] Buttons are in the order OK / Cancel / Yes / No / Apply / Help.
  • [UI-R1230] The text of buttons that open a further dialog ends with "...".

Dialog Keyboard Usage

  • [UI-R1300] Pressing ESC closes the dialog without modification (same as button Cancel).
  • [UI-R1310] Pressing OK closes the dialog and applies the changes.
  • [UI-R1320] Pressing F1 opens a related help page.
  • [UI-R1330] When an edit control in the dialog has focus,
    • after pressing Alt-TAB twice
      • (switching to another application and back to CANdelaStudio),
    • the edit control still has focus
      • (i.e. typing inserts characters).
  • [UI-R1340] When an edit control in the dialog has focus,
    • pressing ENTER applies default action
      • (one of the global buttons OK / Cancel...).
  • [UI-R1350] The TAB key navigates throught the controls in left-to-right, top-down order.

Mouse Scrolling

  • [UI-R1410] When you move the mouse pointer over a combo-box (without giving it focus) and scroll the mouse wheel, the selection does not change.
  • [UI-R1420] When you move the mouse pointer over a group of radio buttons (without giving them focus) and scroll the mouse wheel, the selection does not change.
