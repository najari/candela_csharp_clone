Data Type Dialog

Restrictions for Editing

If a datatype is already used, you can no more modify properties that influence the length of the datatype (e.g. bit length and field size).

Motivation: all telegrams containing data objects that reference the data type would have to be adjusted. If the bit length of the data type changes, the positions of all data objects that follow the data object with this data type must be adjusted. This could have unforeseen consequences.

Depending on which length you entered under "Bit length / Field size", the "Encoding" selection list shows available encodings for that length.

Name

Shows and lets you edit the name of the data type (as in the General page).

Tip: it may be helpful to include the size of the data type in its name and qualifier, like “HexDump (1Byte)”, “ASCII (256)”.

Bit Length / Field Size

The length of the data type specifies the length of all data objects and bitfields that reference the data type.

Length (Byte:Bit)

Specifies...

  • for an individual value with fixed length (atomic, non-field): its length
  • for a field data type: the length of one element (automatically defined by the encoding)

The left edit control defines the number of bytes, the right edit control defines the number of bits.

When you enter a number of bits >= 8, CANdelaStudio automatically computes the number of bytes so that the number of bits is < 8.

Field fix (Elements)

Specifies a field (array) with a fixed, specified number of elements (a string for example).

The input control defines the number of elements.

Field variable (min:max elements)

Specifies a field (array) with a variable number of elements.

  • the left input control defines the minimum number of elements,
  • the right input control defines the maximum number of elements,

Consumption

Shows the maximum space consumption of a value created for the given data type, in bits and bytes, including leading size bytes or a terminating zero element.

For a field (array) data type, the number of elements is appended, e.g.

  • "[3]" = 3 array elements
  • "[3..5]" = 3 to 5 array elements

Bitmask

For numeric encodings, the optional bitmask is applied during the conversion of values.

Byte Order

The byte order is applicable for element sizes > 1 byte.

Encoding

The encoding combo-box shows only entries available for the bit length / field size selected in the controls above.

Example: to specify an "IEEE Float (double)" encoding, the length must be 8 bytes.

Display Format

The display format combo-box shows only entries available for the selected encoding [DTDEP-R120].

CDS-38786 (8.5) corrects the handling of BCD.

String Type

The "String type" combo-box is only released if you have selected

  • "Bit Length / Field Size": either "Fixed field" or "Variable field (min:max)", and
  • "Encoding" either "ASCII" or "UNICODE".

Select here the type of string termination.

Precision

The Precision input field in the Properties dialog of a data type is enabled if the following conditions are met:

  • Raw value and Formula conversions
    • Length: 4 or 8 bytes
    • Encoding: "IEEE Float (single)" or "IEEE Float (double)"
    • Display format: "Floating point"
  • Linear, Characteristic curve and Piecewise linear conversions:
    • Display format: "Floating point"

See Data Type Precision.

Note: CANdelaStudio used to show the explanation "significant digits" in the property dialog (correction: CDS-39461) which was misleading ("significant digits" includes the digits before the decimal point). The toolchain correctly used the value as "decimal places".

Unit

The input control shows / edits a physical unit (e.g. "°C", "km", "U/min", "kp", "hp").

The unit can consist of any characters and may be a maximum of 65535 characters long.

If configured in a special attribute, the dialog allows selection from a list of predefined units.

Pages

  • Text Table
  • Linear
  • Characteristic Curve
  • Piecewise Linear
  • Procedure

  • Formula
    • Formula Raw to Phys Formula.

  • Mux

  • End-of-Service Iteration
