Property Page "Settings"

See the Requirements Settings (Data Model).

The dialog has two parts:

  • Property List (top of dialog)
  • Settings (bottom of dialog)

Requirements Property Page "Settings"

Property List

The list on top of the Property Page "Settings" allows inspection and editing of user-defined properties [RQ-R040].

Name

[RQUI-R240] The "Name" column shows localized.

New

A new user-defined property can be created by clicking the New button or clicking the magic line.

If a row is selected, the new user-defined property will be inserted before the selected row. Note: this refers only to the order of the columns in the requirement list. Technically the new user-defined property will be added at the end of the corresponding user defined property list (common or dtc).

If no row is selected, or when clicking the magic line, the user-defined property will be added at the end of the list.

The default settings for creating new user-defined properties are

  • value type = String
  • property type = (all).

Specific Columns

  • [RQ-R030-Identifier]: name "Identifier", value type = Number, property type = (all).

Delete

[RQUI-R210-Mandatory] You cannot delete mandatory properties.

[RQUI-R210-Optional] You can delete optional specific properties [RQ-R030-Optional] (CDS-39287 8.5 SP2).

Values have Type (Property Type)

The value type of the property [RQ-R040-Type] can only be string or int, which can be selected in a combo box.

For Requirements of Type

[RQUI-R250] The column shows the requirements type(s) at which the property exists.

It is...

  • [RQUI-R250-Specific] fix for specific properties [RQ-R030-Optional],
  • [RQUI-R250-UserDefined] modifiable for user defined properties [RQ-R040-ForType].

In-Place Editing

The name and the value type and the property type can be changed by editing the cells of the table.

Fix Properties

The fix properties are shown in another color to indicate that they cannot be deleted.

Move Up / Move Down (Order of Properties)

Further in this form the order of the property columns of the requirements list can also be defined with the help of Move up/Move Down. (R240.0)

Show in Table

The checkbox to the left of the first cell "Name" defines whether the property is shown in the requirement list (R240.0).

Settings

The list at the bottom of the Property Page "Settings" provides general settings for requirements.

Prefix for new ID

[RQUI-R100-IDPrefix] CANdelaStudio uses this prefix [RQ-R092] for the requirements ID [RQ-R020] of a new requirement.

Default Data Type for Generation

[RQUI-R100-DataType] The combobox specifies the optional default data type [RQ-R094] for creating data objects from requirements.

Library / Variant

[RQUI-R100-Variant] the CANdelaStudio requirements GUI provides a selection of a library or variant [RQ-R093] for linking of requirements with diagnostic objects, as a combobox in the Settings page at the top of the "Diagnostic Objects" group box.

  • CANdelaStudio supports libraries for requirements since v11 (CDS-70801).
  • Note: this setting is also controlled in the SWC Sync Dialog [SWCUI-R345].

Update of Diagnostic Objects (CDS-41683 v11)

[RQUI-R100-Update] Radio buttons control the behavior for diagnostic objects referenced in multiple variants:

  • [RQUI-R100-Copy] "Replace References with Copy"
  • [RQUI-R100-UpdateRefs] "Update References"

See the description of the setting [RQ-R096], which takes effect in the operation "Update Diagnostic Objects" [RQ-R520].

Diagnostic Classes Relevant for Requirements

  • [RQUI-R100-DiagnosticClasses] Checkboxes represent the information whether the Diagnostic Classes support requirements.
