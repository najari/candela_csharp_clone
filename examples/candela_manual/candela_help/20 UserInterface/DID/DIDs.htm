DIDs (List in Variant) (CDS-37944 8.5)

DID List in Variant

The DID list shows all DIDs of the variant.

DIDs referenced in multiple variants (like diagnostic instances) have a special icon (double sheet).

You can conveniently create diagnostic instances to read or write the DID using the combobox in the "Diagnostic Class" column: selecting a diagnostic class will...

  • delete the diagnostic instance from the currently specified diagnostic class (if not "none"), and
  • create the DID in the selected diagnostic class, using the defaults from the diagnostic class template (note: any modifications to the existing diagnostic instance are lost).

The filter at top right provides convenient search for a DID and data objects of a DID.

For details, see below.

DID List

[DIDUI-R700] DID List: for each variant,

  • the CANdelaStudio tree contains a “DIDs” node
  • between “Identifying Features” / “Identifying Patterns” and “Diagnostic Classes”.
  • See the Navigation tree.

[DIDUI-R702]: the DID list has the following columns:

  • [DIDUI-R702-Identifier] Identifier shows the DID Identifier,
    • see [DID-R025-DefaultDisplay]
  • [DIDUI-R702-Name] Name shows the DID name.
    • Identifier and Name are shown in bold if the DID is required or required as Reference (CDS-71432 v12)
  • “In Diagnostic Class”, see [DIDUI-R704] below.
  • “Used in Fault Memory”, see [DIDUI-R706] below.
  • DID Data
    • format see [DID-R155-DefaultDisplay]
    • cf. the checkbox "Show DID Data" in the DID Overview [DIDOV-R660]

[DIDUI-R704] Column “In Diagnostic Class” (CDS-39318 8.5)

  • The column shows...
    • a comma + blank separated list of usage info from any diagnostic class (in document order of diagnostic classes) that contains a DID Data Reference using the DID, or
    • “(none)” if there is no such diagnostic class.
  • Each usage info contains the diagnostic class name.
  • If...
    • there is more than one diagnostic instance that contains a DID Data Reference using the DID, or
    • the diagnostic instance identifier is different from the DID identifier,
    • the usage info contains...
      • a comma + blank separated list of the diagnostic instance identifiers,
      • prefix “0x”,
      • hex digits filled to the size (1 or 2 bytes) of the identifier.

Examples:

  • DID 0x0100 is used by diagnostic instance 0x0100 in “Stored Data”
    • usage info: “Stored Data”.
  • DID 0x0100 is used by diagnostic instance 0x0200 in “Stored Data”
    • usage info: “Stored Data (0x0200)”
  • DID 0x0100 is used by diagnostic instances 0x0100 and 0x0200 in “Stored Data” and 0x01 in “PIDs”
    • usage info: “Stored Data (0x0100, 0x0200), PIDs (0x01)”

[DIDUI-R705] Editing in Column “In Diagnostic Class” (CDS-39318 8.5)

  • CANdelaStudio does not provide edit mode…
    • if any of the variants in which the DID is referenced is read-only (not obvious)
    • if the existing diagnostic instance shown is required or “required as reference” (not obvious)
  • In edit mode, the column provides a combo-box containing
    • “(none)”
    • the name of each diagnostic class (in document order)...
      • that has service 0x22, 0x2E or 0x2F, cf. Identifiers in UDS and OBD Services, or
      • that has the “DID Data Reference” semantics set, see [DID-R050-DIDDataReferences].
  • If you select…
    • … “(none)”, CANdelaStudio deletes each diagnostic instance that contains a DID Data Reference using the DID.
    • … a diagnostic class D, CANdelaStudio...
      • deletes each diagnostic instance that contains a DID Data Reference using the DID, in any diagnostic class shown in the combo-box, except D;
      • if it does not yet exist, creates a diagnostic instance for the DID in the diagnostic class D,
      • as specified in Diagnostic Instance Creation from DID [DI-R020],
      • referenced in all variants in which the DID is referenced.
    • CANdelaStudio does not allow the operation if the identifier would violate the restriction from the text table at the variable value (CDS-39936 8.5).
  • [DIDUI-R705-ReSort] A modification triggers re-sort of the list (as opposed to [DIDUI-R730-NoReSort]).

[DIDUI-R706] Column “Used in Fault Memory” (CDS-39299 8.5)

  • … is read-only and contain “yes” iff. the DID is referenced…
    • from Common Snapshot Data
    • from DTC Specific Snapshot Data in the variant
    • by a DID Reference in fixed data in a ProtocolService with signature 0x19
    • by a DID Reference in the variant in any diagnostic class with semantics “Fault Memory”
    • by a DID Reference from Extended Data Records.

[DIDUI-R708] Layout Persistence (CDS-39958 8.5)

  • [DIDUI-R708-1]: the DID lists in the existing and newly created variants in CANdelaStudio has one common setting of column widths.
  • [DIDUI-R708-2]: dito for splitter position in one upon the other layout.
  • [DIDUI-R708-3]: dito for splitter position in side by side layout.
  • [DIDUI-R708-4]: dito for layout one upon the other vs. side by side.

[DIDUI-R710] New DID

  • via local toolbar button, “Please click here” and context menu,
  • creates a new DID...
  • with identifier, qualifier and name not existing in any variant,
  • see operation [DID-R200].
  • [DIDUI-R710-Locked] The button is disabled if the current variant or library is locked (CDS-68898 9.1).

[DIDUI-R712] New DID in All Variants

  • via local toolbar button and context menu,
  • creates a new DID in all variants,
  • see operation [DID-R202].

[DIDUI-R715] Paste

  • performs the operation [DID-R205] or [DID-R280].

[DIDUI-R720] Delete DID

  • deletes the selected DID(s) from the variant,
  • see operation [DID-R220].
  • CANdelaStudio shows a message if deletion is not allowed.
  • If the DID is used by a Diagnostic Instance that "represents the DID" (as of D001),
    • CANdelaStudio prompts
      • "Do you really want to delete the selected DID from the current variant?\n\n<n> diagnostic instances that use the DID will be deleted, too!";
    • otherwise CANdelaStudio prompts
      • "Do you really want to delete the selected DID from the current variant?"
  • [DIDUI-R720-Rq] In Expert View, if the selection contains DIDs required in all variants “as reference” or “yes”, the prompt contains a hint like "DIDs required or required as reference will be set to not required." (CDS-70802 v12).
  • [DIDUI-R720-Locked] The button is disabled if the current variant or library is locked (CDS-68898 9.1).

[DIDUI-R725] Select from Repository opens the Select from Repository dialog to import DIDs from a repository.

  • [DIDUI-R725-Locked] the button is disabled if the current variant or library is locked (CDS-68898 9.1).

[DIDUI-R730] Modifications to DID properties...

  • use the operations [DID-R210] / [DID-R230] and
  • report restrictions with a message box.
  • [DIDUI-R730-NoReSort] CANdelaStudio keeps the modified DIDs at their position
    • i.e. no automatic re-sort.
    • Exception: refresh of list when modifying “Diagnostic Class” [DIDUI-R705-ReSort].

[DIDUI-R740] Show References like for diagnostic instances...

  • shows variants in which the DID is referenced [DID-D005],
  • provide navigation to the object.

[DIDUI-R745] Show Uses

  • shows all objects that use [DID-D001] the DID in the current variant.

[DIDUI-R750] Other operations:

  • Properties

[DIDUI-R760] Replace Reference with Copy

[DIDUI-R765] Replace Copy with Reference in Base Variant

[DIDUI-R772] Checkbox “modifiable” in the DID property dialog:

  • for the property [DID-R010]
  • see operation [DID-R222]
  • Shown insensitive in Standard View.

[DIDUI-R774] Combo-box “required in all variants” in the DID property dialog:

  • layout like for diagnostic instances
  • for the property [DID-R012]
  • see operation [DID-R224].
  • Shown insensitive in Standard View.
  • CANdelaStudio shows a specific message if a pre-condition in the variants is not fulfilled
    • e.g. set to “as reference”, and there is a variant in which the DID is not referenced.
