Communication Control

Note:

  • in the "Communication Type" byte, for bits...
    • Normal Communication Messages (bit 0)
    • Network Management Communication Messages (bit 1)
  • the default value in the template is 0x3 (both bits set),
  • the value 0x0 is ISO SAE Reserved (in UDS 2013 and 2019),
    • but the description in the template does not forbid the use of 0x0.
    • If you need to explicitly define value 0x0 as invalid, you might define a data type of length 2 bits, with 0x0 as an invalid value.

Routine Control

[VUDS-R530]

  • Class Type is "Routine" (CDS-41739 9.0; previously "ctl").
  • Used Protocol Services:
    • Start
    • Stop
    • Request Results
      • former "Results", added verb, avoid issue CDS-71748 (CDS-71750 v12)
  • Combined Proxy Components
    • Control Options (Start)
    • Status (Start)
    • Control Options (Stop)
    • Status (Stop)
    • Results
      • former "Status (Results)", qualifier was "Results" already (CDS-71750 v12)
    • Start NR
    • Stop NR
    • Request Results NR
      • former "Results" with qualifier "RequestResults", avoid issue CDS-71748 (CDS-71750 v12)

Fault Memory

This diagnostic class describes the Fault Memory.

DTCStatusAvailabilityMask vs. StatusOfDTC

[VUDS-R560] In the Primary Fault Memory, the DTC Status related Proxy Components are combined as follows:

DTCStatusAvailabilityMask vs. StatusOfDTC in Vector UDS 2.5.0

See DTC Status in CANdela [DTCSB-D560] for background.

Responses with an Optional DTC: 0x19 0x0A .. 0x0F

The data structure is as described in the chapter "Fault Memory in CANdela" [FM-D570].

FAULTREAD

[VUDS-R550] The services for Snapshot Data have the semantics [DCLT-R320] "FAULTREAD" (CDS-71774 v12):

  • 19 04 Read Snapshot Record
  • 19 05 Read Snapshot Identification
  • 19 18 User Defined Fault Memory - Read Snapshots

In ODXStudio, this avoids the checker warning ODXStudio012 (Warning Level 1).

User Defined Fault Memories (CDS-42499 9.0)

This diagnostic class describes the User-Defined Fault Memory.

The Used ProtocolServices reference the text table "User Defined Fault Memories" that restricts the set of possible diagnostic instances for user defined fault memory.

See Use in the Vector Toolchain for support by CANdesc/AUTOSAR.

[VUDS-R510] The DTC Status proxy components are (CDS-68938 9.1)...

  • combined in 19 17 request, 19 18 and 19 19 positive response (zz)
  • separate in 19 17 positive response before the iteration (uu)
19 17 zz 01        59 17 01 uu *[yy tt]
19 18 yy fd 01     59 18 01 yy zz *[fd fd xx]
19 19 yy ww 01     59 19 01 yy zz *[fd vv]

DID Semantics

[VUDS-R520] The template uses the DID semantics for all diagnostic classes with 0x22 (CDS-69924 v10):

  • in ECU Identification and Variant Coding
  • not in special Protocol Services for Periodic Data, Dynamically Define... and OBD (which have 0x22 0xxx constants).

Powertrain Diagnostic and Freeze Frame Data

Combined Components:

  • [VUDS-R572] Supported OBD PIDs (CDS-71900 v13)
    • 0x41, "ReadSupported PID (OBD)", Positive Response
    • 0x62 0xF4, "ReadSupported PID (UDS)", Positive Response

Vehicle Information

Combined Components:

  • [VUDS-R574] Supported OBD IDs (CDS-71900 v13)
    • 0x49, "Read supported Info Types (OBD)", Positive Response
    • 0x62 0xF8, "Read supported Info Types (UDS)", Positive Response
  • [VUDS-R576] InfoTypeData
    • 0x49, "Read Info Type Data (OBD)", Positive Response
    • 0x62 0xF8, "Read Info Type Data (UDS)", Positive Response
    • Note that the "Number of Data Items" is present in the 0x09 Protocol Service, but not in the 0x22 WWH-OBD Protocol Service.
    • The data behind the 0x09 "Number of Data Items" is the same as that behind the 0x22 <Identifier> (CDS-72042 v13).

Security Jobs

[VUDS-R529] The jobs predefined in the template are used for UDS Service 0x29 [VUDS-R8290].

  • The actual job file named "UnusedJob" is not relevant.
  • The main information of each job is in the default value of the input parameter "Role" for use by the security source,
    • as described in [AUTH-R100].
