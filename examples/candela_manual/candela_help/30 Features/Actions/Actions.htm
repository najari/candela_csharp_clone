Actions (CDS-539 1.4)

Introduction

Using actions, CANdelaStudio lets you automatically or manually execute external applications.

Use Cases

  • automatic conversion of a document exported to RTF
  • store a document in a central repository
  • fetch a document in a central repository
  • post-process an exported ODX file
  • open an exported file in an editor or word processor
  • run a code generator
  • run a checker on an exported file
  • etc.

Actions

[ACT-R100] CANdelaStudio provides actions to run external commands via command line.

  • Actions are configured for the CANdelaStudio installation.
  • They are stored in the file Actions INI.

[ACT-R110] An action is identified by a qualifier.

  • The qualifier is language independent
  • ... and has the character repertoire of CANdela qualifiers.

[ACT-R120] The name of an action is language-dependent.

[ACT-R130] Errors in action processing do not alter the subsequent behaviour of CANdelaStudio.

Example Action

Property Value
Name Report
Qualifier Report
Commands notepad "$LastReportPath;"
Start in (empty)

The action...

  • opens the HTML file from the last report in an editor
  • uses the Windows application "notepad" as an editor
    • which can be run without specifying the full directory path to notepad.exe
  • protects the file path by double-quotes

Action Types

[ACT-R140] CANdelaStudio supports user-defined and internal actions:

User-defined Actions

  • can be freely edited
  • shown in the main menu under Tools
  • are executed manually via the menu item

Examples:

  • start an editor for a special data format
  • start a compiler

Internal Actions

  • are predefined by CANdelaStudio
  • their qualifier is read-only
  • you cannot delete them
  • not shown in the Tools menu
  • are automatically executed after some internal event, e.g. after an export, or after adding a revision to the revision history.

Command Line

The command line of an action is a string that can be executed by the operating system.

Multiple Commands

  • Multiple commands are on separate lines.
  • CANdelaStudio will run them in sequence.
  • CANdelaStudio ignores lines that have white-space only.

Command

  • Each command must be specified as in the Windows command processor:
    • the complete path to the application
    • optional parameters
    • separated by blanks
    • If the name or the parameters contain a blank themselves, double-quotes "" must be put around each one.
  • If the folder of the application is in the Windows PATH variable, the name of the application suffices (e.g. "notepad")
  • For internal actions, the command line may be empty.
  • For user-defined actions, the command line must not be empty.
  • CANdelaStudio expands windows environment variables in an action command line (CDS-22742 7.1 SP2)

Return Codes

  • Since the return codes of commands are not standardized, CANdelaStudio
    • cannot track whether a command was executed successfully, and
    • cannot break for errors, but unconditionally runs each command.

  • To support the weak convention that value 0 means "success", CANdelaStudio reports a non-zero value in the log, like:

      Command '<interpreted command line>' returned code <return value> (expected 0)

Start in... (CDS-9034 6.0)

An action has an optional property "WorkingDirectory".

If the working directory is specified, CANdelaStudio executes the action within this directory.

Variables

[ACT-R300] When the command needs an information from CANdelaStudio (e.g. the path to an exported file) as a parameter, you need to specify the information in the command line. Since such information may vary over time, CANdelaStudio provides variables which it substitutes with the respective value before running the command.

The set of variables supported is hard-coded (see the list below).

Format

[ACT-R310] The format of using a variable with qualifier V in the command line is:

Mode Format Description
required $V; the variable must have a non empty value when CANdelaStudio executes the action.

If a required variable has not been set at the time the action shall be executed, then CANdelaStudio does not execute the action, but shows a message instead.
optional $?V; the value of the variable may be empty when CANdelaStudio executes the action.
  • The $, $? and ; are delimiters for the variable qualifier.
  • if the value of the variable may contain blanks, you have to put double-quotes around the variable to protect the value in the command line

Static and Dynamic Variables

[ACT-R320] Any variable is either static or dynamic:

Variable Type Description Examples
static CANdelaStudio remembers its value at some point of execution the name of the last specification report file
dynamic CANdelaStudio computes its value at the time the value is needed current date, name of current document

Variable LogfileTmpPath

Use this variable to transfer output of an external application (e.g. a checker) into the CANdelaStudio logging: run an action command with a temporary output path, then let CANdelaStudio transfer that output into logging(CDS-13574 6.5 SP1).

If the variable is used in a command line, on action execution, CANdelaStudio...

  1. computes a temporary path T
  2. in the action command line, replaces the variable by T
  3. runs the command line
  4. if file T exists, put contents of the file into logging (after each action command line when using multiple command lines)
  5. deletes the file T
