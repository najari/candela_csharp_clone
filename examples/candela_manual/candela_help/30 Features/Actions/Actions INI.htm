Actions.ini

Location of the Actions INI File

The actions configured by the user are stored in an INI file "actions.ini", the path of which is derived from an entry [General]Actions in CANdelaStudio.ini (not editable in GUI). You can find this file (e.g. for CANdelaStudio 8.5) at

C:\ProgramData\Vector\CANdelaStudio\8.5\actions.ini

or in the installation directory of CANdelaStudio in sub directory Bin.

If on reading, [General]Actions is missing or the file referenced does not exists, then there are no actions available (i.e. for hard-coded actions, name equals qualifier, command line is empty).

As a default for writing, [General]Actions should point to actions.ini in the CANdelaStudio.exe directory, and the hard-coded actions should be written into it.

Contents of the INI File

The INI file contains a section [General], [CommandLine] and one section for any GUI language of CANdelaStudio, e.g. [de-DE]. Each section contains entries with the form

<actionQualifier>=<value>

The [CommandLine] section contains the command lines of all actions, using the action qualifier as a key and the command line as a value, like:

Report=winword $File;

The [General] section contains default names of all actions, the language sections contain the action names for the respective language.

On reading any action, CANdelaStudio...

  • looks for its name in the section of the current GUI language.
  • If not present, it looks for an entry under [General].
  • If not present, and it is a hard-coded action, it uses the default name. Else it uses the qualifier.

On writing any action, CANdelaStudio writes its name into the section of the current GUI language. If there is no entry for the action in [General], it writes the action into [General], too.

In Section [Version], CANdelaStudio stores its own version number in the key Version. If the section and/or key is not present in the Actions INI file, CANdelaStudio assumes the INI file has been created by a previous version which did not yet support UTF-8, and migrates the file contents to UTF-8 (to support multi-language names, all data must be stored in UTF-8).
