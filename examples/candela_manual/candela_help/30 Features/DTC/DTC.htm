DTC

A DTC represents an internal error event in the ECU and transports it via a protocol to a client.

See also the Fault Memory Introduction and the user interface DTC List.

DTC Lists in CANdela

[DTC-R001] A DTC in CANdela is either

  • in the list of Available DTCs (DTC Pool), or
  • in a list within a Fault Memory (in a variant or library).

Snapshot data and extended data for a DTC...

  • are not described at the DTC directly
  • but are stored and edited in separate lists
  • and both have a reference to their DTC.

Therefore e.g. copying a DTC does not copy its snapshot data, since CANdela does not consider them being "part" of the DTC.

OBD DTCs

A CANdela template distinguishes [ECT-R001]...

  • Primary/User-Defined/WWH-OBD DTCs (3 byte)
  • OBD-II DTCs (2 byte)

Relationship of UDS and OBD-II DTCs:

  • CANdelaStudio (as of v13) does not have built-in support for this relationship
  • See [DTC-R220] below for a convention for Vector DEM code generation.

DTC Referencing

[DTC-D020 DTC Referencing]: Possible references (sharing) of DTC related objects:

Object Sharing
Diagnostic Instance yes
DTC List as a whole no
DTC yes (into DTC Pool only)

See also [DTCP-R002-UDFM] for DTC references in User Defined Fault Memory.

DTC List

[DTC-R020 DTC List]: A DTC List exists in the contexts

  • [DTC-R020-Pool] in the DTC Pool or
  • [DTC-R020-DiagInst] in a diagnostic instance (in a Variant or Library), see [DTC-D020] above.

[DTC-R020-ErrorCodeTable]: Each DTC list corresponds with an Error Code Table [ECT-R001] defined in the template.

DTC Data Object and DTC Data Type

In the generic CANdela data model,

  • a data object (parameter)
  • references a data type (conversion) [DO-R100].

This also holds for DTCs:

DTC Data Object and DTC Data Type

[DTC-R021 DTC Data Object]: in a diagnostic instance, ...

  • a DTC Data Object represents...
    • the data object ("parameter") on the line.
  • it contains a DTC Data Type which...
    • represents the mapping between codes and error texts
    • similar to a Text Table;
    • the DTC Data Type contains the list of DTCs.
  • An individual DTC in the DTC Data Type...
    • (described below) holds code, error text and the DTC specific properties
    • similar to one entry in a text table.

Note: the DTC Data Object is shown in a property dialog [DTCUI-R021] on the DTC list and used in exports to represent the DTC "parameter".

DTC Existence

[DTC-R022 Existence]: A DTC exists in one or multiple DTC Lists, see [DTC-D020] above.

DTC Code

[DTC-R025 Code]: A DTC has a Code = an unsigned number

  • [DTC-R025-Size] the maximum Code size is controlled by the corresponding Error Code Table [DTC-R020-ErrorCodeTable].
  • [DTC-R025-Unique] the Code must be unique within a DTC List (even in the DTC Pool).
  • [DTC-R025-Zero] in UDS, the DTC 0x000000 has a special meaning
    • 0x19 0x02 reportDTCByStatusMask may fill a response with dummy DTCs 0x000000 for page-buffered handling when the number of DTCs decreases while creating the response.

[DTC-R028] For display purposes (see "Display of DTCs"), the DTC Code may be structured into

  • [DTC-R028-Base] a 2 byte root part (base DTC)
  • [DTC-R028-FTB] a 1 byte Failure Type Byte or
  • [DTC-R028-FMI] a 1 byte Failure Mode Identifier.

DTC Identity

  • [DTC-D210-Identity] DTC A in one variant and DTC B in another variant are considered “the same DTC” (DTC per se) if they have the same code.
  • [DTC-D210-ModifyCode] If you modify the DTC code in one place, the DTC becomes another “DTC per se” at this place.

DTC Error Text

[DTC-R030 Error Text]: A DTC has an Error Text.

  • [DTC-R030-MultiLang] It is multi-language.
  • [DTC-R030-Empty] It may be empty.
  • [DTC-R030-NoLineBreak] It must not contain line-breaks (CDC-13683 8.1 SP2).
  • [DTC-R030-NotUnique] It need not be unique within a DTC List.

DTC Authorization Properties

See DTC Authorization.

DTC Columns

[DTC-R040 DTC Columns]:

  • A DTC has user-defined properties (columns), defined at the corresponding Error Code Table [DTC-R020-ErrorCodeTable].
  • Each DTC has a value for each column.
  • [DTC-R040-ColumnSort]: the columns at a DTC are in the same order as the column definitions in the Error Code Table (CDS-8349 5.5).
  • For default values of new DTCs, see [DTCC-R080].

Attributes

A DTC has attributes [ATTR-R050-DTC].

DTC and Vehicle System Groups

A DTC can be associated with Vehicle System Groups [VSG-R100-DTC].

References

See [DTCP-R002] for references into DTC Pool.

DTC Byte Order

In UDS and KWP, the DTC is described with high-low (Motorola) byte order.

[DTC-R050 Byte Order] The CANdela data model (like ODX) supports a byte order at the DTC object.

Note:

  • CANdelaStudio displays the byte order [DOCUI-R620]
  • but does not provide editing.
  • Vector test systems evaluate it correctly.

Failure Type Byte / Failure Mode Identifier

Failure Type Bytes (FTB) or Failure Mode Identifiers (FMI) must be enabled in the template in the Document Property Page "Display of DTCs":

  • Failure Mode Identifier
  • Failure Type Byte

DTC in Code Generation

[DTC-R210] Vector DEM needs to identify DEM internal data objects that represent e.g.

  • DTC Aging Counter
  • DTC Healing Counter
  • ...

For this purpose, it evaluates the attribute "Faultmemory Relevance" [SATTR-R210] at a data type. See the Vector UDS Template [VUDS-R310].

[DTC-R220] In order to associate UDS and OBD-II DTCs, Vector DEM evaluates a DTC column "UDS DTC Reference" [ECT-R520] at the OBD-II DTCs.

  • See the Vector UDS Template [VUDS-R480].
