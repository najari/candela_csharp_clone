DTC Status Bits

Introduction

Fault Memory in System Context

An ECU implementation manages state for a DTC using DTC Status Bits.

For UDS, see "UDS DTC Status Byte" [FMUDS-D050] and "Uses of DTC Status in UDS Services" [FMUDS-D560]

DTC Status Bits in CANdela

CANdelaStudio represents DTC Status Bits in 4 contexts:

Context Description
ECU: DTC Status Mask supported by an ECU Setup in the template on document level (see below). For editing, see next item in this list.
Services: DTC Status Bits in services Setup in the template in the Fault Memory Protocol Services and Diagnostic Class Templates using a DTC Status Proxy Component. The dialog also defines the DTC Status Bits common on document level.
Request: Default values to be sent by a test system to the ECU Described in the DTC Status Bits Dialog in a Fault Memory diagnostic instance.
Response: Values reported by the ECU described in the same dialog

DTC Status Mask (Document Level)

[DTCSB-R010] Several DTC Status Bits may be combined in a DTC Status Bit Group (defined in a CANdela template).

[DTCSB-R050] The total length of the DTC Status Bits is defined by a data type.

A DTC Status Bit Group

  • describes one or multiple DTC status bits
  • at a fix position within the DTC status byte object
  • [DTCSB-R060] has a Convention = info whether in a document derived from the template, the bits of the group are either...
    • mandatory, or
    • optional, available by default, or
    • optional, not available by default

Examples:

  • KWP
    • "DTC Fault Symptom" (4 bit, bits 0-3, optional, available by default);
  • UDS
    • "Test failed" (1 bit, bit 0),
    • "Test failed this monitoring cycle" (1 bit, bit 1).

The DTC Status Bit Groups are defined in one place (since 8.0) in the template, i.e. they are common to all ProtocolServices.

DTC Status in the Diagnostic Class Template

[DTCSB-D560]

  • For proper AUTOSAR code generation,
    • the DTCStatusAvailabilityMask Proxy Components must be combined,
    • the StatusOfDTC Proxy Components must be combined,
    • but no DTCStatusAvailabilityMask Proxy Component may be combined with any StatusOfDTC Proxy Component.
      • otherwise the DEM_STATUS_AVAILABILITY_MASK value will not be detected and will default to 0xFF.
  • Cf. [FMUDS-D560] for the types of Proxy Components.

Note: For CANdesc code generation (as of 2019-07), the document will be converted to 6.5 format which includes an 8.0 to 7.5 migration that separates any DTCStatus Proxy Components contained in one collection in a primitive (CDS-23911 8.0).

Example:

  • 59 0C tt zz tt will be migrated to 59 0C pp zz tt which produces the expected values in CANdesc
  • 59 0C tt *[zz tt] will be left unchanged and lets CANdesc default to 0xFF (not expected)
  • 59 0C pp *[zz tt] will be left unchanged and lets CANdesc use the values specified in the document, as expected.

See...

  • DTC Status in UDS [FMUDS-D560] for the meaning of DTCStatusAvailabilityMask vs. StatusOfDTC.
  • as an example: DTC Status in the Vector UDS Template [VUDS-R560]

Migration 7.5 to 8.1 (CDS-31607 8.1)

[DTCSB-D200] DtcStatusBit old data type attribute:

  • attribute at data object
  • type string (not translatable)
  • qualifier "OldDtcStatusBitDataTypeQualifier"

Not relevant to identify the attribute:

  • diagnostic class restriction: qualifier of 3-byte FaultMemory (if such a diagnostic class template exists)
  • type restriction: only data objects
  • suggested category: "Editor"
  • "Visible in Standard view" = false
  • "Properties modifiable" = false
  • "Export to specification" = false
  • default value = ""

[DTCSB-R200] when loading a 7.5 file in >= 8.0,

  • if in 7.5 format the Convention values [DTCSB-R060] of two DtcStatusBitGroups are different,
  • then CANdelaStudio sets the global DtcStatusBitGroupList convention...
    • to "required", "never" or "optionalDefaultNo" only if all original conventions have the respective value
    • otherwise to "optionalDefaultYes"

[DTCSB-R210] If the data type of a DTCStatusbit data object has been changed, CANdelaStudio...

  • stores the qualifier of the old data type in the attribute [DTCSB-D200]
  • sets the data type authorization to not modifiable, not deletable, with debug message.

[ODXE-R220] ODX Export evaluates the attribute.
