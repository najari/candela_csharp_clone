Events Operations (CDS-42224 v12)

See also the Events Introduction, the Events Data Model and the Event Consistency Conditions.

Supports Events

[EVOP-R010] Modify the document-level Boolean switch Supports Events [EV-R010].

  • only in Expert View
    • Motivation: let the person responsible for the template (process) decide.
  • User Interface: File | Properties | Document Info [DOCUI-R600]
  • When set from true to false:
    • CANdelaStudio deletes all Events [EV-R020] in the document.

Authorization

[DIOP-D010] All the following operations are subject to basic restrictions for editing in a diagnostic instance. For the effect in the user interface, see [EVUI-R010].

Event List

See the Event list in the user interface [EVUI-R020].

[EVOP-R020 New] in a Diagnostic Instance, create an Event

  • CANdelaStudio creates an Event with
  • ... name and qualifier unique in the Events list
  • ... atomic Event properties set to the default values specified in the data model
    • especially this means no reference to Operation Cycle [EV-R120], Enable Condition [EV-R200], Storage Condition [EV-R210], Debounce Algorithm [EV-R220], Connected Indicators [EV-R140]
  • possible in Standard View, see also [DIOP-D010]
  • not possible if the flag "Supports Events" [EV-R010] is false

[EVOP-R030 Modify] modify an Event

  • respects the Event Consistency Conditions
  • possible in Standard View, see also [DIOP-D010]

[EVOP-R040 Delete] delete an Event

  • CANdelaStudio deletes the Event from the Event list [EV-R020] in the diagnostic instance.
  • Note: since the Event carries the association to a DTC [EV-R230], that association is automatically deleted, too.
  • possible in Standard View, see also [DIOP-D010]

Clipboard Operations

[EVOP-R050] Paste Event within a Diagnostic Instance

  • inserts a copy of the Event
  • with a number suffix for name and qualifier to make it unique (as usual)
  • [EVOP-R050-Ref] keeps the optional reference to a DTC [EV-R230]
  • references the same Event Master Data than the original Event
  • respects the Event Consistency Conditions
  • not possible if the flag "Supports Events" [EV-R010] is false
    • this should not be relevant, since the Diagnostic Instance cannot contain an Event to be copied.

[EVOP-R060] Paste Event into a different Diagnostic Instance

  • inserts a copy of the Event
  • makes name and qualifier unique if necessary (as usual)
  • [EVOP-R060-Master] if the source Event references an Event Master Data object [EV-D040],
    • and the target diagnostic instance contains an Event Master Data object M with the same qualifier (other properties may differ),
    • then the operation lets the Event copy reference that object M;
    • otherwise the operation copies the object and lets the resulting Event reference the copy.
  • [EVOP-R060-Ref] if the source Event references a DTC [EV-R230],
    • and the target Diagnostic Instance contains a DTC with the same code,
    • then the Event copy references that DTC,
    • otherwise the Event does not reference a DTC.
    • Cf. Procedure How to Copy Events and DTCs and DTC Paste [DTCOP-R040].
  • respects the Event Consistency Conditions
  • not possible if the flag "Supports Events" [EV-R010] is false

Event and DTC

  • possible in Standard View, see also [DIOP-D010]

[EVOP-R244] Create / Map Events

Data Constellations for Create / Map Events

  • for each DTC in a given list of DTCs,
    • no matter whether Events exist that reference the DTC [EV-R230] or not,
  • if there is an Event whose name equals the DTC error text,
    • if the Event already references any DTC [EV-R230]: no action (with status message)
    • otherwise: lets the Event reference the DTC [EVOP-R230]
  • otherwise: creates a new Event [EVOP-R020]:
    • sets Event name and qualifier from the DTC error text (no FTB/FMI handling),
    • if the resulting qualifier already existed: makes it unique,
    • leaves defaults for all other Event properties.
    • lets the new Event reference the DTC [EVOP-R230].
  • possible in Standard View,
    • see also [DIOP-D010]
  • not possible if the flag "Supports Events" [EV-R010] is false
  • See also the user interface [EVUI-R284].

[EVOP-R284] Create / Map DTCs

Data Constellations for Create / Map DTCs

  • for each Event in a given list of Events
    • that does not reference a DTC [EV-R230],
  • if there is no DTC whose error text equals the Event name,
    • creates a new DTC [DTCOP-R010],
    • sets the error text from the Event name (no handling for FTB/FMI),
    • sets the error code to the maximum existing error code + 1
      • wrapping around from 0xFFFFFF to 0x000000
      • avoiding error codes used by DTCs "Required" or "Required as Reference" [DTC-R012] in the DTC pool
  • lets the Event reference the (existing or new) DTC [EVOP-R230]
  • possible in Standard View,
    • see also [DIOP-D010] and
    • [DTCOP-R010-PoolOnly] document authorization "Creation of DTCs"
  • See also the user interface [EVUI-R284].
