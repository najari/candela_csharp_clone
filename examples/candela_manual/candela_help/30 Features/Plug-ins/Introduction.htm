Introduction to CANdelaStudio Plug-ins

What is a Plug-in?

In CANdelaStudio, a plug-in is a software component that adds a specific feature to the product. Plug-ins enable customization. Common examples are plug-ins used to manipulate or check a CDD document for a customer specific process.

Plug-ins are implemented in the form of a DLL module that needs to provide a specified interface (the CANdela Plug-in Interface). They have to be implemented in the context of a customer project by Vector employees (Exception: Repository plug-ins can be implemented by customer or 3rd party, see below).

The Module Information [MENU-R1260] shows installed plug-ins.

Different Kinds of Plug-ins

CANdelaStudio supports three different kinds of plug-ins:

  1. Old style CDLPLG plug-ins (deprecated)
  2. New style CANdela plug-ins
  3. Repository plug-ins

CDLPLG Plug-ins

This plugin type has been the common type for CANdelaStudio versions up to 8.2. Existing plug-ins can be maintained and used with CANdelaStudio 8.5 and higher.

These plug-ins have the file name extension '*.cdlplg' and reside in the 'plugins' subdirectory of the CANdelaStudio installation.

CANdela Plug-ins

CANdelaStudio 8.5 SP2 introduced a new plug-in interface (CDS-37835) with more comfort and safety. This kind of plug-in replaces the old style CDLPLG plug-ins.

These plug-ins have the file name extension '*.dll' and reside in the 'plugins' subdirectory of the CANdelaStudio installation.

Repository Plug-ins

CANdelaStudio 8.1 introduced a specific plug-in approach to support the repository feature.

Repository plug-ins have the file name extension '*.dll' and reside in the 'plugins' subdirectory of the CANdelaStudio installation.
