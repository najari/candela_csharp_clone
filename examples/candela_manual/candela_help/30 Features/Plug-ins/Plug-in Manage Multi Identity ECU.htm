Plug-in "Manage Multi Identity ECU" (CDS-22808 8.0, CDS-829)

See also the procedure How to Manage a Multi Identity ECU.

Use-Case

Efficiently describe ECUs which are nearly identical.

Example:

  • Door ECU has multiple identities,
  • ... it decides at runtime whether it has been assembled left or right, front or rear.
  • Depending on the assembly location, the ECU uses a different CAN ID:
ECU Name CAN ID
Door front left CAN ID 0xA1
Door front right CAN ID 0xA2
Door rear left CAN ID 0xA3
Door rear right CAN ID 0xA4

In general:

  • multiple ECUs ("identities") are based on the same CDD file
  • only few parameters differ, typically...
    • ECU name
    • CAN ID (also if an ECU is used in different architectures)

Solution Overview

CANdelaStudio does not support to describe multiple ECUs directly in one CANdela document.

But you may...

  • maintain one document as the master
  • do each modification in the master document
  • after each modification, clone the master document to copies, one for each other "identity"
  • in each copy, again change the ECU name and the CAN ID

The plug-in Manage Multi Identity ECU automates this process:

  • it provides a dialog where you define the differing properties for the other identities
  • a button creates the document copies
  • the copies are regular CANdela documents, which you can also edit manually if needed.

The plug-in stores the info from the dialog in an ECU attribute in the master document.

See also the procedure How to Manage a Multi Identity ECU.

Specification

Dialog for Plug-in "Manage Multi Identity ECU"

Definitions

[PMulti-D001.0 INI file structure]:

[Group]
Key=Value

Dialog

[PMulti-R010.0 Dialog]: the dialog shall describe ...

  • [PMulti-R010-a] a list of alternative ECUs (excluding the one described in the ECU passed to the plugin).

For each alternative ECU:

  • [PMulti-R010-b] the qualifier and name (name in the current language)
  • [PMulti-R010-c] the path to save (optionally; default: temporary directory).
  • [PMulti-R010-d] For each supported interface in the ECU passed to the plugin: a list of...
    • [PMulti-R010-d1] communication parameter qualifier
    • [PMulti-R010-d2] a value for the communication parameter

[PMulti-R040.1 Text Area]: the dialog shall contain a big edit control (text area) that edits the string of [PMulti-R020].

Insert Alternative ECU

[PMulti-R050.1 Button "Insert alternative ECU"]: the dialog shall contain a button "Insert alternative ECU", for which it...

  • [PMulti-R050-a] ... generates a string as described in [PMulti-R020]
    • from the communication parameters of the open ECU,
    • the name and qualifier shall be name and qualifier of the open ECU with a suffix,
    • path: empty [PMulti-R010-c].
  • [PMulti-R050-b] ... appends that string at the end of the edit control of [PMulti-R040].

Generate Documents

[PMulti-R060.1 Button "Generate documents"]: the dialog shall contain a button "Generate documents". On pressing the button, ...

  • [PMulti-R070-a] the dialog shall check the contents of the edit control syntactically as described in [PMulti-R090].
  • [PMulti-R070-b] If no syntax error is detected, document generation shall continue as follows:
  • [PMulti-R060-a] generate one CANdela document per alternative ECU...
  • [PMulti-R060-b] ... in the path defined at the alternative ECU (if path given, see [PMulti-R020-c], otherwise in the temporary folder);
  • [PMulti-R060-c] if not given in the path, the file name shall be the qualifier of the alternative ECU;

  • [PMulti-R060-d] each document shall contain the contents of the ECU passed to the dialog, but superseded by the data of [PMulti-R010] -b and -d.

    Note: if the description of the alternative ECU contains e.g. one communication parameter, only that one is superseded, the other ones remain unchanged.

  • [PMulti-R060-e] On exporting the superseded data of [PMulti-R010-b] to the cloned document, the dialog shall check the superseded data semantically if it corresponds to a communication parameter.

  • [PMulti-R060-f] If it detects a semantic error, "Generate documents" shall stop at once (the CANdela documents written to disk up to the interruption persist afterwards).

  • [PMulti-R060-empty] (CDS-29391 R010) for a communication parameter that has an empty value in the edit control, ...
    • if the communication parameter is of type "string", the value in the document shall be an empty string;
    • if the communication parameter is not of type "string" (including an enum), the value in the document shall be the same as in the master document (i.e. generation shall ignore the empty string).
    • for communication parameter type, see [ATTR-R020].

OK/Cancel

[PMulti-R075.1 Pressing OK]: on pressing OK, ...

  • [PMulti-R075-check] the dialog shall check the contents of the edit control against the syntax described in [PMulti-R020].
  • [PMulti-R075-nok] If the contents violates the syntax, the dialog shall let the user confirm to leave the dialog.
  • [PMulti-R075-a] If the contents matches the syntax, or the user confirms to leave, the dialog shall be left obeying [PMulti-R030] and [PMulti-R035]
  • [PMulti-R075-b] otherwise, the dialog shall inform the user.

[PMulti-R080.0 Cancel]: on leaving with ESC or Cancel, ...

  • [PMulti-R080-a] if the user has modified the contents of the control of [PMulti-R040],
  • [PMulti-R080-b] the dialog shall confirm with the user whether to really leave the dialog and discard all changes.

Check

[PMulti-R090.1 Button "Check"]: the dialog shall contain a button "Check", which checks the syntax of the edit control contents against the syntax described in [PMulti-R020].

  • [PMulti-R090-empty] (CDS-29391 R001): the check shall ignore communication parameters with empty contents.
  • [PMulti-R090-key]: the check requires the key to contain only [a-zA-Z0-9_] (CDS-29662 R010 a).

The check shall...

  • ... [PMulti-R090-string] for a communication parameter of type string, text (translatable), or enumeration [ATTR-R020]: ignore the value (CDS-29662 R010 b);
  • ... [PMulti-R090-nonString]: for all other types, require the value to contain only [a-zA-Z0-9_] (it may be empty) (CDS-29662 R010 b).

For the first line that does not match the syntax, the dialog shall...

  • [PMulti-R090-a] inform the user in a static text,
  • [PMulti-R090-b] select the line (or even part of it),
  • [PMulti-R090-c] stay in the dialog.
  • [PMulti-R090-d] If no syntax error is detected, the dialog shall inform the user in a static text.

Storage

[PMulti-R020.0 Mapping to String]: the dialog shall map the info of [PMulti-R010] to a string as follows (= structure of an INI file, see [PMulti-D001]):

  • [PMulti-R020-a] the ECU qualifier is a group
  • [PMulti-R020-b] name is a key/value pair in the group, with key "Name"
  • [PMulti-R020-c] path is a key/value pair in the group, with key "Path"
  • [PMulti-R020-d] each communication parameter value is a key/value pair, with
    • [PMulti-R020-d1] key = interface qualifier "." communication parameter qualifier
    • [PMulti-R020-d2] value = the value shown in CANdelaStudio (e.g. enum symbol)
  • [PMulti-R020-e] empty lines shall be ignored

  • [PMulti-R020-f] lines starting with "#" shall be ignored (= comments)

    Example:

      [DoorFrontLeft]
  Name=Tür vorne links
  Path=
  CAN_D.CANID=0x602
  • [PMulti-R030.0 ECU Attribute]: the dialog shall take/store the string defined in [PMulti-R020] from the value of an ECU attribute with...
    • [PMulti-R030-a] qualifier "MultiECU"
    • [PMulti-R030-b] type = language independent
  • [PMulti-R035.0]: if such an attribute does not exist, the dialog shall create one on OK exit, with
    • [PMulti-R035-c] category "Editor"
    • [PMulti-R035-d] name "MultiECU"
    • [PMulti-R035-e] authorization: not visible
