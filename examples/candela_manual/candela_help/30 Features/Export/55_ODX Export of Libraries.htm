ODX Export of Libraries

Since 8.5 SP2 (CDS-37946), CANdelaStudio supports libraries.

Standard Case

Export of Variants and Library (left: CANdela data; right: exported ODX data)

  • [ODXE-R500 ECU-SHARED-DATA] Export creates an ECU-SHARED-DATA from a library and its contained diagnostic instances
    • e.g. library "E1"
    • e.g. diagnostic instances "E11" and "E12"
  • [ODXE-R510 Reference to ECU-SHARED-DATA] If a CANdela diagnostic instance in a variant is referenced in a library, export represents it as DIAG-COMM/TABLE-ROW that is inherited/referenced from the ECU-SHARED-DATA
    • e.g. diagnostic instance "E11" in variant "V1" becomes DIAG-COMM/TABLE-ROW "E11" in ECU-VARIANT "E11" in ODX
    • ... which is inherited/referenced from ESD "E1"
  • [ODXE-R520 Not in ECU-SHARED-DATA] If a CANdela diagnostic instance in a variant is not referenced in a library, export does not put it into the ECU-SHARED-DATA
    • e.g. diagnostic instance "B" in base variant "Common Diagnostics"

Library Takes Precedence

Export into Library not Variants

  • In ODX, exported diagnostic instances are
    • contained in the ECU-SHARED-DATA and
    • only referenced in the variants
  • i.e. from all diagnostic instance references, the library takes precedence (note: references are not directed in CANdela)
  • This means e.g. for diagnostic instances from the CANdela base variant:
    • they are “moved” in ODX from the base variant (BV) to the ECU-SHARED-DATA.
  • [ODXE-R530 Document Level Objects] CANdela document level objects (data types and states) referenced from the library are exported into the ECU-SHARED-DATA
    • e.g. "DT2" and "ST1" referenced by diagnostic instance "E12" are exported into "E1"
    • e.g. "DT1" referenced only in the base variant is not exported into "E1" but into "Common Diagnostics".

Separate ECU-SHARED-DATA for Document Level Objects

ECU-SHARED-DATA for Document Level Objects

In the same CANdela data constellation as in the previous chapter, as an alternative, ...

  • [ODXE-R540 Separate ECU-SHARED-DATA] export may put the CANdela document level objects (data types, states) into a separate ECU-SHARED-DATA.
    • e.g. "DT2" and "ST1" used by diagnostic instance "E12" are exported into "W80222" (a fictive base library for some model range)
    • but e.g. "DT1" and "ST2" not used by a diagnostic instance from the library are also exported into "W80222"
  • "Common Diagnostics", ECU-VARIANTs and other ECU-SHARED-DATA all reference into this document level ECU-SHARED-DATA

Export creates this alternative data constellation...

  • [ODXE-R540-manufacturer] depending on the "Diagnostics Based on" (manufacturer) setting of the document,
  • [ODXE-R540-DIAG_LAYER] or if services are designated for a PROTOCOL or FUNCTIONAL-GROUP ODX DIAG-LAYER, using a special attribute "DIAG_LAYER".

Embedded ECU-SHARED-DATA

Export of Embedded ECU-SHARED-DATA

  • [ODXE-R550] If the CANdela library contains an original ODX ECU-SHARED-DATA as an embedded external file [LIB-R026], export just uses this file as is
    • e.g. ESD "E1" with "DT1", "DT2", "E12" and "E11"
  • [ODXE-R550-ignore] export does not use the corresponding CANdela objects
    • e.g. "DT1*", "DT2*", "E12*" and "E11*"
  • This is based on the assumption that the CANdela objects are identical to the objects in the embedded ODX ECU-SHARED-DATA since they are write-proteced on import [ODXI-R512].
