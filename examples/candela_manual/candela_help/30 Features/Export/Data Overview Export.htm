Data Overview Export (CDS-4348 4.0 SP4)

The export stores an overview of all data objects of a CANdela document as a CSV file.

Use Cases

  • Import of an A2L file into a CANdela document, then export of the data objects to CSV
  • Export of an overview of all data objects of a variant or all variants of the CANdela document

Export

R001.0: Add menu item "Data overview" ("Datenübersicht") to menu “File|Export”, below "Service overview".

R002.0: In the “Save as…” dialog, use the same elements as for “Service overview”:

  • combo box “File type” with entries “Data overview (*.csv)” and “All files (*.*)”
  • list box for target group selection below combo box “File type”
  • the file name of the CANdela document will be used as a suggestion for the file name of the CSV file. If there is no file name, the ECU name will be used as a suggestion.

R003.0: In the CSV file, export a header containing date and time of export as well as the column titles (as in Service overview), like:

<filepath>
2016-10-24T08:35:11+02:00
Variant;Diagnostic class;Diagnostic instance;Service;Data object;Data type;Default value;Const value;Label

R004.0: the CSV file top-level structure shall correspond with the following pseudo-code:

for all variants
  for all diagnostic classes
    for all activated diagnostic instances
      for all services
        export data objects.

R005.0: in the CSV file, for one service, first export one line for the service using object names, like:

"Basis-Variante";"Sessions";"Default";"Start"

The columns must correspond with the header specified in R003.0.

R006.0: In the CSV file, for one service, export one line for each data object of the service, where columns specified in R005.0 are left empty, and only data object columns are filled:

;;;;Data object;Data type;default value;const value;Label

The columns must correspond with the header specified in R003.0.

Background: column order must be consistent with the CANdelaStudio user interface (telegram table).

R007.0: Add a Unicode Byte Order Mark (BOM) to the file.

[DOE-R010 DIDs] Data Overview Export shall not export a DID Data Reference [DID-R160] but instead the DID Data [DID-R155] (CDS-40126 8.5 SP3).

Columns

The following columns will be created on export in the CSV file (in this order):

  • Variant: Name of the variant
  • Diagnostic class: Name of the diagnostic class
  • Diagnostic instance: Name of the diagnostic instance
  • Service: Name of the service to which the data object belongs
  • Data object: Name of the data object
  • Data type: Name of the data type referenced by the data object
  • Default value: Default value of the data object (if any, empty if none)
  • Const value: Constant value of the data object (if any, empty if none)
  • Label: Label of the data object as imported from A2L, see below.

The number format of default and const value depends on the display format defined at the data type.

At the top of the table, the file name of the exported document as well as date and time of export will appear.

Export will be restricted to specified target groups: if a service or its diagnostic instance is not part of a specified target group, then it will not be exported.

Services and data objects of deactivated instances will not be exported.

Export of ASAP2 Labels (CDS-4740 4.0 SP2)

A2L import stores the “Label” of a data object in an attribute of the data object [IA2L-R100-DA]. If this attribute is present, its contents will be added to the exported table (column “Label”, see above). The information will be used e.g. by code generation (CANdesc).

Note: Labels are only present in a CANdela document if it contains data objects imported from an A2L file.
