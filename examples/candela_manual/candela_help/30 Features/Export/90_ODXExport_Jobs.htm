Jobs

The following section describes the mapping of CANdela-Jobs to ODX-SINGLE-ECU-JOBs.

Export of Jobs

[ODXE-R1090-Jobs]

With CANdela 5.5 it is possible to optionally restrict the export of SINGLE-ECU-JOBs to Jobs that have at least one Function with syntax 'Class, jar, java'. In this case, the JAVA-function is exported as PROG-CODE. In case no JAVA-Function is defined and the option is set, the Job is skipped and a warning is emitted.

Deactivated Jobs

With CANdelaStudio 7.0 SP1 it is possible to deactivate Jobs. In case a Job is deactivated it will not be exported to ODX.

SINGLE-ECU-JOB.SHORT-NAME/LONG-NAME

With CANdela5.5 the new Service-Property 'JobShortCutQualifer/JobShortCutName' is used as SHORT-NAME/LONG-NAME.

DIAG-SERVICE Value
SHORTNAME JobShortCutQualifier
LONGNAME JobShortCutName

Table 25: Short- and Longname of Diag-Service

During migration of documents from 5.0 to 5.5 the Value is calculated by concatenating Job and DiagInstance-Qualifier/Name as done before. In case the Odx-attribute 'SINGLE-ECU-JOB.SHORT-NAME' (With Template) is set, the value will be used as JobShortCutName.

The TextId of the ShortCutName is used as TID in ODX.

SEMANTIC

With 6.0 Release, each CANdela-Job has the property "Semantic". Here the user is able to specify the SEMANTIC of the ODX SINGLE-ECU-JOB directly.

PROG-CODE

For each function a PROG-CODE is exported with the following properties:

CANdela-Function ODX-PROG-CODE
Filename of the CANdela-Function CODE-FILE
Syntax SYNTAX
Version REVISION
EntryPoint ENTRYPOINT

Table 26: PROG-CODE properties

The CODE-FILE is also exported to the FILE-SYSTEM.

INPUT-PARAM/OUTPUT-PARAM

For every CANdela-Input/Output-Parameter, an ODX-INPUT/OUTPUT-PARAM is generated.
