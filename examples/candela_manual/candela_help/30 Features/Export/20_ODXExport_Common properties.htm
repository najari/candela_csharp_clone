Common properties

ODX SHORT-NAME

Usually the ODX SHORT-NAME is generated from the Qualifier of the corresponding CANdela-Object.

ODX LONG-NAME

Usually the ODX LONG-NAME is generated from the Name of the corresponding CANdela-Object.
With CANdela 7.1 it is possible to specify LONG-NAMEs up to 255 characters.

ODX-DESCs

In ODX-DESCs the following XHTML tags are used for formatting text: "br", "i", "u", "font", "sub", "sup", "ul", "ol", "li". In ODX 2.0.1 scheme the elements "u" and "font" are not used. So they cannot be used in valid ODX 2.0.1 files.

CANdela description ODX DESC
normal text normal text
bold text text of b-tag
italic text text of i-tag
bullet list ul-list with li-items
numbered list ol-list with li-items

Table 2: Mapping of CANdela description to ODX DESC

Corresponding format elements for "sub" and "sup" do not exist in CANdela. Hence, they are not used by the export.

In ODX2.2.0 a paragraph may not contain Lists anymore. Hence, a list (<ul><li>) is always used as start of description.

ID

[ODXE-R1020-ID]

Usually the ID of the generated elements is a consecutive number.

With 5.5 Release, the possibility exists for all manufacturers. This feature is optional (see Options).

Hierarchical IDs

[ODXE-R1020-HierarchicalIDs]

By specifying the ODXExport-Option "CreateHierarchicalIds", stable IDs
are generated. Therefore a SHORT-NAME-PATH is calculated by concatenating the SHORT-NAME of the current element to the SHORT-NAME of all elements in the hierarchy above. The individual SHORT-NAMEs are separated by a "_".

OID

[ODXE-R1020-OID]

With CANdelaStudio 5.5 it is possible to export optionally OIDs for certain ODX-Objects (‎Configuration of Export). In case where a 1:1 mapping exists between CANdela-Object and ODX-Object, the CANdela-OID is directly used for ODX. In cases where an ODX-Object is generated from more than one CANdela-Object, a concatenation of CANdela-OIDs is used as ODX-OID.
