Vehicle System Groups at Data Objects (CDS-4250 5.5)

Introduction

[VSG-R100-DataObject] The Optional Subsystems feature can be extended to describe even optional data objects.

In order to express that an individual data object is available only when a specific Vehicle System Group has been detected (= in a specific “configuration”), the user must enter the qualifier of that Vehicle System Group into a special data object string attribute.

  • If the attribute value is empty, the data object is available in all “configurations”.
  • If the data object is “not available” in some configuration, this means that...
    • the data object is transported over the line,
    • but it behaves like a “reserved” data object [DO-R200] (= no value and no conversion is known).
    • A data object being “not available” does not mean that the transported telegram is shorter!

Note: marking an individual data object as "not available"...

  • does not require that the diagnostic instance is assigned to the Vehicle System Group
  • which would switch the entire diagnostic instance.

Attribute "Systems"

[VSG-R110-AttributeSystems] This requires a special data object attribute in the document:

  • attribute type String [ATTR-R020-string]
  • qualifier "Systems"
  • category "Editor"
  • usage "system" [ATTR-R070]

Relation with Availability for Variants

Vehicle System Group Availability for Variants

OBD PID 0x13 / PID 0x1D use-case

OBD Powertrain Diagnostic and Freeze Frame Data (services 0x01 and 0x02) have different structure depending on the fact whether PID 0x13 or 0x1D or none of them is supported. Each of these three variations can be described by an optional subsystem that is associated with the respective diagnostic instances.
