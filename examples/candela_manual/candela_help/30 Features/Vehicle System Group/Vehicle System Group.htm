Vehicle System Group ("System view") (CDS-1436)

Use-case

Garage technicians using diagnostic test tools want to see a single view containing all diagnostic features associated with a specific vehicle system.

Introduction

Vehicle System Group

[VSG-R010] A CANdela document contains 0..n Vehicle System Groups (VSG).

  • A Vehicle System Group defines a specific "view" onto the data of the ECU.
  • Additionally, it may describe a function ("system") that has been implemented in multiple ECUs.
  • A Vehicle System Group can be associated with diagnostic objects.
  • If associated with an Identifying Feature, a Vehicle System Group describes an optional subsystem.

Free-text Semantics

Vehicle System Group Semantics

The "semantics" of a Vehicle System Group can be used to mark it as the definition of a LIN Master or a LIN Slave (CDS-7907 6.0).

Predefined values in the user interface are "Slave" and "Function".

Associated Objects

[VSG-R100 Association] A Vehicle System Group can be associated with...

  • [VSG-R100-DiagInst] diagnostic instances,
  • [VSG-R100-JobCnr] job containers,
  • [VSG-R100-DTC] DTCs and
  • [VSG-R100-DataObject] data objects (after configuration in the template, [VSG-R110-AttributeSystems])

[VSG-R100-Cardinality] The association is n:m, i.e.

  • 0..n VSGs associated with a DTC
  • 0..n DTCs associated with a VSG

[VSG-R100-Direction] The association is not directed, it can be accessed both from the VSG and the DTC (the GUI shows it at both objects).

[VSG-R050 VSG and Library]: objects in a library (even data objects) can be associated with a Vehicle System Group. Motivation: like ESD in ODX.

Available in Variant (CDS-13682 7.0 SP1)

Use-case

Vehicle System Group Available for Variant

  • a Vehicle System Group "Control Folding Top (LIN)" is assigned to diagnostic instances and DTCs relevant for folding top functionality
  • some variants include a folding top, some don't
  • for variants that do not include a folding top, it should not be possible to erroneously assign the Vehicle System Group "Control Folding Top (LIN)"

Data Model

  • [VSG-R080] CANdelaStudio allows to define that a VSG is not available for a (base or extended) variant ("variant exclusion").
  • [VSG-R085] If a variant gets copied, the copy has the same exlusion settings (except if the VSG is missing in the target).

Note: this is a relationship between the two entities "variant" and "VSG", which may be seen from both sides:

  • exclude a variant from a VSG
  • exclude a VSG from a variant.

Exclusion can be defined for existing variants only (there is no way e.g. to pre-define exclusion for future variants in the template).

[VSG-R200 Library and Availability for Variants]: a library is not relevant for the VSG „Availability for Variants“. Motivation: a test system will never identify the Library, [LIB-D010].

Semantics:

Assume variant V has been excluded from a VSG.

a) the GUI will try to avoid association of objects in V with that VSG. But it is not considered an error if such an object (e.g. a diagnostic instance) is associated with the VSG, and there may be operations that lead to such an association.

b) if the VSG has identification (= is an "optional subsystem"), then after a test system has detected V, it shall skip (not send) the identification services of this VSG
