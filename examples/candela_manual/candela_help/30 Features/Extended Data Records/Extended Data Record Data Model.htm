Diagnostic Class Template

Diagnostic Instance

Extended Data Records List

[EDR-R030] A Fault Memory Diagnostic Instance contains a list of 0..n Extended Data Records.

  • [EDR-R030-Card] Cardinality: Diagnostic Instance 1..1 -- 0..n Extended Data Records
  • [EDR-R030-Type] Extended Data Records are not allowed in a Diagnostic Instance of a type [DCLT-R200] other than "Fault Memory".
    • cf. modification of the class type [DCLTOP-R200-EDR]
    • and the correction on loading [LOAD-R200-EDR].
  • [EDR-R030-OBDII] Extended Data Records are not allowed in an OBDII Fault Memory Diagnostic Instance.
  • [EDR-R030-Protocol] Extended Data Records are allowed without restriction by the Protocol Standard [DOCUI-R120].
  • [EDR-R030-UserDef] Extended Data Records are allowed in a Fault Memory diagnostic instance of any Fault Memory Type: Primary or User Defined Memory [UDFM-D100].

[EDR-R035] The Extended Data Records have no persistent sort order.

  • Assumption: the user interface sorts them ascending by Number.

Extended Data Record Properties

This chapter describes all properties and relationships of an Extended Data Record.

[EDR-R110] An Extended Data Record has Name, Qualifier, Description.

  • [EDR-R110-Qualified] Name and Qualifier must be unique in the list [EDR-R030].

[ATTR-R050-EDR] An Extended Data Record has Default Attributes.

Extended Data Record Number

[EDR-R120] An Extended Data Record has a Extended Data Record Number (SRN)

  • [EDR-R120-Range] Value range: 1..0xEF.
  • Note - UDS reserves the other values:
    • 0x00: reserved by ISO/SAE.
    • 0xF0 – 0xFD: "reserved by ISO/SAE for future reporting of groups in a single response message."
    • 0xFE: "requests the server to report all legislated OBD stored DTCExtendedData records in a single response message."
    • 0xFF: "requests the server to report all stored DTCExtendedData records in a single response message."
  • [EDR-R120-Unique] Extended Data Record Numbers shall be unique in the Extended Data Records list (i.e. within the Fault Memory).
  • [EDR-R120-DefaultDisplay] Default display of the Extended Data Record Number:
    • 2 hex characters
    • upper case
    • with leading zeroes
    • examples: "0x01", "0xF0"

Storage Trigger

[EDR-R150] An Extended Data Record has an enumeration property Storage Trigger (CDS-71894).

  • Values, default and order of the values are as for Snapshot Records, see [SR-R150].

[EDR-R155] An Extended Data Record has a string property customTrigger

  • Details are as for Snapshot Records, see [SR-R155].

Updated

[EDR-R160] An Extended Data Record has a Boolean property Updated (CDS-71894).

  • Details are as for Snapshot Records, see [SR-R160].

Motivation:

  • The property has no use for DEM internal elements
  • ... but it is relevant for DEM external data elements:
    • DEM must “update” their internal representation.

Extended Data

[EDR-R200] A Fault Memory Diagnostic Instance contains Extended Data.

  • [EDR-R200-DataObjects] Extended Data consists of a list of 0..n Parameters [DO-R010] (a Telegram Table).
  • TODO use in path, [OBJP-R200]

Extended Data stored for Extended Data Records

[EDR-R300] The diagnostic in contains a Boolean for each (DTC, Extended Data Record) combination.

  • It describes whether the ECU shall at runtime store the Extended Data Record for the given DTC.
    • Example: specify that the ECU does not store the Occurrence Counter for DTC 0xC003113.
  • [EDR-R300-Default] Default: true.

Consistency Conditions

[EDR-D100]

  • [PC-D050-ededrUse] If a Primitive contains an ed proxy component, it must also contain an edrproxy component.
  • [PC-R050-edrUnique] A Primitive may contain at most one edr proxy component.
  • [PC-R050-edUnique] A Primitive may contain at most one ed proxy component.
