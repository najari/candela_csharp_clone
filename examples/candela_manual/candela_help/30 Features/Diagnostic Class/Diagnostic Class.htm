Diagnostic Class

Introduction

CANdelaStudio divides diagnostic services into "diagnostic classes".

A diagnostic class represents a "use-case", or “functional unit” (in UDS). See the diagnostic instance chapter for the idea of object orientation behind diagnostic classes and diagnostic instances.

The set of diagnostic class in a CANdela document is predefined in the diagnostic class template. Typically it is specific for the manufacturer process.

A diagnostic class contains

  • diagnostic instances
  • job containers

CANdelaStudio shows diagnostic instances that can occur only once in a variant (e.g. Fault Memory) on the same level as diagnostic classes.

Diagnostic Class and DIDs

[DCL-D001] A diagnostic class is DID enabled if

  • [DCL-D001-a] it has the “DID Data Reference” semantics set [DID-R050], or
  • [DCL-D001-b]
    • [DCL-D001-service] it has service 0x22, 0x2E or 0x2F (cf. Identifiers in UDS and OBD Services),
    • and [DCL-D001-b1] either no diagnostic instance exists in the diagnostic class,
    • or [DCL-D001-b2] at least one diagnostic instance contains a DID Data Reference as the single data object in a telegram.
