Negative Response

Page "Available Negative Response Codes"

Introduction

UDS

  • UDS defines Negative Responses,
  • which contain a Negative Response Code (NRC).
  • Each NRC represents a specific error situation, like "Service not supported".
  • UDS describes detailed conditions that trigger the different NRCs (message flow diagrams).

CANdela

  • In CANdelaStudio, you may effectively assign a fixed set of NRCs to each service
    • e.g. to service 22 F1 90: NRC 0x13, 0x22, 0x31, 0x33
  • Additionally, you may assign one NRC for each State Group
    • e.g. NRC 0x33 if security access has been denied.
  • For details, see the chapters below.
  • These NRCs assignments only roughly describe the detailed NRC conditions in UDS.
    • The same typically holds for other protocols.
  • All these NRCs are taken from a set of "Available Negative Response Codes" defined centrally on document level.

Vector Toolchain

  • A tester must simply display the interpreted value of the response code.
    • Using the description in CANdelaStudio, you cannot make a tester show a warning or error message if it receives an NRC not valid for a given service.
  • CANoe.DiVa
    • ignores any NRC definition in the CANdela document at a service.
    • For test generation, it purely uses the UDS protocol standard (ISO-14229).
  • The same holds for code generators.

Recommended Use of NRCs

  • Unless needed for specific tools, or for documentation purposes,
  • don't describe NRCs at individual services.
  • Describe the Available Negative Response Codes (on document level).
  • As a template author, you may additionally define default NRCs on Protocol Service level
    • e.g. default NRCs for all service instances of Protocol Service 0x22, or of Protocol Service 0x19 0x04.

5 Locations of NRCs in the CANdela Data Model

The CANdela data model supports Negative Response Codes in 5 places (for details, follow the hyperlinks to chapters below):

  1. [NRC-R010-Pool] The Available Negative Response Codes on document level (CDS-2048, 3.0)

  2. [NRC-R020] Negative Response Codes for Unsupported Services (response codes independent from any service, e.g. „General Reject“, "Subfunction not supported")

  3. [NRC-R030] Default response codes for a service at the Protocol service

  4. [NRC-R040] Response Codes at the service in a diagnostic instance

  5. [NRC-R050] Response Code at a state group (CDS-2390, 3.0)

[NRC-R110] The numeric codes must be unique within every location.

NRC Pool

[NRC-R010-Pool] The NRC pool contains a set of negative response codes with all NRCs of the document, i.e. it is the superset of the NRCs of all other locations.

  • Adding an NRC to the pool has no effect on the other locations.
  • Modifying an NRC (i.e. the text) in the pool must be reflected in all other locations (with user confirmation).
  • Deleting an NRC from the pool must be reflected in all other locations (with user confirmation)

Consistency Conditions

[NRC-R100] (CDC-43755 9.1) in a template, ...

  • if the bit length of NRCs != 8,
  • then CANdelaStudio writes a warning like "Negative Response Codes have bit length != 8".

Note: in a document, there is no way to make the warning disappear, therefore CANdelaStudio does not show it - it shall be noticed by the template author.

Negative Response Codes for Unsupported Services

[NRC-R020] The UnsupportedServiceNegResponse is a Primitive [PS-R100]...

  • stored at the document,
  • displayed in the CANdelaStudio tree under “Negative Responses”)

The ECU sends this primitive if it cannot associate a test system request with a supported service or supported service subfunction.

Default NRCs

[NRC-R030] Default response codes for a service at the Protocol service are used only when you create a service. They define the initial set of NRCs at the service.

CANdelaStudio shows them in the Protocol Service dialog [PSPUI-R110] at the Compontent that represents the Negative Response.

The properties of default NRCs must be identical to those of the respective pool NRCs.

Negative Response Codes at a Service

See also the NRC list in the user interface [DIUI-R410].

Negative Response Codes at a Service

[NRC-R040] An NRC at the service references an NRC in the list of Available Negative Response Codes (NRC pool) on document level.

  • You may add any NRCs from the pool (but no other ones).
  • You may add an NRC even if it is already used in the Negative Response Codes for Unsupported Services (described in the chapter above).
    • This "overwrites" the NRC at the service.
  • At the service, you can change the description of the NRC.
  • "Deleting" an NRC locally has no impact on the pool.

CANoe.DiVa ignores any NRC order or definition in the CANdela document at a service. The test generation is purely based on the UDS protocol standard (ISO-14229).

If the service is blocked [STTR-R020-no] in some state of a state group, the NRC associated with that state group [NRC-R050] is part of the NRC list of the service (automatically).

Negative Response Code at a StateGroup

[NRC-R050 State Group NRC] A state group has an NRC associated.

The ECU shall send this NRC if it receives a service request, but the current state of the state group blocks [STTR-R020-no] execution of the service.

The following sub-chapters list limitations for using this NRC defined at a state group.

NRC at Session and Security Access

For state group Session, ...

  • the Vector tools CANdesc and CANoe.DiVa do not use this NRC, but implement the more detailed behavior specified by UDS.
  • AUTOSAR modules don't use it, either.

According with UDS, the ECU may send different NRCs:

  • 0x12 Subfunction not supported
  • 0x7E Subfunction not supported in active session
  • 0x7F Service not supported in active session

Therefore a single NRC from the state group is not appropriate for Session. The same holds for state group Security Access.

In CANdelaStudio, just specify one of the possible NRCs at these state groups.

NRC at Other State Groups

For state groups other than Session and Security Access, ...

  • CANdesc and CANoe.DiVa use the NRC at the state group when the ECU rejects a service request due to a state of that state group.
  • AUTOSAR modules don't use it.

Effect on Services

[NRC-R060] When you...

  • create a diagnostic instance with some service, and
  • the default state transitions for the service specify that the service cannot be executed in some state (shown as "No" in the list),
  • then CANdelaStudio automatically adds the NRC from the state group in the NRC list of the service.
  • In the list, CANdelaStudio shows the NRC with a special icon [DIUI-R420-Icon] to indicate that it originates from the state group.

[NRC-R070] You can delete this NRC (CDS-12776 6.5).

  • If you add it again, CANdelaStudio will automatically show it with the special icon.
  • [NRC-R070-NotAdded] When you later specify that the service cannot be executed in some state of the state group,
    • the NRC of the state group will in principle apply to the service.
    • But CANdelaStudio does not automatically add the NRC in this situation (you may just have deleted it!),
    • nor does it prompt to add the NRC - you can always add the NRC manually, as necessary.
  • [NRC-R070-Migration65] CANdelaStudio does automatically add the NRC from the state group when you load a document of a version before 6.5 into version 6.5 or later (CDS-12776 R022, 6.5).
