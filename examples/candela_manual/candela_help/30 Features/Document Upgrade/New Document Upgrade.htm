New Document Upgrade (CDS-70041 v11)

[DOCUP-R600] Operation to transfer data from a newer template version to a document based on an older template version, with selection of variants to be affected.

You start it via ribbon tab Document | Template | New Document Upgrade [MENU-R568], opening the dialog [DUUI-R100].

Note: as of v11, the operation transfers only modifications of...

  • Default Attributes
  • Data Types
  • DIDs
  • Diagnostic Instances

Use-Cases

Each CANdela document is based on a CANdela template.

You may want to modify a template...

  • for bugfixing
    • e.g. the old template contains a typo Paramter,
    • correct it to Parameter
  • for adding a new diagnostic feature
    • e.g. add a new Security Access policy,
    • or add a new DID.

For both cases, it may be desirable to update existing documents as well, so that they are based on the new template:

  • apply the bugfix Parameter
  • add the new Security Access policy or the new DID.

Overview

The document upgrade...

  • lets you select the old (original) template on which your document is based,
  • and the new (modified) template.
  • It computes the changes made in the new template,
  • and applies these to your document,
    • to selected variants only.
    • It copies over data that has been modified in the template only.
    • It keeps data unchanged which has been modified in the document only.
  • For conflicts (data modified in the document as well in the new template),
    • it shows a dialog to resolve the conflicts,
    • i.e. select which data to use in the result.
  • Finally, the operation allows to create a revision entry for the document upgrade.
    • The revision is pre-filled with generated information about the differences.
  • Some data constellations may need further attention.
    • For this purpose, the document upgrade fills a Rework list which you can check afterwards.
    • Document Upgrade clears the Rework List at each run [DOCUP-R655].

Types of Data in a CANdela File

A CANdela template contains...

  • Template Data
    • e.g. Protocol Services, Diagnostic Class Templates, Default Attributes
    • in Standard View in a document based on the template, you cannot modify these objects
  • Document Data
    • (in the following, this includes Base Data from the diagram above)
    • e.g. data types, diagnostic instances and DIDs in the base variant
    • in Standard View in a document based on the template, you can modify these objects

[DOCUP-R610] For Template Data, Document Upgrade...

  • [DOCUP-R610-Coverage] as of v11, supports only changes of...
    • Default Attributes.
    • Note: the wizard documents this in the static text [DUUI-R150].
  • [DOCUP-R610-Other]
    • It detects all other template data changes,
    • but does not transport them to the document.
    • Therefore, it reports them in the Rework List [DOCUP-R650].
  • [DOCUP-R610-Always] The operation applies the supported changes always, unconditionally.
    • E.g. when a Default Attribute has been changed from unsigned to enum, there is no choice for you ("template wins").
    • When this change effects in loss of document data, the operation adds the change to the Rework List,
    • e.g. when the operation cannot automatically convert an overridden unsigned value to an enum value.

[DOCUP-R615] For Document Data, Document Upgrade...

  • [DOCUP-R615-Coverage] as of v11, transports only changes of....
    • DIDs
    • Diagnostic Instances
    • Data Types
  • [DOCUP-R615-Other]
    • It detects all other Document Data changes,
    • but does not transport them to the document.
    • Therefore, it reports them in the Rework List [DOCUP-R650].
  • [DOCUP-R615-NoConflict] The operation applies these changes only if there is no conflict.
    • For details about possible conflicts, see the types of changes in the following chapter.

[DOCUP-R620] A conflict arises for each object modified/deleted both in the document and in the new template.

  • You may resolve the conflicts in the second page of the dialog [DUUI-R200].

Variant Selection

[DOCUP-R640] The operation uses the variant selection [DUUI-R140] to restrict application of template changes to the given variants.

  • [DOCUP-R640-Global] Since all objects in a CANdela document must conform with the template (which is a strength of the CANdela data model), some Template Data changes cannot be confined to a subset of variants.
    • E.g. removing a Default Attribute automatically removes all its Overridden Attributes in all variants.
  • [DOCUP-R640-ReworkList] The operation reports such changes that violate the variant restriction in the Rework List [DOCUP-R650].

Rework List

[DOCUP-R650] Document Upgrade puts the following information into the Rework List:

  • [DOCUP-R610-Other] Template data changes not handled by the Upgrade
  • [DOCUP-R640-Global] Template data changes that take effect on a variant not selected [DUUI-R140].
  • [DOCUP-R615-Other] Document Data changes not handled by the Upgrade.

[DOCUP-R655] Document Upgrade clears the Rework List at each run!
