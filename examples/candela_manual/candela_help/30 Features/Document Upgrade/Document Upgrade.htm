Document Upgrade

[DOCUP-R001] Operation to transfer document data onto another template, started via ribbon tab Document | Template | Document Upgrade [MENU-R560].

Besides this, there is the New Document Upgrade [DOCUP-R600] (v11).

Availability (CDS-16383 6.5 SP2)

[DOCUP-R005] If...

  • an ECU attribute with qualifier "ProhibitDocUpgrade" exists and
  • has a non-zero value, and
  • the user selects "DocUpgrade" or "DocUpgrade (Template only)",

... then CANdelaStudio...

  • refuses the operation,
  • shows a message like "DocUpgrade is not allowed for this document" and
  • additionally writes a log message.

Handling of Base Variant

[DOCUP-R010-EvenBaseVariant] Menu item "Document Upgrade" takes even the contents of the base variant from the template.

[DOCUP-R010-TemplateOnly] Menu item "Document Upgrade (Template Only)" preserves the base variant of the document, ignores that of the template.

Locked Library

[DOCUP-R040] If a library in a document is locked [LIB-R020], document upgrade shall not modify its contents.

Libraries

[DOCUP-R050] If the library property "created in template" [LIB-R022] is true, CANdelaStudio shall take the library from the template, otherwise the one from the document.

DIDs

[DOCUP-R070 DID References in Document Upgrade]

For a DID referenced [DID-D005] in the source document between diagnostic layers (variants and/or libraries), ...

  • "Document Upgrade" and "Document Upgrade (Template Only)":
    • ... shall preserve the reference in all diagnostic layers in the upgraded document which have an equivalent in the source,
    • ... for DIDs reference with a library: If the library alreadys contains a DID with the same qualifier or Identifier, Document Upgrade shall break the reference and leave the original DID of the template.

[DOCUP-R072 DID Authorization in Document Upgrade]

  • "Document Upgrade" and "Document Upgrade (Template Only)":
    • ... shall handle DID authorization the same way container authorization properties are handled in [DOCUP-R300].

Authorization Properties of Containers (Diagnostic Instances and Job Containers)

[DOCUP-R300] In the upgraded document, for authorization properties of containers (as for example defined in [DIA-R020] -- [DIA-R050] for diagnostic instances) ...:

  • Document Upgrade [DOCUP-R010-EvenBaseVariant]:
    • ... takes over the values of the container in template,
    • ... sets the values back to default, if a container is not existing (missing) in the template.
  • Document Upgrade (Template Only) [DOCUP-R010-TemplateOnly]:
    • ... keeps the values of the container in the document which is upgraded,
    • ... even if the corresponding container is missing in template (in contrast to DocUpgrade).

Activation

[DOCUP-R400] A diagnostic instance which is deactivated in cdd and in cddt shall still be deactivated after DocUpgrade.

Requirements

[DOCUP-R310] in document upgrade "template only" [DOCUP-R010-TemplateOnly]...

  • the requirements pool of the original document shall be identically in the resulting document,
  • the requirements pool of the template shall be dropped.

See Requirements Data Model R085.

Attributes

[DOCUP-R500] in document upgrade, if...

  • the document contains an overriding value (ID + symbol) for an enumeration attribute [ATTR-R020-enum],
  • and that numeric ID has been deleted in the target template,
  • then CANdelaStudio shall drop the overriding attribute (CDC-41487 8.5 SP3).
