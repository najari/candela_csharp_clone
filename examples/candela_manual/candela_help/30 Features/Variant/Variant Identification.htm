Variant Identification

See also the dialog for Identifying Features.

Introduction

A diagnostic tester device in the garage needs to detect the ECU’s variant to determine e.g. its coverage of diagnostic support. The variant can be determined by analyzing the response telegrams of specific services.

In development phase, ECUs are subject to permanent software releases which may produce many implementation variants. In most cases this does not affect the diagnostic part of the ECU’s implementation. From this it follows that the diagnostic variants are a subset of the real ECU variants.

The “Variant Identification” feature in CANdela describes how a variant gets identified. The solution allows specifying more than one identification per variant, to take the diagnostic independent ECU variants into account.

The “Variant Identification” feature enables the client to do variant identification in an automated and efficient way. The test system must send some requests and determine the variant from the response values.

In the CANdela data model, the data objects evaluated are called "Identifying features". Their values specific to a variant are called "Identifying patterns".

Identifying Feature

In the base variant, the Identifying Features describe which services the client shall send to the ECU, and which response data objects shall be inspected to identify the variant.

Starting with 8.0, Job output parameters can be used for variant identification, too (CDS-25092).

Starting with 8.1 SP1 (CDS-32113), data objects within a DID can be used for variant identification - the same objects as within a diagnostic instance (including objects in a bitfield, but not: data object referencing a complex data type, reserved data object). The implementation uses the data object path into the DID and the service path into the diagnostic instance.

Identifying Pattern

Extended variants (all variants except the base variant) contain Identifying Patterns.

An Identifying Pattern describes which concrete values of the data objects mentioned in Identifying Features identify the given variant.

  • An Identifying Pattern defines values for a subset or all response data objects. At runtime, the client will match the ECU response against these values. The variant is detected only if all defined values match (conjunction, “AND” condition).

  • You can specify multiple Identifying Patterns per variant. The variant is detected if either one of the patterns matches (disjunction, “OR” condition).

Example

The following example shows two variants identified by using the diagnostic instance “EcuIdentification” and the data objects “SWVersion” and “HWVersion” of the response.

Variant A has two alternative Identifying Patterns: (0x010000, 0xA32200) and (0x010100, 0xA32200). Actually, the values for the first data object (0x010000 vs. 0x010100) distinguish the variants, while the values for the second data object are identical (0xA32200).

Mandatory Identifying Features and Patterns (CDS-7937 5.0)

R001.1: add flag whether an identification feature is mandatory (= pattern must be specified). Default value is false.

R003.1: consistency check shall throw an error if for any mandatory Identification feature, the pattern is not set in any of the document's variants. No data export shall be possible.
