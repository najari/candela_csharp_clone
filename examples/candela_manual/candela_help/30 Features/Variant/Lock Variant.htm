Lock Variant

Introduction

Objective: protect released variants from changes.

Use-cases

UC001: the diagnostic description containing an already released variant is used for a further variant to describe a new car model.

Scenario: there is a sequence of development variants, lock the last one, continue development after it, maybe again with locking another one.

UC002: old (maybe even released) variants must be corrected.

Data Model

[VAR-R010.2 isLocked]: a variant shall have a Boolean property “isLocked”

  • applies to base and extended variants
  • Semantics: prevents from modifications of data in the variant in Standard View.
  • default: false

Operations

Lock Variant

[VAR-R015] The operation Lock Variant...

  • [VAR-R015-a] sets the "locked" property of [VAR-R010] to true
    • does not modify referencing of diagnostic instances and job containers;
    • does not modify “modify primary” [DIA-R040] and “modify secondary” authorization in the diagnostic instances and job containers of the locked variant.
  • [VAR-R015-c] Data Types: in each data type referenced from within the variant,
    • if the datatype has “modify” authorization true (= is “writable”), the operation...
    • [VAR-R015-c1] sets “modify” authorization to false
    • [VAR-R015-c2] adds a hint to the datatype description (in the editing language): The data type '<name>' was set to read-only when variant '<name>' has been locked..
    • Note: this definition appends the text…
      • at a datatype that is writable: only for the first variant getting locked;
      • at a datatype that is already not writable: not even for the first variant getting locked.
    • [VAR-R015-cDID] this also applies to data types referenced from DIDs in the variant (CDS-40782).
  • [VAR-R015-d] DTCs: for each DTC, ...
    • [VAR-R015-d1] if it is “required as reference” or DTC referencing from DTC Pool [DLA-R100-PoolOnly] is enforced, sets the DTC to not modifiable + write info in output window
    • [VAR-R015-d2] if the DTC is not “required as reference”, clones it.
  • [VAR-R015-DIDs] DIDs: for each DID referenced from within the variant (8.5 CDS-37944), ...
    • i.e. for DID Data Reference and DID Reference
    • if the DID has “modify” authorization true (= is “writable”),
      • sets “modify” authorization to false,
      • adds a hint to the DID description (only in the editing language), like DID '<name>' was set to read-only when variant '<name>' has been locked.
    • Note: this definition appends the text…
      • at a DID that is writable: only for the first variant getting locked;
      • at a DID that is already not writable: not even for the first variant getting locked.

Unlock Variant

[VAR-R016 Unlock Variant] The operation Unlock Variant...

  • set the property of [VAR-R010] to false.
  • [VAR-R016-Reset] Data Types (CDS-69019 9.1): for each data type that...
    • was set write-protected by "Lock variant",
      • detection: the data type description matches the regex pattern "The data type.*has been locked." (in any language);
    • and the variant being unlocked is the only locked variant that uses it,
    • CANdelaStudio removes the info (in all languages) "The data type.*has been locked."
      • it does not modify the "up-to-date" info of the description (in any of the languages)
    • ... and sets the data type "modifiable".
    • Note: on lock variant, CANdelaStudio adds the info text only if the data type is modifiable [VAR-R015-c], so the "unlock" does not erroneously un-protect a formerly protected data type.

Compare

[VAR-R020]:

  • In normal document comparison: Calculate difference but do not update the locked property. If a variant is locked in the target document skip the variant on update (do not update).

  • In document upgrade mode: When transferring a variant (base or extended) to the new instantiated template, keep the locked property at the variant and assure the correct state of its contents according to [VAR-R015] above.

  • When updating a non locked variant ensure that diagnostic instances which are also referenced by a locked variant are not updated.

Migration

[VAR-R030 Migration]:

b) migration 7.0 => 7.1: default false.

c) migration 7.1 => 7.0: drop the property (maybe write to file anyway to read it in 7.1).

Requirements not covered

U001: Disable any editing in the variant (it is still possible to add a diagnostic instance, modify a diagnostic class etc.).

U002: there is no referencing of a complete variant in CANdela. But yes, it will still be possible to reference containers of a locked variant.

U003: no editing with confirmation of diagInstances or datatypes. The feature just uses the existing authorization mechanism.

U004: editing of a locked variant is possible in expert mode (where authorization is not respected), no password.

U005: no icon for datatypes.

U006: the locking does not apply to data in the import pool.
