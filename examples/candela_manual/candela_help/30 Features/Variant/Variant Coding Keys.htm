Variant Coding Keys (VCK)

Variant coding keys are supported for specific manufacturers only. They are also called "Supplement keys".

They must be enabled on document level.

With the advent of ODX, the ODX-E component of ODX supports the VCK use-case.

A data object in the diagnostic class Variant Coding controls a certain feature of the ECU. Typically, a text table provides a list of possible values for one such data object. Only data objects with text tables are considered in the VCK context.

The set of all such data objects define the possible "variant codings" (configurations) of the ECU. One configuration is defined by taking one value from each text table.

A VCK is an arbitrary typically short string ("key", "fragment") that represents such a text table value.

For documents with VCK mode != "none", CANdelaStudio does not automatically (re-) computes VCKs (CDS-19410 7.0 SP1) in...

  • entry mask of diagnostic instance
  • attribute property page.

CANdelaStudio still provides recomputation in the entry mask "Variant Coding Keys".

Export

You can export the variant coding keys into a file.

The "Variant Coding Keys" file format is based on XML (Extensible Markup Language). You can view it in an XML-enabled browser, for example. The VCK file format is described in the CANdelaStudio documentation folder.
