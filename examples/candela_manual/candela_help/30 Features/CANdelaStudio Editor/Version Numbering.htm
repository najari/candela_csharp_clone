Version Numbering

Semantic Versioning https://semver.org emerges as a best practice for using version numbers.

The following describes the use of Semantic Versioning for various entities in the context of CANdelaStudio.

The structure of a typical version number is: MAJOR.MINOR.PATCH

CANdelaStudio

[VER-R100] CANdelaStudio versions just distinguish the product releases (no further semantics).

  • They have a single number,
  • incremented by 1 in each release.
  • This holds since version 10.
  • Version 9.1 used the old version numbering.
  • Recommended: when written without context, use "v11" instead of "11".

CANdela File Format

[VER-R200] File format versions define whether a file can be loaded without the Persistors (converter add-on)

  • The file format versions have 3 numbers
  • MAJOR number: incremented to the current CANdelaStudio version for breaking changes or compatible additions
    • a breaking change prevents from direct loading
    • even a "compatible addition" (from the data model point of view) prevents from loading, since it (typically) adds a new XML element.
    • The MAJOR version is <= the CANdelaStudio version.
  • MINOR number: 0
    • Motivation:
      • the Persistors must support old CANdelaStudio versions;
      • old CANdelaStudio versions handle changes in MAJOR and MINOR as breaking, which triggers external conversion.
      • Therefore the Persistors cannot use MINOR in the way semantic versioning does.
  • PATCH number: incremented by 1 for addition of XML attributes
    • does not prevent from direct loading,
    • added XML attributes will be lost in roundtrip.
  • This rule holds since v13.
  • Multiple CANdelaStudio versions can have the same file format.
  • Advantages:
    • file format may be unchanged over multiple CANdelaStudio versions
    • no need to run the Persistors migration in these cases
  • Disadvantages:
    • given a CANdelaStudio version, you cannot directly tell the file format version, and vice versa.

Vector UDS Template

[VER-R300] The version of the Vector UDS Template describes whether a modified template version can be used in the existing process of a customer without loss of functionality.

  • MAJOR number
    • incremented to the current CANdelaStudio version for breaking changes
    • <= the CANdelaStudio version.
    • E.g. adding Events: breaking change, since DTC properties must be removed, which are then missing in older CANdelaStudio versions that do not support Events.
  • MINOR number
    • incremented for compatible changes
    • E.g. Adding/removing an AUTOSAR attribute (the process will still work)
