Version Compatibility

Data constellations to avoid for tools based on older CANdelaStudio document versions:

CANdelaStudio 13

When saving to a file version < 13, CANdelaStudio does not preserve AUTOSAR properties of the v13 AUTOSAR Fault Memory.

CANdelaStudio 12

  • When saving to a file version < 12, CANdelaStudio does not preserve Events, see [EV-R250].

CANdelaStudio 11

(none)

CANdelaStudio 10

  • (customer specific) do not enable segment numbers" > 99 if the document shall be processed or exported by CANdelaStudio versions before v10.
  • CANdelaStudio will preserve the segment number value
    • since it is stored in a generic attribute,
  • ... but will not interprete it as necessary.

CANdelaStudio 9.1

  • when using the new State Group semantics "Authorization" [STG-R050-Authorization],
    • the qualifier should be "Authorization"
    • so that loading loading the data constellation again from a version < 9.1 will detect the semantics [STG-R210].
  • when using Vehicle System Group Identification for a variant other than the base variant [VSG-R150], a CANdelaStudio version < 9.1 will load the file but not support the feature. If you don't modify the identifying feature there, you can again load the file in CANdelaStudio >= 9.1 and use the feature.

CANdelaStudio 9.0

(none)

CANdelaStudio 8.5

  • Libraries (cannot be represented in documents < 8.5)
  • DIDs differing between variants are down-migrated with name and qualifier made unique, see DID Operations.

CANdelaStudio 8.2

  • 64-bit integer data type [DTENC-R200] - it will be down-migrated to a byte array.

CANdelaStudio 8.1

  • Expert view: do not set the DID semantics “DID Data Reference” at more than one combined component in the template. In 8.0, it becomes a “DID Definition”, for which only one may exist.

  • Expert view: do not set the DID semantics “DID Data References” or “DID References” at a combined component without having “DID Reference” at another combined component. In 8.0, these become “DID Referencer”, “DID Referencer with Number” and “DID Definition”, and having one of the first is not allowed without having a DID Definition. For a telegram table where the diagnostic class template specifies whDo not insert a DID Data Reference to the same DID in one telegram table.

  • 8.1 SP1 supports an Identifying Feature to reference a data object within a DID (CDS-32647). In 8.0, the Identifying Feature cannot use a data object within a DID.

    A workaround in 8.1 is to manually replace the DID Data Reference by the data object contained in the DID. If the DID Data Reference is required by the DID semantics in the Diagnostic Class Template, the DID semantics should be removed for that Diagnostic Class Template.

CANdelaStudio 8.0

  • In the “Identifying Features” list, do not reference output parameters of jobs. CANdelaStudio drops them on saving to a pre 8.0 format.

CANdelaStudio 7.5

  • Do not use a dynamic-length data object (e.g. zero-terminated string) before the end of a telegram (when used before the end of the telegram, this data object and all data objects following in the telegram will be represented by one combined dynamic-length data object in the older document version)

CANdelaStudio 7.1

  • Do not use a name longer than 128 characters (it must be truncated in the older document version)

  • Do not use state transitions or target groups (audience) at jobs (it will be missing in the older document version)

  • Do not protect access to job files (the job files will not be accessible in the older document version)

CANdelaStudio 7.0

  • Do not use revision history at variants (it will be missing in the older document version)

  • Do not de-activate jobs (they will be activated in the older document version)

  • Do not use state transitions at jobs (they will be dropped in the older document version)

CANdelaStudio 6.5

  • Do not use Iteration or Multiplexer datatypes

  • Do not use field datatypes with leading size greater one byte

  • Do not use numeric field datatypes with zero termination

  • Do not use multiple complex datatypes with variable length (see 6.5 SP 2 feature CDS-16887)

  • Do not use variable length DIDs, for details see next item (notes for versions older than 6.0).

CANdelaStudio 6.0

  • Do not use variable length DIDs. Background: CANdelaStudio 6.0 SP 1 allows variable length DIDs (CDS-12845; e.g. a packet datatype may contain a data object which references a field datatype with min length < max length). In CANdelaStudio 5.5 and 6.0 Release, a check forbids variable length DIDs, therefore CANdelaStudio 6.0 SP 1 on saving to 5.5 and 6.0 format sets min length = max length - the DID will not be variable in 5.5 and 6.0 Release! Additionally, the min length is preserved in a special attribute and will be restored when loading the document again in 6.0 SP 1 or higher.

CANdelaStudio 5.5

  • Qualifiers that are longer than 64 characters will be shortened to 64 characters for use in 5.0 documents (CDS-7946)
  • Multiplexer selector behind the multiplexer itself (will be replaced by proxy with semantics “any”, i.e. no structure information) (CDS-7621)
  • Files with manufacturer "Standard" [DOC-R110-String] will be saved to 5.0 with manufacturer "unknown", which 4.0 SP4 cannot open (see 5.0 chapter).

CANdelaStudio 5.0

  • Environment data that depend on data other than DTCs (e.g. UDS RecordNumber; CDS-5368). Such data will be stored as proxy with semantics “any”, no data objects, in a 4.0 file.
  • In services that may be combined, do not use variable-length datatypes that have no length information.
  • [VCMP-R051] Files with manufacturer [DOC-R110] "unknown" will be saved to 4.0, but 4.0 SP4 cannot open them (CDS-70649).

CANdelaStudio 4.0

  • Identification feature that references a data object within a bitfield: in CANdelaStudio 3.0, this identification feature is reported as a non-fatal inconsistency, which prevents the file from being used for exports or in other Vector tools. But you can adapt the reference in CANdelaStudio 3.0 or newer.
