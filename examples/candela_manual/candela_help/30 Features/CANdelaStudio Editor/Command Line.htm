Using The Command Line

Introduction

The CANdelaStudio command line offers a series of options which you can use e.g. to import and export CANdela documents in batch mode, without starting the CANdelaStudio user interface.

You can specify these options in a batch file, or directly in a Windows command window.

See the examples chapter below.

The candelastudio URI Scheme provides a similar mechanism.

Batch Mode and Licensing

[CLI-R040] Running CANdelaStudio in batch mode via the command line needs the same license as running the CANdelaStudio user interface. See run without a license.

Command Line Parameters

[CLI-R050] upper and lower case is significant, like

  • /l en-US" (ok) vs.
  • /l en-us" (not ok).

[CLI-R100] CANdelaStudio supports the following command line parameters:

Option Parameter Description
(single argument) <Path to a CANdela document (CDD)> [CLI-R100-argument] CANdela document to open.
The path argument may contain a trailing object path, separated by "#" (like the query part of a URL).
Any object path syntax is allowed.
See examples below.
/a <Qualifier1>; <Qualifier2>; ... [CLI-R100-audience] List of target group qualifiers separated by semicolons.
Restricts the export to the specified target groups (audience).
/c 0, 1 [CLI-R100-interactive] Starts the import of the specified file in interactive mode (1).
The standard value is 0.
/check 0, 1 [CLI-R100-check] Runs an ODX consistency check of the Tools submenu.
Relevant additional parameters:
/e [CLI-R100-odx] denotes the version (odx201, odx210, odx220),
/g [CLI-R100-logfile] the logfile for check results.
See an example below.
/d 0, 1 [CLI-R100-DTCs] Specifies whether CANdelaStudio shall import DTCs (1) or not (0) from the file specified by /i [CLI-R100-importFile].
The standard value is 0.
/deact 0, 1 [CLI-R100-deact] (only evaluated if command line option /fullEcu [CLI-R100-fullEcu] is set to 1, and with [CLI-R100-pvcdiImport])
This option deactivates the existing services during ODX import into the CANdela document.
After import, the CANdela document applied in a Vector tester offers the same diagnostic services as the ODX file.
For batch import, if parameter /deact is given, it overrides the INI file setting.
If parameter /deact is not given, the INI file setting takes effect.
In interactive import, the INI file setting takes effect (ignoring /deact).
/e "import" or <type of export>
(see the following lines)		 [CLI-R100-DataExchange] Specifies a data exchange (an import or export).
import [CLI-R100-import] Specifies an import into a CANdela document.

Additional parameters for imports (see an example below):
/r [CLI-R100-referenceFile] existing CANdela document to import into;
/i [CLI-R100-importFile] file to import
/o [CLI-R100-output] resulting output CANdela document
/fullEcu [CLI-R100-fullEcu] import a full ECU or data types and DTCs only
/deact [CLI-R100-deact] only with /fullEcu: deactivate the existing services

The file to import may have Excel file type *.xlsx (CDS-39472 8.5).
swcsync [CLI-R100-swcsync] Runs SWC Sync [SWC-R100].
Additional parameters (see an example below):
/r [CLI-R100-referenceFile] existing CANdela document to sync into;
/i [CLI-R100-importFile] files to import, multiple files semicolon-separated;
/o [CLI-R100-output] resulting output CANdela document
/v [CLI-R100-variants] optional single value for the variant qualifier, default: the selected variant in the requirement settings [RQ-R093]).
/lib [CLI-R100-lib] like /v but for a library [RQ-R093]).
The command line parameter does not change the selected variant in the requirement settings of the document.
importRequirementsAndUpdate [CLI-R100-importRequirementsAndUpdate] Imports requirements from a .csv file [RQ-R800] and updates diagnostic objects. [RQOP-R500].
Additional parameters (see an example below):
/r [CLI-R100-referenceFile] existing CANdela document to import into;
/i [CLI-R100-importFile] .csv file to import;
/o [CLI-R100-output] resulting output CANdela document
/v [CLI-R100-variants] optional single value for the variant qualifier, default: the selected variant in the requirement settings [RQ-R093]).
/lib [CLI-R100-lib] like /v but for a library [RQ-R093]).
The command line parameter does not change the selected variant in the requirement settings of the document.
<type of export>
(see the following lines)		 Additional parameters for exports (see an example below):
/i [CLI-R100-importFile] existing CANdela document to export;
/o [CLI-R100-output] resulting output file
dext [CLI-R100-dext] Export into the AUTOSAR Diagnostic Extract [DEXT-R010]. Additional parameters (see an example below):
/i [CLI-R100-importFile] .cdd file to export;
/o [CLI-R100-output] resulting output .arxml file;
/v [CLI-R100-variants] optional single value for the variant qualifier, default: the base variant.
DTC [CLI-R100-DTC] Export of DTCs of a selected variant to Excel (format .xlsx).
Additional parameters (see an example below):
/i [CLI-R100-importFile] .cdd file to export from;
/o [CLI-R100-output] resulting output .xlsx file;
/v [CLI-R100-variants] required value for a single variant qualifier, export uses the first singleton diagnostic instance with spec FaultMemory.
/u [CLI-R100-documentLanguage] export language.
If parameter "/u" is not given, export uses the first completely translated language.
Language-independent export is not available via command line (cf. GUI option "xlsx (language-independent)", CDS-28395).
diogenes [CLI-R100-diogenes] Export into the customer specific format.
docprops [CLI-R100-docprops] Creates an XML file containing administrative information of the CANdela file: revision history, template, protocol standard.
mdx [CLI-R100-mdx] Export into the customer specific format.
odx114, odx115 CANdelaStudio since 9.0 no longer supports the export to ODX 1.1.4 or 1.1.5 (CDS-42708).
odx201, odx210, odx220 [CLI-R100-odx] Export to ODX.
To specify the ODX output format (.odx or .pdx), use the additional parameter /x [CLI-R100-odxFileFormat], like
/e odx201 /x pdx
pvcdiExport [CLI-R100-pvcdiExport] Export a CANdela Document into a PVCDI file, see introduction [PVCDI-D010] and [MENU-R1020]. /i [CLI-R100-importFile] .cdd file to be exported; /o [CLI-R100-output] resulting output .pvcdi file; /v [CLI-R100-variants] optional single value for the variant qualifier, default: the base variant. /lib [CLI-R100-lib] like /v but for a library, no default.
pvcdiImport [CLI-R100-pvcdiImport] Imports a PVCDI file into a existing CANdela document, see introduction [PVCDI-D010] and [MENU-R1010]. /r [CLI-R100-referenceFile] existing CANdela document to import into; /i [CLI-R100-importFile] .pvcdi file to import /o [CLI-R100-output] resulting output CANdela document /v [CLI-R100-variants] optional single value for the variant qualifier, default: the base variant. /lib [CLI-R100-lib] like /v but for a library, no default. /deact [CLI-R100-deact] if set to 1, deactivates diagnostic instances not touched by the import
and services in touched diagnostic instances not contained in the imported file (default 0).
rtf [CLI-R100-rtf] Export into the Rich Text Format (Microsoft).
services [CLI-R100-services] Export of services into a .csv file.
textdiff [CLI-R100-textdiff] Export of the comparison result to text.
vsg [CLI-R100-vsg] Export of Vehicle System Groups into an XML file.
xhtmldiff [CLI-R100-xhtmldiff] Export of the comparison result to XHTML.
xmldiff [CLI-R100-xmldiff] Export of the comparison result to XML.
/ecuPrfx 0, 1 [CLI-R100-ecuPrfx] Specifies whether CANdelaStudio should use the ECU qualifier as a prefix for all qualifiers on import or export of an ODX file.
/expert 0, 1 [CLI-R100-expert] For Admin edition: if you specify a CDD on the command line, "/expert 1" opens it in expert mode. (since 8.0 SP2)
/f 0, 1 [CLI-R100-datatypes] Specifies whether CANdelaStudio shall import data types (1) or not (0) from the file specified by option /i [CLI-R100-importFile].
The standard value is 0.
/fullEcu 0, 1 [CLI-R100-fullEcu] Specifies whether CANdelaStudio shall import...
all ECU data contained in an ODX file (1), or
data types and DTCs only (0).
/g <File name> [CLI-R100-logfile] File name of the log file (optional)
/h 0, 1 [CLI-R100-overwriteDTCs] Specifies whether CANdelaStudio shall overwrite DTCs (1) or not (0) during import of the file specified by option /i [CLI-R100-importFile].
The standard value is 0.
/i <File name> [CLI-R100-importFile] (required)
For exports: file name of the CANdela document (CDD) to export.
For imports: file name of the file to import.
For compare: file name of the "left" file for comparison [CMP-R135-CompareCommandLine].
For plugin: file name of the CANdela document [CLI-R100-plugin].
/ini <File name> [CLI-R100-ini] File name of INI file to use.
If the file is read-only, it is used but not modified (CDS-19468 7.0 SP1).
/j 0, 1 [CLI-R100-overwriteDataTypes] Specifies whether CANdelaStudio shall overwrite existing data types (1) or not (0) during import of the file specified by option /i [CLI-R100-importFile].
The standard value is 0.
/k 0, 1 [CLI-R100-finallyWait] Finally keep going (don't wait for ENTER, 1) or don't keep going (wait for ENTER, 0) (since 8.0 SP2).
The standard value is 1.
/l de-DE, en-US, ja [CLI-R100-language] Language in which the CANdelaStudio user interface should be started.
For selecting the language of the document, see /u [CLI-R100-documentLanguage].
/lib <Qualifier> [CLI-R100-lib] A library qualifier (CDS-70801 v11).
Defines the library as a target for requirements synchronization [RQ-R093], see [CLI-R100-swcsync] and [CLI-R100-importRequirementsAndUpdate].
/m view, viewx, standard, pro, admin [CLI-R100-edition] CANdelaStudio edition to run.
Your CANdelaStudio license defines the maximum edition to run.
/m does not accept a higher edition.
„admin“ is the highest edition, down to „viewx“.
E.g. CANdelaStudio /m standard or CANdelaStudio /m viewX
Note: this command line switch will be ignored, if pool licensing or KEYMAN Dongle licensing is used. The same choice is provided by the CANdelaStudio Launcher "Set license" [CDSL-R810].
/n 0, 1 [CLI-R100-execActions] Execute actions after an export (1), or skip them (0).
The standard value is 0.
/newEcu <ECU name> [CLI-R100-newEcu] Creates a new CANdela document (CDD) with the given ECU name from a template.
CANdelaStudio automatically derives the ECU qualifier from the name.
/r [CLI-R100-referenceFile] defines the template the new document shall be instantiated from,
/o [CLI-R100-output] defines the path and file name of the new document.
/newVariant <Variant name> [CLI-R100-newVariant] Creates a new variant given name (CDS-69032 v13). The input must be a document, not a template. See examples below.
CANdelaStudio automatically derives the ECU qualifier from the name.
/v [CLI-R100-variants] defines the reference variant to use as base (name or qualifier). If omitted, defaults to Base Variant.
/o [CLI-R100-output] defines the path and file name of the new document (not a template).

If the name of the variant is already in use in the document, it gets disambiguated,
as well as the qualifier derived from the specified name of the new variant.
Possible in Standard View. The operation references all diagnostic instances.
/o <File name> [CLI-R100-output] File name of the output document for import and export (required)
/p <Qualifier1>; <Qualifier2>; ... [CLI-R100-vsgFilter] List of vehicle system group qualifiers separated by semicolons.
Only relevant for the specification report.
Limits the export of diagnostic instances, job containers and DTCs to those associated with one of the specified vehicle system groups ([RP-R100-VSG], CDS-4316 4.0 SP2).
/pool <Import file> [CLI-R100-poolFiles] One or multiple import files to be imported without user interaction into the import pool.
This is not for a batch operation - CANdelaStudio will be left open to inspect to import pool.
Separate multiple files by semicolon, like PathToImport1.cdi;PathToImport.cdi.
See an example below.
/plugin <plug-in name> [CLI-R100-plugin] Runs a plug-in. The plug-in parameter denotes the plug-in name as shown in the tools menu and reported at start-up in the logfile (available via context menu in output window).
The parameter is used with the input and output CANdela document parameters...
/i [CLI-R100-importFile] (note: /i, not the single argument [CLI-R100-argument]!) and
/o [CLI-R100-output]
to load the source document and optionally save the modified document after plug-in execution.
If you do not specify the parameter for an output file, CANdelaStudio does not save the document, even if it has been modified.
See an example below.
/q 0, 1 [CLI-R100-quiet] When run in batch mode, CANdelaStudio shall be...
quiet (not open a separate console window, 1) or
verbose (open a separate console window for all messages, 0).
In interactive mode, value 1 suppresses message boxes at start-up: beta warning, hint about View edition, User Feedback dialog.
/r <File name> [CLI-R100-referenceFile]
For import: file name of the CANdela document into which to import (reference document).
For compare: file name of the "right" file for comparison. [CMP-R135-CompareCommandLine]
For creating a document from a template: the template file name.
/t de-DE, en-US, ja [CLI-R100-tmxLanguage] (only for the specification report) Desired language code for the TMX template.
If the parameter is not specified, or the TMX template does not contain the desired language code, then report uses the language code of the CANdela document.
If the TMX template does not contain that language code, report uses the TMX template for the language code "en-US".
/translation 0, 1 [CLI-R100-translation] For Pro edition: if you specify a CDD or CDDT on the command line, "/translation 1" opens it in translation view. (since 9.1, CDS-69393)
/u de-DE, en-US, ja [CLI-R100-documentLanguage] Desired document language, e.g. to open a document in CANdelaStudio in the
desired languare (open via commandline) for batch exports (export via commandline).
If the parameter is not specified, exports use the first completely translated language of the input CANdela document.
If the parameter is specified, but the language cannot be used (for example because it is not completely translated in the document), the export aborts with an error message.
For selecting the language of the user interface, see /l [CLI-R100-language].
/v <Qualifier1>; <Qualifier2>; ... [CLI-R100-variants] List of variant qualifiers separated by semicolons.
Limits the operation to the specified variants.
/x odx, pdx [CLI-R100-odxFileFormat] Desired file format for ODX export (use in conjunction with /e [CLI-R100-odx] and the parameters odx201, odx210 and odx220).
The standard value is pdx.

Examples

Path to CANdelaStudio

Typically, you need to specify the complete path to the CANdelaStudio executable. Depending on your version of Windows and of CANdelaStudio, this path will look like

"C:\Program Files\Vector CANdelaStudio 9.1\Bin\CANdelaStudio.exe"

A complete command will look like

"C:\Program Files\Vector CANdelaStudio 9.1\Bin\CANdelaStudio.exe" /e odx201 /i KWP-ExampleEcu.cdd /o MyODX.odx

The following examples use the variable CDS for the path to CANdelaStudio. In a .bat file or command window, you can set it like this:

SET CDS="C:\Program Files\Vector CANdelaStudio 9.1\Bin\CANdelaStudio.exe"

The command must be written on one line.

Export a Variant to ODX

Export variant "Variant 1 (by reference)" of the document "KWP-ExampleEcu.cdd" into the ODX file "MyODX.odx":

%CDS% /e odx201 /i KWP-ExampleEcu.cdd /o MyODX.odx /v Variant_1_by_reference /x odx

Export DTCs

Export DTCs of variant "A Sample" (qualifier "A_Sample")" of the document "UDS-ExampleEcu.cdd" into the Excel file "MyDTCs.xlsx":

%CDS% /e DTC /i UDS-ExampleEcu.cdd /o MyDTCs.xlsx /v A_Sample

Import Data Types from CDI

Import a set of data types stored in a CDI file into a CANdela document:

%CDS% /e import /r KWP-ExampleEcu-4.0.cdd /i MyCdi.cdi /o KWP-ExampleEcu-4.0.cdd /u en-US /f 1 /g import.log

ODX Import Using Batch File

  1. Save the following text in a file named like RunCANdelaStudio.bat
    • Put the SET CMD… %DEACT% into one line without hyphenation!
    • Adapt the path to CANdelaStudio.exe
    • It assumes you have a folder D:\Temp on your computer.
  2. Run the batch file by double-click in Windows Explorer.

RunCANdelaStudio.bat:

@echo off
SET CDS="C:\Program Files\Vector CANdelaStudio 9.1\Bin\CANdelaStudio.exe"
SET REFFILE="D:\Temp\EmptyTarget.cdd"
SET PDXFILE="D:\Temp\Example.pdx"
SET LOGFILE="D:\Temp\Import.log"
SET OUTFILE="D:\Temp\Import.cdd"
SET DEACT=1
SET CMD=%CDS% /e import /fullEcu 1 /r %REFFILE% /i %PDXFILE% /g %LOGFILE% /o %OUTFILE% /deact %DEACT%
echo %CMD% > D:\Temp\RunCANdelaStudio.log
%CMD%

Run Plug-In

%CDS% /i input.cdd /o output.cdd /plugin "Enable ODX mode" /g logfile.txt

Run ODX Check

Run the consistency check for ODX 2.2.0:

%CDS% /i input.cdd /check 1 /e odx220 /g logfile.txt

Import into Pool

%CDS% /pool PathToImportFile.cdi PathToCDD.cdd

Create Variant

using [CLI-R100-newVariant]

%CDS% /i input.cdd /o output.cdd /v ReferencedVariantNameOrQualifier /newVariant NewVariant /g logfile.txt
// overwrite the input file:
%CDS% /i input.cdd /o input.cdd  /v ReferencedVariantNameOrQualifier /newVariant NewVariant /g logfile.txt
// overwrite the input file:
%CDS% /i input.cdd               /v ReferencedVariantNameOrQualifier /newVariant NewVariant /g logfile.txt

Use an Object Path

Open a document and navigate to a qpath:

%CDS% D:\ABS_ESP-Example.cdd#qpath:/C_Sample

Open a document and navigate to an rpath:

%CDS% C:/UDS-ExampleEcu.cdd#rpath://Door/CommonDiagnostics/ProcessorType_Read/RDBI_RQ

Open a document and navigate to an ODX path (e.g. copied from an ODXStudio checker report):

%CDS% "D:\ABS_ESP-Example.cdd#ODX/DIAG-LAYER-CONTAINER[SHORT-NAME='ABS_ESP']/ECU-VARIANTS/ECU-VARIANT[SHORT-NAME='C_Sample']"

AUTOSAR Command Line Operation Examples

Create a new CDD from a specified template [CLI-R100-newEcu]:

SET CDS="C:\Program Files\Vector CANdelaStudio 9.1\Bin\CANdelaStudio.exe"
SET CDD="D:\Temp\Vector_UDS.cdd"
SET LOGFILE="D:\Temp\Import.log"
%CDS% /newEcu TestECU /r "C:\Users\Public\Documents\Vector\CANdelaStudio\9.1\Examples\Vector_UDS_2.2.0.cddt" /o %CDD%

Import requirements from a CSV file and update diagnostic objects [CLI-R100-importRequirementsAndUpdate]:

SET RQCSV="C:\Users\Public\Documents\Vector\CANdelaStudio\9.1\Examples\Import\SampleRequirements.csv"
%CDS% /e importRequirementsAndUpdate /r %CDD% /i %RQCSV% /o "D:\Temp\WithRq.cdd" /g %LOGFILE%

Run SWC Sync [CLI-R100-swcsync]:

SET SWC="C:\Users\Public\Documents\Vector\CANdelaStudio\9.1\Examples\Import\Demo_SystemDescr_MyECU.arxml"
%CDS% /e swcsync /r %CDD% /i %SWC% /o "D:\Temp\WithSWCSync.cdd" /g %LOGFILE%

Export PDX from CDD [CLI-R100-odx]:

%CDS% /e odx220 /x pdx /i %CDD% /o "D:\Temp\Test.pdx"

Export DEXT from CDD [CLI-R100-dext]:

%CDS% /e dext /i %CDD% /o "D:\Temp\Test.arxml"

Return Codes

[CLI-R200] CANdelaStudio.exe returns...

  • 0 on success;
  • non-0 on failure.

If you need information about the status, inspect the logfile.

Besides that, CANdelaStudio returns only few detailed status codes:

Code Description
-2 unknown
-1 application error
0 success
1 import failure (completely)
2 import failure (some data)
