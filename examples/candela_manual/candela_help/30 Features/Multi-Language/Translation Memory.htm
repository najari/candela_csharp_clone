Translation Memory

Automate your Translation Process

If you have translated a document, you can build up a “translation memory”. All translated item pairs will be placed in a separate translation memory file (*.tmx). You can apply this translation memory to any CANdela document. Each translatable item in the CANdela document will be translated automatically if it is already defined in the translation memory file. You can expand your translation memory with each translated CANdela document.

Use cases

Translation view shall support (semi-) automatic translation. There are different use cases:

Translation Memory Use-Cases

To support both use cases, the translation view holds an internal "translation memory" which can be

  • filled by strings manually translated in translation view,
  • saved and reloaded from an external file,
  • used for automatic translation of strings.

The file format used to store this translation memory is the open format "Translation Memory eXchange" ("TMX", see http://www.gala-global.org/lisa-oscar-standards).

Data Exchange with a Translation System

An external translation system must not directly translate the CDD file, since it would not correctly handle the "up-to-date" info.

There are two ways of using the CANdelaStudio Translation Memory:

  • Save translated terms only: save translations to a TMX file and apply them in another document.

  • Save even non-translated terms: save all strings to a TMX file, translate the strings (e.g. using a specialized translation application), then load the the translated strings back into the Translation View and automatically translate the document.

Translation view can use the translations from the TMX file to automatically translate the strings and set the "up-to-date" flag.

Semi-automatic translation

Strings already translated are stored in a "translation memory" which may be kept persistent in a TMX file. The user may apply such a translation given to the non-up-to-date strings displayed in the translation view. Applying a translation is value-based, i.e. all strings having the same value will potentially be affected.

If there is exactly one translation for some value, CANdelaStudio translates it without further notice.

If there are different translations for some value, CANdelaStudio offers a choice (like spell checker in Word).

Care must be taken when using this feature to "import" a translation from an "external" translation system. Since translation applies to non-up-to-date strings only, external modification of up-to-date strings will not be applied – except you first mark all strings as "not up-to-date".

Learning Translation Memory

Translation memory contains 0..n translation units (TU), each containing 1..n translation unit values (TUV). Translation is always done for two languages at a time, whereas translation memory may contain n languages.

Translation Status

Column "Term/Translation in TM": user actions automatically change the column value for one or all TUs:

  • if TM is empty, leave column empty (even in any of the cases below)
  • if TU is not "isUpToDate", leave column empty.
  • Learning to TM and applying from TM trigger re-computation. E.g. after learning, a "new" pair will become "checked".
  • Editing one TU immediately checks the TUV and sets the value to the result.
  • Re-loading TM from an external file triggers re-computation.

TMX File

The TMX file generated contains all translatable texts that were exported to ODX.

Each text has a TextID, stored in a “prop” element at the text (“translation units” = “tu” element):

TextIDs in CANdelaStudio, ODX and TMX

Example:

<prop type='x-CANdela-text-id'>New_ECU_1_12</prop>

The “type” attribute contains the string “x-CANdela-text-id”. Other applications can trigger on this attribute to identify the property as a TextID.

Example TMX file

<?xml version='1.0' encoding='UTF-8' standalone='no'?>
<!DOCTYPE tmx SYSTEM 'tmx13.dtd'>
<tmx version='1.3'>
<header creationtool='CANdelaStudio'
  creationtoolversion='8.2.3001'
  segtype='phrase'
  o-tmf='TXT'
  adminlang='en-US'
  srclang='*all*'
  datatype='plaintext'
  creationdate='2016-03-02 14:35:48+01:00'
  changedate='2016-03-02 14:35:48+01:00'>
</header>
<body>
<tu tuid='1'>
<tuv xml:lang='de-DE'><seg>Diese CANdela-Vorlage basiert auf ISO 14229-1:2006.</seg></tuv>
<tuv xml:lang='en-US'><seg>This CANdela template is based on ISO 14229-1:2006.</seg></tuv>
<tuv xml:lang='fr-FR'><seg>La template CANdela est basée sur l' ISO 14229-1:2006.</seg></tuv>
<tuv xml:lang='ja'><seg>ISO 14229-1:2006に基づいたCANdelaテンプレート・ファイル</seg></tuv>
</tu>
<tu tuid='2'>
<tuv xml:lang='de-DE'><seg>Allgemeine Verweigerung</seg></tuv>
<tuv xml:lang='en-US'><seg>General reject</seg></tuv>
<tuv xml:lang='fr-FR'><seg>Rejet général</seg></tuv>
<tuv xml:lang='ja'><seg>General reject（拒否）</seg></tuv>
</tu>
</body>
</tmx>
