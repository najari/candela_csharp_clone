Multi-Language CANdela Documents

Languages

A CANdela document stores a set of languages [DOC-R300].

Multi-Language Document Parts

[ML-R100 Translatables] A CANdela document contains language-dependent strings (“translatables”):

  • [NAME-R010] name,
  • [DESC-R010] description,
  • [TT-R110-ML] text table: Assigned Text (e.g. “on”, “off”), Additional Info
  • [DTC-R030-MultiLang] error text,
  • [ATTR-R020-enum] Symbol of enumeration attributes (e.g. release state of a variant)
  • [ATTR-R020-text] Values of text attributes
  • [DTCC-R010-Symbol] Values of enumeration DTC Columns
  • [DTCC-R010-Translatable] Values of text DTC Columns like “Set Condition”

Not translatable are:

  • [QUAL-R110] Qualifiers (intentionally language independent)
  • [REV-R010-ModLang] Revision entries
  • [RQ-R070] Requirement properties.

[ML-R110] Each multi-language string is stored as one string instance for each language [DOC-R300] of the document. Each instance has...

  • [ML-R110-Lang] an indication of the language/country,
  • [ML-R110-Uptodate] the info whether the string contents is up-to-date.
    • When you edit a multi-language string in one language, CANdelaStudio sets the instances for other languages to "not up-to-date".
    • In Translation View [VIEW-R200], you can translate these instances and set them up-to-date.
    • See [DOC-R300-Uptodate] for the effect on the document.

Creating a Multi-Language Document

If you create a CANdela document using Ribbon File | New [MENU-R010], CANdelaStudio lets you select...

  • the document template file (.cddt) and
  • the language

... for your document.

Your editing in the document will apply to the selected language only, so that the document will no longer be up-to-date for other languages [DOC-R300] contained in the document.
