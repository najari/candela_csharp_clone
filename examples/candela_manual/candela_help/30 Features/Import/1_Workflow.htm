Preparation (optional) - CANdelaStudio Plug-in »Enable ODX Mode«

The plug-in "Enable ODX Mode" creates several CANdelaStudio attributes in a CANdelaStudio document resp. Template within attribute category ODX. These attributes are not required for the Import or Export operation, but if they exist, they are used to store round-trip information during the Import and to use round-trip information for the Export.

The first step of the plug-in is asking for a CANdelaStudio document resp. Template to which the changes are applied. It is recommended to apply the plug-in on the used CANdelaStudio Template first, because these attributes are then also available in all CANdelaStudio documents which are based on this Template. However, it is possible to apply the Plugin to a CANdelaStudio Document directly.

User Guidance and Data Selection

The user guidance and data selection for importing ODX data is done by a wizard starting in the CANdelaStudio menu: File --> Import --> Open Diagnostic Data Exchange (ODX).

All read ODX files are checked if they fulfill the ODX XML scheme. If a file does not fulfill the ODX XML scheme, the errors are printed in the log file and the file itself is not used in the following import steps.

Import of an ODX ECU Description

To import an ODX ECU description CANdelaStudio offers a wizard to specify details. The wizard is available in "File --> Import --> Open Diagnostic Data Exchange (ODX)". The first radio button "Complete ODX ECU description" must be selected.

The option "Deactivate all CANdelaStudio instances before import" indicates that the resulting CANdelaStudio file applied in a Vector tester offers the same diagnostic services as the ODX file used in a tester. "ODX overwrites CANdela" removes an existing CANdelaStudio Service if an ODX DIAG-SERVICE with the same Service signature (e.g. SID + ID) is imported to ensure uniqueness of IDs/LIDs. And "Deactivate all CANdelaStudio instances before import" just deactivates all existing Services. Then, if a DIAG-SERVICE which corresponds to a deactivated Service is imported, the CANdelaStudio Service is reactivated again. In short, we can say that nothing else from the resulting CANdelaStudio document is executable than the imported ODX data.
More information regarding the activation/deactivation of DiagInstances and Job Containers can be found in Hints and Tips.

Selection of Import Mode "Complete ODX ECU description"

Clicking on "Next" a file selection dialog appears. All ODX files which belong to the ECU description must be selected here. The import has only access to the selected files. If a pdx file is chosen, no additionally selected files are read or evaluated since the pdx file is self-contained. For both options "Import of an ODX ECU description" and "Import of selected parts", all standardized ODX file name extensions (pdx, odx, odx-f, odx-v, odx-d, odx-m, odx-c) can be provided as source files for reading. All selected files are evaluated by the import.

Selection of files which shall be loaded

Clicking on "Next" in the dialog of Figure 1-3 all loaded ODX BaseVariants are listed. Here one of the loaded ODX BaseVariants can be chosen for the import. All ODX EcuVariants for the selected ODX BaseVariant are imported as well. That means an ECU-VARIANT can only be imported by importing its BASE-VARIANT. Doing so all ECU-VARIANTs of the BASE-VARIANT which can be read from the selected files are imported. There is no further selection provided. The entire ECU diagnostic data is imported.

Variants with selection of services/jobs

The ODX Import also provides a Variant Import mode. With this option loaded BASE-/ECU-VARIANTs can be excluded from import (via a filter dialog - select row and press F2) or even mapped to existing variants of the CANdelaStudio document.

Filtering of DIAG-COMMs

The "Import of Variants" option not only provides ways to (de-)select and map ECU-VARIANTs, it's also possible to filter DIAG-COMMs for each variants selected for import.

In order to enable the DIAG-COMM filter dialog, the "Select services/jobs" checkbox in the variant mapping window must be activated.

Check DIAG-COMM filter option to activate filter dialog

In the subsequent wizard dialog a list of available Services and Jobs is displayed as a tree for each DIAG-LAYER to be imported. As default, all DiagComms are selected. DiagComms can be deselected by unchecking their checkbox. Deselected DiagComms are excluded from the import.

For each DiagComm, its Service-ID, LONG-NAME and FUNCT-CLASS (in braces, if available) is displayed. In case one single DIAG-SERVICE contains a dynamic TABLE, each TABLE-ROW is listed as a separate Service.

The list of DiagComms can be reduced by using the text filter field on top of the dialog. The filter searches for textual matches inside the complete DiagComm list, i.e. not only the LONG-NAME may be used for search but also the Service-ID (e.g. "$10") or the FUNCT-CLASS (e.g. "SESSION").

Import of selected parts only (DTCs, data types, data objects, units)

Selection of Import Mode "Selected parts only"

DOPs which are importable as CANdelaStudio Data Types can be imported into the CANdelaStudio data type list. The same goes for units. DTCs can be imported into CANdelaStudio DTC tables. And PARAMs which are importable as CANdelaStudio data objects can be imported into a telegram table (via context menu of the telegram table, see Figure 1-10) or into the volatile CANdelaStudio Import Pool.

CANdelaStudio Import Options

Additionally to the different Use Cases which can be chosen in the Import GUI, the ODX Import behavior can be controlled by a set of options. Details can be found in Import Options.

Import related attributes

To automatically modify the behaviour of the Import on specific CDD files, the user may set CANdelaStudio Attributes on these documents. For Import steering, there are multiple locations where attributes can be set in a CANdelaStudio document; the most usual ones are described in Import Attributes.
