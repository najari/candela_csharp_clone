SWC Sync (CDS-39137 8.5 SP2)

For the context of the SWC Sync, see the AUTOSAR Diagnostic Workflow:

Vector Tools in the AUTOSAR Workflow

See also the SWC Sync Dialog.

Use-Cases

  • Requirements-based (OEM):
    • import diagnostic requirements into CANdelaStudio at an early development stage, creating diagnostic objects from them,
    • then develop the AUTOSAR SYS-EX
    • and update the diagnostic objects in CANdelaStudio based on the requirementsID,
    • so that both the SYS-EX and a DEXT exported from CANdelaStudio can be used for Diagnostic Configuration
  • Not requirements-based (supplier):
    • develop the AUTOSAR SYS-EX,
    • initially create diagnostic objects in CANdelaStudio,
    • later update these diagnostic objects based on the AUTOSAR UUID
    • so that both the SYS-EX and a DEXT exported from CANdelaStudio can be used for Diagnostic Configuration

Handle both SYS-EX objects that are...

  • under development
    • you can manually exclude them from synchronization
  • new
    • there is no matching requirementsID or UUID in the CANdela document
    • SWC Sync puts them into the Import Pool to allow manual assignment later

Example Tooling

  • Vector tools such as PREEvision or DaVinci Developer,
  • 3rd party tools such as DOORS or XDIS

User Requirements

Context:

  • an ECU specified using an AUTOSAR SYS-EX.
  • CANdelaStudio supports to design the diagnostic communication in detail.
  • CANdelaStudio supports exporting a diagnostic extract (DEXT).

[SWC-R100] SWC Sync Operation The CANdelaStudio SWC Sync synchronizes objects in a CANdela document with objects in an AUTOSAR System Extract file (*.arxml).

[SWC-U0300] The exported DEXT is usable together with the original SYS-EX,

  • e.g. during mapping for...
    • DCM and
    • DEM configuration.

SWC Sync updates the CANdela document:

  • [SWC-U0400]: it links diagnostic objects with the corresponding objects in the SYS-EX,
  • [SWC-U0600]: it updates existing diagnostic objects if they have specific attributes set (e.g. the Sync ID [RQ-R115] or Instance Type [SWC-R200])
    • overwriting any changes to the diagnostic object within CANdelaStudio
    • only in the variant selected in the requirements setting tab (not all variants) (SWCSYNC-17)

[SWC-U0800]: CANdelaStudio supports repeated execution of the SWC Sync (to reflect development of the SYS-EX in the CANdela document).

[SWC-U1000]: Given a SYS-EX, the SWC Sync does not need further user interaction.

Prerequisites: Attributes

Ensure CANdela attributes for AUTOSAR have been created by the checkbox [DOCUI-R500] in the dialog of menu File|Properties, page "Document Info".

See the list SWC Sync CANdela Attributes.

Not to Confuse with: Network Description Import

SWC Sync reads a SYS-EX...

  • containing software components (SWCs) with ports

... as opposed to the Import from a Network Description...

  • in menu item "DTCs and Data" | "Import from an "AUTOSAR (*.arxml)" file" [MENU-R266];
  • which imports DTCs and data objects from a network description (not from software components).

How to Start SWC Sync

  • button [MENU-R280] in the ribbon tab "Data Exchange", or
  • button [RQUI-R220] in the Requirements page.

SWC Sync Operation Sequence

  • Start SWC Sync as described above
  • CANdelaStudio prompts for an AUTOSAR system extract (SYS-EX)
    • maybe multiple files
    • file dialog with multi-selection
  • CANdelaStudio reads a SYS-EX
  • [SWCUI-R0180]: During processing of the system extract (while the dialog is not yet visible), CANdelaStudio shows a progress indicator.
  • CANdelaStudio shows the SWC Sync Dialog,
  • ... then performs the sync operation, which...
    • updates diagnostic objects based on matching requirement ID or matching AUTOSAR UUID, and
    • puts new diagnostic objects into the import pool.
  • [SWC-R0230] ... finally informs you whether the sync was done successfully, with warnings or with errors.
  • [SWC-R0240]: The log contains:
    • warnings and errors during reading the SYS-EX,
    • warnings and errors during the sync operation,
    • updates to diagnostic objects.

Extraction of CANdela Objects from SYS-EX

[SWC-R1310] SWC Sync assumes the SYS-EX contains exactly one ECU-INSTANCE.

[SWC-R1320] SWC Sync reads data...

  • from ApplicationSwComponentType
  • not from ComplexDeviceDriverSwComponentType (cf. CDS-71598)
  • [SWC-R1330] SWC Sync assumes a 1:1 relationship of Port Interface and Port Prototype (see [SWC-R0810]).
  • [SWC-R1340] SWC Sync supports only the IO control use case “IO control by Sender Receiver Interface”.
  • [SWC-R1350] SWC Sync expects diagnostic requirements information as SD (Special Data) at the relevant objects in the SYS-EX.

Expected SDG structure:

ADMIN-DATA
  SDGS
    SDG
      GID = "DiagnosticReferenceInfos"
      SD
        GID "RequirementId"
        - the SD value is the requirement ID (string)
      SD
        GID "DiagnosticObjectName"
        - the SD value is the diagnostic object name (string)
          used during definition of the diagnostic requirements.
        - SWC Sync does *not* require this complementary information for synchronization.
  • In SYS-EX, these SDs are optional.
  • For SWC Sync, the requirement ID is required.

For details about extraction, see the SWC Sync Reference chapters (find links below).

Types of Imported Objects

[SWC-U0500] The SWC Sync extracts the following data from a SYS-EX file (each hyperlink navigates to the respective details chapter):

  • a list of DTCs
  • a list of Data Objects used in stored data records
  • dito in present value data records
  • a list of Routines,
    • each containing up to six lists of data objects,
    • corresponding to the optional request and response parameters of the Start, Stop and Request Routine Results subfunctions of UDS service 0x31
  • a list of IOControls,
    • each containing up to five lists of data objects,
    • corresponding to the control state recordss of the subfunctions of UDS service 0x2F
  • a list of Data Types referenced by the data objects extracted
