Handling of specific ODX elements

The following chapters describe the handling of specific ODX elements during the ODX Import operation on the basis of representative ODX data. The description will be top-down, meaning it will start with the high-level ODX elements, and then move down into the more specialized child elements.

It starts with common data, i.e. data which is common in many ODX elements.

It continues with the description how DIAG-LAYERs...

... and DIAG-COMMs are imported. The import of the DIAG-COMM properties of a DIAG-SERVICE is described in the same chapter...

... whereas the import of all the other specific DIAG-SERVICE properties (including the data which they use: REQUESTS, PARAMs etc.) is described in the DIAG-SERVICES chapter. The latter one is done by representative ODX DIAG-SERVICE data and how it can be imported into CANdela Services.

The following chapter describes how PARAM properties are imported, with the next chapter going into detail regarding the data these PARAMs use via reference, e.g. DOPs, STRUCTUREs, UNITs).

The last chapter describes the Import of SUB-COMPONENTs, which are imported as CANdelaStudio VehicleSystemGroups.
