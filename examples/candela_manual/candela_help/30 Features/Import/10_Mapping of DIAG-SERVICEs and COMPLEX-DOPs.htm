Mapping of DIAG-SERVICEs and COMPLEX-DOPs

Mapping of REQUESTs, POS-RESPONSEs, NEG-RESPONSEs and GLOBAL-NEG-RESPONSEs

  • An ODX DIAG-SERVICE can reference...
    • at most one REQUEST,
    • zero, one or several POS-RESPONSEs and
    • zero, one or several NEG-RESPONSEs.
  • A CANdelaStudio Service always has...
    • one Request,
    • at most one PosResponse and
    • at most one NegResponse.
  • The CANdelaStudio Service in which a DIAG-SERVICE is imported determines the number of Request, PosReponses and NegResponses expected at the ODX DIAG-SERVICE:
    • If the CANdelaStudio Service has a PosResponse,
      • the DIAG-SERVICE must specify at least one POS-RESPONSE etc.
      • Otherwise the DIAG-SERVICE cannot be imported into the CANdelaStudio Service.
    • If the DIAG-SERVICE specifies more than one POS-RESPONSE,
      • and the CANdelaStudio Service has one PosResponse,
      • import checks each PosResponse whether it is importable,
      • and imports the first one which fits the CANdelaStudio Service restrictions.

A VALUE referencing an END-OF-PDU-FIELD can be imported as a CANdelaStudio Iterator End if the byte position of the VALUE (within REQUEST resp. RESPONSE) is the same as the byte position of Iterator End.

PARAM with ENV-DATA-DESC to CANdelaStudio Mux (predefined in ProtocolService)

A VALUE referencing an ENV-DATA-DESC can be imported as a CANdelaStudio Multiplexer multiplexing DTCs if the byte position of the VALUE (within REQUEST resp. RESPONSE) is the same as the byte position of the Multiplexer. To remain consistent the byte position of the VALUE referencing the DTC-DOP must be the same as the byte position of the CANdelaStudio DTC table (Proxy DTC).

The content of the ENV-DATA STRUCTUREs is imported as telegram tables of the Multiplexer if the PARAMs lie in the valid byte range of the corresponding telegram table. Note: Min-, Max and Fix-Length of the telegram table are considered and are not modified.

Mapping of ENV-DATA-DESC to CANdelaStudio Multiplexer

ENV-DATA-DESC has exactly one ENV-DATA for ALL-VALUE

The ENV-DATA for ALL-VALUE will be taken as the default environment data in CANdela. The ENV-DATA for ALL-VALUE will be taken for all other CANdelaStudio environment data as first part in telegram table.

Mapping of ENV-DATA-DESC with ALL-VALUE to CANdelaStudio Multiplexer

ENV-DATA-DESC has no ENV-DATA for ALL-VALUE

In case of missing ALL-VALUE, the ODX Import checks whether all DTCs are covered.

  • If not all DTCs are covered in ENV-DATA-DESC: The import checks, if an empty default environment data is allowed by CANdelaStudio template.

  • If "min byte size" is > zero -> CANdelaStudio skips the import. CANdelaStudio ensures the correctness of the diagnostic specification.

  • If "min byte size" == zero. Default environment data remains empty.

If all DTCs are covered in an ENV-DATA-DESC: Import searches for ENV-DATA with _max(count(DTC-VALUE)). This ENV-DATA will be taken as Default environment data.

Mapping of other PARAMs

PARAM with DTC-DOP to CANdelaStudio DTC Table

A VALUE referencing a DTC-DOP can be imported as a CANdelaStudio DTC table (Proxy DTC) if the byte position of the VALUE (within REQUEST resp. RESPONSE) is the same as the byte position of the DTC table.

Mapping of VALUE with DTC-DOP to CANdelaStudio DTC Proxy

For each DTC the CANdelaStudio error text is determined by the value of DTC.TEXT and the values of the DTC table columns are determined by the non-recursive SDG structure. The mapping of SDG to DTC column is done by SDG.SHORTNAME to DTC column qualifier mapping. They must be exactly the same. Note: The qualifiers of the DTC columns can only be shown and modified in the CANdelaStudio Expert Mode.

Mapping of DTC SGD/SD content to content of CANdelaStudio DTC table column

Mapping of DTC-DOP and DTC SDGs to CANdelaStudio DTC Table

Starting with CANdelaStudio 7.5 SP3 also LINKED-DTC-DOPs are supported.

TABLE-KEY and TABLE-STRUCT

A TABLE-KEY referencing a TABLE can be imported as a CANdelaStudio Variable Values (which is fix within a DiagInstance) if the byte position of the TABLE-KEY (within REQUEST resp. RESPONSE) is the same as the byte position of the Variable Value. Each TABLE-ROW is imported as CANdelaStudio DiagInstance in which the Variable Value is set to the value of TABLE-ROW.KEY.

The DiagInstances can only be created if the corresponding TABLE-ROW STRUCTURE can be imported into a telegram table. That means the byte positions (within REQUEST resp. RESPONSE) of the PARAMs within the TABLE-ROW.STRUCTURE (determined by the byte position of TABLE-STRUCT) lie within the valid range of the telegram table.
