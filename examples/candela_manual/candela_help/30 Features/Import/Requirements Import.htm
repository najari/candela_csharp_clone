Requirements Import

Import from .csv

File Format

[RQ-R800]: Import reads data from a .csv file formatted as described in the CANdelaStudio CSV Requirements Exchange Format.

This operation is also available in a combined operation [MENU-R270] via the ribbon tab Data Exchange.

Hierarchy

[RQ-R810]: if...

  • the hierarchy in the .csv file (as defined by the “Level” column) does not match the rules described in [RQ-R640],
  • then import “normalizes” it to match the rules.

Example: a heading with level 3 directly after a heading with level 1 gets corrected: level 3 to 2.

Input Completeness and Deletion

[RQ-R815] if...

  • the .csv root element already exists in the CDD as a requirement R,
  • and at least one requirement in the subtree of R is not contained in the .csv,
  • then CANdelaStudio prompts whether to delete these requirements missing in the .csv.

Note: deleting the requirements does not automatically delete linked diagnostic objects.

  • These will be shown as “dangling”,
  • so you can inspect them in the regular “Linking with diagnostic objets” view
  • and delete them there - no need for a separate new dialog.

Rows

[RQ-R820]: if import of a row is not possible at the location indicated in the .csv file due to type restrictions, the violating row gets imported as a Text requirement (import does not create additional elements).

[RQ-R830]: for all rows whose ID is already in the CDD, the resulting tree structure in the CDD is the normalized hierarchy (see [RQ-R810]) from the .csv file.

[RQ-R840] a level 1 row whose ID is not yet in the CDD will be top-level in the CDD.

[RQ-R850] a row with level > 1 whose ID is not yet in the CDD will be put as last element under the element corresponding with its parent row.

Note: the element of the parent row may have been positioned by ID (RQ-R830], or by top-level rule [RQ-R840], or by its parent ([RQ-R850] recursively).

[RQ-R855] the order of siblings in .csv file and CDD gets be preserved as far as possible. For conflicts, the .csv file order takes precedence.

[RQ-R860] an element of the CDD for which there is no row in the .csv file has the same parent element after import as before.

Vehicle System Groups

[RQ-R870] VehicleSystemGroups [RQ-R680] get imported as follows:

  • split by comma, for each part:
    • if the part matches an imported VehicleSystemGroup Requirement Name or ID,
    • import treats the part as reference to that Requirement.
  • if there is at least one part that does not match:
    • (rare use-case, e.g. in case VSG Requirement Name or ID contains a comma):
    • for each VSG Requirement in the .csv file,
    • import matches its Name and ID against the remaining (non-matching parts).
    • If it matches, import treats the matching string as reference to that Requirement.
  • import uses the remaining value as a reference to a VSG Requirement not contained in the import file
    • the reference may be resolved later in CANdelaStudio e.g. during an update of diagnostic objects.

Example:

  • property "VehicleSystemGroups" at DTC Requirement has value “Slave A,ID4711”,
  • VSGRq1 Name = “Slave A”,
  • VSGRq2 ID = “4711”.
  • Result: DTC Requirement references VSGRq1 and VSGRq2.

Example:

  • property "VehicleSystemGroups" at DTC Requirement has value “Actuator C,Slave A,B,ID4711”,
  • VSGRq1 Name = “Slave A,B”,
  • VSGRq2 ID = “4711”.
  • Step 1:
    • checking parts “A”, “B”, “ID4711”,
    • only “ID4711” matches,
    • so DTC Requirement references VSG2.
  • Step 2:
    • matching VSGRq1 Name “Slave A,B” against remaining VehicleSystemGroups value “Actuator C,Slave A,B”,
    • DTC Requirement also references VSG1.
  • Step 3:
    • treating the rest “Actuator C” as a reference to a VSGRq “Actuator C” not contained in the .csv file.

Duplicate Column Names (CDS-71308 v10 P1, v11 P1, v12)

[RQ-R890] When a column name occurs more than once in the .csv file, import...

  • ensures the column name exists only once after import;
  • merges the cells:
    • if for a given requirement, the columns contain no or an identical value of identical type,
    • then import accepts that value,
    • otherwise import emits an error message

Cells

[RQ-R880] For a property that does not exist at the requirement (row), i.e. ...

  • either a Specific Property [RQ-R030],
  • or a User-Defined Property restricted to exist at DTC Requirements [RQ-R040-ForType],

import discards the value.

Action Variable RqCSVImportTmpPath (CDS-24780 7.5 SP2)

[RQ-R895] The Action variable RqCSVImportTmpPath automates import of requirements into CANdelaStudio, as a post-step after running an external command.

In detail: if an action contains the variable in a command line, on action execution, CANdelaStudio...

  1. computes a temporary file path T
  2. in the action command line, replaces the variable by T
  3. executes the command line (runs your external command)
  4. then, if file T exists, imports it as a .csv requirements file (same as interactive import into requirements view, described above)
  5. deletes the file T
