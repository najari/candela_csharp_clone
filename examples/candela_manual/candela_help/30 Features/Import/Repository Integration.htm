Repository Integration (CDS-30694 8.1)

Introduction

The CANdelaStudio Repository feature...

  • provides a special type of import
  • in a simple selection list
  • from an arbitrary data source (database, XML file, ...)
  • is made available using a custom DLL implementation
  • for
    • DIDs (CDS-30694 8.1)
    • DTCs (CDS-32365 8.2 SP2)

Select DID from Repository

The integration of repositories in CANdelaStudio...

  • supports different data sources: customer databases, CSV, Excel, ODX, CDD may be integrated
  • is platform independent
  • is network enabled
  • is highly scalable: database from 100 to 100000 DIDs or DTCs
  • transports data via the accepted ODX standard
  • provides an open client API that allows integration into other tools
  • comes with sample implementations for an easy start.

Architecture Overview

Repository Integration Architecture

General CANdelaStudio Requirements

[RPS-R100 Plug-in Interface] CANdelaStudio provides an open plug-in interface that allows access to any diagnostic repository.

[RPS-R110 Plug-in Implementation] Repository plug-ins may be implemented by Vector, Customers or 3rd party developers. The plug-ins needs to be implemented as a Dynamic Link Library (DLL) with a defined C-API interface (see API Specification)

CANdelaStudio Integration

[RPS-R200 Plug-in Loading] CANdelaStudio supports one plug-in DLL under the CANdelaStudio installation folder:

InstallDir\Bin\Plugins\DiagnosticRepository.dll

In order to switch to another repository, the plug-in DLL has to be replaced.

[RPS-R200-Conditions] Conditions for loading the plug-in:

  • file name ends with .dll
    • ... not with .cdlplg as for regular CANdelaStudio plug-ins
  • the DLL provides the defined API entry points [RPS-R480]
  • the version number of the API corresponds to the minimal requirements of CANdelaStudio.

[RPS-R210 Plug-in Selection] CANdelaStudio does not provide a selection mechanism for plug-ins so far.

[RPS-R220 Plug-in Configuration] CANdelaStudio allows to configure a repository plug-in at runtime:

  • after loading the plug-in, CANdelaStudio reads a parameter [INI-R220] from the INI file
  • ... and passes it to the plug-in by calling the API function SetRepositoryConfig(string ConfigString).
  • The format of the configuration string is...
    • up to the plug-in (maybe vendor specific)
    • subject to restrictions of the Windows INI file format
    • maximum length 16kByte

[RPS-R460 Default Configuration for Repository Samples] If CANdelaStudio detects that...

  • bin\Plugins\DiagnosticRepository.dll is the sample Local Repository [RPS-R300]
    • based on the name returned from API
  • and CANdelaStudio.ini [INI-R220] does not contain configuration for the plug-in,
  • then as a default configuration, CANdelaStudio passes the path of the sample files [EX-R400] to the plug-in.

[RPS-R230 Repository Dialog] See the Select from Repository dialog.

ODX Envelope

ODX Envelope Constraints

[RPS-R500] An ODX Envelope is a complete, self-contained ODX-D file.

[RPS-R600] Only ODX version 2.2.0 is allowed as envelope.

[RPS-R610] An ODX envelope contains of exactly one DIAG-LAYER-CONTAINER.

[RPS-R620] The DIAG-LAYER-CONTAINER must contain exactly one DIAG-LAYER of kind “ECU-SHARED-DATA”.

[RPS-R630] The DIAG-LAYER must not use any PARENT-REFs.

[RPS-R640] The DIAG-LAYER must not use any IMPORT-REFs.

[RPS-R650] The DIAG-LAYER must not use any SHORT-NAME refs.

[RPS-R660] The DIAG-LAYER must not have any unresolvable (dangling) ODX-LINKs.

[RPS-R670] The DIAG-LAYER container must fulfill the ODX checker rules.

ODX Envelope for DTCs (CDS-32365 8.2 SP2)

[RPS-R800] The DIAG-LAYER must contain exactly one valid DTC-DOP specifying the DTCs.

[RPS-R820] The DTC-DOP must contain exactly one DTC which shall get imported

[RPS-R840] A DTC-REF is not allowed inside the DTC-DOP

[RPS-R860] The import ignores any bit-length of the DTC-DOP.

[RPS-R900] The DTC properties...

  • are specified in SDGs;
  • each SDG contains one DSG-CPATION for the target qualifier used in the CANdela fault memory
  • ... and one SD containing the according value.

[RPS-R920] DTC Properties:

  • Their number is not limited.
  • Use one SDG for each DTC column (property).
  • Import maps the SDGs to DTC columns / DTC attributes by mapping...
    • the SDG-CAPTION SHORTNAME
    • with the qualifier of the DTC property or attribute.
    • Import ignores SDGs that do not match.
    • The plug-in DLL must ensure that the SDG shortnames are matching with the DTC property and DTC attribute qualifiers of the CANdela document.
    • Tip: CANdelaStudio shows the qualifier in expert view in the Error Code Table, and in the column tooltip in the DTC List in standard view.
  • See DTC Import [DTCI-R170] for details of column mapping.
