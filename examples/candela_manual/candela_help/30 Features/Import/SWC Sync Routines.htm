SWC Sync Routines

Extraction of SYS-EX Routines

A SYS-EX Routine is an instance reference to a port, with the following conditions:

  • The parent SWC type belongs to the ECU-INSTANCE.
  • The SWC type includes a SWC-SERVICE-DEPENDENCY with a ROLE-BASED-PORT-ASSIGNMENT pointing to a P-PORT-PROTOTYPE.
  • Note: SWC Sync does not check the role name (typically “RoutineServices”).
  • The P-PORT-PROTOTYPE references a CLIENT-SERVER-INTERFACE.
  • The SWC-SERVICE-DEPENDENCY contains a DIAGNOSTIC-ROUTINE-NEED.
  • The requirement SDs are at the port interface of the P-PORT-PROTOTYPE.

The CLIENT-SERVER-OPERATIONs of the CLIENT-SERVER-INTERFACE represent the data objects for the routine control records and routine status records:

  • operation “Start” represents the “StartRoutine” protocol service
  • operation “Stop” represents the “StopRoutine” protocol service
  • operation “RequestResults” represents the “RequestRoutineResults” protocol service

The ARGUMENT-DATA-PROTOTYPEs with direction “IN” represent the routine control record of the respective protocol service.

The ARGUMENT-DATA-PROTOTYPEs with direction “OUT” represent the routine status record of the respective protocol service.

Sync of Routines

Control Option and Routine Status Records

[SWC-R0810]: For (one or more) CANdela routine diagnostic instances...

  • whose “Instance Type” attribute [SWC-R200] equals the port interface requirement ID of a SYS-EX routine,
  • SWC Sync updates the control option and routine status records.
    • Note: SWC Sync expects the requirement ID at the port interface, not at the port prototype.
  • [SWC-R0820] SWC Sync...
    • replaces all data objects belonging to a routine control option record or a routine info / routine status record of any routine service subfunction
    • ... by new data objects based on the SYS-EX data object lists belonging to the routine,
    • ... following the same rules as in syncing stored and present value data records (see previous chapter).

[SWC-R0830]: If...

  • no such CANdela routine diagnostic instance exists,
  • or a routine record or subfunction is missing,

... SWC Sync...

  • writes a warning to the log,
  • with a hint that such a routine diagnostic instance must be created with the appropriate “Instance Type” attribute value
  • either manually or automatically (e.g. after a re-import of updated requirements from PREEvision, DOORS…).

[SWC-R0840]: SWC Sync does not modify...

  • any routine diagnostic instance which does not have an “Instance Type” attribute value corresponding to a routine extracted from the processed SYS-EX (it completely ignores such routine diagnostic instances).
  • ... including any data objects contained within such a routine,
  • even if those data objects have a sync ID [RQ-R115], and there are SYS-EX data objects with the same sync ID.

Update of SWC Service Dependency References

[SWC-R0850]: SWC Sync...

  • update the “ASR SWC ServiceDependency Ref” [SWC-R210] attribute from the instance ref of the SYS-EX routine
  • for each CANdela routine diagnostic instance whose “Instance Type” attribute [SWC-R200] equals the port interface requirement ID of a routine,
  • but only if there is no other CANdela routine diagnostic instance with the same “Instance Type” in any of the variants that the diagnostic instance belongs to.
