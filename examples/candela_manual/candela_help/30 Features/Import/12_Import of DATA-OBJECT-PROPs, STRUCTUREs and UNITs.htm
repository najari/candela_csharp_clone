STANDARD-LENGTH-TYPE

DOPs using a STANDARD-LENGTH-TYPE to define its coded type are imported as data types with the defined Length (Byte:Bit) into CANdela.

DOPs with DIAG-CODED-TYPE/BASE-DATA-TYPE having A_BYTEFIELD are always imported as a CANdelaStudio field data type with fix size.

MIN-MAX-LENGTH-TYPE

DOPs using MIN-MAX-LENGTH-TYPE are imported as CANdelaStudio field.

If MIN size is equal to MAX size, it is imported as a fixed field, otherwise a field with variable length is created.

If no MAX-Length is given, 65536 is taken as max value.

MIN-MAX-LENGTH-TYPE/TERMINATION CANdelaStudio Type
ZERO Zero termination (no pad. / maxLen / EOS) (for variable fields)

Zero termination (with pad. / maxLen / EOS) (for fixed field: MIN-LENGTH=MAX-LENGTH)
END-OF-PDU None

LEADING-LENGTH-INFO-TYPE

DOPs using the LEADING-LENGTH-INFO-TYPE are imported as a variable field into CANdela.

INTERNAL-CONSTRs

Range exclusion is handled similar to intervals (see chapter interval correction). The open limits of intervals are corrected and added as additional excluded ranges. We mark them as undefined value with the description: "Did not find value as a close interval limit in exclude definitions".

Mapping of ODX VALID-TYPEs to CANdela:

ODX VALID-TYPE CANdelaStudio invalidity
NOT-VALID Invalid signal
NOT-DEFINED Undefined
NOT-AVAILABLE No signal

SCALE-CONSTR/SHOR-LABEL is imported "assigned Text" of invalid value in CANdela.

COMPU-METHOD IDENTICAL

A DATA-OBJECT-PROP using COMPU-METHOD of type IDENTICAL is imported as CANdelaStudio "Identity" data type.

COMPU-METHOD TEXTTABLE

A DATA-OBJECT-PROP using COMPU-METHOD of type TEXTTABLE is imported as CANdelaStudio "Text table" data type.

The interval correction of its COMPU-SCALEs (e.g. usage of open limits on double values) is defined in chapter interval correction.

COMPU-METHOD LINEAR

A DATA-OBJECT-PROP using COMPU-METHOD of type LINEAR is imported as CANdelaStudio "Linear" data type.

In addition the following checks are done:

  • No denominator in ODX File leads to denominator = 1 in linear function.
  • No Numerator in ODX File causes the data object property to fail.
  • More than one denominator (nonlinear) causes data object property to fail.

COMPU-METHOD SCALE-LINEAR

A DATA-OBJECT-PROP using COMPU-METHOD of type SCALE-LINEAR is imported as CANdelaStudio "Piecewise linear" data type.

For each COMPU-SCALE, the same checks are done as in DATA-OBJECT-PROP of type LINEAR.

In Addition the interval correction is implemented.

COMPU-METHOD TAB-INTP

A DATA-OBJECT-PROP using COMPU-METHOD of type TAB-INTP is imported as CANdelaStudio "Characteristic curve" data type.

In addition the following checks are done:

  • COMPU-SCALE without LOWER-LIMIT causes DATA-OBJECT-PROPERTY to fail.
  • COMPU-SCALE without closed LOWER-LIMIT causes DATA-OBJECT-PROPERTY to fail.
  • COMPU-SCALE with UPPER-LIMIT causes DATA-OBJECT-PROPERTY to fail.

COMPU-METHOD COMPUCODE

A DATA-OBJECT-PROP using COMPU-CODE of type PROG-CODE is imported as CANdelaStudio "Procedure" data type.

In addition the following checks are done:

  • COMPU-SCALE without closed LOWER-LIMIT causes DATA-OBJECT-PROPERTY to fail.

COMPU-METHOD RAT-FUNC

A DATA-OBJECT-PROP using COMPU-CODE of type RAT-FUNC is imported as CANdelaStudio "Formula" data type. The formula is specified in way like e.g:

(a1\*x\^0 + b1\*X\^1 +c1\*X\^2 + ...) / (a2\*x\^0 + b2\*X\^1 +c2\*X\^2 + ...)

COMPU-METHOD SCALE-RAT-FUNC

A DATA-OBJECT-PROP using COMPU-CODE of type SCALE-RAT-FUNC is imported as CANdelaStudio data type.

Interval correction

Overview

ODX Intervals (COMPU-SCALE, SCALE-CONSTR) DOUBLE INT
Interval with closed limits Supported Supported
Interval with open limit (lower and/or higher limit) NOT supported Supported
Interval with infinite limits (lower and/or higher limit) Supported (*) Supported

(*) Supported on 4 Byte floats, but not supported on 8 Byte doubles

Supported actions are marked with additional information on stdout. Unsupported actions cause the complete data object property to fail.

Open limits on coded type INTEGER

The interval correction works as following:

  • Each open limit is handled separately.

  • Check, if the open (lower/ upper) limit is also a closed (upper/lower) limit of another interval. If not so, the value is added to the range exclusion as invalid value with the description: "Did not find value as a close interval limit".

  • The limit is corrected by adding +/-1 to the according limit and closing the interval.

Infinite limits

Each infinite limit is changed to the according min max value of the given type.

The following MIN / MAX values where applied, depending on the byte size:

Byte Size Minimum Maximum
UINT_8 0 255
INT_8 -128 127
UINT_16 0 65535
INT_16 -32768 32767
UINT_24 0 16777215
INT_24 -8388608 8388607
UINT_32 0 4294967295
INT_32 -2147483648 2147483647
DOUBLE_32 -FLT_MAX FLT_MAX

FLT_MIN and FLT_MAX are definitions in <float.h>.

Import of STRUCTUREs

STRUCTUREs in ODX are imported into CANdelaStudio packet data types by the usage of the following restrictions:

  • RESERVEDs larger than 8 Bytes inside are imported as multiple 8 Byte gaps.
  • A STRUCUTRE containing a PARAM with a variable size will be skipped.
  • STRCUTUREs in STRUCTUREs will be transformed to the highest level of any STRUCTURE.
  • Bit positioned PARAMs will be stored in newly created bit fields.
  • If several PARAMs lay on the same bit/byte position, the first possible "way through" is chosen.

Import of UNITs

The UNIT/DISPLAY-NAME, referenced by a DATA-OBJECT-PROP is imported into the unit field at the corresponding CANdelaStudio data type.

Furthermore, the conversion of the unit to its SI representation is imported into the description field of the CANdelaStudio data type.

In Addition, all UNITs defined in an ECU-SHARE-DATA are imported into a CANdelaStudio enum attribute "Units" (created by the "enable ODX mode" plugin). For any further modifications in CANdela, these units are available inside the data type property page.
