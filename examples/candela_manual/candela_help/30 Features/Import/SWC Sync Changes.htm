SWC Sync Changes

Changes in CANdelaStudio 8.5 SP3

  • Enabled loading of multiple arxml files at once.
  • Routine parameters only exchanged between application and DCM are ignored.
  • Routine info byte is ignored if the synched diag instance is marked as predefining it.
  • Text table values are correctly interpreted as decimal values.
  • CANdela display format is set for linear data types.
  • Implemented heuristic for computation of float display precision.
  • Corrected warning message on unmappable io ctrl diag instance.
  • All physical float values are set to 8 byte double.
  • Conversions of float encoded parameters are now checked against CANdela supported bitlengths.
  • Boolean encoded parameters are now interpreted as 1 byte sized types.
  • Overlapping text table ranges now lead to a clear error message.
  • Sync of DID referencing io control instances now correctly updates the DID.
  • AUTOSAR element references shall not be specified at IO ctrl packets but at the data objects contained in those packets (SWCSYNC-44)
  • Support ports in nested compositions and two or more context-component-ref elements (SWCSYNC-41)
  • Discern P-, R- and PR-PORT-PROTOTYPEs in synchronized AUTOSAR target refs (SWCSYNC-38)
  • Rebuild bitfield structures when synchronizing bit-sized objects (SWCSYNC-18)
  • Accept identical data types defining a compu method without linear and without text table part (SWCSYNC-14)
  • Support specification of deviating bit lengths for CANdela data types resulting from ASR data types (SWCSYNC-23)
  • Affect only the variant selected in the requirements setting tab (SWCSYNC-17)
  • Reflect value range restrictions of synched ASR data objects by creating separate CANdela data types (SWCSYNC-16)
  • Store single value init values in the usual default value column (SWCSYNC-15)

Changes in CANdelaStudio 9.0 SP1

  • SWCSYNC-58: Avoid qualifier postfixing and duplication of data types as far as possible
  • SWCSYNC-47: IO ctrl elements shall not be stored inside of a packet data type but directly inside the DID's telegram table
  • SWCSYNC-63: Avoid data object suffixes upon repeated synchronization
  • SWCSYNC-66: Display format of identity data types shall be decimal, not hex
  • SWCSYNC-69: Linear datatypes with non-integral scale shall have float phys encoding and display format
  • SWCSYNC-72: Data type names shall be unique after SWC Sync
  • SWCSYNC-75: Init values shall be written into data objects' implementation default attribute as coded values
  • SWCSYNC-78: Heuristic to compute the display precision shall also consider init values
  • SWCSYNC-85: Post summary list of unsynchable objects at the end of the SWC Sync log.
  • SWCSYNC-88: In case of ranged text table entries, the SWC Sync shall use the lowest range value as inverse value for phys-to-coded computation.
  • SWCSYNC-91: The SWC Sync shall repeat and summarize all warning, sorted by category, at the end of the SWC Sync log.
  • SWCSYNC-94: When warning that no IO ctrl or routine instance can be found with a certain instance type, the SWC Sync shall also post the corresponding requirement id.
  • SWCSYNC-97: For the phys side of text table entries, the SWC Sync shall prefer the AUTOSAR compu scale's short label over the symbol over the compu const vt.
  • SWCSYNC-100: Post the full path to the synchronized arxml files in the SWC Sync log.
  • SWCSYNC-103: The info message on missing routine components shall sound less like a warning.
  • SWCSYNC-106: SWC Sync shall issue a warning if an object is synchronized twice in the same sync run.
  • SWCSYNC-109: IO control enable masks shall yield all bits individually.
  • SWCSYNC-112: Support to define an array as a struct member inside the I/O Control Data Port.
  • SWCSYNC-119: Improve error reporting when encountering a missing reference from a RoleBasedPortAssignment to a PortPrototype.

Changes in CANdelaStudio 10

  • SWCSYNC-3: Store objects which cannot be synchronized in the import pool.
  • SWCSYNC-4: Extend SWC Sync with a GUI.

Changes in CANdelaStudio 12

  • SWCSYNC-163: Support setting of attribute ASR3_Legacy_Combine_DID for DIDs modelled with and without the CANdela DID feature [SWC-R1610-DiagInst]
