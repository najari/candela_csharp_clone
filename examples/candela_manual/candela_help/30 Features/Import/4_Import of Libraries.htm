ODX Import of Libraries

Since 8.5 SP2 (CDS-37946), CANdelaStudio supports libraries.

ODX Import Scopes with "Library"

[ODXI-R500] ODX Import supports libraries in the existing import scopes (the scopes are linked with the respective chapters below)...

  • Complete ODX ECU description
  • Variants with selection of services/jobs
  • Selected parts only

... but also supports a special import scope...

  • Library

General Rules

The following general rules apply to all import scopes described below.

  • [ODXI-R500-Origin] CANdela Library information originates from ECU-SHARED-DATA in ODX.
  • ECU-SHARED-DATA information will be stored in...
    • ... [ODXI-R500-ESD] ECU-SHARED-DATA on document level (as before 8.5 SP2, for details see below)
    • ... [ODXI-R500-Lib] a CANdela Library (since 8.5 SP2)
  • [ODXI-R560 Conflict] If the qualifier of an existing library is identical to the SHORT-NAME of an imported ECU-SHARED-DATA, import deletes all existing DIDs and diagnostic instances in the library and replaces them by imported ones.
    • This avoids naming conflicts between existing and imported data.
    • Assumption: it is not a use-case to add data to an existing library via ODX import.
    • Note: this is opposed to DIDs and diagnostic instances in a variant, which import only deactivates.

Library Creation

[ODXI-R510 Library Creation] Import creates a CANdela Library only if...

  • ... [ODXI-R510-DS] the ECU-SHARED-DATA defines at least one DIAG-SERVICE,

    and [ODXI-R510-DCL] a CANdela diagnostic class can be identified for the DIAG-SERVICE.

  • or [ODXI-R510-TABLE] the ECU-SHARED-DATA contains at least one TABLE,

    and [ODXI-R510-TABLEREF] the TABLE or one of its TABLE-ROWs is referenced statically or dynamically by at least one DIAG-SERVICE (inside or outside the ECU-SHARED-DATA),

    and [ODXI-R510-DCLTABLE] a CANdela diagnostic class can be identified for the DIAG-SERVICE or TABLE (see next chapter).

Therefore an ECU-SHARED-DATA containing only DOPs or UNITs will not be imported as a library.

[ODXI-R512] A Library created or updated by the import will be locked [LIB-R020] using the operation [LIB-R120] (e.g. referenced data types will be write-protected).

Motivation: preserve the state of the ODX data in the document, i.e. ECU-SHARED-DATA corresponds with a locked Library.

[ODXI-R514] Import stores the originating ECU-SHARED-DATA as an Embedded External File at the library [LIB-R026].

Identify Diagnostic Class

[ODXI-R520 Identify Diagnostic Class] In order to identify a CANdela Diagnostic Class, import does...

  • [ODXI-R520-CONN] not evaluate a TABLE-DIAG-COMM-CONNECTOR defined at the TABLE. Reason: the constellation is not used in practice.
  • [ODXI-R520-ESD] even evaluate DIAG-SERVICE or TABLE information from an ECU-SHARED-DATA which itself is not imported but in ODX is referenced with the imported ECU-SHARED-DATA.

ODX SHORT-NAME Reference

[ODXI-R530 SHORT-NAME References] Import will only create a diagnostic instance in the imported library if the ODX DIAG-SERVICE or TABLE does not contain a SHORT-NAME reference (SN-REF).

Background:

if an ODX object in an ECU-SHARED-DATA contains an SN-REF, the SN-REF will be resolved locally in any variant that references the ODX object. This is ODX functionality. E.g. if...

  • a DIAG-SERVICE contains a parameter which references a DOP via an SN-REF,
  • and two variants contain two different DOPs with that SHORT-NAME,
  • then within the two variants, the parameters in the DIAG-SERVICE effectively reference different DOPs.

The CANdela data model does not provide an SN-REF mechanism but explicit references only.

Import Scope: Complete ODX ECU Description

Context: you import a complete ODX BASE-VARIANT (corresponding with the CANdela ECU).

  • Import creates a Library for each ECU-SHARED-DATA [ODXI-R500-Origin] that is referenced directly or indirectly in the BASE-VARIANT
  • Exception: [ODXI-540] for an ECU-SHARED-DATA that contains only DOPs or UNITs [ODXI-R510], Import does not create a Library but imports the ECU-SHARED-DATA into the ECU-SHARED-DATA list on document level [ODXI-R500-ESD] (as before CANdelaStudio supported libraries).
  • [ODXI-R550 References] Import references Diagnostic instances between the Base variant, extended variants and Libraries.

Import Scope: Variants with Selection of Services/Jobs

Context: you import selected CANdela variants, based on variants of one ODX BASE-VARIANT.

Import Scope: Selected Parts only

Context: you import selected parts from the ODX file.

Import creates...

  • from DTC-DOP/DTCs: DTCs in the selected variants (as usual; [ODXI-R570] libraries are not available as import target)
  • from DOP-BASEs: data types in the data type list (as usual)
  • from PARAMs: data objects in the import pool (as usual)
  • [ODXI-R580] no libraries

Import Scope: Library

Context: you import one ECU-SHARED-DATA into a library.

  • Import creates a library [ODXI-R500-Lib] from the selected ECU-SHARED-DATA
  • Import handles other (referenced) ECU-SHARED-DATA and conflicts with libraries already existing in CANdela as for Complete ODX ECU description above.
  • [ODXI-R590 Mapping Dialog] a dialog lets you map
    • DIAG-SERVICEs that do not use a TABLE
    • and TABLEs to a CANdela diagnostic class (which must have an appropriate Combined Component in the diagnostic class template). Cf. [ODXI-R520].
  • Import references diagnostic instances between variants and the involved libraries if they have the same qualifier and contain identical data, like for Complete ODX ECU description [ODXI-R550 References].

Examples:

Import of ECU-SHARED-DATA not-inherited: results in...

  • separate library,
  • no data referenced.

Import of ECU-SHARED-DATA with data referenced in a not imported ODX variant: results in...

  • separate library,
  • variant not imported,
  • no data referenced.

Library Import not referenced

Import of ECU-SHARED-DATA with data referenced in another (not imported) ODX ECU-SHARED-DATA: results in...

  • separate library,
  • other ECU-SHARED-DATA not imported,
  • no data referenced.

Library Import - other ECU-SHARED-DATA not Imported

Import of ECU-SHARED-DATA with data referenced in another (also imported) ODX ECU-SHARED-DATA: results in...

  • each ECU-SHARED-DATA imported as a library
  • data referenced between the libraries.
