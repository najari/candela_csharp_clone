Shortcut Qualifier and Shortcut Name

Overview

A service and a job have the two "shortcuts" properties...

  • [SHC-R100 Shortcut qualifier]
  • [SHC-R110 Shortcut name].

The shortcut qualifier is unique in variant scope [SHC-R410] and therefore typically used...

  • in ODX which describes a service on variant level (no diagnostic instance)
  • in CAPL to address a service
  • in general, in a test system in a service centric view.

Initial Value in CANdelaStudio

[SHC-R300] CANdelaStudio initializes the shortcut qualifier as a combination of...

  1. the diagnostic instance (or job container) qualifier,
  2. an underscore as separator,
  3. the service (or job) qualifier.

[SHC-R310] For the name, CANdelaStudio uses the respective names and a blank as separator.

Consistency Conditions

[SHC-R410 Shortcut Qualifier Uniqueness] A shortcut qualifier...

  • must be unique within the variant.

[SHC-R420 Shortcut Qualifier Characters] A shortcut qualifier...

  • may contain only the characters 'a' to 'z', 'A' to 'Z', '0' to '9' and underscore '_'.
  • The first character must not be a digit (like for a qualifier).

[SHC-R430 Shortcut Name Characters] A shortcut name...

  • may contain all characters of the Unicode set, which are also valid for XML (like for a name).

See the consistency check.

Coupled Shortcut Names and Qualifiers

[SHC-R500] Shortcut name and qualifier are implicitly coupled if...

  • the shortcut qualifier equals the shortcut qualifier that would be generated from the shortcut name,
  • and the qualifier of the parent diagnostic instance (resp. job and parent job container) is not fixed

When you modify a coupled shortcut name, CANdelaStudio modifies the coupled shortcut qualifier accordingly.

This coupling is equivalent to implicitly coupled CANdela names and qualifiers.

Validation and Migration to 8.5

Since version 8.5 (CDC-36987/CDC-39185), CANdelaStudio checks the shortcut qualifier on loading:

[SHC-R600]: on loading a file with format < 8.5, ...

  • for each the service/job shortcut qualifier that is not consistent ([SHC-R410] and [SHC-R420]),
  • CANdelaStudio...
    • writes a warning,
    • if not in read-only mode: recomputes the service shortcut qualifier.

Note: in read-only mode (when loaded in a test system), the shortcut qualifier shall remain unchanged, in order to avoid breaking paths in a script.

[SHC-R610]: on loading a file with format >= 8.5, ...

  • for each service/job shortcut qualifier that is not consistent ([SHC-R410] and [SHC-R420]),
  • CANdelaStudio...
    • writes an error,
    • does not load (like for qualifiers).
