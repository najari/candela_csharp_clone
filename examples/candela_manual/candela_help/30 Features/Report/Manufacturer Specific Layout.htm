Manufacturer Specific Layout (CDS-282)

Use Case

You want to generate the RTF report in a company specific layout (front page, headers, footers, font…).

Scope

Layout that may specific:

  • front page
  • headers
  • footers
  • headlines

No impact on:

  • number of columns in tables
  • order of chapters

Selection

Selection of the specific layout:

  • without user interaction
  • based on the free text “manufacturer” info in the CANdela file:
  • if there is a specific layout with the name <Manufacturer>_Template.tmx (e.g. Vector_Template.tmx), then report uses that layout,
  • otherwise it uses the default layout Neutral_Template.tmx.

Details

  • each layout is described in a structured XML file in .TMX format, stored in the CANdelaStudio installation subfolder bin/Report;
  • you can also adapt the file Neutral_Template.tmx for the default neutral layout;
  • a layout file contains multiple RTF fragments;
  • one main fragment contains RTF for the front page, headers, footers;
  • other typically small fragments cover e.g. specific headings
  • a fragment contains placeholders which thereport replaces by data from the CANdela document (language of the document, etc.)

Placeholders

Report supports two types of placeholders in the fragments:

Fixed String Placeholder

Used for a constant text to be translated in different languages, e.g. the string “Diagnostic Specification”.

Fixed string variables look like this: _fst_name_

  • fst = “fixed string”
  • the _ is used to discern the report variables from RTF codes

The value of a fixed string variable is taken from the fixed text TMX repository.

Data Placeholder

Used for data from the CANdela document.

  • E.g. _dat_author_ gets replaced with the name of the document author.
Placeholder Replacement
_dat_audience_ Audience (target groups) specified for the report
_dat_authorname_ Name of the author (from the last history item)
_dat_compactline_ Note about compact report
_dat_date_ Same as _dat_docdate__
_dat_deflang_ Language in which document has been opened
_dat_department_ Department of the author
_dat_docdate_ Date of last history item
_dat_docstatus_ String status of last history item (manufacturer dependent)
_dat_docversion_ Version of last history item
_dat_ecuname_ Name of the ECU
_dat_editor_ Formatted author information
_dat_genbyline_ Formatted info about generation (_dat_moduleversion_, _dat_processdate_)
_dat_historyline_ Formatted info from last history item
_dat_manufacturername_ "Diagnostics Based on"
_dat_moduleversion_ Version of report generator
_dat_processdate_ Date of report generation
_dat_revision_ Same as _dat_docversion_
_dat_status_ Same as _dat_docstatus_
_dat_tabwidth_ Needed for RTF internally.
_dat_targetline_ Formatted info about audience
_dat_targetnames_ Same as _dat_audience_
_dat_templateline_ Formatted info about template
_dat_templatename_ Name of the CANdela template
_dat_templateversion_ Version of the CANdela template
_dat_variantline_ Formatted info about variant
_dat_variantname_ Name of the variant (if not all variants are exported)
_dat_vgsline_ Formatted info about Vehicle System Groups (vgs sic!, not vsg)
_dat_vgsnames_ Vehicle System Groups specified for the report (vgs sic!, not vsg)

Example RTF Fragment

<tu tuid='frontpage'>
<tuv
xml:lang='en-US'><seg>{\rtf1\ansi\ansicpg1252\uc1\deff0\_dat_deflang_
\deflangfe1031
{\fonttbl
{\f0\fnil\f 
\b _fst_author_:\b0 _dat_authorname\par
... }
</seg>
</tuv></tu>

Explanation:

  • _dat_authorname_ gets replaced with the name of the document author
  • _fst_author_ gets replaced with the translated fixed string for ”author”
  • <tu tuid='frontpage'>... is the XML structure hosting the frontpage fragment
  • {\rtf1... } is the RTF fragment value
  • backslashed words are individual RTF codes, like \b and \b0 to start and end of bold text.

How to Apply a Specific Layout TMX File

Recipe to apply a specific layout TMX file e.g. Vector_Template.tmx:

  1. Copy the Vector_Template.tmx to the CANdelaStudio\bin\Report folder
  2. Set the manufacturer in File|Properties|Document Info to "Vector"
  3. Export to document
