Report

Format

CANdelaStudio can export a document to...

  • RTF
  • HTML (CDS-4432 6.5)

Filter

[RP-R100 Filter] The document can be filtered by

  • [RP-R100-Variants] Variants
  • [RP-R100-Audience] Audience (Target Groups)
  • [RP-R100-VSG] Vehicle System Groups.

[RP-R110 Language] You can select the language for fix strings contained in the report.

Report skips...

  • de-activated diagnostic instances and job containers
  • diagnostic instances and job containers assigned to a specific target group that you have excluded from export

Cf. the diagnostic instance icons in the navigation tree.

Report Structure

Front Page

[RP-R120 Front Page] The front page contains

  • the ECU name
  • the manufacturer string
  • the editor (from the last revision item)
  • the version (dito)
  • for a document: the template
  • the target group selection for the report

For export to RTF, you can adapt the layout of the front page (requires knowledge of RTF).

Authors and Revision History

[RP-R130] Contains the information entered in the Revision History Dialog, if enabled in Ribbon Tab File | Options [OPT-R500].

Document Conventions

[RP-R140] Contains a fixed text.

Abstract

[RP-R150] Contains the text entered in the dialog File | Properties dialog "Short Description".

Overview

[RP-R160] Describes

  • the ECU (name, description)
  • each variant (name, description, Identifying Patterns)

R075.0 (Report): in the overview chapter, for a locked variant, add “(locked)” behind the variant name.

Communication Parameter

[RP-R170] Contains the interfaces and communication parameters.

Services Supported for Interfaces

[RP-R175] For a given interface, ...

  • if there is at least one Used Protocol Service that is not supported [SSI-R100] for the interface,
  • then the report lists all supported Used Protocol Services for the interface.

Diagnostic Content

[RP-R180] Contains the variants.

See details below for...:

  • DIDs [RP-R900]
  • DTCs [RP-R310]
  • Events [RP-R320]
  • Write Description of Data Objects [RP-R260]

State Dependency of Service Execution

[RP-R190] Contains the State Dependency info.

Data Types

[RP-R200] Contains the Data Types.

Option "Write even objects not used in document" [OPT-R440] applies to this chapter.

Attributes Overview

[RP-R210] Contains the Attribute values of all objects in the document.

Note: the chapter does not list DTC attributes (which would make the list very long). DTC attributes with setting “visible in separate table column” [ATTR-R090] are exported in the contents chapter [RP-R180].

Protocol Services

[RP-R220] Contains the Protocol Services.

Negative Responses

[RP-R230] Contains the Negative Response Codes on document level and for unsupported services.

Service Index

[RP-R240] Lists Services by their abstract.

Index

[RP-R250] Lists the diagnostic objects by their name.

Write Description of Data Objects (CDS-1562)

Use Case

You may want to...

  • see the name and complete description of a data object at a glance (in the table),
  • avoid long descriptions printed into a table cell.

Writing Descriptions

[RP-R260] Writing Descriptions

[RP-R260-Cell] Report prints the description in italic font if written with the name in one table cell.

[RP-R260-Option] A user option controls how descriptions are exported:

  • never: data object descriptions are not included in the report
  • always: data object descriptions are always included in the table cells (with the data object name)
  • large ones as table footnote: a long data object description is numbered and shown in the report as a footnote below the table, if...
    • it is longer than 60 characters, or
    • it contains a line break;
    • otherwise it is included in the table cell.

Fix Strings from TMX File (CDS-2630)

Use case

You want to generate the RTF or HTML report with explaining texts in his language.

This is about generated text (fix strings) like “Author:”, not about texts specified in the CANdela document.

Specification

In the file selection dialog for report, you can select from a set of languages, which is taken from the file Bin\Report\FixStr.tmx in the CANdelaStudio installation folder. The file contains fix string translations.

For detailed information about the TMX standard refer to "Translation Memory eXchange" ("TMX") at http://www.gala-global.org/lisa-oscar-standards .

State Dependency

There are a lot of different state graphs (service- and variant centric graphs) and therefore not all of them are shown within the RTF-Export. Additional information (provided in tooltips within CANdelaStudio) must be presented in another form (e.g. in tables).

The state groups are listed under every variant. The corresponding State Graph (see 2.1) is shown and a table describes the state dependencies in detail.

Services of the same DiagClassServiceTemplate which are all of the same behavior are combined (DiagClassName/*/DiagClassServiceTemplateName). Services which cannot be combined are listed separately with their service prefix and their name (DiagClass-Name/InstanceName/ServiceTemplateName). If the behavior of a Service differs from the behavior in other variants then the name and the service prefix is printed italic.

Service Prefix State1 State2 State3
AnyClass/*/AnyServiceTmpl 12 xx - n.a. State1
SomeClass/Instance1/ServiceTmpl1 13 01 - n.a. n.a.
SomeClass/Instance2/ServiceTmpl1 13 02 - n.a. n.a.
SomeClass/Instance3/ServiceTmpl1 13 03 - - n.a.
  • - executable
  • n.a. Service(s) are not applicable within this state.
  • StateX executable with state change to <State>.
  • Services which are not relevant are also listed.

DIDs

Note: available since 8.1 (CDS-19553), per variant since 8.5 (CDS-37944).

DIDs in Report

[RP-R900] if the variant contains at least one DID, Report writes DIDs in the chapter of the variant, before the diagnostic instances (CDS-37944 R900, 8.5).

[RP-R910] the chapter contains

  • a sub-chapter for each DID,
    • including the DID number (like at diagnostic instances), and
  • a table showing DID Data.

[RP-R920] Report writes a DID Data Reference...

  • like a data object referring to a data type;
  • the “data type” part is a hyperlink to the DID in the variant (even if one or both are shared in multiple variants),
  • it contains the name of the DID and the DID Number, like Engine Speed ($0101).

[RP-R925] Report writes for a DID Reference (CDS-37676)...

  • a data object for the identifier (from the piggyback data object stored in the DID Reference)
  • the DID data, like for a DID Data Reference (see R920).

[RP-R960] Report puts each DID occurrence into the index, ...

  • like for diagnostic instances
  • for variant oriented and compact report

DTCs

[RP-R310] The report represents...

  • a DTC in an own subchapter;
  • each DTC property as a table row;
  • the properties in the order (as in the user interface):
    • DTC Columns [DTC-R040]
    • Vehicle System Groups [VSG-R100-DTC]
    • Attributes with “visible in separate table column” set [ATTR-R090] (without regard to "Export to specification" [ATTRA-R030])

Events

[RP-R320] The Report does not write Events.

Motivation:

  • Events are a new feature in v12 anyway, and the use-case for representing Events in the Report is not clear
  • the Event list [EVUI-R020] in the user interface has many columns which would not fit into an RTF report page as is
  • the Event list may contain a huge number of Events, which would make the Report file huge (cf. Microsoft Word limits [RP-D410-Limit] below).

Automatic Update of Fields

[RP-R410] This feature is controlled by the option [OPT-R410].

  • [RP-R410-Check] If you check the option, CANdelaStudio automatically runs Microsoft Word after the export, so that Microsoft Word updates fields in the generated RTF document, e.g. ...
    • the table of contents
    • cross-references
  • [RP-R410-Uncheck] If you uncheck this option, ...
    • the generated RTF document contains the fields,
    • but when you open the document, Microsoft Word does not update the fields automatically,
    • so e.g. the table of contents will not be shown.
    • In Microsoft Word, you can then press Ctrl-A F9 to update all fields.

Microsoft Word: Limit for Fields

[RP-D410-Limit] Microsoft Word (as of 2016) has a built-in limit for the number of fields it can handle in a document.

  • In a huge exported RTF document, Microsoft Word may leave some fields empty.

Huge RTF Files with Graphical State Dependency

[RP-D420-Image] Automatic update of fields in the generated RTF document may take a long time in case Microsoft Word additionally saves each image in WMF (Windows Meta File) format.

You may...

  • either disable automatic updates of fields [OPT-R410],
    • open the file in Microsoft Word,
    • save it to DOCX format,
    • then update fields manually in Microsoft Word;
  • or apply a fix for Microsoft Word, see http://support.microsoft.com/kb/224663.
