Procedural Conversion (Procedure)

[DTPROC-R010] A Procedural Conversion converts a raw value from the ECU fo a physical value, and optionally back.

The procedure is interpreted by the runtime environment of the test system (e.g. Java, CANapeScript, CAPL).

See also the dialog.

Conversion Functions

[DTPROC-R100] A Procedure uses a mandatory function for converting raw to physical values.

[DTPROC-R110] A Procedure uses an optional function for converting physical to raw values (the opposite direction).

Function Properties

Each function (i.e. direction) can have job files for multiple runtime systems (e.g. one for Java, one for a manufacturer specific system).

[DTPROC-R120] Each function is expected to have... - one input parameter and - one return value. - Their type is determined by the coded and physical value type of the Procedure Data Type.

Consistency Conditions

[DTPROC-R210] If the Procedure Data Type is used in a request, at least one physToCoded Function must exist.

[DTPROC-R220] If the Procedure Data Type is used in a positive response, at least one codedToPhys Function must exist (which is required anyway).
