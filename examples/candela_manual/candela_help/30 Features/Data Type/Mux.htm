Multiplexer Data Type (Mux) (CDS-10216 in 6.5)

A Multiplexer data type defines multiple telegram tables ("Mux cases").

At runtime, the value of a data object sent before or after the Multiplexer (the so-called Selector) describes which telegram table is actually being transmitted (like a switch-case statement in a programming language).

The Multiplexer contains a default telegram table ("default case") which applies if at runtime there is no telegram table specified for the value of the selector data object.

See also the dialog.

Relation to Multiplexer Component

The behavior of the multiplexer data type is similar to that of the multiplexer component of a protocol service, but...

  • the multiplexer component is predefined in the protocol service in the template,
  • its data in a diagnostic instance is described using a "local Multiplexer data type".

Constraints

Creation and use of a Mux can be forbidden in the template, e.g. if a tool chain does not support it see Data Type Authorization).

R006.3 Constraints:

  • A multiplexer data type must not be referenced inside a Bit field.

  • A Mux must specify a selector data type, iff. it is used as a local data type for a Mux component defined in a Protocol Service

  • the data object used as selector for the Mux...

    • must exist in the same telegram table where the Mux is used and
    • must be located before the Mux
    • must be referenced by the data object that references the Mux data type (repair: CDC-42027 8.5 SP3)

  • the selector data object must not refer to a “complex” datatype.

  • the size of the Mux must not exceed any proxy component size restriction of which it is used in.

  • if the Mux contains at least one data object that has variable length, the object that uses the Mux is subject to the same restrictions as if it directly used a data object that has variable length (e.g. usage only at end of PDU).

  • If the telegram sizes of the cases (including the default case) differ, the data type becomes a variable size data type, and the same restrictions apply as for other data types with variable size (e.g. usage only at end of PDU).

  • the representation in a diagnostic instance for a Mux proxy component must contain exactly one data object that has selector not set and references a Mux.

  • A Mux case’s data object collection (including the default case’s collection) may remain empty. However in case of a local mux of the Mux proxy component, the collection size restrictions of the Mux proxy component must be considered.

  • a Mux with variable length must be used only at the end of a PDU

  • a data object referencing a Mux must not have a default or const value.

  • [MDT-R220] If cases for all valid selector values exist for a selector with a fixed set of values, the Default Case is not relevant, as for Mux Components [MUX-R220].
