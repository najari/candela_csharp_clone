Introduction

[DT-R100] A CANdela document contains data types on document level, for use in the template part and in all variants.

A simple data type [DT-R200] describes

  • re-usable properties of a Data Object:
  • the length of (raw) values available in the ECU and transferred via a bus
  • and their conversion into physical values (like temperature, angle, speed, length, etc.).

Example:

  • Raw byte 0x20 received
  • using data type "Temperature (1Byte)"
  • gives physical value t = 16°C.

A complex data type [CDT-R100] (packet, iteration, multiplexer...) contains multiple data objects.

A text table data type (a special simple data type) is also used to determine the set of valid values for (amongst others)...

  • Failure Type Bytes
  • Failure Mode Identifiers
  • UDS Identifiers ("variable values")

CANdelaStudio shows data types using specific icons.

General Properties of a Simple Data Type

A simple data type converts between

  • a raw value or coded value (data transported over the line between ECU and test system), and
  • a physical value (data as shown to or entered by the user of a test system).

For this purpose, a simple data type has the following general properties:

Property Description
Coded value type [DT-R110] the type of the coded value, see [DT-R300] below.
Physical value type [DT-R120] the type of the physical value, see [DT-R300] below.
Conversion between coded and physical values and vice versa, see [DT-R200] below.
Invalid values see [DT-R400], defined on coded values.
Bitmask see [DT-R500].
Precision see [DT-R600].
Unit see [UNIT-R005].

Conversions

[DT-R200] A simple data type specifies a conversion:

  • Identity (Raw Values)
  • Text table
  • Linear formula
  • Piecewise Linear
  • Characteristic Curve
  • Procedural Conversion
  • Formula
  • technically also a data type: DTC

Value Type Properties

[DT-R300] The coded value type and the physical value type of a data type (see chapter above) have the following properties:

Property Description
Encoding the type of the value / of a single element, see [DTENC-R100]. See also Start Range / End Range.
Quantity See [DT-R310] below.
Bit Length The length of the value / of a single element, see [DTL-R100].
Minimum Size
Maximum Size		 Number of elements for a field, semantics see [DTL-D200].
String Termination For a field, describes how the number of elements can be determined (leading size info, zero termination...), see [DTST-R100].

Not all combinations of above properties are valid, see chapter Data Type Property Dependencies.

Quantity

[DT-R310] The Quantity property of a Data Type distinguishes between...

  • [DT-R310-atom] atom describes a single value (character, integer...)
  • [DT-R310-field] field describes a field (array) of values of the same size (integer array, character string).

See chapter "Raw Encoding and Bit Length" [DTDEP-R100] for possible constellations.

Data Type References

Data types are referenced by multiple other objects, see Data Type References.

Constant and Default Value

A data object references a datatype.

Constant and default value are specified at the data object, not at the datatype, see chapter Data Objects.

Boolean

CANdela (and ODX) do not support a native Boolean data type. Typically, an identity or text table data type will be used instead, with length 1 bit or 1 byte (0 = false, 1 = true).

AUTOSAR supports a Boolean data type (but not arrays of Boolean, as of 2017-07).

In order to let the AUTOSAR Diagnostic Extract Export write a true AUTOSAR Boolean data type, set the attribute "AUTOSAR_Encoding" [SWC-R230].

Attributes for ECU-SHARED-DATA

[DTATTR-R100] A data type originates from ODX ECU-SHARED-DATA if the following three special attributes are set:

  • [DTATTR-R100-DOCTYPE] DOCTYPE
  • [DTATTR-R100-DOCREF] DOCREF. Updated (see [ESD-R210-Attr]) when the user edits the ECU-SHARED-DATA SHORT-NAME [ESD-R060].
  • [DTATTR-R100-ID_REF] ID_REF

For creation of the attributes, see [PEnODX-R002-f].

For reset of the attribute values, see [DTOP-R025].
