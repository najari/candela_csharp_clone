Data Type Authorization

Document Level Authorization

Specified in File | Properties Property Page Data Type Authorization.

Motivation

A tool that consumes the CANdela document probably does not support all aspects of CANdela data types. To prevent the diagnostic process that uses such tools from breaking, you can forbid the individual features described in the following.

Creation of Data Types

[DTAUTH-R110] Controls whether specific kinds of data types can be created in the document.

Allowed Type of Data Type Nesting

[DTAUTH-R120]

  • [DTAUTH-R120-Any] Any: no restriction
  • [DTAUTH-R120-Packets] Only packets in packets or in DIDs:
    • allows to nest packet data types,
    • does not allow to nest other kinds of complex data types besides packet data types.
    • In this regard, DIDs are handled like packet data types.
  • [DTAUTH-R120-None] No nesting: a data type in a DID or any complex data type is not allowed to contain a data object that references another DID or complex data type.

Allow 64 Bit Integer

[DTAUTH-R150] The use of 64 Bit Integers [DTENC-R200] must be enabled explicitly (since test systems probably do not support such integers).

Combined Proxy Component Level Authorization

Specified in the property page "Extended" of a Combined Proxy Component [CPC-R060].

Creation of Data Types

[DTAUTH-R210] The option restricts the use of Data Types in the telegram tables of individual Combined Proxy Components.

  • The option refines the document level authorization setting [DTAUTH-R110] above:
  • the stricter one of the authorization options applies.

Invididual Data Type Authorization

Specified in the Data Type property page.

  • [DTAUTH-R310] Modifiable: specifies whether properties of the data type can be modified, e.g. name and length.
  • [DTAUTH-R320] Deletable: specifies whether you can delete the data type.
