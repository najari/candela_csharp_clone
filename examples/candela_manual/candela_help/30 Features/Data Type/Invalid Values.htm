Invalid Values - Validity of range in conversion

See the Data Types Dialog.

Motivation

In some protocols, special result value bit combinations are reserved for expressing fault situations.

Definition

[DT-R400] CANdelaStudio describes special conversion result values using a set of “Invalid values” (also called "range exclusions") at a data type.

An invalid value is defined by...

  • [DT-R410] start and end of the range
    • on coded values
  • the kind of invalidity [DT-R420] (below)
  • [DT-R430] an optional “assigned text”
    • 1 to 64 characters, if given.

Semantics

In principle, the range of possible values for a data type depends on...

  1. the valid range defined by the conversion itself,
    • e.g. text table data type: coded value has no entry (start/end/assigned text);
    • e.g. linear formula: optional lower and upper limit restricts the value range;
  2. the list of invalid values.

For converting a coded value to a physical value (or vice versa), Vector test systems apply these ranges as follows:

  1. if the value is outside the valid range (i.e. the conversion does not allow to compute a value): error;
  2. otherwise apply the conversion, use the result value,
    • additionally, if the coded value is in the invalid values: warning.

Overlap

An invalid value may overlap with values inside and outside the valid range of the conversion.

In a test system, the invalid value takes effect only inside the conversion range (as described in the previous chapter).

Example for a 1 byte text table:

Coded Value Assigned Text Invalid Value Effect in test system
0 .. 9 "no" 0
5		 Warning for coded value 0
Warning for coded value 5
10 .. 19 "yes" 19 Warning for coded value 19
- - 20 no effect (coded values 20 .. 255 lead to an error)

CANdelaStudio reports an overlap inside the conversion range as a warning (CDS-12057, 6.0).

Invalid Values vs. Conversion Result

  • in the CANdela data model, invalid values are defined on the coded value;
  • in the ODX data model, invalid values are defined on the physical value;
  • therefore when e.g. converting a coded to a physical value, a Vector tester...
    • based on the CANdela data model (CDD): checks invalid values on the input value of the conversion,
    • based on the ODX data model: checks invalid values on the output (result) value of the conversion.
  • and vice versa when converting a physical to a coded value.

Invalidity

[DT-R420] An invalid value has one of the following values for kind of invalidity (CDS-2178, 3.0):

Invalidity Description Equivalent in ODX
Not implemented 1) a signal has not been implemented in the ECU, i.e. it is not available.
E.g. you use a general „static“ specification which is not completely being implemented in all ECUs.
In this case, some data may be not available in some vehicle configuration.		 "Not available"
2) a signal is invalid.
The internal check in the ECU found that it cannot provide a valid signal.
The reason may be one of the following:
Invalid signal 2a) the signal value is internal to the ECU, or "Not valid"
Unexpected result 2b) the ECU received an expected signal from another ECU with an unexpected value "Not available"
No signal 3) the ECU did not receive a signal it expected from another ECU. "Not available"
Undefined 4) Any situation for which none of the other signal types may be assigned. "Not defined"
