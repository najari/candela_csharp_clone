Data Type Length

See the Data Type Feature.

Bit Length

[DTL-R100] The Bit Length of a data type specifies the space it consumes on the line.

Atom

[DTL-R110] For quantity “atom” [DT-R310-atom], the encoding [DTENC-R100] defines the allowed data type length.

Field (Array)

[DTL-R120] For quantity “field” [DT-R310-field], ...

  • only field elements of
    • 1 byte size (unsigned, BCD, Ascii) or
    • 2 byte size (for encoding Unicode) are supported.
    • See chapter "Raw Encoding and Bit Length" [DTDEP-R100].
  • The maximum supported length is 65536 bytes (CDS-5184).
  • The maximum possible number of field elements is derived from that byte limit.
  • E.g. for a field with 2-byte Unicode characters, no leading or terminating size info, the maximum number of elements is 65536 bytes / 2 = 32768 elements.

Fix and Variable Length

Tools that process diagnostic messages may have restrictions with respect to variable length data objects, especially if such an object occurs in the middle of a message.

The length (number of bytes on the line at runtime) of a data type can be...

[DTL-D100 Fix Length]:

  • length known at authoring time

[DTL-D110 Variable Length]:

  • length not known at authoring time. There are two variations:

  • [DTL-D120 Deterministic Variable Length]:
    • length at runtime can be computed from data on the line
      • e.g. using a leading size byte, see [DTST-R100].
    • Being deterministic is relevant e.g. for a data object in the middle of a telegram, to determine where the next data object starts.
    • Note: a communication library must take special steps to interprete such a data object, therefore some libraries possibly do not support this constellation. To support this case, such data types can be forbidden in the CANdela document
  • [DTL-D130 Non-deterministic Variable Length]:
    • length at runtime cannot be computed from data on the line.
    • A data object that references a non-deterministic data type can occur only at the end of the telegram.

Sizes

[DTL-R200] The Minimum Size and Maximum Size properties of a Data Type define

  • ... for a data type with Quantity field [DT-R310-field]
  • ... the minimum/maximum number of elements.
  • Sometimes the properties are also called "Min elements", "Max elements".

[DTL-D200] Semantics of Minimum Size / Maximum Size

  • consumption for string termination by max length
    • See String Termination cases [DTST-R100-zeroMaxEOS] and [DTST-R100-zeroPadMaxEOS]
    • E.g. Maximum Size = 2:
      • a\0 allowed
      • ab allowed
      • ab\0 not allowed
  • capacity for the other terminations.
    • E.g. Maximum Size = 2 allows:
      • ab\0 allowed e.g. for case [DTST-R100-zero] of String Termination
  • cf. CDS-13987 "New values for field datatype termination" in 6.5
