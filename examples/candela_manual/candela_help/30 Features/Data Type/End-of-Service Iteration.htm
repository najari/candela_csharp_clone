End-of-Service Iteration

For an overview, see the Complex Data Types Introduction.

Introduction

Describes iterated transport of data objects in a telegram until the end of the service. In addition, you can also specify the minimum and maximum number of iterations.

Use-cases

  • UDS 0x19 0x04: describe list of DTC and Snapshot Data
  • UDS 0x19 0x0C: with upper limit 1, describe the optional DTC

Details

[EOS-R100] End-of-Service Iteration Data Type:

  • [EOS-R110] needs selector: no
  • [EOS-R120] minimum number, 0 by default
  • [EOS-R130] optional maximum number of iterations
  • [EOS-D100] Code that “synthesizes” a PDU must treat the min/max numbers as hard constraints.
  • [EOS-D110] Code that “interpretes” a PDU must handle violations of the min/max numbers as warnings (not errors, i.e. do not stop interpretation).
  • Note that “synthesizes” applies both
    • e.g. to a test system (for the request) as well as
    • e.g. to an ECU implementation (for the pos response),
    • and vice versa for “interpretes”.
  • For DEXT Export, see [DEXT-R225].
  • [EOS-R140] must not be used at a position before the end of the PDU (primitive)
    • even if it has deterministic length – it is “end of service”!
  • More constraints: see Iteration Data Type Constraints.
