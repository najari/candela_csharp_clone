Used Protocol Service

See also the dialog description.

Introduction

Used Protocol Services are a key feature of the CANdela data model:

[DCLT-R305] A Used Protocol Service associates...

  • a Protocol Service (e.g. UDS 0x22) with
  • a Diagnostic Class (diagnostic use case, e.g. "Identification", "Variant Coding", "Stored Data"...).

See the overview in the Protocol Service chapter.

In the data model, a Diagnostic Class Template contains Used Protocol Services, see [DCLT-R160].

Example

If you define...

  • a single Used Protocol Service "Read"
  • referring to UDS 0x22
  • in diagnostic class template "Identification",

this means that any diagnostic instance in the diagnostic class "Identification" can use UDS 0x22, but can use no other UDS service.

The same Protocol Service can be used in multiple diagnostic class templates.

Note: editing a Used Protocol Service re-computes qualifiers, see [DCTUI-D410].

Relation to Interfaces

See Services Supported for Interfaces.

Convention

[DCLT-R310 Used Protocol Service Convention] The Convention of a Used Protocol Service specifies whether (in a diagnostic instance) the service based on the Used Protocol Service is

  • required: you cannot delete it;
  • optional, default on: CANdelaStudio automatically creates it in a new diagnostic instance, but you can delete it;
  • optional, default off: CANdelaStudio does not automatically create it in a new diagnostic instance, but you can create it later.

[DCLT-R310-RqOn] At least one of the Used Protocol Services in a diagnostic class template must have the convention "Required" or "Optional (on)".

Semantics

[DCLT-R320 Used Protocol Service Semantics] The property represents the ODX service semantics. It will be used by ODX Export of services.

CANdelaStudio does not restrict the values of this property.

It is the default for the respective property of a service [SVC-R200].

Reference to Text Table (CDS-18874 8.0)

The range of identifiers to use in diagnostic instances of a given diagnostic class can be restricted in the diagnostic class template.

  • [DCLT-R400] a "Used ProtocolService" that references a ProtocolService which has a variable value references a text table that defines the possible identifier values. The text table must have the same length as the variable value.

  • R002.0: a "Used ProtocolService" that references a ProtocolService which has no variable value shall not reference such a text table.

Semantics: in a Diagnostic Instance, only identifiers are allowed that are defined in all text tables of the Used ProtocolServices.

The text table at the ProtocolService (which existed before 8.0) is since 8.0 only taken as a default for the text table at the "Used ProtocolService".

The consistency check reports a fatal error for a Used ProtocolService that references a text table with a different length than the one in the referenced ProtocolService.

R030.0: The consistency check reports an identifier value which is not a valid raw value of the datatype of any referenced Used ProtocolService for which a service exists in the diagnostic instance.

R040.0: There is no warning if the user shares variable values that reference different text tables.
