Combined Component

See also the dialog description and the overview of Protocol Service Components.

A Combined Component represents (references) one or multiple Protocol Service Components within a Diagnostic Class Template:

  • a Combined Variable Value Component references one or multiple Variable Value Components (for the identifier, subfunction...);
  • a Combined Proxy Component references one or multiple Proxy Components (for the data to read or write).

[CCM-R020] A Combined Component may reference Components even from different Protocol Services.

Combined Variable Value Component

[CVC-R050] All Variable Value Components of the Used ProtocolServices are combined in one Combined Variable Value Component.

See [DCLT-R400] for a Text Table restricting Identifier values.

Combined Proxy Component

  • All Proxy Components referenced by a Combined Proxy Component will transmit the same data.
  • CANdelaStudio represents all Proxy Components of one Combined Component by a single telegram table in the entry masks for diagnostic instances.
  • A Combined Component has a DID Semantics [DID-R050].
  • A Combined Proxy Component can restrict the use of kinds of data types in its telegram tables, see [DTAUTH-R210].
  • [CPC-R060] A Combined Component can restrict the use of variable but deterministic length [DTL-D120] data objects in its telegram tables:
    • [CPC-R060-End] Only at the end of a telegram
    • [CPC-R060-Anywhere] Anywhere
    • The setting is shown in the Combined Proxy Component Property Page Extended [CPCUI-R060].
    • The document level setting [DLA-R060] may already restrict this for the entire document.
  • [CPC-R020] Editing Combined Components is possible in Expert View only.
  • [CPC-R070] Proxy Components in Negative Responses are never combined.

Combined Proxy Component Semantics

  • [CPC-R100] The Semantics property has the same value as the semantics of the referenced Proxy Components [PC-R100].
  • [CPC-R102] All combined proxy components must have the same semantics.
  • [CPC-R104] All proxy components with semantics dtc must be combined (CDS-3384).
  • [CPC-R106] All proxy components with semantics obdDtc must be combined.
  • [CPC-R108] All proxy components of the same semantics must be combined, for the following semantics:
    • [CPC-R108-sr] sr [PC-R050-sr]
    • [CPC-R108-sd] sd [PC-R050-sd]
    • [CPC-R108-edr] edr [PC-R050-edr]
    • [CPC-R108-ed] ed [PC-R050-ed]

Consistency Conditions

See also conditions for semantics [CPC-R100]ff.

[CPC-R110] When multiple variable value components are combined in a Diagnostic Class Template, they must have the same byte-order (CDS-4453).

[CPC-R120] All Proxy Components referenced by a Combined Proxy Component must have the same value for "mandatory at runtime".

Note: this condition may force the use of two separate Protocol Services instead of using only one with an optional part (as shown in the example in the Mandatory and Mandatory at Runtime chapter), if the Proxy Component of the Protocol Service shall be combined with non-optional Proxy Components from other Protocol Services.
