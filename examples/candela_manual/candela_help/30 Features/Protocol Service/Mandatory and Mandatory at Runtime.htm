Mandatory and Mandatory at Runtime (CDS-2532)

Component Property Page Proxy

Properties

Protocol Service components have the properties

  • [PS-R510] mandatory
    • (user interface: "required in document")
    • controls authoring: whether data must be specified in the CANdela document;
    • opposite: optional.
  • [PS-R520] mandatory at runtime
    • controls execution: whether data specified in the CANdela document may be omitted at runtime.
    • If one Component is optional, all the Components following are optional, too.
    • If one Component has been omitted at runtime, all the Components following must be omitted, too.
    • See [PS-R540] below for the effect in a telegram table in a diagnostic instance.

Constellations:

Mandatory Document: Data specified Mandatory at Runtime Effect at Runtime
no yes yes Data must be present
no Data may be present or not
no yes No data present, since not specified
no dito
yes yes yes Data must be present
no Data may be present or not
no: constellation not allowed! (n/a) (n/a)

Example

To describe an optional parameter, you can either...

  • define two Protocol Services:

2A: Two Services

  • ... or define only one Protocol Service, with Mandatory at Runtime un-checked:

2A: One Service with MandatoryAtRuntime False

Effect at Different Types of Components

[RS-R430]

Component Effect
Constant Component is optional.
Variable Value Component is optional.
Proxy Component is optional. See [PS-R540] below.
Multiplexer Component is optional.
Iteration "Mandatory" is implicitly set, since the definition of Components within the Iteration already fulfills the "mandatory" condition.
Fixed Data dito.

[PS-R540] If...

  • a Proxy Component is optional,
  • and within a diagnostic instance, in a telegram table that refers the Proxy Component,
  • you define top-level data objects,
  • then the individual top-level data objects can be omitted at runtime, starting from the end.

Mandatory vs. Minimum Length

[PS-R550] There are two related properties that control the length of telegrams in diagnostic instances:

  • minimum length
    • [PS-R550-MinLength] must be > 0 always
  • mandatory
    • [PS-R550-Mandatory] if true, data length must be at least the minimum length;
    • [PS-R550-Optional] if false (optional), data length may be 0 or at least the minimum length.

Constellations:

mandatory optional
min. length 0 (not allowed, cf. CDS-5034) (not allowed; would be redundant)
min. length x > 0 telegram length >= x telegram length is 0 or >= x

[PS-R550-Mux] For a Multiplexer, ...

  • mandatory and minimum length apply to each Mux case individually,
  • i.e. the following Multiplexer Proxy Component constellation is valid:
    • mandatory: false
    • min. length: 1 byte
    • Mux case 0x01:
      • data object with 1 byte fix length
    • Mux case 0x02:
      • data object with 0..5 bytes
