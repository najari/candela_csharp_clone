LIN

LIN Standardization

  • "Road vehicles - Unified diagnostic services (UDS)"
    • was released in a second edition 2013-05-15 as ISO 14229-1 2013(E).
  • "Road vehicles -- Unified diagnostic services (UDS) -- Part 7: UDS on local interconnect network (UDSonLIN)"
    • defines methods to implement diagnostic data transfer between a client and the LIN slave nodes through the LIN master node.

CANdela Template

See the Vector UDS on LIN Template.

LIN Frames and Supported Interfaces

  • There is no need for a LIN specific Interface in the “Supported Interfaces” list of a LIN CDD.
  • The LIN specification...
    • fixes two LIN frames for Diagnostics and for Slave Reconfiguration:
      • 0x3C: Master Request Frame
      • 0x3D: Slave Response Frames
    • defines the values for the diagnostic timings P2 and P2extended
  • The LIN Description File (LDF)...
    • defines further settings relevant for diagnostics
      • e.g. the node address

Diagnostics: UDS Services

  • The CANdela document (CDD) describes UDS services as usual.
    • They are transported between Master and Slave using the two LIN frames and timings as described above.

Slave Reconfiguration: 0xBx Services

LIN Services Bx in the Vector UDS on LIN Template

Note: you can copy the 0xBx Services from the Vector UDS on LIN Template (in CANdelaStudio Expert View).

The 0xBx Services for slave reconfiguration are...

  • part of the LIN protocol itself;
  • not supported by UDS on LIN
    • see UDS on LIN (ISO 14229-7) - Table 3 "Overview of applicable ISO 14229-1 diagnostic services and data ranges"
    • "Services which are not listed in Table 3 are not supported"
  • The 0xBx Services are somewhat “compatible”,
    • i.e. the SID is sent as if these were “normal” UDS services.
  • However, it is e.g. not allowed to send a Negative Response with NRC=”Response Pending” for them.

In CANoe

  • Part of CANoe is a generic diagnostic description for LIN.
    • The 0xBx Services were never defined in this diagnostic description,
    • except the 0xB2 service “Read By Identifier”
      • (do not mix this with the UDS 0x22 “Read Data by Identifier”)
  • CANoe supports the 0xBx Services...
    • typically as part of the LIN protocol implementation via CAPL;
    • but you can also send them via the Diagnostic Feature Set...
      • either with a diagnostic description (CDD, ODX) defining them,
      • or in CAPL with the following workaround:
testcase TestB4Service()
{
  byte buffer[2]={0xB4, 0x08};
  diagRequest SerialNumber_Read dummyReq; // Use any request defined in the diagnostic description
  long ret;

  DiagSetTarget("Door");

  diagResize(dummyReq, elcount(buffer));
  diagSetPrimitiveData(dummyReq, buffer, elcount(buffer));
  DiagSendrequest(dummyReq);
  ret=testWaitForDiagRequestSent(dummyReq, 1000);
  // ...
}
