Iteration Component

To define a data element that shall be transfered multiple times in sequence, an iterative component is used. Specific types of iterative components are used depending on the end criterion.

End Of Service Iteration Component

... contains a list of iterated Components, until the end of the telegram. It has no selector.

Properties:

  • Mandatory
    • defaults to true
  • Minimum number of iterations
    • defaults to 0 (i.e. at runtime, the entire data of the iteration may be omitted)
  • It is valid to have...
    • Mandatory = false
    • Minimum number of iterations = 0
    • This is the default in the user interface.
  • Maximum number of iterations
    • optional, default: not specified

Numerator Iteration Component

... contains a list of iterated Components. A selector denotes a Component within the same Primitive; this Component must be located before the Numerator Iteration Component itself.

A Component which shall be used as Selector must meet the following conditions (cf. CDS-3833):

  • Mandatory must be ‘true’
  • MandatoryAtRuntime must be ‘true’
  • Semantics must be ‘any’
  • Fix bit length must be >= 8 bits and <= 32 bits

Only Proxy Components may be used as Selector!

End Marker Iteration Component

... contains a list of iterated Components.

  • One of those is used as a Selector.
  • If no Selector is specified explicitly, the first contained Component is used as a Selector.
  • the End Marker Iteration Component must contain at least one Component.
  • All Components before the Selector must have fix length.

A Component which shall be used as a Selector must meet the following conditions (cf. CDS-3952, CDS-3827, CDS-3830, CDS-3832, CDS-3931, CDS-4134):

  • Mandatory must be ‘true’
  • MandatoryAtRuntime must be ‘true’
  • Min bit length must be >= 8 bits
  • Max bit length must be > 0 and <= 32 bits (a max bit length of 0 means: infinite data)
  • All Components lying before the Selector must have fix length

Only Proxy Components may be used as Selector.

The tester at runtime uses the raw value of the Component marked as Selector and compares that raw value against the value defined in the End Marker Iteration Component.

At runtime, ...

  • the iteration that contains the EndMarkerValue (at the Component marked as Selector) does not contain useful data for the other Components (i.e. the tester will not display the value of the other Components to the user). Rationale: otherwise there would be no way to transport "0 iterations" over the line.

  • the iteration that contains the EndMarkerValue stops at the Component marked as Selector (i.e. if the EndMarkerIterComponent contains Components behind the Selector, for the last iteration there will be no data on the line that correspond with these Components). If there are top-level Components that follow the EndMarkerIterComponent, data for these Components starts immediately behind the EndMarkerValue.

  • the CANdela EndMarkerValue (= an integer) defines a byte stream which will be compared with the byte stream representing the Selector. The EndMarkerValue integer denotes the byte stream in HighLow byte-order (HighLow by definition, independent of any byte-order used in the ProtocolService). E.g. to define that the byte sequence 0x47, 0x11 stops the iteration at runtime, use the EndMarkerValue 0x4711 (mapping 0x4711 to the sequence 0x47, 0x11 implies HighLow).
