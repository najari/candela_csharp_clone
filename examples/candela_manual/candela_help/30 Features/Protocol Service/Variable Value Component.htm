Variable Value Component

[PS-R400] A Variable Value Component is the Component where e.g. an identifier must be specified within a DiagInstance.

"Specification" Property

[PS-R400-Specification Variable Value Component "Specification"] The following values are available for the "Specification" property:

  • Access mode
  • Address
  • Common ID
  • CPID
  • DID
  • DPID
  • ID
  • Info type
  • Local ID
  • Mode
  • Option
  • PID
  • Status
  • Subfunction
  • TID

Use in CANdela Layers

A Variable Value Component from the Protocol Service is referenced...

  • by a Combined Variable Value Component in the diagnostic class template, which is referenced...
  • by a Variable Value (e.g. identifier) in the diagnostic instance. There is at most one such value in a diagnostic instance. This is similar to the Combined Proxy Component/telegram table mechanism.

See the overview in the Protocol Service chapter.

Some manufacturers do not require the identifier to be unique. This is controlled by an option (see CDS-844).

Consistency Conditions

  • A Protocol Service used in a singleton diagnostic class must not have a Variable Value Component (cf. CDS-3280).
  • A Protocol Service used in a non-singleton diagnostic class must have one Variable Value Component (cf. CDS-3280).
  • There is at most one Variable Value Component per primitive.

Semantics

The Variable Value Component has a semantics (e.g. identifier or subfunction) which is usually given by manufacturer specifications.

Since several Variable Value Components may be combined in a diagnostic class template, there may be an ambiguity: which semantics should be presented to the user?

For this reason, a Combined Variable Value Component also has a semantics, to be defined by the editor of the template. At best, it is identical with the semantics of all combined Variable Value Components, but this is not a required consistency condition.

Reference to Text Table (CDS-8032 in 5.5)

  • [PS-R450 Text Table] A Variable Value Component has a mandatory reference to a text table.

Since 8.0, this text table is only used as a default for a text table at the Used Protocol Service [DCLT-R400] in a diagnostic class template.

Restrictions on the datatype

  • TextTable only
  • length restriction: max. 4 bytes, only byte-sized, atomar; or field with fix length
  • Note: no restrictions with regard to range exclusions, attributes, bitmask, byte-order.

BitLen and ByteOrder properties of the Variable Value are taken from the datatype.

The consistency check shall fail (fatal, prevent loading) if above restrictions are not fulfilled (e.g. not a text table, …).

Use of the text table

Let consistency check fail (non-fatal, e.g. prevents exports)...

  • iff a Protocol Service is used in a diagnostic instance with an identifier value which is not a valid raw value of the datatype of any referenced Variable Value Component (e.g. not covered by a textual mapping, or excluded via range exclusion).
  • In other words, the identifier value must be valid in the data types of all referenced Variable Value Components
  • Background: a DiagInstance references one Combined Variable Value Component which references 1..n Variable Value Components).
