Protocol Service

Overview

Diagnostics is about services:

  • a tester sends a request (specific byte sequence) to an ECU,
  • the ECU sends a positive or negative response.

There are different diagnostic protocols with different services.

UDS (Unified Diagnostic Services; ISO 14229) is widely spread and a recommended basis for new diagnostic projects.

There are different diagnostic use-cases: Stored Data, Routine, Fault Memory...

Services in CANdela

CANdelaStudio does not hard-code the data structures of diagnostic protocols. The CANdela data model is generic and supports different protocols.

The template defines a structure (“grammar”) which provides slots to be filled in an ECU document. This provides an abstraction for the user of CANdelaStudio Standard View. Typically,...

  • the template pre-defines the details of the protocol (like the service ID);
  • the document allows to describe only the payload data (velocity, temperature, …).

In CANdela,...

  • services from the protocol (0x22) are called Protocol Services,
  • whereas individual "services" (0x22 0xF1 0x00) are called Services.

Overview: CANdela Layers

The following diagram shows how the Diagnostic Class Template as a middle layer controls...

  • the use of Protocol Services and
  • the use of data (variable value, telegram table):

Protocol Services, Diagnostic Class Template and Diagnostic Instances (3 Layers)

Layer: Protocol Service

(edited in the CANdela template) defines the structure of individual services, like

Read Data By Identifier:
  0x22 <identifier> <data>

Effect:

  • the Protocol Services restrict the possible byte sequences,
  • you cannot use an arbitrary byte sequence for a request described in a CANdela document.

Layer: Diagnostic Class Template

(edited in the CANdela template) represents a diagnostic use-case (like Identification, Variant Coding, Fault memory...).

It references multiple Protocol Services, like

Identification:
  use Protocol Service 0x22 "Read Data by Identifier"

Variant Coding:
  use Protocol Service 0x22 "Read Data by Identifier"
  use Protocol Service 0x2E "Write Data by Identifier"

Effect:

  • the diagnostic class template relates Protocol Services with diagnostic use-cases,
  • you cannot use an arbitrary Protocol Service in a given use-case.

Layer: Diagnostic Instance

(edited in a CANdela document for a concrete ECU) conforms with the structure defined in the diagnostic class template.

Typically there are multiple diagnostic instances for a diagnostic class template. A diagnostic instances contains

  • the individual services based on the Protocol Services of the diagnostic class template (the "methods" in an object oriented view)
  • the individual data objects filled in at the places where the Protocol Service has a Proxy Component.

Effect:

  • you just describe the data objects (payload) that shall be transported for a given diagnostic use-case,
  • you may describe service details if necessary (like support of physical and/or functional addressing),
  • you don't need to know the protocol details.

Primitives

[PS-R100] A Protocol Service has three primitives:

  • request (required)
    • can be missing exceptionally in special templates (LIN, J1939);
    • CANdelaStudio expert view does not allow to produce this constellation (please contact Vector).
  • positive response (optional)
    • positive and negative response can be missing for some special services
    • e.g. "ControlDTCSetting - No Response Required"
  • negative response (optional)

Each primitive must have at least one Protocol Service Component.

Besides primitives in Protocol Services, a CANdela ECU description contains a special primitive that defines Negative Response Codes for Unsupported Services [NRC-R020].

Protocol Service Components

Each primitive (e.g. a request) contains a list of components: constant, variable, proxy, fixed data, multiplexer and iteration.

See the Protocol Service Components.

Default Negative Response Codes

[NRC-R030] The ProtocolService has a special data object that contains default negative response codes (NRCs). If you create a service, the NRCS are initialized from these defaults.

See the Negative Response Feature.

Service Signature (Service Prefixes)

Service Signature in CANdelaStudio (red marked numbers in column Request)

The diagnostic protocol consists of services provided by the ECU and typically requested by an external test system.

Both participants must be able to:

  • ... from the hex sequence transported over the line
  • ... unambiguously detect the indented service.

A “Service prefix" is the sequence of leading Constant Components and Variable Values (cf. CDS-844, CDS-2275, CDS-4944):

  • Constant Components
    • typically the Service ID like 0x19 or 0x22
    • defined including their values in the Protocol Service
  • Variable Value Components
    • typically for the Data Identifier (DID), routine ID etc.
    • defined in the Protocol Service
    • the value is defined in a diagnostic instance
  • not key properties: constant data objects
    • within a Fixed Data Component
    • or in a telegram table for a Proxy Component

Example for a service in a diagnostic instance:

Component List in Request Value Value Defined in the...
Constant Component 0x22 Protocol Service
Variable Value Component 0xF0 0x40 Diagnostic instance
Proxy Component (data objects) Diagnostic instance

This service has the signature 22 F0 40.
