Protocol Service Components

Overview

There are different types of Protocol Service Components:

Component Example Description
Constant Service ID 0x22 Value predefined in the template, cannot be changed in the document.
Variable Value Identifier, Subfunction... Value to be defined in a diagnostic instance
Proxy Response data for 0x22 Data objects to be defined for individual services in diagnostic instances
Proxy with semantics any Transfer data for 0x36 Data not described in the CANdela document but only known at test system runtime
DTC Status 0x19 Data describes status of DTC in ECU
Multiplexer (Mux) Snapshot data per DTC
 Data structures that vary depending on another transported value, the "selector"
Iteration Snapshot data for multiple DTCs Repeated data structures. There are different iteration components with different iteration conditions.
Fixed Data Address and size combinations for 0x23 Data objects predefined in the Protocol Service, not to be changed in a diagnostic instance.
To be used if a protocol service will always be transferring the same data objects regardless of the diagnostic class in which it is used.

Data Definition Stages

Using the above described components, data values are specified in one of 3 possible stages:

  1. when editing a template (Constant Component)
  2. when editing a diagnostic instance in aCANdela document (Variable Value, Proxy, Mux Component)
  3. at runtime of a test system (Proxy Component with semantics any)
