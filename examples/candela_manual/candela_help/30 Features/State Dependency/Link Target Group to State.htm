Link Target Group to State (CDS-68998 9.1)

Context

The Authorization feature provides a special State Group "Authorization". Based on the user's role at runtime, execution of a service may be blocked by the ECU. In CANdela, the user role is described as a state.

Use-case

Export to ODX only those services that may be executed in a given user-role (i.e. state of State Group "Authorization").

The export [MENU-R120]...

  • can be filtered by relevance for audience (target groups),
  • but not by state transitions.

Therefore it may be desirable to "link"...

  • the "Authorization" state transitions at a service (cf. the State Transitions dialog)
  • to the relevance for audience (cf. the Target Groups dialog),

so that a service...

  • "blocked" for a user-role (i.e. state)
  • is "not relevant" for the corresponding target group.

Setup of the Link (CDC-43751 9.1)

[ST-R500] the values of a target group and a state are "linked" iff.

  • [ST-R500-Qual] target group and state have the same qualifier, and
  • [ST-R500-Attr] the Attribute "SyncWithTargetGroup" (unsigned or enum) exists at the state, and the effective (default or overridden) value is != 0.
  • [ST-R500-Authorization] the state is in the first StateGroup with semantics "Authorization" [STG-R050-Authorization] (CDC-43785 9.1)

Recommendations for attribute creation:

  • enum [ATTR-R020-enum]
  • 0 = no, 1 = yes
  • default 0 [ATTR-R040]
  • sort by ID
  • name "Synchronize with Target Group"
  • category "Editor" [ATTR-R100]
  • modifiable = false [ATTR-R080]

Modifying Linked Properties

[ST-R510] For a service in any diagnostic instance...

  • where the values of a target group and a state are "linked" ([ST-R500] above),
  • [ST-R510-Locked] in a non-locked variant,
  • [ST-R510-Auth] with both...
    • primary [DIA-R040] and
    • secondary [DIA-R050] properties modifiable (CDS-70161 v11),
  • [ST-R510-TargetGroup] ... setting relevance of a target group...
    • to "no" sets the state transition to "(no)" [STTR-R020-no]
    • to "yes" sets the state transition to "(yes)" [STTR-R020-yes]
    • [ST-R510-StateAuth] if State Authorization [ST-R050] is "modifiable"=yes.
  • [ST-R510-State] ... setting the state transition...
    • to "(no)" sets the target group relevance [DI-R200] to "no"
    • to "(yes)" or to a target state sets the target group relevance [DI-R200] to "yes".
    • [ST-R510-NotRelevant] If the diagnostic instance is not relevant for the target group, then setting the state transition is not possible (CDC-43786 9.1)

Caution: when you set a target group to "yes", ...

  • CANdelaStudio automatically sets the state transition to "(yes)",
  • but you may need to set the transition to a specific state manually
    • e.g. for ECU Reset in Daimler Star 3: transition to state "anybody".

Note: CANdelaStudio property dialogs save modified values on pressing the OK button. Therefore the automatic changes will be visible only after re-entering the dialog.

Consistency Check

[ST-R600 Link Target Group to State]

  • If the SyncWithTargetGroup attribute [ST-R500-Attr] at States exists
  • and has an effective (default or overridden) value != 0
  • and
    • a State SQ in the first StateGroup with semantics "Authorization" [STG-R050-Authorization] and
    • a Target Group TQ with the same qualifier Q exist
  • then for each service S,
    • for any such State SQ and Target Group TQ,
    • if S is relevant for TQ, but the state transition at S in state SQ is "no",
    • or S is not relevant for TQ, but the state transition at S in state SQ is != "no",
    • then the check reports a warning and prevents from export, like "Target Group and State not synchronized: "<Q>" in service "<S>", diagnostic instance "<DI>".

  • [ST-R610] if there is more than one State Group with semantics "Authorization" [STG-R050-Authorization], constraints check emits a status message (CDC-43785 9.1)

      Multiple State Groups have semantics "Authorization". Target Group/State linking will use the first one only.
