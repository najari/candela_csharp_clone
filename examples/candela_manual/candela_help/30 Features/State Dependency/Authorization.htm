Authorization (CDS-68998 9.1)

(looking for "Authorization" to control authoring in CANdelaStudio? See Authorization.)

In 2017, the traditional security access using Security service 0x27 (seed/key) is considered out-dated and unsafe. In times of DoIP and other over the air interfaces, more and more scenarios for attacks to a vehicle are possible.

As a consequence, manufacturers migrate to a certificate-based approach for diagnostic authorization. Certificates support a rather different way of access control.

A certificate can be issued...

  • individually for a user,
  • for a use-case or
  • time-limited.

This will enable further use cases, like...

  • coding (temporarily rent increased engine power)
  • current data (retrieve protected information)

The traditional security access is still in use e.g. for legislative requirements like protection of airbag disposal.

Authorization in Vector Tools

Vector Security Manager

A diagnostic tool like CANoe or CANoe.DiVa must be able to provide a certificate at runtime in order to successfully communicate with an ECU.

For user comfort, certificates can be accessed automatically using information from the CANdela document.

  • Vector tools use a central Security Manager
  • ... which provides a generic interface
  • ... to access OEM specific security sources.
  • The CANdela document provides configuration
  • ... and authentication parameters.

Authorization in CANdela Data

[AUTH-R100] CANdelaStudio 9.1 supports Authorization via the existing State Group mechanism.

  • [AUTH-R100-State] A user role is described as a state of the special "Authorization" State Group [STG-R050-Authorization].
  • Blocking the execution of a service is described as usual...
    • by setting a transition to "no"
    • ... for a state of the state group "Authorization".
  • [AUTH-R100-Trans] Changing the User Role is described using State Transitions for Jobs.
    • At runtime, such a job indicates the desired state transition to the Security Manager.
    • The job file of such a job is actually not used (there is no runtime system involved that interprets instructions in the job file).
    • For interactive use in a Vector tool, the job must be stored in a job container with qualifier "Security_Jobs" (recommended name: "Security Jobs").
    • CANoe.DiVa automatically uses jobs causing state transitions, independent of the job container.
  • [AUTH-R100-Job] Authentication Parameters: the Security Manager passes the job input parameters as key/value pairs to the security source:
    • key: the data object qualifier (typically: "Role"),
    • value: the data object default value [DO-R350].
  • [AUTH-R100-Link] Optionally, target groups can be linked with Authorization states at a service.
