Library (CDS-37946 8.5 SP2)

Libraries Tree Node and List

Introduction

  • A library is an authoring feature.
  • It is not directly relevant for a test system or code generation (it may take effect only if its data is used in variants).
  • A library provides DIDs and diagnostic classes for use in a document.
  • It is either
    • imported from ODX ECU-SHARED-DATA (import scope "Library", not "Selected parts only") and passed through the document to ODX export, or
    • created within the document as a base for copying and referencing across variants. This is especially helpful if the diagnostic process does not allow references into the base variant.

Note: ODX ECU-SHARED-DATA imported via "Selected Parts only" are stored in the ODX ECU-SHARED-DATA list on document level, separate from libraries.

Common Properties

[LIB-D010.0 Library Authoring]: a library is an authoring feature, not relevant for a test system or code generation.

[LIB-R010 Library Definition]: a CANdela document contains a list of 0..n Libraries on document level, each with the following properties:

  • [LIB-R010-a] qualifier, name and description;
  • [LIB-R010-b] diagnostic classes and singleton diagnostic instances (as for Base and ECU variant)
  • [LIB-R010-c] DIDs (as for Base and ECU variant, [DID-R020])
  • [ATTR-R050-LIB] overriding attributes.
  • [REV-R050-LIB] revision history (if configured to be local to variants).
  • [LIB-R010-h] the libraries list shall have a defined persistent order in the document. As a default, it shall be provided to the user in this order.

[LIB-R012.1 Uniqueness]

  • [LIB-R012-a] the qualifier shall be unique in the library list.
    • [LIB-R012-aVar] a library and a variant can have the same qualifier.
  • [LIB-R012-b] the name shall be unique in the library list.
    • [LIB-R012-bVar] a library and a variant can have the same name.

Individual Properties

[LIB-R020.0 Property „locked“]: a library shall have the Boolean property is locked, modifiable in expert mode.

Semantics:

  • [LIB-R020-a] protects against modification of the contents (also: update, document upgrade [DOCUP-R040], import),
  • [LIB-R020-b] but not against modification of properties (name, qualifier…) or deletion.

[LIB-R022.0 Created in Template] whether a library has been created in a .cddt file can be deduced from the existing OID at qualified objects, there is no explicit property.

[LIB-R025.0]: a library does not have:

  • [LIB-R025-a] Identifying Features,
  • [LIB-R025-b] Identifying Patterns

[LIB-R026.0 Embedded External File]: a library shall have an optional embedded external file („ExtDoc“).

Semantics: if the library has been imported from an ODX ECU-SHARED-DATA (ESD), the ExtDoc contains that ESD [ODXI-R514], otherwise the ExtDoc is empty / not set. It may be used in an export to ODX [ODXE-R550]. No CANdela operations process the ExtDoc.

Note: before 8.5, such ESD was put into a ODX ECU-SHARED-DATA list on document level. After migration, this list still exists ([LIB-R200-b]). The GUI shall clarify [ESD-R050] that new imported ESDs are not shown in the list on document level, since they belong to the Library.

Note: the central ESD list is still needed e.g. for ESDs from DOPs and units [ODXI-540].

Libraries in Document Context

[DTCA-R020-reqLIB], [DTCA-R020-reqAsRefLIB] The required authorization of a DTC in DTC pool does not apply to Libraries, see operation [DI-R010-LibDtcReq].

[DIA-R020] The required authorization of a diagnostic instance in base variant does not apply to Libraries.

[DID-R012] The required authorization of a DID in base variant does not apply to Libraries.

[VSG-R050] Objects in a library can be associated with a Vehicle System Group.

[VSG-R200] A library is not relevant for the VSG „Availability for Variants“.

[LIB-R038.0]: the structure of diagnostic instances in a library is controlled by the DiagClassTemplates (like for diagnostic instances in an ECU variant).

[LIB-R040.0]: services in a library shall have state transitions (like in variants; cf. the state dependencies user interface [STUI-R200-LIB]).

[LIB-R042.0]: a library may contain DTC references into the DTC Pool.

[OBJP-R200-LIB] A library shall have a path: like qpath:/[LIBRARY]ES_WV81024; cf. its namespace [LIB-R012].

[LIB-R060.2 Document Order]: the CANdelaStudio data model shall handle objects in the order (cf. GUI [TREE-R010 Order]):

  • DTC Pool
  • (since 8.2) Global Fault Memory
  • (since 8.5) Libraries
  • base variant
  • variants.

[LIB-R070.0 Library Object Reference Semantics]: for an object referenced in a library (e.g. a DID), the semantics of the reference is…

  • like for a referenced diagnostic instance: the object exists at several locations, can be deleted at any of them, and disappears if deleted at the last location; pasting from one location does not effect in pasting the other location, too.
  • not like a data object reference to a data type: directed relationship; pasting the data object also pastes the data type if needed.

Base Library

[LIB-D080] Base Library = the first library (in document order) that has the attribute

  • qualifier: "IsBaseLibrary"
  • type: enum [ATTR-R020-enum]
  • enum ID == 1

[LIB-D080-First] If multiple libraries have the attribute set to 1,

  • the value 1 is ignored at all but the first such library.
  • Note: CANdelaStudio does not prevent you from setting the value to 1 at multiple libraries.

Tip: to find out which library in a list of libraries is the base library, use attribute overview on the "Libraries" tree node and inspect the values of the attribute with qualifier "IsBaseLibrary".

Attributes

[LIB-R080.0]: objects imported from ODX into a library shall contain special attributes that allow reconstruction of the position in ODX during ODX Export (like objects imported elsewhere).

[ATTR-R050-LIB] There shall be a separate default attribute list for libraries.

Operations

The CANdelaStudio data model shall support library operations as follows:

[LIB-R100.2 New Library]: create a Library. The properties shall be as follows: it shall…

  • [LIB-R100-10b] contain no diagnostic classes or diagnostic instances (cf. [LIB-R010-b])
  • [LIB-R100-10c] contain no DIDs (cf. [LIB-R010-c])
  • [LIB-R100-20] not be locked, cf. [LIB-R020]
  • [LIB-R100-22] get a unique OID, no TemplateOID (cf. [LIB-R022]).
  • [LIB-R100-26] contain no ExtDoc (cf. [LIB-R026])

Do not allow this…

  • [LIB-R100-n1] if uniqueness of qualifier and name would be violated (see [LIB-R012])

[LIB-R105.1 Delete Library]: delete a Library.

  • [LIB-R105-a] An object contained in the library that is also referenced outside the library (e.g. in a variant) shall still exist outside the Library.
  • [LIB-R105-b] If the object contained attributes indicating that the object originated from the library (see [LIB-R080]), then the attributes must be deleted. Note: this is presently done when you delete the ESD.
  • [LIB-R020-b] this shall even be allowed if the library is locked.

[LIB-R108.1 Move Library]: provide an operation to move multiple libraries in the persistent order [LIB-R010-h] one object to the front / to the back.

[LIB-R115.0]: do not provide copy/paste for a library as a whole. Motivation: use import instead; avoid complications due to transitive dependencies.

[LIB-R117.0]: provide copy/paste for objects in a library like for objects in a variant.

[LIB-R120.0 Lock/Unlock] (cf. [LIB-R020])

Do the same as when locking a variant (CDS-16124), i.e. write-protect data types, keep diagnostic instances referenced etc.

[LIB-R125.1 Library vs. „Reference Identical Diagnostic Instances and Job Container“] (menu Edit): include Libraries.

[LIB-R130.0]: do not provide „Reference as Base Variant“ for a Library.

[LIB-R135.0]: operations traversing a document shall follow the order of [LIB-R060].

Migration 8.5

[LIB-R200.0]: after loading an older document in CANdelaStudio 8.5, ...

  • [LIB-R200-a] no library exists.
  • [LIB-R200-b] ECU-SHARED-DATA of the older document is not changed.

[LIB-R210.1]: when saving to an older document, drop each Library.

  • [LIB-R210-a] Move its ECU-SHARED-DATA (if it exists) to the global list (note: there can be no conflicts).
  • (LIB-R210-b dropped)
  • [LIB-R210-c] Preserve the ODX attributes that depend on the ESD (note: objects that are referenced in a library and in a variant are not deleted in the variant).
  • [LIB-R210-d] drop the attribute definitions for libraries (cf. [ATTR-R050-LIB]).

Report

[LIBUI-R500.0 Report of Libraries]: if

  • the CANdela document contains libraries, and
  • the option [OPT-R520] is set,

then report shall write the libraries in an additional chapter "Libraries" between "Communication Parameter" and "Diagnostic Content" (like for a variant):

  • a level 2 chapter for each library (heading text: library name)
  • the library description (if any) as paragraphs
  • a "DIDs" level 3 sub-chapter
  • sub-chapters for the diagnostic classes, diagnostic instances, job containers and jobs.

[LIBUI-R510.0]: if the CANdela document does not contain a Library, the report shall completely suppress the „Libraries“ chapter.

[LIBUI-R520.0 Report Index]:

  • [LIBUI-R520-a.0]: diagnostic objects of a library shall be linked in the index (like diagnostic objects of variants).
  • [LIBUI-R520-b.0]: the libraries themselves shall be linked in the index with type "Library".

Example:

My Library
    Library 30

[LIBUI-R530.0 Library Compact Report]: if the option [OPT-R520] is set, then compact report shall include libraries [OPT-R520-Compact] in the "Diagnostic Content" chapter:

  • [LIBUI-R530-a.0] it shall use the fix string "In libraries/variant(s): " instead of "In variant(s): ".
  • [LIBUI-R530-b.0] it shall list all libraries in which the diagnostic object occurs comma separated, before the enumerated variants or "all variants".

Example:

In libraries/variant(s): LIB-140, LIB-43l54, all variants

Note: if a diagnostic object occurs in all variants, compact report shall use "all variants" (as before). It shall always enumerate the libraries individually (no "all libraries"), motivation: it is not an expected use-case to have a diagnostic object referenced in all libraries.
