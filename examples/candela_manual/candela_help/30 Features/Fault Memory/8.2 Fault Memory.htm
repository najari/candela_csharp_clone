8.2 Fault Memory

See also the introduction to Fault Memory, Fault Memory in UDS and Fault Memory in CANdela.

In v13, the 8.2 Fault Memory has been replaced by the AUTOSAR Fault Memory.

The 8.2 Fault Memory introduced a new way to describe

  • snapshot data and
  • extended data

in the CANdela data model.

Before CANdelaStudio 8.2: Service Context

Before CANdelaStudio 8.2, the CANdela data model described snapshot data and extended data only in the context of the services (in the diagnostic instances) where they are transported over the line. This typically includes multiplexers.

CANdelaStudio 8.2 .. 12: Just the Data

CANdelaStudio since 8.2 .. 12 still supported the description in the service context, but provided an alternative, "domain oriented" description: just the data, outside the services.

Notes:

  • All the data were only available in an ECU document if the new 8.2 data model had been enabled.
  • ODX Import did not support import into the new data model (former ODXI-R410).
  • A test system like CANoe still needs the data structure in a communication oriented way. CANdelaStudio 8.2 .. 12 defined "Communication View" for this purpose.

Snapshot Records in a CANdela Document (8.2 .. 12)

  • Snapshot Record came in two variations:
    • Specific Snapshot Record, identified by a number 0..0xFE (UDS: 0x00 = “legislated purposes”, in the request 0xFF = “all records”)
    • General Snapshot Record, had no number, just in case details were not known.
  • Snapshot Data came in different variations:
    • Common Snapshot Data: DIDs stored for all DTCs
    • Any Snapshot Data: allowed not only DIDs, but any kind of data (e.g. data objects, or references to DIDs including the DID Number). The objects were defined locally within the Any Snapshot Data.
    • DID Snapshot Data could contain only DIDs;
    • Semantics on the line (= for communication oriented clients): it is a “DID Reference” =
      • DID Number, size 2 byte
      • DID Data (contents of DID)
      • The order of the DIDs on the line was not defined
      • For consistent behavior, without loss of generality, CANdelaStudio always presented the DIDs in ascending order of DID numbers (as specified in UDS).
    • DTC Specific Snapshot Data
      • specified for a given CommonSnapshotData and an individual DTC in a diagnostic instance (not in DTC Pool).
    • Relation of Common Snapshot Data and DTC Specific Snapshot Data
      • For Any Snapshot Data and DID Snapshot Data , DTC specific SnapshotData is placed in the telegram behind the Common SnapshotData.

Extended Data Records in a CANdela Document (8.2 .. 12)

See also the introduction to Fault Memory.

“Extended Data Record” is part of the UDS service 0x19 0x06 and others. Such data is also called “Statistical Data”. It provides data for the point in time of the request (not of an event in the past).

Details:

  • the Extended Data Record Number: in the range 0..0xFD (UDS reserves 0xFE = “all OBD records” and 0xFF = “all records” in the request)
  • «is stored for DTC» specified in a diagnostic instance whether the ECU stores data of an ExtendedDataRecord for a given DTC. If not, a test system shall not provide the EDRN in the 0x19 0x06 request.
