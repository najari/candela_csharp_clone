UDS Services for the Main Protocol Use-Cases

For the protocol use-cases listed in the Fault Memory chapter, UDS provides the following services:

Use-case UDS Primary UDS User-Defined
Read DTCs 19 02 19 17
Read Snapshot Data 19 04 19 18
Read Extended Data 19 06 19 19
Clear Diagnostic Information 14 14

Read DTCs

  • a test system requests the list of DTCs
  • in the response, the header of the list contains the number of DTCs
  • each list entry includes...
    • a 2 or 3 byte DTC (error code)
    • a 1-byte status value about the DTC status (maturity - confirmed or not...)

Snapshot Record in UDS

“Snapshot Records” are part of the UDS service 0x19 0x04.

They are also called “Environment Data” or “Freeze Frames”.

UDS 2020:

The typical usage of DTC Snapshots is to store data upon detection of a system malfunction.

In UDS, the service 0x19 0x04 has the following structure:

UDS Service 19 04

The main data returned in the positive response:

  • DTCSnapshotRecordNumber
  • DTCSnapshotRecordNumberOfIdentifiers
  • DTCSnapshotRecord
  • dataIdentifier
  • snapshotData

See also Fault Memory in CANdela.

Extended Data Record in UDS

“Extended Data Records” are part of the UDS service 0x19 0x06. Such data is also called “Statistical Data”.

UDS 2020:

DTCExtendedData consists of extended status information associated with a DTC.

DTCExtendedData contains DTC parameter values, which have been identified at the time of the request. A typical use of DTCExtendedData is to store dynamic data associated with the DTC...

Examples: DTC occurrence counter, DTC aging counter, time of last occurrence.

See also Fault Memory in CANdela.

Uses of DTC Status in UDS Services

[FMUDS-D560] The UDS Fault Memory Services contain different types of DTC Status information (8 bits each):

  • DTCStatusMask:
    • used in a Request
    • bit-wise filter for StatusOfDTC values stored in the ECU
    • the default value (CDS-10222, 6.0) specifies a proposal to the user of a test system.
  • DTCStatusAvailabilityMask:
    • used in a Positive Response
    • describes which DTC Status bits the ECU implementations supports
    • at runtime, will be the same for all services
  • StatusOfDTC:
    • used in a Positive Response
    • describes the status of a concrete DTC
    • at runtime, will vary depending on DTC information stored in Fault Memory

For hints about DTC Status in CANdela, see [DTCSB-D560].

UDS DTC Status Byte

[FMUDS-D050] UDS DTC Status Byte

  • bit 0 testFailed: result of the most recent test of the monitor
    • OBD relevant
  • bit 1 testFailedThisOperationCycle: whether testFailed occurred in the current Operation Cycle.
    • set when result is FAILED,
    • reset on start of the Operation Cycle.
    • OBD relevant
  • bit 2 pendingDTC: whether testFailed occurred in the current or last completed Operation Cycle
    • set when result is FAILED,
    • reset on start of the Operation Cycle, if test passed in the current Operation Cycle
    • OBD relevant
  • bit 3 confirmedDTC: malfunction detected enough times so that DTC shall be stored in memory
    • set when result is FAILED and the failure counter exceeds a defined threshold
    • reset by aging at start of an Operation Cycle, or by clearing or overwriting the DTC
    • OBD relevant
  • bit 4 testNotCompletedSinceLastClear: test never completed since last call to ClearDiagnosticInformation
    • set when result is FAILED or PASSED
    • reset by clearing the DTC
    • OBD relevant
  • bit 5 testFailedSinceLastClear: test failed since last call to ClearDiagnosticInformation
    • set when result is FAILED
    • reset by aging, or by clearing or overwriting the DTC
    • OBD: optional for OEM
  • bit 6 testNotCompletedThisOperationCycle: test never completed during the current Operation Cycle
    • set when result is FAILED or PASSED
    • reset by starting an Operation Cycle, or by clearing the DTC
    • OBD relevant
  • bit 7 warningIndicatorRequested: status of warning Indicators associated with the DTC
    • set when result is FAILED, and the criteria for at least one warning Indicator are fulfilled (AUTOSAR [SWS_Dem_00566])
    • reset when the criteria for the Indicators are not fulfilled, or by clearing the DTC
    • OBD: optional for OEM
  • Value after DTC clear: 0x50 (bits 4 and 6 set; cf. AUTOSAR [SWS_Dem_00385]).
