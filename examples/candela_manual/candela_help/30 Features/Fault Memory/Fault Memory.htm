Fault Memory

Overview

Fault Memory in System Context

The following are important parts of a Fault Memory implementation:

Monitor watches for failure of a hardware component, communication, algorithm
Event reported if the monitor detects a failure, see the Events Introduction
Event Status tracked by the ECU, see DTC Status Bits
Snapshot Data data from the time of the failure (below),
also called "environment data", "freeze frames",
e.g. the engine speed at the time of failure occurrence
Diagnostic Protocol used to report a failure from the ECU to a test system;
e.g. UDS
DTC represents the event in the diagnostic protocol, see Diagnostic Trouble Code (DTC)
Statistical Data data from the time of the request (below),
also called "Extended Data",
e.g. the number of DTC occurrences

UDS

  • Unified Diagnostic Services (UDS; ISO 14229)
  • defines services for Fault Memory: DTCs, Snapshot Data, Extended Data (see below)

WWH-OBD

  • World Wide Harmonized On-Board-Diagnostic (ISO 27145)
  • Adds some UDS services.
  • Reserves Snapshot Record 0x00 (Freeze Frame)

OBD on UDS

  • SAE J1979-2
  • Classic OBD-II to be replaced by UDS services
  • New subfunctions for Fault Memory access
  • Reserves Snapshot Record 0x00 and 0xF0 (Freeze Frame)
  • Schedule (potential, as of 2019-09):
    • 2023: CARB allows OBDonUDS for new vehicles?
    • 2026: CARB requires OBDonUDS for new vehicles?
  • Used in AUTOSAR Adaptive

[FM-D050] CANdelaStudio v13 (of 2020-02) is prepared for OBD on UDS:

  • OBD on UDS has not yet been published!
    • Therefore, AUTOSAR does not yet support the new Snapshot Record Number 0xF0.
  • As of 2020-02, CANdelaStudio v13 can represent OBD on UDS Snapshot Records,
  • but it does not support creating such Snapshot Records.
  • Further support to come when OBD on UDS has been published and details have been clarified.

DTCs

  • an ECU reacts to an event and stores information about it
  • on request by a test system, the ECU sends a list of DTCs.

See also Read DTCs (UDS), and Fault Memory in CANdela.

Snapshot Data (Environment Data, Snapshot Record)

Snapshot Data Occurrences

  • Each time an error (event) occurs, the ECU may store environment data.
  • A test system requests the environment data for a given DTC.
  • Each DTC may have a specific structure of environment data, but multiple DTCs may as well use the same structure.

When using the same DTC for different error symptoms, typically the environment data describes which symptom occurred.

See also Snapshot Record in UDS, Fault Memory in CANdela and the AUTOSAR Fault Memory Introduction.

Extended Data (DTC Statistics, Extended Data Record)

  • a test system may request statistical data for a given DTC
  • the ECU responds with the status of the DTC and a list of statistical data collected for the DTC
  • the information is from the point in time of the request (not of an event in the past).

See also Extended Data Record in UDS, Fault Memory in CANdela and the AUTOSAR Fault Memory Introduction.

User-Defined Fault Memory

An ECU implementation may support multiple Fault Memories:

Fault Memory Typical Use
Primary OEM, after-market
User-defined (0..n) OEM, supplier, development
Mirror Preserve data if primary gets erased.

See also User-Defined Fault Memory in UDS, and User-Defined Fault Memory in CANdela.

OBDII Fault Memory

[FM-D100] OBDII Fault Memory

  • a diagnostic instance with Class Type [DCLT-R200] FaultMemory
  • containing a Combined Proxy Component with semantics "OBD-DTC" [PC-R050-obddtc].

Clear Diagnostic Information

  • resets data stored in the ECU Fault Memory: DTCs, Snapshot Data, Extended Data.
