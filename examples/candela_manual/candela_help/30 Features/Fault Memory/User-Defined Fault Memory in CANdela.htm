User-Defined Fault Memory

Definition

[UDFM-D100] a Protocol Service for User-Defined Fault Memory starts with one of the three constant byte sequences 19 17 / 19 18 / 19 19.

[UDFM-D105] a DTC List for User-Defined Fault Memory only is a DTC List used only in Protocol Services for User-Defined Fault Memory [UDFM-D100], no other Protocol Services.

Note: it is possible to mix Protocol Services for User-Defined Fault Memory and other ones in one diagnostic class template.

Recommended Modelling

[UDFM-D110] Recommended Modelling for User Defined Fault Memory - allows to create additional user defined fault memories in a variant:

  • The template contains the ProtocolServices 19 17, 19 18 and 19 19.
    • Example: the Vector UDS Template
  • For the DTC, they contain a 3 byte Proxy Component with semantics dtc.
  • For the memory selection byte, they contain a Variable Value Component.
  • A separate diagnostic class template uses these Protocol Services.
    • Note: CANdelaStudio does not provide a separate class type [DCLT-R200] for user-defined fault memory, use "Fault Memory".
  • The text table at the Used Protocol Service allows to restrict the set of user-defined fault memories (UDS: 0..255).
  • Due to the use of a variable value component, ...
    • the Diagnostic Class Template is not a singleton [DCLT-R150-multiple],
    • therefore in a document, a new user-defined fault memory can be created as a new diagnostic instance.
  • Note: the AUTOSAR DEM Specification supports only IDs in the range 0x10 to 0xFF (chapter 4.1 "Limitations" as of AUTOSAR 4.3.1)

Alternative Modelling

[UDFM-D120] This modelling provides one single user defined fault memory in a variant. If differs from the modelling recommended above as follows:

  • For the memory selection byte, the Protocol Services contain a Constant Component;
    • the constant value is arbitrary.
  • Therefore, ...
    • the Diagnostic Class Template is a singleton [DCLT-R150-singleton].

Data Model

[UDFM-R200] A DTC List for User-Defined Fault Memory only [UDFM-D105] takes the DTC Columns from the Error Code Table of the respective byte size [ECT-R001].

  • If the Protocol Service has been correctly modelled, this is the "Primary/User-Defined/WWH-OBD" Error Code Table [ECT-R001-3].

[DTCP-R002-UDFM] A DTC List for User-Defined Fault Memory only [UDFM-D105] must not contain references to the DTC Pool.

Migration

[UDFM-R400]

  • When loading a pre 9.0 file in CANdelaStudio 9.0,
  • in a DTC List for User-Defined Fault Memory only [UDFM-D105],
  • if a DTC is referenced from the DTC Pool [DTC-D020],
  • then CANdelaStudio replaces the reference with a copy [DTCOP-R050].

Use in the Vector Toolchain

AUTOSAR

Up to R18 (2017-03), the embedded software generator did not support User Defined Fault Memory.

CANdesc code generation

  • CANdesc creates dispatch table entries for service 0x19 and the respective subfunction (0x17 / 0x18 / 0x19)
  • With Vector DEM:
    • Vector DEM supports only one SecondaryMemory.
    • CANdesc checks the Memory Selection parameter, accepts only the first one defined in the CDD and rejects all other requests.
    • CANdesc does not forward the Memory Selection to the Vector DEM but just asks for "SecondaryMemory".
  • Not with Vector DEM:
    • the application is responsible for accessing the appropriate User Defined Fault Memory,
    • CANdesc passes all request parameters to the application.
