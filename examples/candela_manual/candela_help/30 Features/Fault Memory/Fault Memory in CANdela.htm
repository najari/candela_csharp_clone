Types of Fault Memory in CANdela

CANdelaStudio supports two types of fault memory (in the template: Error Code Tables):

  • Primary ("normal") fault memory
    • with DTC lengths of possibly 16, 24, and 32 bits;
    • this includes User-Defined Fault-Memory in CANdela
  • OBDII fault memory
    • with a DTC length of 16 bits.

Each type of fault memory...

  • typically occurs once per variant
  • defines the DTC length
  • defines the DTC Columns

Snapshot / Extended Data Variations in CANdela

[FM-D200] CANdelaStudio provides two ways to model Snapshot Data and Extended Data:

Generic

[FM-D200-Generic] generic, within the service structure (the "old" way):

  • data is defined in the diagnostic instance only,
  • typically using a multiplexer;
  • the service is shown like "19 04 zz yy";
  • user interface: see the snapshot data list;
  • See the chapter Snapshot Records (Generic).

Generic Snapshot Data: Multiplexer in Fault Memory

AUTOSAR

[FM-D200-AUTOSAR] as separate data structure, conforming with AUTOSAR, see the AUTOSAR Fault Memory Introduction):

  • the service is shown like "19 04 zz sr".

Specialized Data Structure for AUTOSAR - opened by button with "Camera" icon

Special DTC Representations in CANdela

CANdelaStudio supports...

  • Failure Type Bytes or
  • Failure Mode Identifiers

... for a DTC of 24 bits or greater.

Responses with an Optional DTC: 0x19 0x0A .. 0x0F

[FM-D570] The UDS Services "($19) ReadDtcInformation - Report*DTC", like "($19) ReadDtcInformation - Read supported DTC", all have an optional DTC in the Positive Response.

To describe the optional DTC, you can describe them as follows (note: uu, ww, tt are placeholders, the concrete letter may vary):

Component Description
0x59 ServiceID
e.g. 0x0A Subfunction
uu DTCAvailabilityMask
*[...] EndOfServiceIteration, number of iterations 0..1 to specify the contents being optional
ww DTC
tt StatusOfDTC
