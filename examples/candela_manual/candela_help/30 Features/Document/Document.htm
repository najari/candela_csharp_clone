Document

The following describes properties on the CANdela document level.

See also the document-level settings for Requirements

Template Info

In a template: empty.

[DOC-R100] In a document: stores info about the Document Template on which the CANdela document is based:

  • name
  • qualifier
  • label (version number of the last revision entry [DOC-R130])
  • [DOC-R100-SaveNumber] save number of the document's template (taken from the save number [DOC-R200])

Note: CANdelaStudio shows the info in File|Properties page Document Info.

Manufacturer Related Properties: Diagnostics Based on vs. Manufacturer

Manufacturer Related Properties

Diagnostics Based on

[DOC-R110] This is the key information about any process specific handling of the Document Template or document, like hard-coded behavior in a data export or in a test system.

Shown in menu File | Properties | "Document Info" | "Diagnostics based on".

The property is fix, you cannot change it in CANdelaStudio (not even in Expert View).

It either contains

  • [DOC-R110-Enum] a value from a predefined set of "manufacturers" (this was the initial way in CANdelaStudio), or
  • [DOC-R110-String] the special predefined value "Standard" followed by a free-text specification (since 6.5; it avoids incompatible extension of the predefined set)
    • Versions older than 5.0 will not load such files, see [VCMP-R051].

Note:

  • before CANdelaStudio 5.5 added the modifiable string property "manufacturer" described in the following chapter, the "Diagnostics Based on" property was called "manufacturer".
  • it is sometimes still referenced as "the manufacturer of the document".

Manufacturer (5.5, CDS-7869)

[DOC-R120] The "Manufacturer" property is a free text...

Manufacturer Free Text

... that will be printed on the title page of a report:

Manufacturer Free Text in Report

It has no effect on the processing of the diagnostic description in the toolchain (as opposed to "Diagnostics Based on" above).

Do not confuse with Diagnostics Based on (above)!

Shown in menu File | Properties | "Document Info" | Manufacturer.

Version

[DOC-R130] The version of a document or template is the version number [REV-R010-Version] of the last revision entry.

CANdelaStudio uses the document version in these contexts:

  • template info in a document [DOC-R100] (above)
  • saving a document using a base directory with a version subdirectory [OPT-R155]

See also Version Numbering of the Vector UDS Template [VER-R300].

Protocol Standard (CDS-2371 3.0)

[DOC-R140] A CANdela document contains information about the Protocol Standard:

  • "J1939"
  • "KWP"
  • "UDS"
  • "OBD2" (CDS-5233 5.0)

shown in File | Properties | Document Info [DOCUI-R120].

Save Number

[DOC-R200 Save Number] A document has an unsigned integer value that CANdelaStudio...

  • increments with each Save operation
  • shows in File|Properties|Document Info
  • remembers separately [DOC-R100-SaveNumber] for the document template
  • handles in the "convert document to template" operation [DOC-R710]

Variant Coding Keys

[DOC-VCK] The document has a top-level VCK Mode setting:

  • none
  • numeric ("native" mode, display as unsigned int)
  • StringsDC (DCS supplement key string)

See Variant Coding Keys.

Languages

[DOC-R300 Languages] A document stores...

  • a set of languages.
  • including some country-specific variations of languages, like “English (USA)”, “English (Great Britain)”.

You may edit the set of languages in the File|Properties dialog, page Document Info.

See the Multi-Language Feature.

[DOC-R300-Uptodate] A document is up-to-date for a language if all multi-language strings are up-to-date [ML-R110-Uptodate] for that language.

[DOC-R300-First] The first language in the document must always be up-to-date.

  • When you open a document for editing a non-first language, then on saving, CANdelaStudio puts that language first.

DTC Format

[DOC-R400] The DTC numbers in a CANdela document can be specified using one of the following conventions:

  • [DOC-R400-14229] ISO 14229-1 / HEX
    • The 3 byte DTC number is used as a single value.
    • Display of DTCs: hexadecimal or with prefixes "PCBU", controlled by the global editor setting in Ribbon Tab File | Options | Display.
  • [DOC-R400-J2012] ISO 15031-6 / SAE J2012
    • The 3 byte DTC number is structured in 16 + 8 bits,
    • Byte 0 (LSB) is the Failure Type Byte (FTB).
    • [DTC-R500] A text table data type with 8 bits size specifies the FTB values.
    • Display of DTCs: decimal (defined by the SAE standard)
  • [DOC-R400-J1939] SAE J1939-73 (Version 4)
    • The 3 byte DTC number is structured in 19 + 5 bits,
    • bits 0..4 are the Failure Mode Identifier (FMI).
    • [DTC-R510] A text table data type with 5 bits size specifies the FMI values .
    • Display of DTCs: decimal (defined by the SAE standard)

The DTC Format can be edited in the template via File | Properties | Display of DTCs [DOCUI-R610].

The DTC list applies the DTC Format, see "Editing Failure Type Byte" [DTCUI-R030] and "Editing Failure Mode Identifier" [DTCUI-R040].

AUTOSAR (CDS-71296 v13)

AUTOSAR Type

[DOC-R530] The ECU attribute [ASR-D001_AUTOSAR_Type] controls the DEXT export of the document:

  • [DOC-R530-None] "None": the document does not support AUTOSAR
    • You can the DEXT export on such a document, see [DEXT-R130-Warn].
  • [DOC-R530-Classic] "Classic"
  • [DOC-R530-Adaptive] "Adaptive"
  • You specify the AUTOSAR Type in Ribbon Tab File | Properties | Document Info [DOCUI-R500].

AUTOSAR Version

  • [DOC-R540] The ECU attribute [ASR-D001_AUTOSAR_Version] specifies the AUTOSAR version.
  • The value is free text.
  • You specify the AUTOSAR Version in Ribbon Tab File | Properties | Document Info [DOCUI-R500].

See the list of available AUTOSAR versions [DEXT-D050].

Supports PVCDI

[DOC-R420] Boolean property "Supports PVCDI" specifies whether the document is relevant for PREEvision CANdela Data Interchange (PVCDI).

  • If set, this triggers the PREEvision UUID Repair [SV-R110] on saving.
