Bit Ordering (CDS-3035 4.0)

[DOC-R500] A document has an option "Display most Significant Bit on Top".

The options controls whether bit fields are shown...

  • [DOC-R500-LsbFirst] with bit 0 on top (default), or
  • [DOC-R500-MsbFirst] with highest bit on top.

User Interface

The option is edited in the File | Properties Property Page "Options for Bit Fields".

Availability for Manufacturers

[DOC-R500-Manufacturers] The second option is available only for selected values of the "Diagnostics Based on" (formerly "manufacturers") property:

Diagnostics Based on - in File | Properties Dialog

Effect

See the Bitfield Display Variations.

For "highest bit on top", in bit fields, CANdelaStudio always creates implicit gaps [BF-R200].

Example

For bit 0 on top (as always in CANdelaStudio < 4.0)

  • Data model (in this order, note there is no explicit position):
    • Data object1 (1 bit)
    • Data object2 (7 bit)
  • Display in the user interface, export in RTF:
    • 0 - Data object1 (1 bit)
    • 1 - Data object2 (7 bit)
  • Export in ODX, MDX and any other exports:
    • BitPos 0, Data object1 (1 bit)
    • BitPos 1, Data object2 (7 bit)

For highest bit on top (starting with CANdelaStudio 4.0, available for some manufacturers only):

  • Data model (in this order, note there is no explicit position):
    • Data object1 (1 bit)
    • Data object2 (7 bit)
  • Display in the user interface, export in RTF:
    • 7 - Data object1 (1 bit)
    • 6 - Data object2 (7 bit)
  • Export in ODX, MDX is (objects in this order, note the explicit position):
    • BitPos 7, Data object1 (1 bit)
    • BitPos 6, Data object2 (7 bit)
  • Export in any other exports is (same as with bit 0 on top, i.e. ignores the flag):
    • BitPos 0, Data object1 (1 bit)
    • BitPos 1, Data object2 (7 bit)

Restrictions

Copy/paste between documents with different settings for this option transfers bit objects in the order displayed (it does not preserve the order on the line).

Operations

[DOC-R505] (Expert view) If you change the option [DOC-R500], for each bit field CANdelaStudio...

  1. adds a trailing reserved data object, if the data objects in the bit field do not cover the entire capacity,
  2. then reverses the data object list in the bit field.

The reserved data object is needed so that the position of the existing data objects is preserved.

[DOC-R510] (Expert view)

  • A document provides the operation to Reverse Bit Fields
    • context menu on ECU in tree [TREE-R020].
  • This reverses all bitfield elements in the document.
  • Motivation: if for some reason the order of bitfield elements on the line is wrong.
