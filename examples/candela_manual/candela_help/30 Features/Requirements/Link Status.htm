Link Status

CANdelaStudio visualizes the relationship of requirements and diagnostic objects: whether properties are equal, whether the one contains child elements missing in the other etc.

  • [RQOP-R100-Linking]: the linking information in the CANdelaStudio requirements list shall be based upon the selected library or variant [RQ-R093].

General assumptions

The link status displayed in CANdelaStudio is based on the following assumptions:

  • each typed requirement is intended to be linked, otherwise it is “not ok” (“dangling”)
  • a not-linked diagnostic object is “ok” (does not lead to “conflict”)
  • a diagnostic object that was linked but the requirement does no more exist is “not ok” (“dangling”)
  • headings (which are not typed) and diagnostic classes (which are not linked) reflect the link status of their content
  • if a diagnostic instance uses a DID [DID-D001] via a DID Data Reference, the data objects within the DID shall be considered children of the diagnostic instance

Requirement Link Status Definition

  • Rq := requirement;
  • DO := diagnostic object;
  • PropertyNotEqual := Rq is referenced by DO and properties are not equal
  • PropertyEqual := Rq is referenced by DO and properties are equal
  • ChildConflict := any child has status “conflict”;
  • ChildNotPresent := Rq is referenced by DO which has any child that references Rq2 which is not a child of Rq;
  • ForeignChild := any child is referenced by DO and the parent of DO does not reference Rq.
  • [RQ-R200-DIDDiagInstConflict] DIDDiagInstConflict := at a Data DiagInst Requirement, the special DiagClass value of [RQ-R030-DID] does not correspond with the DID use [RQ-R180-DiagClassDIDs]

  • (definition of “equal” see [RQ-R180])

Diagnostic Object Link Status Definition

  • PropertyNotEqual := DO references an existing Rq and properties are not equal
  • PropertyEqual := DO references an existing Rq and properties are equal
  • ChildConflict := any child has status “conflict”;
  • ForeignChild := any child references an existing Rq and the parent of Rq can be linked (e.g. not a heading) and is not referenced by DO.
  • DIDDiagInstConflict as in previous chapter

  • (definition of “equal” see [RQ-R180])

    Type Status Condition
    DiagClass none no descendant relevant for requirements, else
    conflict any child has status “conflict”, else
    dangling any child has status “dangling”, else
    equal
    DiagInst none DO does not have a reference to an Rq
    AND (all children have status “none” OR all children have status “equal”)
    conflict PropertyNotEqual OR
    DIDDiagInstConflict (i.e. linked Rq has the special qualifier, OR not linked but uses a DID linked with a Rq that has the special qualifier), OR
    ChildConflict(*) OR
    ForeignChild, else
    dangling any child has status “dangling”, OR
    DO references non-existing Rq, else
    equal
    DID
    (CDS-39520 8.5 SP2)    		 none DO does not have a reference to an Rq
    AND (all children have status “none” OR all children have status “equal”)
    conflict PropertyNotEqual OR
    DIDDiagInstConflict (i.e. linked Rq does not have the special qualifier, OR used by a DiagInst linked with a Rq that has the special qualifier), OR
    ChildConflict(*) OR
    ForeignChild, else
    dangling any child has status “dangling”, OR
    DO references non-existing Rq, else
    equal
    DataObject,
    DTC,    		 none DO does not have a reference to an Rq
    VSG
    conflict PropertyNotEqual else
    dangling DO does have a reference, but to a non-existing Rq, else
    equal

(*) If DO does not have a reference, and all children have status „none“ or „equal“, then ChildConflict occurs, since DO would have to reference the other parent.
