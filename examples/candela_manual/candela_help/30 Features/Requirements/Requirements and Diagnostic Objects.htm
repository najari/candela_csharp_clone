Requirements and Diagnostic Objects

In this chapter, everything said about requirements includes headings.

Current Library or Variant

See Requirements Settings [RQ-R093].

Object Association

[RQ-R100.7 Associate Diagnostic Object with Requirement]:

[RQ-R100-a] a diagnostic object can be associated with a requirement:

  • [RQ-R100-DI] diagnostic instance,
  • [RQ-R100-DID] DID (CDS-39520 8.5 SP2),
  • [RQ-R100-DO] data object,
  • [RQ-R100-DTC] DTC,
  • [RQ-R100-VSG] Vehicle system group (8.0 CDS-26227).

The following diagnostic objects in particular cannot be associated with a requirement:

  • [RQ-R100-Bitfield] bit-field,
  • [RQ-R100-ReservedObject] reserved object,
  • [RQ-R100-Service] service.

There is no restriction of the types, any type of diagnostic object listed above can be associated with any type of requirement (but see [RQ-R105]: the GUI for mapping shall allow mapping only “compatible” types).

[RQ-R100-b] the association is n:1, i.e.

  • one diagnostic object can be associated with at most one requirement (due to R110 below);
  • one requirement can be associated with 0..n diagnostic objects (in a library or variant, cf. [RQ-R093]).

[RQ-R100-c] The association does not imply automatic property updates; e.g. a change of the data object name does not automatically change the requirement name.

[RQ-R100-e] if a diagnostic object is associated with a requirement, and the user deletes the requirement (e.g. by an import), the diagnostic object shall still contain the info that it was associated with the given requirements ID (“dangling reference”). If the user imports or creates a requirement with the same ID, the data object shall be automatically associated with that requirement.

Note: if e.g. a diagnostic instance is referenced in multiple variants, the requirements ID is present and shown identically in all of them. This is a feature of the CANdela data model.

Property Association

Different Constellations of Property Association

[RQ-R100-Prop Association with Attribute] (CDC-36449 8.5 SP2) A user defined property...

  • that exists for all requirement types (see [RQ-R040-ForType])
  • is associated with a CANdela attribute at an object
  • if the name of the requirement property matches the qualifier or name (in this order) of the attribute,
  • and the attribute has usage "user" [ATTR-R070].
  • See the operations:
    • Requirement and Diagnostic Object Equality: [RQ-R180-UserDefinedAll]
    • Creating diagnostic objects: [RQ-R560-Attribute]
    • Creating requirements: [RQ-R580-AttributeToUserDefined]

[RQ-R100-DTCProp Association with DTC Column] A user defined property...

  • that exists “for requirements type” DTC only (see [RQ-R040-ForType])
  • is associated with the additional column of a CANdela DTC
  • if the name of the requirement property matches the qualifier or name (in this order) of the additional DTC column of CANdela.
  • See the operations:
    • Requirement and Diagnostic Object Equality: [RQ-R180-UserDefinedDTC]
    • Creating diagnostic objects: [RQ-R560-DTCUserDefined]
    • Creating requirements: [RQ-R580-DTC]
  • Note: a property “for requirements type” DTC is not associated with a CANdela attribute.

Example:

Requirements property “Setzbedingung” will be associated with a DTC Column having...

  • name “Setzbedingung” (matching)
  • qualifier “SetCondition”;

Requirements property “ResetCondition” will be associated with a DTC Column having...

  • name “Rücksetzbedingung”,
  • qualifier “ResetCondition” (matching).

R100 g) (deleted) (before 8.0 CDS-26227, a Vehicle System Group was associated by name/qualifier).

Compatible Types

[RQ-R105.3 Compatible Types] the following table shows which types of headings/requirements are “compatible” with which diagnostic objects.

Note: the set of diagnostic objects available here is defined in [RQ-R100] above.

Requirement type Diagnostic object
Data DiagInst Requirement Diagnostic instance, DID
FaultMemory DiagInst Requirement Diagnostic instance
Routine DiagInst Requirement Diagnostic instance, DID
IOControl DiagInst Requirement Diagnostic instance, DID
DTC Requirement DTC
Data Requirement Data object
VehicleSystemGroup Requirement Vehicle System Group

[RQ-R107 Assignable]

  • a heading or a text requirement and any diagnostic object are “assignable”.
  • Any other type of requirement and a diagnostic object are “assignable” if they are compatible (see [RQ-R105]).

Import Pool

[RQ-R110.2 Requirements and Import Pool]

The association of a data object with a requirement [RQ-R100] shall use the same requirements ID as the synchronization in import pool [IP-R030]. In other words, ...

  • for a data object associated with a requirement,
  • if the import pool contains a data object with the ID of that requirement,
  • then the sync feature of the import pool shall synchronize that data object.

Requirements ID Storage

[RQ-R115.0 Requirements ID Storage]

  • the requirements ID is stored in a special string attribute typically called "RequirementsId".
  • Note: the qualifier may vary, it is specified in the value of the ECU string attribute SynchronizationAttribute.
  • CANdelaStudio automatically creates these special attributes as soon as you generate a diagnostic object from a requirement, or link the diagnostic object with a requirement.

Note: Requirements in DiVa

  • Requirements links used in DiVa are stored at services.
  • They have nothing in common with the requirements described here.
  • There is no automatic migration, no check, no conflict between these kinds of requirements.
  • The requirements links used in DiVa are stored in a string attribute, also described in the Vector Application Note AN-IDG-1-011 "How to use DOORS with CANdelaStudio" (CDS-3940).

R120.0: (specific for attribute based implementation of [RQ-R100-e] if the attribute required to store the association of [RQ-R100]) does not exist when needed, the attribute shall be created at the respective diagnostic objects (see chapter 2.1 of AN-IDG-1-014, use name/qualifier “RequirementsID”, at data object only).

R150.1: a) for an association of [RQ-R100], when the user modifies any property (except the association property) of the diagnostic object or of the requirement (except the ID), the association is not affected.

b) If the user manually changes the ID of a requirement, CANdelaStudio prompts whether it should automatically update all string references of this ID at diagnostic objects.
