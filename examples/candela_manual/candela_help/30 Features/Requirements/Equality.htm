Requirement and Diagnostic Object Equality

[RQ-R180.0 Equality] A requirement and a linked diagnostic object that are “compatible” [RQ-R105] are considered “equal” under the conditions described in the following tables.

Details:

  • [RQ-R180-Case] all string comparisons are case-sensitive

  • [RQ-R180-MultiLang] equality to the name (or description) of a CANdela object is true if at least one of the up-to-date names (or descriptions) in any language matches.

    Motivation: equality shall be independent of the language in which the user opens the CANdela document.

    Drawback: if the name matches only in a language not shown, the user has no idea why they are equal. Additional info about equality details would be helpful (cf. compare view for diagnostic objects).

Equality of Property Values

Rule for Empty Values

The objective of the "equality" definition is to show whether a requirement is fulfilled by a diagnostic object.

[RQ-R180-RuleEmptyValues] Therefore, the definition of "equality" is not symmetric: an empty requirement property...

  • means: "there is no restriction to the property at the diagnostic object"
  • does not mean: "the property at the diagnostic object must be empty".

In programming terms: the empty requirement property is interpreted as null, not as the empty string.

Constellations for Mandatory Properties

The following constellations may occur:

Diagnostic Object Property Requirements Property Equal
a (empty) yes (*)
a a yes
a b no

(*) CANdelaStudio before 8.5 SP3 (CDS-41840) treated this constellation as "not equal", e.g.

  • a DTC column filled by default with "t.b.d." and
  • an empty DTC Requirements property.

[RQ-R180-PropertyEquality] Summary: a mandatory diagnostic object property and a requirement property are equal if...

  • the requirements property is empty,
  • or equals the diagnostic object property.

Constellations for Optional Properties

If the diagnostic object property itself is optional (e.g. a DTC column may exist or not), the following additional constellations occur:

Diagnostic Object Property Requirements Property Equal
(does not exist) (empty) yes
(does not exist) a yes (*)

(*) Note: the last constellation is handled as "equal" since...

  • the requirement "a" is indeed not fulfilled,
  • but the template takes precedence:
    • it does not contain the DTC column,
    • therefore the update of diagnostic objects cannot make the values equal,
    • therefore the requirement is treated as "equal".

[RQ-R180-OptionalPropertyEquality] Summary: an optional diagnostic object and a requirement property are equal if...

  • the diagnostic object property (e.g. DTC column, attribute) does not exist,
  • or the requirements property is empty,
  • or equals the diagnostic object property.

Note:

  • DTC columns and attributes are template properties,
  • you cannot create them in Standard View,
  • therefore CANdelaStudio does not allow to create them from requirements (not even in Expert View, to save the implementation effort).
