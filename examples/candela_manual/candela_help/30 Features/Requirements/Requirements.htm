Requirements

CANdelaStudio Requirements View

You can use CANdelaStudio to describe requirements for an ECU.

Use-Cases

Within CANdelaStudio

  • write requirements in CANdelaStudio,
  • automatically create diagnostic objects from the requirements.

Use a Requirements Tool

  • write requirements in a requirements tool, like Rational DOORS, or in Vector PREEvision,
  • import the requirements into CANdelaStudio,
  • create diagnostic objects from the requirements.

Take-over from a CANdela Document

  • based on an existing CANdela document, create requirements from the diagnostic objects,
  • export the requirements for use in a third-party requirements tool.

Overview

Requirements Pool

In a CANdela document, diagnostic objects describe the diagnostic behaviour of an ECU (e.g. ECU, variant, service, data object, data type).

Besides the diagnostic objects, a CANdela document contains a requirements pool. The requirements can be...

  • imported/exported
  • synchronized with diagnostic objects

File-Based Data Exchange

In order to exchange requirements with other tools like Rational DOORS or Vector PREEvision, CANdelaStudio...

  • does not support a direct tool coupling,
  • but a file-based data exchange: CANdelaStudio supports a .csv based file format to import and export requirements.

In Rational DOORS, requirement properties can be configured freely (with flexibility like in Microsoft Excel). Therefore you cannot export a .csv file from DOORS and import it directly in CANdelaStudio - CANdelaStudio does not know your DOORS conventions. A converter is required to adapt the data

  • from the conventions used in DOORS
  • to the exchange format supported by CANdelaStudio.

This can be done in both directions.

Vector is ready to assist you on a service project basis in converting between the CANdelaStudio exchange format and the specific formats of a third-party tool.

Types of Requirements

Screenshot Showing different Types of Requirements

CANdelaStudio supports different types of requirements:

  • Text: plain text requirement, no properties related with diagnostic objects, therefore ignored when CANdelaStudio creates diagnostic objects from requirements.
  • Heading: to define a nested structure of requirements (like chapters in a text editor)
  • "Typed" requirements, from which CANdelaStudio can automatically create diagnostic objects (and vice versa). A typed requirement...
    • represents a specific type of diagnostic object,
    • and has additional properties like bit length or display format.

Typed requirements cover

  • DIDs,
  • diagnostic instances,
  • DTCs,
  • data objects,

but not services and data types.
