CANdelaStudio CSV Requirements Exchange Format

Purpose

This document describes the exchange format for requirements to be imported into / exported from CANdelaStudio.

It is based on the CANdela requirements feature.

Tip: for an example .csv file, create some requirements in CANdelaStudio and export them.

Requirements Exchange Format

Lexical Structure

[RQ-R600]: the .csv file shall be compatible with MS Excel 2010:

  • Rows are separated by line-breaks,
  • Cells are separated by semicolon “;”.
    • Empty cells at the end of a row can be omitted
      • (i.e. no need to enumerate semicolons for all empty cells).
    • CANdelaStudio Import accepts multiple separator characters on reading a .csv file (CDS-26093 7.5 SP2):
      • , = Comma
      • | = Pipe symbol (Ascii 124)
      • ; = Semicolon
      • TAB = TAB character (Ascii 9)
      • CANdelaStudio Import analyzes the first row to detect the separator character.
    • Microsoft Excel writes different separators, depending on the region settings of Windows, e.g.
      • , = Comma (US)
      • ; = Semicolon (German)
  • Within a cell, semicolon “;”, double-quote or line-break are preserved by...
    • enclosing the cell value with double-quotes, like "This is ""one"" cell"
    • doubling a double-quote within the cell-value.
    • Note: a cell with an enclosed line-break means there are multiple text lines for one .csv row!
  • Cell enclosing: it is ok (but not required) to enclose each cell by double-quotes,
    • even if it does not contain characters that must be preserved.

Syntactic Structure

[RQ-R610]: A heading / requirement corresponds with one row of the .csv file.

[RQ-R620]: A heading property / requirement property corresponds with one column of the .csv file.

  • Each row contains all columns.
  • If the property represented by a given row does not apply to the heading/requirement of a given column,
    • then the cell is empty.

[RQ-R630]: the order of rows corresponds with the order of the headings / requirements.

[RQ-R635]: the order of columns is free.

[RQ-R640]: the requirements hierarchy information is stored in an additional column called “Level”:

  • Top-level headings/requirements have level 1.
  • If heading/requirement A contains heading/requirement B,
    • then the level of B is: (level of A) + 1.

[RQ-R645]: initial rows with an empty first cell are considered comments that do not contain requirements.

  • Comments may be used to transport meta properties.
  • The recommended format is to put the property name into cell 2, the value into cell 3, like:
;SaveNo;47
;Date;2012-11-13

[RQ-R650]: The first non-comment row contains the names of the properties:

  • [RQ-R650-ID] “ID” of requirement.
  • [RQ-R650-NameDesc] “Name” and “Description” of heading/requirement
    • For a DTC requirement,
      • [RQ-R650-DTCName] “Name” corresponds with the DTC error text,
      • [RQ-R650-DTCDesc] “Description” with a DTC column with qualifier “Description” (if defined in the CANdela template).
  • [RQ-R650-TypeSpec] The property name [RQ-R030] for type specific requirement properties,
    • e.g. “BitLength” or “Code”
  • [RQ-R650-Level] “Level” of heading/requirement [RQ-R640]
  • [RQ-R650-User] The property name of a user-defined property [RQ-R040].
    • [RQ-R650-DTC] If the property is specific to DTC requirements,
    • its name is prefixed by “DTC.”,
    • like “DTC.Set Condition”
    • This does not apply to the DTC “Code” which is a type specific requirement property known to CANdelaStudio.
  • [RQ-R650-Type] “Type” representing the element type [RQ-R012],
    • with blanks and the suffix “Requirement” omitted, as follows:
Element Type Type in File
Heading Heading
Data DiagInst Requirement DataDiagInst
FaultMemory DiagInst Requirement FaultMemoryDiagInst
Routine DiagInst Requirement RoutineDiagInst
IOControl DiagInst Requirement IOControlDiagInst
Data Requirement Data
DTC Requirement DTC
VehicleSystemGroup Requirement VehicleSystemGroup
Text Requirement Text

[RQ-R660]: An optional “Type” restriction to “integer” is represented by a “{int}” suffix of the respective cell in the first row.

  • This is the default (= may be omitted) for the columns of “Level” and “BitLength”.

[RQ-R665]: Integer values (even DTC Code) are represented in decimal format, like "269".

  • On reading a .csv file, CANdelaStudio also accepts numbers in hexadecimal format, like "0x113".

[RQ-R670]: Values of the “Services” column get mapped to...

  • CANdela service qualifiers and
    • Services shall be separated by a comma, like “Read,Write”.
  • optionally primitives
    • Primitives shall be written behind the service qualifier as
      • “RQ” (= request),
      • “PR” (= positive response)
      • separated by a blank,
      • like “Read PR,Write RQ”.
  • Note: this is the representation in the .csv file, not necessarily the representation in CANdelaStudio.

[RQ-R680]: Values of the “VehicleSystemGroups” column contain a comma separated list of...

  • either the Name or the ID of a VehicleSystemGroup Requirement,
  • or the qualifier or name of a Vehicle System Group in the CANdela document.

Note: this even allows for comma in a Name or ID of a VehicleSystemGroup and is not assumed to lead to ambiguities in practical situations.

Restrictions

  • A Name shall fulfill the rules for names in CANdela.
  • A Name shall not contain a line-break.
  • Integer values must obey the description in R665 above.
  • Properties used by CANdelaStudio to update diagnostic objects (e.g. Services, DiagClass, DisplayFormat, Semantics) shall not contain line-breaks. Exception: the Description is free-text and may contain line-breaks.
  • User defined properties [RQ-R040] may have any contents; it is up to the customer specific process to define restrictions for these values.
