Requirements Data Model

Text only Requirements and Requirements for Diagnostic Objects

The CANdela requirements data structure supports...

  • text only requirements
  • requirements that represent diagnostic objects

Text only requirements may be linked with diagnostic objects manually, but are not used in the Update Diagnostic Objects operation.

Requirements that represent diagnostic objects may also be linked with diagnostic objects manually. But additionally, the "update" operations create diagnostic objects for them automatically, and vice versa.

Variants

  • [RQ-R010-Variant] The set of requirements stored in a CANdela document shall be independent of variants.

  • Operations are based on the Current Library or Variant for Requirements [RQ-R093].

Element Types

[RQ-R012 Requirements Element Types]

The requirements data structure consists of the following element types:

Element Types with General and Specific Properties

Element Type Description

a diagnostic instance referencing a DID containing data objects, or
a DID containing data objects (CDS-39520 8.5 SP2).
FaultMemory DiagInst Requirement Represents a Fault Memory diagnostic instance for DTCs
Routine DiagInst Requirement Represents a Routine diagnostic instance for DTCs
IOControl DiagInst Requirement Represents an IO Control diagnostic instance
Data Requirement Represents a data object
DTC Requirement Represents a DTC in Fault Memory
VehicleSystemGroup Requirement Represents a Vehicle System Group

Notes:

  • A heading can occur only on top-level or contained oin another heading, not in a requirement. In other words, headings define the top-level structure, and requirements are filled into the headings (or on top-level directly). The contents of e.g. a diagnostic instance requirement cannot be structured by headings.

  • A heading behaves as a container for other headings and data (like a heading in the structure view e.g. of MS Word), not as a terminal element with heading text only (like a heading e.g. in the layout view of MS Word or in HTML). It is a “chapter”, not a mere “title”.

Properties Specific for Requirement Types

[RQ-R030.4 Specific Properties] there are different types of requirements, with specific properties (in addition to those of [RQ-R020]). Requirement types not listed here have only the general properties of [RQ-R020] and the user-defined properties of [RQ-R040] below.

User-Defined Properties

[RQ-R040.1 User-Defined Properties]: each requirement can have user-defined properties in addition to the properties specified in [RQ-R020]/[RQ-R030].

User-Defined Properties

  • [RQ-R040-Scope] The properties are not specific to a single requirement, but all requirements have the same set of properties (exception for DTCs see the table row "for requirement type").

  • [RQ-R040-Unique] A property is identified by its name.
    • this means the name must be unique, independent of "for requirement type"
    • i.e. you cannot have have both a general property "Condition" and a also property "Condition" for requirement type "DTC".
    What Description
    Property name [RQ-R040-Length] No length restriction.
    [RQ-R040-Charset] No character set restriction.
    [RQ-R040-NonEmpty] Must not be empty.
    [RQ-R040-Level] The property name “Level” is reserved for .csv data exchange.
    [RQ-R040-DTC] The property name prefix “DTC.” is reserved for .csv data exchange.
    [RQ-R040-Predefined] The property name cannot be one of the specific property names shown in [RQ-R020]/[RQ-R030].

    Note: a TAB or line-break does not make sense in a property name, but is not excluded by this specification (for now).

    Note: other than for the specific properties [RQ-R030], CANdelaStudio uses the name of the user-defined properties both in the user interface and in .csv data exchange, and the name may contain any characters.
    Property value [RQ-R040-ValueString] The value of the property at each requirement is a string.
    [RQ-R040-ValueEmpty] The string may be empty.
    [RQ-R040-ValueLength] The value has o length restriction, except as specified by the property type.
    [RQ-R040-ValueCharset] The value has no character set restriction, except as specified by the property type.
    Property type [RQ-R040-Type] Optional boolean restriction for all values of the given property (not specific to a single requirement, similar to CANdela attributes), to contain an unsigned integer number as a string.
    [RQ-R040-TypeDefault] Default is to allow any string value.
    for requirement type [RQ-R040-ForType] Optionally restricts the property to exist at DTC Requirements.
    [RQ-R040-ForTypeDefault] Default is to exist at all types of requirements.

R042.0: the set of user-defined properties of [RQ-R040] can be changed in standard mode:

  • add
  • change the name or type
  • delete a user-defined property.

R044.0: changes of the property type discard all existing values that do not fit the new type (after user confirmation).

[RQ-R070] all string values have only one language (not shown in translation view). There are no TextIDs. There are no OIDs.

[CMP-R400-Rq] R080.0 The compare feature does not cover requirements.

[DOCUP-R310] R085.1: in document upgrade, the requirements pool of the original document shall be identically in the resulting document (i.e. the requirements pool of the template shall be dropped).

[RQ-R090.0 ID Creation]: new requirements shall get a unique ID value. The new ID string shall get a prefix specified in the settings (see below).
