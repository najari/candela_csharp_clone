Snapshot Records Overview

Protocol Service

For v13 AUTOSAR Fault Memory, a Proxy Component has additional semantics for Snapshot Records:

  • [PC-R050-sr] Snapshot Records
  • [PC-R050-sd] Snapshot Data

Note: sr/sd are relevant for the following UDS Protocol Services:

  • 19 03 reportDTCSnapshotIdentification
  • 19 04 reportDTCSnapshotRecordByDTCNumber
  • 19 05 reportDTCStoredDataByDataRecordNumber
  • 19 18 reportUserDefMemoryDTCSnapshotRecordByDTCNumber

Note: not relevant are:

  • 19 42 reportWWHOBDDTCByMaskRecord
    • 19 42 FunctionalGroupIdentifier DTCStatusMask DTCSeverityMask
    • 59 42 FunctionalGroupIdentifier DTCStatusAvailabilityMask DTCSeverityAvailabilityMask DTCFormatIdentifier *[DTCSeverity DTC StatusOfDTC]
  • 19 55 reportWWHOBDDTCWithPermanentStatus
    • 19 55 FunctionalGroupIdentifier
    • 59 55 FunctionalGroupIdentifier DTCStatusAvailabilityMask DTCFormatIdentifier *[DTC StatusOfDTC]

Diagnostic Class Template

  • [CPC-R108] Proxy components with the same semantics, one of sr, sd, edr, ed, must be combined.
  • [PC-R050-sdMux] At most one of (sd proxy component, Multiplexer component) can be used in a Primitive.

Diagnostic Instance

CANdelaStudio holds the following properties locally to a diagnostic instance.

  • Therefore they can be referenced between multiple variants.
  • If you want to modify of the following properties within one variant only, you must first replace the reference of the diagnostic instance by a copy [DIOP-R040].

Snapshot Record Numeration Type

[SR-D050] In AUTOSAR, a Fault Memory has the property DemTypeOfFreezeFrameRecordNumeration with the values Calculated and Configured.

CANdelaStudio 13 supports this information as part of the Diagnostic Instance for AUTOSAR Fault Memory.

[DI-R310] A Fault Memory Diagnostic Instance that has a Snapshot Records List (see [SR-R030]) has a Snapshot Numeration Type.

Values:

  • Configured, see [DI-R310-Configured] below
  • Calculated, see [DI-R310-Calculated] below

Scope: the Snapshot Numeration Type...

  • [DI-R310-UDS] ... affects UDS Snapshot Records [SR-D130-UDS],
  • [DI-R310-OBDonUDS] does not affect OBD on UDS Snapshot Records [SR-D130-OBDonUDS].
    • Note: for WWH-OBD, see [SR-R130-OBDonUDS]
  • Typically, the OEM pre-defines the Snapshot Numeration Type.
    • Switching the Numeration Type is not a typical use-case for a CANdela document!

Notes:

  • You may modify this property in the Diagnostic Instance property dialog [DIUI-R350].
    • Modification depends on [DIA-R040] Primary properties modifiable, see [DIA-R040-NumerationType].
  • The description of Snapshot Numeration Type for Snapshot Records in the generic Multiplexer based modelling [FM-D200-Generic] is different:
    • using a special attribute see [SR-R023]
    • in DEXT export: [DEXT-R340]

Snapshot Numeration Type "Configured"

[DI-R310-Configured]

  • you can freely define Snapshot Record Numbers [SR-R120], gaps are allowed
  • uses the “checkbox feature” [SR-R300]
  • the number of Snapshot Records is only limited by the valid Snapshot Record Numbers
  • the numbering represents chronological order.
  • A Snapshot Record has a Storage Trigger property, see [SR-R150].
  • A Snapshot Record has an Update property, see [SR-R160].
  • In practice, the possible combinations of trigger and update property values limit the number of Snapshot Records.

Example for Numeration Type "Configured": Snapshot Records to Store for DTC

DTC First Occurred (0x10) Most Recent Occurred (0x20)
DTC A x
DTC B x x
DTC C x
  • First Occurred (0x10): Storage Trigger "Test Failed", Update = No
  • Last Occurred (0x20): Storage Trigger "Test Failed", Update = Yes

Snapshot Numeration Type "Calculated"

[DI-R310-Calculated]

  • UDS Snapshot Records [SR-D130-UDS] are defined only implicitly,
    • i.e. there is no Snapshot Record qualifier, name etc.
    • Especially, there is no Storage Trigger [SR-R150] and Updated [SR-R160] information.
      • If described, these properties will not be transported via DEXT.
  • For each DTC, you specify the maximum number of Snapshot Records Stored [DTC-R310]
  • Each DTC can have a different number of Snapshot Records stored (DemMaxNumberFreezeFrameRecords).
  • At each DTC, the numbers of the stored Snapshot Records must be in the range 1..DemMaxNumberFreezeFrameRecords, without gaps.
  • The numbering represents chronological order.
  • Effect on the “checkbox feature” [SR-R300]:
    • for a given DTC, the “checkbox” is implicitly true for a range of SRNs 1..MaxSnapshotRecordNumber

Example for Numeration Type "Calculated": Snapshot Records to Store for DTC

DTC MaxSnapshotRecordNumber SR 0x01 SR 0x02
DTC A 1 x
DTC B 2 x x
DTC C 1 x

Snapshot Records List

Snapshot Records List

[SR-R030] A Fault Memory Diagnostic Instance contains a list of 0..n Snapshot Records.

  • [SR-R030-Card] Cardinality: Diagnostic Instance 1..1 -- 0..n Snapshot Records
  • [DI-R310-Calculated] if the Snapshot Numeration Type is "Calculated",
    • UDS Snapshot Records [SR-D130-UDS] are not explicitly defined
  • [SR-R030-Type] Snapshot Records are not allowed in a Diagnostic Instance of a type [DCLT-R200] other than "Fault Memory".
    • cf. modification of the class type [DCLTOP-R200-SR]
    • and the correction on loading [LOAD-R200-SR].
  • [SR-R030-OBDII] Snapshot Records are not allowed in an OBDII Fault Memory Diagnostic Instance.
    • cf. accordingly Snapshot Data [SR-R200-OBDII]
  • [SR-R030-Protocol] Snapshot Records are allowed without restriction by the Protocol Standard [DOCUI-R120]
  • [SR-R030-UserDef] Snapshot Records are allowed in a Fault Memory diagnostic instance of any Fault Memory Type: Primary or User Defined Memory [UDFM-D100].
  • User interface: see [SRUI-R200].
  • Note: modification depends on [DIA-R040] Primary properties modifiable, see [DIA-R040-SnapshotRecord].

[SR-R035] The Snapshot Records have no persistent sort order.

  • Assumption: the user interface by default [SRUI-R210] sorts them ascending by Snapshot Record Number.

[SR-R040] The list of Snapshot Records corresponds with the Combined Proxy Component with semantics sr [PC-R050-sr].

Snapshot Record Properties

This chapter describes all properties and relationships of a Snapshot Record.

[SR-R110] A Snapshot Record has Name, Qualifier, Description.

  • [SR-R110-Qualified] Name and Qualifier must be unique in the list [SR-R030].
  • Name and Qualifier are used in object paths [OBJP-R200].
  • User interface: see [SRUI-R2000].

Snapshot Record Number

[SR-R120] A Snapshot Record has a Snapshot Record Number (SRN)

  • [SR-R120-Range] Value range: 0x00..0xFE.
    • SRN 0x00 is used by OBD II.
    • SRN 0xFF is reserved as wildcard "all records" in the 19 04 Request.
  • [SR-R120-Unique] Snapshot Record Numbers shall be unique within the Snapshot Records list.
  • Note: [DI-R310-Calculated] if the Snapshot Numeration Type is "Calculated",
    • UDS Snapshot Records [SR-D130-UDS] are not explicitly defined.
  • [SR-D120-OBDonUDS] As of the draft at 2020-02,
    • OBD on UDS (SAE J1979-2; see the next chapter "Protocol") reserves SRNs 0x00 and 0xF0.
    • In CANdelaStudio 13, you can create Snapshot Records with Protocol "UDS" only.
    • SRN 0xF0 is available for an UDS Snapshot Record.
    • For the support of OBD on UDS in CANdelaStudio 13, see [FM-D050]
  • [SR-R120-DefaultDisplay] Default display of the Snapshot Record Number:
    • 2 hex characters
    • upper case
    • with leading zeroes
    • examples: "0x01", "0xF0"

Protocol

[SR-R130] A Snapshot Record has a property that defines the Protocol for which the Snapshot Record is used:

  • [SR-R130-UDS] UDS (ISO-14229), or
  • [SR-R130-OBDonUDS] OBD on UDS (SAE J1979-2).
    • Also used for WWH-OBD (ISO 27145).
      • Motivation: as of 2020, we expect more widespread use for OBD on UDS than for WWH-OBD.
      • Therefore, in the context of Snapshot Records, CANdelaStudio uses the term OBD on UDS only.
  • [SR-R130-Default] In CANdelaStudio 13, you can create Snapshot Records with Protocol "UDS" only.
  • UDS and OBD on UDS have different sets of Snapshot Data, see [SR-R200] below.

Common Terms

[SR-D130-UDS] UDS Snapshot Record

  • a Snapshot Record [SR-R030] with Protocol UDS [SR-R130-UDS];
  • for the Snapshot Record Number, see [SR-R130-Default].

[SR-D130-OBDonUDS] OBD on UDS Snapshot Record

  • a Snapshot Record [SR-R030] with Protocol OBD on UDS [SR-R130-OBDonUDS];
  • for the Snapshot Record Number, see [SR-R130-Default].

Storage Trigger

[SR-R150] A Snapshot Record has an enumeration property Storage Trigger which describes at which point in time the DEM module stores the Snapshot Record.

  • Used only if Numeration Type is “configured” [DI-R310-Configured]
  • It is used in combination with the Boolean property "Updated" [SR-R160] (below)
  • Default: testFailed
  • Order of values: alphabetically, as given by the AUTOSAR atp.EnumerationValue.
  • The set of Storage Triggers used may differ...
    • between OEMs and
    • between Fault Memory Diagnostic Instances.

Example:

Snapshot Record Storage Trigger Updated
First Occurred testFailed no
Most Recent Occurred testFailed yes
Confirmed confirmed no

Possible values:

(in parentheses: the AUTOSAR atp.EnumerationValue)

Value (AUTOSAR atp.EnumerationValue) Meaning AUTOSAR
confirmed (0) UDS status bit 3 “confirmedDTC” changes from 0 to 1 [SWS_Dem_00803]
fdcThreshold (1) the Fault Detection Counter (FDC; counter or time based) is reached by a positive increment; at most once per operation cycle [SWS_Dem_00799]
pending (2) UDS status bit 2 “pendingDTC” changes from 0 to 1 [SWS_Dem_00801]
testFailed (3) UDS status bit 0 “testFailed” changes from 0 to 1 [SWS_Dem_00800]
custom (4) custom condition, described in the "customTrigger" string property, see [SR-R155]

[SR-R155] A SnapshotRecord has a string property customTrigger

  • Used only if...
    • Numeration Type is “configured” [DI-R310-Configured],
    • Storage Trigger [SR-R150] has value "custom"
  • If Storage Trigger [SR-R150] has a value != "custom",
    • customTrigger must be empty;
    • otherwise, it must not be empty.
  • Example: "testFailedFirst"
  • Note:
    • for code generation, the string is used as a qualifier,
    • DEXT export will convert it accordingly.
    • In order to avoid potential loss of information, use Qualifier characters [QUAL-R120] only.

Updated

[SR-R160] A Snapshot Record has a Boolean property Updated, which describes whether already stored Snapshot Data can be updated (overwritten) [ECUC_Dem_00802].

  • Used only if Numeration Type is “configured” [DI-R310-Configured]
  • Values:
    • true = store/overwrite SD with each trigger (see “Storage Trigger” property [SR-R150] above), [SWS_Dem_00804]
    • false = store SD only if not yet stored, [SWS_Dem_00803]
  • [SR-R160-Default] Default: false.
  • Note: it makes sense to use each Storage Trigger/Update combination only once,
    • but CANdelaStudio does not enforce this restriction.

Attributes

  • [ATTR-R050-SR] A Snapshot Record has Default Attributes.

Snapshot Data

[SR-R200] A Fault Memory Diagnostic Instance contains two sets of Snapshot Data:

  • [SR-R200-UDS] UDS Snapshot Data
    • exists even if no UDS Snapshot Record [SR-R130-UDS] exists;
    • exists even if Snapshot Numeration Type is "Calculated" [DI-R310-Calculated].
  • [SR-R200-OBDonUDS] OBD on UDS Snapshot Data
    • exists iff. an OBD on UDS Snapshot Record [SR-R130-OBDonUDS] exists
  • [SR-R200-Type] These Snapshot Data are not allowed in a Diagnostic Instance of a type [DCLT-R200] other than "Fault Memory".
    • cf. modification of the class type [DCLTOP-R200-SR] and the correction on loading [LOAD-R200-SD].
  • [SR-R200-OBDII] Snapshot Data are not allowed in an OBDII Fault Memory Diagnostic Instance.
    • cf. accordingly Snapshot Records [SR-R030-OBDII]
  • [SR-R200-Protocol] Snapshot Data are allowed without restriction by the Protocol Standard [DOCUI-R120]
  • [SR-R200-UserDef] Snapshot Data are allowed in a Fault Memory diagnostic instance of any Fault Memory Type: Primary or User Defined Memory [UDFM-D100].
  • Snapshot Data are covered by object paths [OBJP-R200].
  • Note: modification depends on [DIA-R040] Primary properties modifiable, see [DIA-R040-SnapshotData].
  • User interface: see [SRUI-R500].

Snapshot Data Lists

Snapshot Data Object Diagram

[SR-R230] The two sets of Snapshot Data:

  • UDS Snapshot Data [SR-R200-UDS] and
  • OBD on UDS Snapshot Data [SR-R200-OBDonUDS]

... each consist of the following lists of DIDs ("Cases"):

  • [SR-R230-Common]: Common Snapshot Data
    • these DIDs are stored for all DTCs
    • the list can be empty
    • Use-case for Common Snapshot Data:
      • OEM spec requires some DIDs to be stored for all DTCs,
      • no exceptions allowed.
    • User interface: see [SRUI-R300].
  • [SR-D230-DTCSpecific] DTC Specific Snapshot Data:
    • [SR-R230-Default]: Default Snapshot Data
      • these DIDs are stored for DTCs for which no Overridden Snapshot Data list [SR-R230-Overridden] exists
      • the list can be empty
    • [SR-R230-Overridden]: Overridden Snapshot Data for one DTC (optional)
      • these DIDs are stored for the specific DTC only
      • the list can be empty
      • [SR-R230-OverriddenEmpty] if the Overridden Snapshot Data list at a DTC exists but is empty,
      • it overrides the Default Snapshot Data list at that DTC anyway:
      • for this DTC, the ECU stores Common Snapshot Data only.
    • Note: CANdelaStudio intentionally allows Overridden Snapshot Data for OBD on UDS [SR-R200-OBDonUDS].
    • User interface: see [SRUI-R700].
  • [SR-R230-OnlyCommon]
    • a DID number (Identifier [DID-R025]) used in Common Snapshot Data...
    • must not be used in Default Snapshot Data or Overridden Snapshot Data.

Snapshot Data Effective for a DTC

[SR-R235] For a given DTC, Snapshot Data DIDs are transported over the line in the following order:

  • first: Common Snapshot Data
    • in their defined order, see [SR-R240-Ordered] below.
  • second: Overridden Snapshot Data (if they exist), otherwise Default Snapshot Data
    • in their defined order, see [SR-R240-Ordered] below.

One Snapshot Data List

[SR-R240] Each List of [SR-R230], i.e. Common, Default, Overridden Snapshot Data, ...

  • [SR-R240-DIDs] contains references to DIDs [DID-R020]
  • [SR-R240-Unique] each DID number (Identifier [DID-R025]) must occur at most once in the list
  • [SR-R240-Ordered] the references are ordered (CDS-69421 v13)
    • Note: CANdelaStudio 13 does not allow to specify an arbitrary order of DIDs.
  • [SR-R240-Empty] the list may be empty
  • [SR-R240-Max] the number of DIDs in the list is not limited
  • [SR-R240-Length] there are no length restrictions from the Protocol Service for the cumulated data contained in all DIDs of the list
    • cf. the Proxy Component [PC-R050-sd]
  • [SR-D240-RuntimeOrder] For each DID referenced in one of the lists, over the line will be transported...
    • first: the 2 byte DID Identifier [DID-R025]
    • second: the DID Data [DID-R155]
  • [SR-D240-RuntimeNoDTC] When all referenced sd Proxy Components are in Primitives that do not contain a dtc/obdDtc component [PC-R050-sdNoDtc],
    • only the DIDs in Common and Default Snapshot Data apply
    • Overridden Snapshot Data must be empty.

[DID-D020] the Consistency Rule for References (“Onion Rule”) applies:

A DID must be referenced at least in those variants in which the diagnostic instance that uses it is referenced.

  • in other words: if a Fault Memory Diagnostic instance is referenced in variants V,
  • then its Snapshot Data can contain only DIDs that are referenced at least in these variants V

Snapshot Record to Store for DTC (Numeration Type "Configured")

(also called "Optional Snapshot Data Storage", "Checkbox Feature")

[SR-R300] The diagnostic instance specifies whether the ECU stores...

  • for a given DTC
  • the Snapshot Data
    • Common, Default and Overridden
  • of a given
    • OBD on UDS Snapshot Record [SR-D130-OBDonUDS],
    • UDS Snapshot Record [SR-D130-UDS] if Snapshot Numeration Type "Configured" [DI-R310-Configured].
  • [SR-R300-Default] Default: true.
    • See operation [SROP-R100].
  • Note: for Snapshot Numeration Type "Calculated" [DI-R310-Calculated], the information whether the ECU stores a given Snapshot Record is only implicitly defined by the number MaxSnapshotRecordNumber [DTC-R310], not by a "checkbox".
  • User interface: see [SRUI-R810].

Example: the ECU stores...

  • for DTC 0xC03113
  • the DIDs specified for 0x01 First Occurrence.

[ODXI-R300] Note: ODX Import (as of v13 Release) does not handle the "checkbox feature".

Note for Vector DEM implementation (as of 2019):

  • DEM stores Snapshot Data based on DTC...
  • in a static table
  • with identical size for each DTC
    • (the maximum size needed for any DTC).
  • Therefore the checkbox feature does not save space in ECU memory!

Number of Snapshot Records to Store for DTC (Numeration Type "Calculated")

[DTC-R310] For Snapshot Numeration Type "Calculated" [DI-R310-Calculated], ...

  • for each DTC, you specify the maximum number of Snapshot Records to store for this DTC ("MaxSnapshotRecordNumber")
    • [DTC-R310-Range] Valid Range: 0 <= MaxSnapshotRecordNumber <= 0xFE
      • cf. the valid range [SR-R120-Range] for the Snapshot Record Number.
    • The ECU stores unnamed Snapshot Records,
    • with Snapshot Record Numbers...
      • starting at 0x01,
      • without gaps,
      • up to at most MaxSnapshotRecordNumber.
  • AUTOSAR 4.4.0: maxNumberFreezeFrameRecords

Default Number of Calculated Snapshot Records (Numeration Type "Calculated")

[DI-R320] For Snapshot Numeration Type "Calculated" [DI-R310-Calculated], you specify...

  • at a diagnostic instance
  • the default value for the Number of Snapshot Records to Store for DTC [DTC-R310] above.
    • [DI-R320-Range] Valid Range: 0 <= MaxSnapshotRecordNumber <= 0xFE
    • same value as [DTC-R310-Range].
  • User interface: see [DIUI-R355].

Consistency Conditions

This chapter mainly references conditions specified directly in the data model chapters.

[SR-D500] Snapshot Record Consistency Conditions

[SR-D150] Storage Trigger/Update combinations need not be unique (makes sense but not required).

  • [PC-D050-sdsrUse] If a Primitive contains an sd proxy component, it must also contain an sr proxy component.
  • [PC-R050-srUnique] A Primitive may contain at most one sr proxy component.
  • [PC-R050-sdUnique] A Primitive may contain at most one sd proxy component.
  • [CPC-R108] Proxy components with the same semantics, one of sr, sd, edr, ed, must be combined.
  • [PC-R050-sdMux] A Primitive must not contain both an sd proxy component and a Multiplexer component.
  • see more in the Proxy Semantics chapter [PC-R100]
  • [SR-R200-OBDonUDS] OBD on UDS Snapshot Data exists iff. an OBD on UDS Snapshot Record [SR-D130-OBDonUDS] exists.
  • [DTC-R310-Range] Valid range of the maximum number of Snapshot Records per DTC
    • Violation emits an error, prevents from export (CDS-72175 U360 v13)
  • [DI-R320-Range] Valid range of the Default Number of Calculated Snapshot Records
    • Violation emits a warning, allows export (CDS-72175 U350 v13)
