Addressing Schemes

Overview

Addressing schemes are described in ISO 15765-2.

Addressing Scheme Description Advantage Disadvantage
Normal CAN ID contains source and target address.
2 CAN IDs for each ECU (send/receive).
E.g. OBD: 0x7DF..0x7EF.		 All data bytes can be used. Requires two CAN IDs per ECU.
Extended CAN ID contains source address,
first data (payload) byte contains target address.
1 CAN ID for all requests of all ECUs:
base address + source address.
1 CAN ID per ECU for the response.
E.g. 11-bit: 0xNss, Data: 0xtt....
E.g. 29-bit: 0xNnNnNnss, Data: 0xtt.... 		Requires fewer CAN IDs. Addressing consumes 1 data byte.
Normal Fixed
(29-bit only)		 CAN ID contains source and target address.
2 CAN IDs for each ECU (send/receive). E.g.
0x0CDAttss (physical addressing)
0x0CDBttss (functional addressing)

Note: the string "NormalFixed" works, "Normal Fixed Addressing" does not.		 All data bytes can be used. Requires two CAN IDs per ECU.
Mixed
(29-bit only)		 For ECUs in different subnets:
CAN ID contains the local addresses,
of which one is the gateway address;
first data byte contains the remote address (local address in the other subnet, also called Address Extension AE). E.g.
0x0CEAggss, Data: 0xtt... (physical addressing)
0x0CDAggss, Data: 0xtt... (functional addressing)		 Supports subnets. Requires two CAN IDs per ECU.
Addressing consumes 1 data byte.
Not directly supported in ODX (see below).

Legend:

  • gg: gateway address
  • ss: source address
  • tt: target address
  • Nn: any

Mixed Addressing

  • is often mistaken for Extended Addressing
    • both use an additional byte in the data (payload) of the CAN frame.
  • ... but the meaning of the byte and the uniqueness conditions for the CAN-ID parts are different.
  • ODX doesn’t know “mixed”
    • ODX data usually stores Mixed Addressing as Extended Addressing,
    • using the same extension byte for requests and responses.

Addressing Schemes in CANdela

A CANdela document typically contains several communication parameters that describe the Addressing Scheme of the ECU.

CANdelaStudio provides a wizard for creating a new interface.

  • the wizard lets you select the addressing scheme,
  • then creates the following communication parameters relevant for addressing:
Addressing Scheme CAN-ID Type Request CAN-ID Response CAN-ID Base Adress ECU Address Default Tester Address Address Extension Default Tx-Priority
Normal 11-Bit/29-Bit x x
Normal Fixed J1939 x x
Extended (Free) (*) 11-Bit/29-Bit x x x Tester Address
Extended (Base) (*) 11-Bit/29-Bit x x x
Mixed - 11 Bit 11-Bit x x x
Mixed - J1939 11-Bit/J1939 x x x x

(*) Authoring Choice for Extended Addressing

For Extended Addressing, CANdelaStudio provides an additional choice for authoring:

  • "Extended (Free)": creates communication parameters to specify...
    • the absolute CAN ID for request, and
    • the absolute CAN ID for response.
  • "Extended (Base)": creates communication parameters to specify...
    • one base address,
    • a relative offset for the request CAN ID, and
    • a relative offset for the response CAN ID.

Note: this is just a matter of authoring - for communication with the ECU, only the resulting CAN IDs are relevant.
