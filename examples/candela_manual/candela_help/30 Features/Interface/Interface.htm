Interface

See also the Interfaces User Interface.

The interfaces in a CANdela document define how a test system can communicate with the ECU, like "Diagnostic CAN" or "Comfort CAN". An ECU may support multiple interfaces.

Each interface contains Communication Parameters that specify communication details on different levels, e.g. "Bus type" or "P2 Client" time. While there is a set of standardized communication parameters, a document may also contain communication parameters for specific test systems.

Data Transport - Bus Level vs. Application Level

Interfaces enable the communication on bus level. On bus level, data packets have limited frame size:

Frame Size Bus Standard
8 bytes “Classic” CAN ISO 11898-1
64 bytes “FD” CAN ISO 11898-1
254 bytes FlexRay ISO 17458-2
4 GB DoIP ISO 13400-2

On the application level, UDS (ISO 14229-1:2013 “Unified Diagnostic Services” §6.4.1.7) describes 4 GB for transport during a single diagnostic service.

Interfaces in CANdela

Interfaces are defined in the CANdela template in the Expert View.

At least one interface must be activated (CDS-1891 2.0).

Deleting an interface means also that all communication parameters (i.e. default attributes belonging to the interface) are deleted.

Command “paste” only pastes the interface but not the communication parameters belonging to the interface.

Note: many existing CANdela documents already have a set of interfaces, which are evaluated by other Vector tools, for example for automatic code generation. These interfaces contain communication parameters that you cannot edit or delete. You should not delete interfaces containing such parameters from the template. Otherwise some of the tools might not work as expected.

Data Storage Based on Attributes

CANdelaStudio stores communication parameters and their interfaces using Default Attributes.
