Introduction: PREEvision CANdela Data Interchange

[PVCDI-D010] PREEvision CANdela Data Interchange is a Vector project started in 2019, directly related with the products PREEvision and CANdelaStudio.

The abbreviation PVCDI is short for "PREEvision CANdela Data Interchange".

To run it in CANdelaStudio, see Ribbon Tab "Data Exchange": Import [MENU-R1010] and Export [MENU-R1020].

Use-cases

  • Derive diagnostic objects from an existing EE model
    • A human inspects the EE model,
      • e.g. SWC connected with sensor and actor,
    • considers possible failure: plug breaks, sensor fails
      • fault conditions that must be treated in a garage
  • PREEvision puts focus on diagnostic info for code generation, not tester parameterization
    • e.g. session/security is not relevant (no effect on connectors, bits...)
    • its just a configuration for daVinci

Diagnostics in PREEvision

PREEvision Layers

Telegram Positions

  • PREEvision will not describe positions in a telegram
  • In PREEvision, the PDU is modelled only late
  • 80% of modelled entities will be DIDs
  • Protocol info is not in PREEvision
  • DID modelling
    • 1 DID in PREEvision
    • corresponding in CANdelaStudio: 1 diagnostic instance, one DID, one data object
  • Bit objects
    • in the current solution, a bit object of PREEvision (= a signal transported via the RTE)...
    • becomes a byte in CANdela

Note the difference:

  • signal
    • some function, maybe transported over a different network
  • diagnostic data object:
    • typically a consolidated information,
    • maybe from multiple signals,
    • the individual sources are no more relevant.

Relation with the "Describe Requirements" Feature

  • Requirements are...
    • neither a core feature of PREEvision
    • nor of CANdelaStudio.
  • PREEvision is not a tool to model general requirements
  • Solution in PREEvision before PVCDI:
    • describe requirements
    • action e.g. "Create a requirement for a DID"
    • includes requirements for Vehicle System Groups (VSG)
  • Solution in PREEvision with PVCDI:
    • use the new diagnostic entities, not requirements
    • action e.g. "Create a DID"
    • PREEvision still supports the export of requirements, including VSGs.

Data Completeness Rules

  • The data model consistency conditions of one product (CANdelaStudio, PREEvision) do not guarantee the conditions of the other product.
  • Each product is responsible to handle the conditions which its own data model imposes.
  • As a consequence, a product may reject data on import, requiring the user to make data consistent first.
