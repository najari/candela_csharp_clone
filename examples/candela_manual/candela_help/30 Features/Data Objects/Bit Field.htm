Bit Field

CANdelaStudio Bitfield

Introduction

Bit objects in a telegram must be stored in a bit field, not on top-level.

Exception: bit objects are allowed on top-level in the job parameter lists and in import pool.

The bit field is used only for wrapping bit objects.

Data Model

The bit field is like a struct in the C programming language: it contains in parallel

  • [BF-R010] a data object describing the entire range,
  • [BF-R020] a list of data objects describing the bit objects.

Entire Range

[BF-R100] The data object describing the entire range has a data type (as usual).

  • [BF-R100-Length] The data type defines the length of the bit field
  • [BF-R100-ByteOrder] ... and the byte order of the bit field, see below.
  • [BF-R100-Simple] Only simple data types are allowed (CDS-71213 v12).

List of Data Objects

[BF-R150] The list of data objects may contain:

  • [BF-R150-DataObject] normal data objects [DO-R100]
    • [BF-R150-Simple] The data objects may only reference simple data types (CDS-71213 v12).
  • [BF-R150-Reserved] reserved data objects [DO-R200]
  • [BF-R150-Bitfield] no other bit fields!

Implicit Gap

  • a bit field need not be filled completely
    • i.e. the sum of the lengths of the individual bit objects may be smaller than the length of the parallel "entire length" data object.
  • the bits not explicitly filled behave like implicit gaps
    • i.e. being filled with reserved data objects.
  • [BF-R200] With the document setting "Display most Significant Bit on Top" [DOC-R500-LsbFirst], CANdelaStudio always creates the implicit gaps.

Byte Order

Byte Order in Bitfield

If the data type assigned to the bit field has quantity atom, ...

  • its byte order defines the byte order used for the bit objects in the bit field.
  • This is the data type referenced by the data object [BF-R010] describing the entire range.
  • The byte order at the data type of the individual bit objects does not take effect!

If the data type has quantity field, ...

  • the byte order of the data object [BF-R010] is not relevant.
  • The optional attribute "ReverseBitFieldBytes" may be used instead, see reverse of bytes [POS-R110].

Display Variation

See the document option Bit Ordering.
