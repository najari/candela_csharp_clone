Attribute

Attributes are a generic data-driven way to extend the data model implemented in CANdelaStudio.

The user of expert view can define an additional property (“attribute”) for a given object type.

The user of standard view can then specify a value at each object of the given object type.

Attribute definitions are called "Default Attributes" in the CANdelaStudio user interface.

An attribute definition is not effective at subordinated objects (there is no implicit inheritance). If you define some attribute for the ECU, it is not effective for the variants.

[ATTR-D010] Note that CANdelaStudio describes Communication Parameters using attributes, therefore Communication Parameters have the same properties as attributes.

Use-Cases

  • describe object properties for code generation of software-components
  • describe object properties for a customer specific process

Properties

Attribute definitions are modifiable in Expert view only.

  • [ATTR-R010] Properties of a qualified object

    • [ATTR-R010-Name] Name,
    • [ATTR-R010-Qual] Qualifier,
    • [ATTR-R010-Desc] Description.

  • [ATTR-R020 Attribute Type] (cannot be modified after creation of the attribute):

    • [ATTR-R020-uns] unsigned
    • [ATTR-R020-sgn] signed
    • [ATTR-R020-flt] float
    • [ATTR-R020-text] text (multi-language), see also [ATTR-R025-length]
    • [ATTR-R020-string] string (single language)
      • see also [ATTR-R025-length]
      • see also [ATTR-R150] for an optional format restriction
    • [ATTR-R020-enum] enumeration, a list of ID + multi-language symbol. The list of enumeration symbols must not be empty.
      • [ATTR-R020-enumDel] Deleting an enum symbol used in overriding values resets these overriding values to the default value. (CDS-68862 v11).
      • [ATTR-R020-display] Display an enum symbol used in overriding values

  • [ATTR-R022] Display Format

    • For Attribute Type "unsigned" [ATTR-R020-uns] only
    • One of:
      • [ATTR-R022-dec] dec
      • [ATTR-R022-hex] hex
      • [ATTR-R022-bin] binary
    • Default: dec

  • [ATTR-R024] Display Order

    • For Attribute Type "enum" [ATTR-R020-enum] only
    • One of:
      • [ATTR-R024] Sort by ID
      • [ATTR-R024] Sort by Symbol
    • Default: Sort by ID

  • [ATTR-R100] category (see below)

  • [ATTR-R040] Default value: value effective at all objects of the object type, if the attribute has not been individually overridden at the object
    • [ATTR-R040-mod] Modifying the default value of an attribute does not reset the overriding values (CDS-68862 v11).
    • See also the format restriction [ATTR-R150-Value].

  • [ATTR-R060] Qualifier Uniqueness the qualifier has to be unique within the set of attribute definitions for one object type, without regard for the category. Example: there may be an attribute with Qualifier "X" at the Service as well as at the data object. If at the data object there is an attribute "X" in category A, then there cannot be an attribute "X" in category B.

  • [ATTR-R070] Usage specific semantics „usage“, defines whether CANdelaStudio treats the attribute in a special way:

    • "user": regular user-defined attribute
      • shown e.g. in the overview and property dialogs
    • "admin": protected attribute (hidden like "system")
    • "system": hidden attribute, used internally to for specific functionality of CANdelaStudio
      • information that Vector could hard-code in the data model, but keeps it as an attribute to save implementation effort.
      • E.g. communication parameters, requirementsID, IDs for data exchange...

  • [ATTR-R080 Authorization] authorization

    • [ATTR-R080-view] iff. true, the attribute is shown in Standard View (independent of isUser)
    • [ATTR-R080-modify] iff. true, the attribute value can be modified in Standard View (independent of isUser)
    • [ATTR-R080-report] iff. true, report lists the attribute value ("Export to Specification")

  • [ATTR-R090 VisibleInTableColumn] the flag “visible in separate table column” controls whether the attribute values are not only shown in the property dialog of the object, but also in a list view of the object.

    CANdelaStudio supports this property for:
    • [ATTR-R090-DiagInst] diagnostic instances in right side of diagnostic class [DIUI-R400];
    • [ATTR-R090-DTC] DTCs [DTCUI-R050-Attributes];
    • [ATTR-R090-DataObj] data objects [DOUI-R700];
    • [ATTR-R090-Job] job [JCUI-R200] (CDS-27480 8.0).
    The flag also applies to the report (CDS-68616 9.1), but...
    • only for the DTC list (where an attribute creates a new line);
    • not for data objects or jobs (where an attribute would create a further column which may break the page layout);
    • not for the separate Attributes chapter.

Attribute Value Length

[ATTR-R025-length]

  • The text control in the user interface limits the length of an edited text to 30000 characters.
  • For values set by an implementation (e.g. import), the limit depends upon your system. 4MB have be seen working. When you only enter the text control without typing, the long text is not shown correctly but preserved.

Attribute categories

[ATTR-R100] Each attribute belongs to an attribute category.

The user of the Expert View can create, change and delete attribute categories.

Attribute categories visible in Standard View form an unstructured set.

[ATTR-R110] Each attribute category (for attribute semantics, see above) has a semantics „usage“:

  • user
  • system (maintained by CANdelaStudio internally)

It controls whether the attribute category is displayed, e.g. in a drop-down list that filters attributes in property sheet. Besides that, there is no recursive effect on attributes - attributes have their own "view" right which should be consistent with that of the attribute category, but that is not enforced.

Convention: attribute categories of communication parameters have a qualifier prefix “COM”.

See also the migration of attribute category "UDS" [MIG85-R001].

Overriding Attributes at CANdela Objects

[ATTR-R140] As a default, the value from the attribute definition is effective at all CANdela objects of the given type (e.g. at all data types).

At an individual object, that default value may be optionally overridden by a specific value.

It makes even sense to specify an overriding value equal to the default value. It fixes the value at the object, so that it does not change even if the default value is changed at the attribute definition.

Note: the overriding value at at an individual object is called overwritten value in CANdelaStudio (for historical reasons).

See also the format restriction [ATTR-R150-Value].

[ATTR-D140] The Effective Value at a CANdela object is...

  • the Overridden Value [ATTR-R140], if the attribute is overridden at the object;
  • otherwise the Default Value [ATTR-R040].

  • since CANdelaStudio 1.3: restricts attributes of diagnostic instances for a subset of diagnostic classes;
  • since CANdelaStudio 6.0(CDS-10512): restricts attributes of for further objects besides diagnostic instances.

String Attribute Values: Format Restriction (7.0 CDS-13042)

[ATTR-R150] A string attribute [ATTR-R020-string] can have a format restriction for the allowed default value [ATTR-R040] and overriding values [ATTR-R140]:

  • the format restriction is defined by a string (not multi-language)
  • an empty string means "no restriction"
  • the character set of the string is not restricted
    • you should not add linefeed!
  • CANdelaStudio interprets the string as a regular expression (regex).
  • [ATTR-R150-Value] For a given string attribute, the default value and overriding values must match the format restriction.
    • A violation is treated as a non-fatal warning,
    • prevents from exports,

    • reported using the format description [ATTR-R155], like

        String attribute value '4.0.1b' does not match pattern '\d+\.\d+\.\d+'

[ATTR-R155] The string property Format Description provides a human readable description of the format restriction [ATTR-R150].

  • the description is a regular string (not multi-language).

Migration

[ATTR-R157] Migrations for the two above properties added in 7.0:

  • [ATTR-R157-Load] When loading a file with version < 7.0 (forward migration), ...
    • CANdelaStudio leaves the properties empty.
    • In particular, it does not modify existing default values or overriding values of an attribute.
  • [ATTR-R157-Save] When saving to a file with version < 7.0 (backward migration), ...
    • CANdelaStudio drops the properties.
