Migrations CANdelaStudio 13

AUTOSAR Fault Memory (CDS-71541 v13)

Snapshot Records Migration (AUTOSAR)

Controlling Migration

  • [MIG13-R130] If an older file contains Protocol Services and Fault Memory Template Settings for Snapshot Records structured conforming with AUTOSAR,
    • then CANdelaStudio as a default migrates them to use the specific Proxy Components [PC-R100] added in v13.
    • This holds for an older file with 8.2 Fault Memory as well as with the generic modelling.
  • [MIG13-R130-Code] Hard-coded: CANdelaStudio 13 does not migrate to the AUTOSAR Fault Memory for the manufacturer [DOC-R110] Daimler (CDS-72218 v13).
  • [MIG13-R130-No] You can suppress the default or hard-coded behavior (see previous items) by adding an attribute in the older file:
  • [MIGR13-D130] Snapshot Data Migration Attribute (CDS-72049)
    • ECU Attribute
    • Qualifier MigrateSnapshotDataToAUTOSARFaultMemory13`
    • Type "Unsigned"
    • Value 0: do not migrate Snapshot Data
    • All other values: do migrate (note: only if data structure fits AUTOSAR)
  • Further properties are recommended but not checked for migration:
    • Name "Migrate Snapshot Data to AUTOSAR Fault Memory 13"
    • Category "Editor"
    • Display Format: "dec"
    • Default value: 0
      • Motivation: the typical purpose of the attribute is to block migration.
    • Usage: "user"
    • Authorization: "view" and "modify", "export to specification" allowed
    • Visible in separate table column: false

8.2 Fault Memory: Unused Common Snapshot Data

[MIG13-R120] For 8.2 Fault Memory with...

  • Snapshot Data individual per DTC and per Snapshot Record,
  • and no DTCs defined, i.e. the DIDs in Common Snapshot Data are not effective anywhere,
  • migration does not represent the DIDs in v13 (it would put them into the DTC Specific Data).

Migration Details

[SR-R600] When loading a file...

  • containing the 8.2 Fault Memory
    • Snapshot Records defined on ECU level,
  • CANdelaStudio first migrates the file to the generic Fault Memory
    • using Mux in ProtocolService.
  • CommonSnapshotData goes into Default
    • if 8.2 DTC Specific is empty, that DTC goes Default
    • if 8.2 DTC Specific is not empty, that DTC gets the CommonSnapshotData as prefix, then DTC Specific DIDs
  • In a second step, that generic Fault Memory may qualify for the migration to AUTOSAR Fault Memory of v13.

[SR-R620] Migration of 8.2 AUTOSAR compatible to v13

Preconditions

  • 8.2 Template Settings
    • has Snapshot Records
    • identical for all Snapshot Records
    • may be individual per DTC
    • allow only DIDs
  • for Snapshot Records != 0, only one set of CommonSnapshotData
  • Snapshot Record 0 defined or not

Result

8.2 v13
Snapshot Records (= ECU level) inserted in each variant that has a 19 04 Fault Memory
diagnostic instance referencing do not change!
Data of SR 0 WWH-OBD part TBD how to transport via generic???
Data of SR != 0 UDS part
8.2 CommonSnapshotData AFM Common
8.2 DTC Specific AFM DTC Specific
the most often occurring 8.2 DTC Specific DID set TBD Optimization: put into AFM Default
8.2 unordered DID references AFM ordered list of DID references

Snapshot Records Migration (Generic)

  • [MIG13-R200] If an older file contains Protocol Services and Fault Memory Template Settings for Snapshot Records not conforming with AUTOSAR,
    • then CANdelaStudio migrates them to the generic Multiplexer based data structure.

Examples:

8.2 Fault Memory not AUTOSAR

  • Snapshot Data individual per Snapshot Record
  • allowing regular data objects, not only DIDs, in Snapshot Data

Result

Generic v13 AUTOSAR Fault Memory
Snapshot Records (if in data type) inserted in each variant that has a 19 04 Fault Memory (TBD multiple ProtocolServices?)
diagnostic instance referencing do not change!
Mux Default Common
n/a Mux Default
Mux DTC Specific Mux DTC Specific
8.2 unordered DID references ordered list of DID references

Extended Data Records Migration

  • [MIG13-R140] If an older file contains Protocol Services for Extended Data Records structured conforming with AUTOSAR, CANdelaStudio migrates them to use the specific Proxy Components [PC-R100] added in v13.
  • [MIG13-R140-Code] The implementation may exclude files based on their "manufacturer" [DOC-R110]
    • as of v13: none.
  • [MIG13-R140-No] You can suppress this migration by adding an attribute in the file:
  • [MIGR13-D140] Extended Data Migration Attribute (CDS-72049)
    • ECU Attribute
    • Qualifier MigrateExtendedDataToAUTOSARFaultMemory13`
    • The further details are as for Snapshot Records [MIG13-R130] above.

"Supports AUTOSAR" Migration (CDS-71296)

[MIG13-R300] If in an older file, ...

  • the attribute AUTOSAR Type [ASR-D001_AUTOSAR_Type] exists and is != none,
  • then migration ensures the AUTOSAR attributes as of v13 exist
    • Plan for the future: attributes of the respective version.

[MIG13-R310] If in an older file, ...

  • the attribute AUTOSAR Type [ASR-D001_AUTOSAR_Type] does not exist
  • but the diagnostic instance attribute "ASR SWC ServiceDependency Ref" [ASR-D001_ASR_SWC_DIServiceDependency_Ref] exists
    • (i.e. it indicates that the checkbox was checked in the old version)
  • then migration creates all attributes [ASR-D001] needed for AUTOSAR support, especially the new ones:
    • AUTOSAR Type [ASR-D001_AUTOSAR_Type] and
    • AUTOSAR Version [ASR-D001_AUTOSAR_Version].

PREEvision UUIDs (CDS-44285 v13)

[MIG13-R110] CANdelaStudio...

  • does not save UUIDs [PUID-R010] to documents older than v13;
    • initializes them when loading documents older than v13.
  • does not save the "Supports PVCDI" property to documents older than v13.
    • initializes it to false when loading documents older than v13.

Identifying Feature using Complex Data Type

[MIG13-R410] An Identifying Feature that uses a data object in a Packet of Iteration Data Type...

  • can be opened in a CANdelaStudio version older than v13 SP1, but...
  • the Identifying Feature will not be "usable",
    • the older CANdelaStudio version will mark it in red color.
