Check Identifier Uniqueness

Use-Cases

Checking the Entire ECU

  • Context: after loading a document, or running Tools | Check Document Consistency [MENU-R950].
  • CANdelaStudio checks all variants and logs conflicts

Adding A Diagnostic Instance

  • Context: creating a new diagnostic instance, or pasting a diagnostic instance into a variant.
  • CANdelaStudio checks the service prefixes of the new diagnostic instance within the affected variants

Adding A Service

  • Context: creating or activating [SVC-R300] a service in a diagnostic instance
  • CANdelaStudio checks the service prefixes of the added service within the affected variants

Identifier and Service Prefixes

Service Prefixes

Actually CANdelaStudio checks the service prefixes (also called "service signature") for uniqueness.

The Service Prefix includes the Identifier.

Scope

[CIU-R010] Service prefixes must be unique within a variant.

  • [CIU-R010-Exception1] Identical Request:
    • a request may be used in different diagnostic instances if it...
      • does not contain any Variable Value Component and
      • does not contain any Proxy Component that has non-“any” destiny
      • (it is considered identical)
  • [CIU-R010-Exception2] Local Scope:
    • Service prefixes may be non-unique within a diagnostic instance.
    • Assumption: within this narrow scope, the duplicate is by intention, e.g. for handling security access.

See the Examples below.

Rules for Checking Identifier Uniqueness (CDS-68583)

  • [CIU-R020] CANdelaStudio checks a diagnostic instance for uniqueness within the variant / library (as described above [CIU-R010]) if...
    • a diagnostic instance enum attribute with the qualifier described in [CIU-D010] does not exist at the diagnostic instance,
    • or the attribute has an effective (default or overriden) value != 0.
    • Consequence: to exclude a diagnostic instance from the check, set the attribute to 0.
    • You can do this conveniently in the context menu [DIUI-R200] of the diagnostic instance.
  • [CIU-R030] CANdelaStudio reports each skipped diagnostic instance with a status message.
  • [CIU-R040] CANdelaStudio reports each violation as an error that prevents from exports.
  • [CIU-R050] CANdelaStudio compares...
    • the constant value of a constant component
    • the value given in the diagnostic instance for a variable value
    • for e.g. proxy component, just the position, not the contents.
  • [CIU-R070] If a diagnostic instance has multiple services, CANdelaStudio checks the prefixes of each service, e.g. 22 70 40 (see also [CIU-R010] above)
  • [CIU-R080] CANdelaStudio also checks de-activated services [SVC-R300] (but not deleted ones).
  • [CIU-R090] if the Protocol Service has the Suppress Positive Response Message Indication Bit (SPRMIB) set, each service of a diagnostic instance actually provides two service prefixes, e.g.
    • 22 70 40 (not suppressing a response)
    • 22 F0 40 (suppressing a response)

Tip: CANdelaStudio shows the service abstracts in a tooltip [SVUI-R500].

Note: The SPRMIB option is available at each protocol service, so within one diagnostic instance, ...

  • there may be some services that support SPRMIB,
  • there may be other services that do not support the SPRMIB.

Customization via Attribute

[CIU-D010 Availability of the "Check Identifier for Uniqueness" Attribute]

The attribute is available iff. ...

  • a diagnostic instances attribute with qualifier "CheckIdentifierForUniqueness" exists
  • with type enum [ATTR-R020-enum]
  • and enum IDs 0 and 1
    • the enum symbol does not matter.

[CIU-D030 Creation Properties] When CANdelaStudio automatically creates [CIU-R200] the attribute, it assigns the following properties (these are not relevant for the check whether the attribute is available):

  • name:
    • "Check Identifier for Uniqueness"
    • in all languages (not only the up-to-date ones)
  • enum symbols:
    • 0 = "no"
    • 1 = "yes"
    • in all languages
  • category "Editor"
    • CANdelaStudio creates the category if it does not exist
    • in all languages
  • all authorization properties true:
    • visible
    • modifiable
    • export to specification
  • default value
    • ID 1
  • If...
    • the attribute qualifier exists with another type,
    • or enum IDs are missing,
    • then CANdelaStudio ensures the attribute has the required type and properties.

Note: you can modify the attribute value...

  • in the attributes list of a diagnostic instance, or
  • directly in the diagnostic instance context menu [DIUI-R200]

[CIU-D040 Check Required] The attribute specifies that a diagnostic instance must be checked iff. the effective ID value (default or overridden) is != 0.

[CIU-D050 Modification] In order to specify that a diagnostic instance...

  • ... shall not be checked, CANdelaStudio sets the value to enum ID 0;
  • ... shall be checked, CANdelaStudio sets the value to the first enum ID != 0.
  • In both cases, if the new value and the default value are both 0 or != 0, CANdelaStudio resets the overriding value.
  • If the attribute does not yet exist, then CANdelaStudio creates or modifies the attribute as described in [CIU-D030] (in each CANdelaStudio View).

[CIU-R200 Migration to 9.0] on loading a document < 9.0,

  • CANdelaStudio initially checks the document for consistency
    • (even if the "cached" property says the document is consistent).
  • If within a variant/library there are a diagnostic instances that have the same identifier,
    • and the attribute is not available [CIU-D010]
    • then CANdelaStudio creates or modifies the attribute as described in [CIU-D030].
  • Then for each diagnostic instance that has the same identifier as another diagnostic instance in the variant/library,
    • CANdelaStudio overrides the attribute with ID 0,
    • and reports these diagnostic instances as an info.

Note: by intention, this affects...

  • not only the second and later diagnostic instances of a given identifier,
  • but also the first one.
  • Motivation: CANdelaStudio does not guess which of the duplicates is the "good one".

[CIU-R210] on loading a document >= 9.0, CANdelaStudio loads the document even if a diagnostic instance that must be checked [CIU-R040] has a duplicate identifier.

Examples

OK: Same Identifier in two Variants

Common-Diagnostics

  • Dynamic Data
    • 010A Wheel Speed [22 01 0A]

Variant A

  • Dynamic Data
    • 010A Wheel Speed [22 01 0A]

OK: Different Identifiers

Common-Diagnostics

  • Dynamic Data
    • 010A Wheel Speed [22 01 0A]
    • 010B Acceleration Sensor [22 01 0B]

OK: Identifiers Differing in MSB only (SPRMIB Disabled)

Common-Diagnostics

  • Sessions
    • 01 Default Session [10 01]
    • 81 Special Session [10 81]

OK: Constants only (Exception 1)

Common-Diagnostics

  • Sessions
    • 11 Special Session1 [10 11]
      • 10 Constant
      • 11 Constant
    • 11 Special Session2 [10 11]
      • 10 Constant
      • 11 Constant

OK: Constants and Proxy "any" only (Exception 1)

Common-Diagnostics

  • Sessions
    • 11 Special Session1 [10 11]
      • 10 Constant
      • 11 Constant
    • 11 Special Session2 [10 11]
      • 10 Constant
      • 11 Constant
      • x Proxy "any"

OK: Constants and Proxy non-"any" in same Diagnostic Instance (Exception 2)

Common-Diagnostics

  • Sessions
    • 33 Request Seed [27 33]
      • Service 1:
        • 27 Constant
        • 33 Access Type (Variable Value)
      • Service 2:
        • 27 Constant
        • 33 Access Type (Variable Value)
        • xx Proxy "data"

OK: Constant and Variable Value in same Diagnostic Instance (Exception 2)

Common-Diagnostics

  • Sessions
    • 33 Request Seed [27 33]
      • Service 1:
        • 27 Constant
        • 33 Constant
      • Service 2:
        • 27 Constant
        • 33 Access Type (i.e. a Variable Value)

Conflict: Same Identifier in different Diagnostic Instances

Common-Diagnostics

  • Dynamic Data
    • 010A Wheel Speed [22 01 0A]
      • 22 Constant
      • 01 0A Identifier (i.e. a Variable Value)
  • Stored Data
    • 010A Maximum Speed [22 01 0A]
      • 22 Constant
      • 01 0A Identifier

(Diagnostic Class does not matter)

Conflict: Constant vs. Identifier in different Diagnostic Instances

Common-Diagnostics

  • Dynamic Data
    • 010A Wheel Speed [22 01 0A]
      • 22 Constant
      • 01 0A Constant (hypothetical)
  • Stored Data
    • 010A Maximum Speed [22 01 0A]
      • 22 Constant
      • 01 0A Identifier

Conflict: Same Identifiers in same Diagnostic Class (since SPRMIB Enabled)

Common-Diagnostics

  • Sessions
    • 01 Default Session [10 01], [10 81]
    • 81 Special Session [10 81], [10 01]
