Diagnostic Instance Operations

Diagnostic Instance Creation

The identifier of the diagnostic instance must be a valid raw value in the text table at the Used ProtocolService (CDS-18874). If set, the assigned text from the text table is used as name of the diagnostic instance.

As a default, the diagnostic instance gets the next valid identifier.

[DI-R010 Diagnostic Instance Creation]:

  • in the DTC list of a variant, for a DTC in DTC pool that has authorization...
    • [DI-R010-VarDtcReq] required="yes", CANdelaStudio shall insert a reference to the DTC;
    • [DI-R010-VarDtcReqAsRef] required="as Reference", CANdelaStudio shall insert a copy of the DTC.
  • [DI-R010-LibDtcReq]: in the DTC list of a library, CANdelaStudio shall not insert references to DTCs in DTC pool.
  • [DI-R010-UDFMDtcReq]: in a DTC List for User-Defined Fault Memory only [UDFM-D105], CANdelaStudio shall not insert references to DTCs in DTC pool.
  • [DI-R010-SegNum]: for a new diagnostic instance for which the SegNum>99 behaviour [SEGNUM-R410] has been configured, CANdelaStudio does not overwrite the SegNum attribute but leaves the default [ATTR-R140] (CDC-44027 v10)

Position of a New Diagnostic Instance (CDS-71276 v13)

  • [DI-R010-Sorted] CANdelaStudio inserts a diagnostic instance sorted:
    • behind the first diagnostic instance whose identifier is < the new identifier (CDS-71276 v13).
    • Rationale:
      • if the list is sorted, CANdelaStudio inserts sorted;
      • if the list is not sorted, CANdelaStudio insert so that at least the beginning of the list is sorted up to the new diagnostic instance.
    • Example:
      • existing Identifiers 10, 20, 30, 05;
      • you create the new Identifier 15
      • resulting Identifiers 10, 15, 20, 30, 05.

Diagnostic Instance Creation from DID (CDS-39296)

[DI-R020 Diagnostic Instance Creation from DID]

CANdelaStudio shall...

  • [DI-R020-PerDID] create [DI-R010] one diagnostic instance for each selected DID,
  • [DI-R020-DIDProperties] ... using name, qualifier and identifier from the DID for the respective properties of the new diagnostic instance;

  • [DI-R020-DIDIdentifier] If the variable value of the Used Procotol Service has length 1 byte, then CANdelaStudio shall use the lowest byte from the DID number for the diagnostic instance identifier (CDS-40554 8.5 SP2).

  • [DI-R020-DIDDataReference] create a DID Data Reference that refers the DID,
    • in the telegram table for the combined component that holds the DID semantics [DCL-D001-a], or
    • for the first combined component of the positive response [DCL-D001-b2].

Paste

[DIOP-R025] Creates a new diagnostic instance based on an existing one.

  • [DIOP-R025-ReqAsRef] The new diagnostic instance has "required as reference" [DIA-R020-reqAsRef] = "no" (CDS-70996 v11, CDS-72195 v13).
  • If you paste into the same diagnostic class, the copy gets a new name and qualifier, for uniqueness.
  • [DIOP-R025-CloneDID] If you...
    • paste into the same diagnostic class,
    • and the Diagnostic Instance references a DID using a DID Data Reference as the single data object in a telegram
      • cf. [DCL-D001-b2];
      • even if "DID semantics" [DID-R050-DIDDataReference] is not set;
    • then CANdelaStudio also pastes (= clones) the referenced DID, using the same name and Identifier (CDS-71907 v13)
    • Effect: let diagnostic instance and DID behave as a single object.
  • [DIOP-D025-OtherVar] Known limitation: if you paste into another variant in the same document, the operation erroneously replaces the existing reference with a copy (like operation "Replace Reference with Copy" [DIOP-R040] below).
  • [DIOP-R025-OtherDoc] If you paste a diagnostic instance into another document,
    • ... and the DiagInstance in the source document uses a DID,
    • ... and the target variant already contains a DID with the same qualifier,
    • then CANdelaStudio pastes the diagnostic instance and lets it use the DID from the target variant (CDS-39865 13.0).
    • Cf. DID Operation [DID-R276].
  • [DIOP-R010-Events]: if the target document does not support Events [EV-R010], the operation neither transfers Events nor Event Master Data.
  • [DIOP-R010-EventRef]: for DTCs referenced by Events in the source, and Events get transferred, ...
    • if the operation pastes the DTC [DTCOP-R040], it lets the resulting Event reference the resulting DTC.
    • if the operation cannot paste a DTC [DTCOP-R040], it lets the resulting Event in the target diagnostic instance reference the existing DTC that has the same code.

Handling of Services:

  • To transport the properties of services in the diagnostic instance, CANdelaStudio tries to associate source and target Used Protocol Services based on their qualifiers.
  • [DIOP-R025-ProtocolService Paste] If the source and target diagnostic class template contains a single Used Protocol Service with different qualifiers, CANdelaStudio associates them based on the qualifiers of their Protocol Service (CDS-26145 9.1).
  • If CANdelaStudio cannot associate a Used Protocol Service, the service properties from the source are lost, and a new service based on the target document may be created.

Handling of Attributes:

  • See CDS-71837 for resetting the attributes on copy.

Paste as Reference

[DIOP-R030 Paste as Reference]

Inserts the diagnostic instance as a reference.

This is possible only within the same document.

As a result, the diagnostic instance is shared [DI-D010] with the source diagnostic instance, so that modifications take effect in both locations.

  • [DIOP-D030-Events] the Boolean flag Supports Events [EV-R010] does not matter here since the flag cannot vary within the same document.

Replace Reference with Copy

[DIOP-R040 Replace Reference with Copy]

For a diagnostic instance referenced (shared) in multiple variants [DI-D010], breaks the reference so that...

  • the diagnostic instance in the current variant is a copy (has no relationship to other variants)
  • the references of the diagnostic instance in all other variants are unchanged.

Note: this operation may also happen automatically when replacing a DID with a copy [DID-R230].

  • [DIOP-R040-ReqAsRef] A diagnostic instance that is "required as reference" [DIA-R020-reqAsRef] cannot be replaced with a copy.
  • [DIOP-R040-Library] In a Library, CANdelaStudio allows to replace a diagnostic instance reference by a copy even if the authorization property is set to "required as reference" [DIA-R020-reqAsRef] (CDS-41289 v10).
  • [DIOP-R040-Events] creates a copy of the Events [EV-R020] and Event Master Data [EV-D040] contained in the Diagnostic Instance.

Replace Copy with Reference in Base Variant

[DIOP-R050]

In an extended variant or library, replaces an object not referenced with the base variant by a reference to the object in the base variant with the same qualifier.

  • [DIOP-R050-DID] for a diagnostic instance that references a DID, first references the DID with the base variant (due to consistency rule [DID-D020]).
  • [DIOP-R050-Events] with the not referenced Diagnostic Instance, deletes the Events [EV-R020] and Event Master Data [EV-D040] contained in the Diagnostic Instance.

Reference Identical Diagnostic Instances and Job Containers

[DIOP-R060]

Compares diagnostic instances and job containers...

  • that have the same qualifier
  • in all variants
  • not in libraries;
  • ignores OID differences
  • ignores TextID differences in mode “Completion only” (respects them in mode “Edit”)

For those that are identical, ...

  • if the diagnostic instance uses a DID,
    • [DIOP-R060-DID] first references that DID in variants where it is identical (CDS-41379 v12)
    • then continues for the diagnostic instance only with those variants where the DID is referenced
      • (respecting the Onion Rule [DID-D020])
  • keeps the diagnostic instance in the first involved variant,
  • replaces the ones in the later variants by a reference with the first one.
  • [DIOP-D060-Events] with the Diagnostic Instance, deletes the Events [EV-R020] and Event Master Data [EV-D040] contained in the Diagnostic Instance.

Modify Name

[DIOP-R100] When you...

  • modify the name of a Diagnostic Instance,
  • and the Diagnostic Instance references a DID that has the same name
  • using a DID Data Reference as the single data object in a telegram (cf. [DCL-D001-b2]),
  • even if "DID semantics" [DID-R050-DIDDataReference] is not set,
  • then CANdelaStudio assigns the new name also to the DID (CDS-71909 v13).

Modify Identifier

[DIOP-R110] When you...

  • modify the Identifier of a Diagnostic Instance
  • and the Diagnostic Instance references a DID using a DID Data Reference as the single data object in a telegram (cf. [DCL-D001-b2]),
  • even if "DID semantics" [DID-R050-DIDDataReference] is not set,
  • then CANdelaStudio accordingly modifies the DID Number (CDS-71910 v13).

Move Data to New DID (CDS-36881 8.2 SP2)

[DIOP-R070] Move to New DID

Conditions:

  • [DIOP-R070-Data] if the diagnostic class template contains at least 1 combined component with semantics "data"[CPC-R100]
    • (cf. [DOOP-R110-Data] for the operation on data objects)
    • otherwise CANdelaStudio does not show the menu item
    • Note: when you select multiple diagnostic instances, the number of data telegram tables [DOOP-R110-Data] can vary from one diagnostic instance to the other. Therefore the menu item sensitivity is controlled by the number of combined components only.

Operation:

  • [DIOP-R070-DiagInst] for each diagnostic instance, CANdelaStudio performs the operation [DOOP-R110] for all data in the first data telegram table [DOOP-R110-Data].
    • Note: in case the diagnostic instance contains more than one data telegram table, CANdelaStudio does not take special action or message (this is a rare situation, the default makes sense, and the result can be inspected easily).
    • Ditto in case the diagnostic instance contains no data telegram table.
  • [DIOP-R070-Conflict] In case there is a conflict (a condition is not met) for some diagnostic instance
    • e.g. data contains DID Reference [DOOP-R110-DIDRef]
    • CANdelaStudio skips the diagnostic instance;
    • writes one info message per diagnostic instance into the output window, like
    • "Skipping diagnostic instance <diagnostic instance name>, its data contains a DID Reference".
  • [DIOP-R070-Message] In case there is no conflict for a given diagnostic instance, CANdelaStudio writes one info message for the diagnostic instance into the output window, like
    • "Created DID <identifier e.g. 0x0001> <name> from diagnostic instance <diagnostic instance name>."

For the user interface, see the diagnostic instances list [DIUI-R070].

See the related operation [DOOP-R110] for data objects.

Conditions for Modifying Operations within a Diagnostic Instance

[DIOP-D010]

  • [DIOP-D010-LockedVar] A modifying operation is not allowed in a locked variant [VAR-R010] (even in Expert View)
    • Motivation: the variant lock may not be obvious, therefore CANdelaStudio prevents even the Expert View user from modifications. In Expert View, you can unlock the variant to enable modifications.
  • [DIOP-R010-DiagInstRO] In Standard View, operations on the respective individual properties are forbidden in a diagnostic instance which has...
    • activation not modifiable [DIA-R030]
    • primary properties not modifiable [DIA-R040]
    • secondary properties not modifiable [DIA-R050]
    • No restriction in Expert View.
  • [DIOP-R010-FixedQual] For any view, operations on the respective individual properties are forbidden in a diagnostic instance which has...
    • Fixed Qualifier [QUAL-R300]
  • Note for Events:
    • some Event operations respect the flag "Supports Events" [EVOP-R010], as noted in detail at the respective operations.
    • See also "Event Operations in Document Context" [EVOP-R500].
