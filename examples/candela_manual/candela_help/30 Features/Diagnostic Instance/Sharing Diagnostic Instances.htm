Sharing Diagnostic Instances in Variants

Use-Case

U001.0: the user adds a new diagnostic instance in the base variant and wants to insert it also in some/all extended variants (as a copy or as a reference).

U010.0: the user wants to insert one or multiple existing diagnostic instances from the base variant in some extended variants (as a copy or as a reference).

U020.0: the user wants to delete one or multiple existing diagnostic instances from the base variant and also from some extended variants where they are referenced (not where there are copies).

Specification

R001.0: When the user adds a new diagnostic instance in the base variant, CANdelaStudio shall provide a convenient way to insert it also in some/all extended variants (as a copy or as a reference).

R010.0: CANdelaStudio shall provide a convenient way to insert one or multiple existing diagnostic instances from the base variant in some extended variants (as a copy or as a reference).

a) A singleton diagnostic instance must be inserted directly into the variant. If it already exists in the target variant, CANdelaStudio must either skip it or overwrite the existing one.

b) A non-singleton diagnostic instance must be inserted into the same folder as in the source variant. If it does not yet exist, CANdelaStudio must create the folder in the target variant.

c) Conflicts (name or identifier already exists) shall be handled in a convenient way even when multiple diagnostic instances are processed.

R020.0: When the user deletes one or multiple existing diagnostic instances from the base variant, CANdelaStudio shall provide a convenient way to delete them also from extended variants where they are referenced.

R100.0: CANdelaStudio shall provide a user option to prompt for R001/R010, or to process the base variant only.

R120.0: CANdelaStudio shall provide a user option to prompt for R020, or to process the base variant only.
