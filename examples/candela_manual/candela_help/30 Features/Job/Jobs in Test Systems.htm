Jobs in Test Systems

A job embedded in a CANdela document can be used in a tester if...

  • the runtime system of the tester supports the programming language of the job, and
  • the tester supports execution of embedded jobs. This is a feature of the tester, and the degree of comfortable integration may vary.

Indigo

Does not support execution of jobs embedded in a CANdela document.

vFlash

Does not support execution of jobs embedded in a CANdela document.

CANoe

(as of CANoe 2018-11)

Does not support direct execution of jobs embedded in a CANdela document (you cannot address Jobs in CAPL).

There is no possibility to access/use data stored in the CDD (except the service definitions) from the diagnostic windows in CANoe.

For manual integration, see Procedure How to Transport a CANoe Automation Sequence Macro as a CANdela Job.

Use Case

  • Develop a script for accessing a particular sequence
    • e.g. a VIN write sequence
  • put it into a CDD file
  • import the CDD file into CANOE or CANoe.DiVa
  • use the script for testing
    • rather than doing it manually.

Overview: Automation Mechanisms in CANoe

CANoe 10 Automation Sequences

  • Automation Sequences
    • Visual Sequence
    • Automation Sequence Macro
    • .NET Snippet
  • Vector Diagnostic Script
    • Diagnostic Console Macro

Visual Sequence

  • no support for diagnostics
  • .vsq file
  • Execution
    • internally converted to CAPL and compiled
    • even during a running measurement
    • cannot be started via CAPL

Automation Sequence Macro

  • since CANoe 5.1
  • records UDS requests (byte sequences) with time stamps
  • Creation
    • starting services in diagnostic console and session control
    • no programming (supports replay only)
  • Execution
    • can be loaded and started from CAPL
    • even during a running measurement
    • no compile, no delay on first run
    • usable only in CANoe, not in CANape
  • CANoe 10 (2017-05) does not automatically use an Automation Sequence Macro embedded in a CANdela document
    • the feature is being discussed for the near future (CANoe >= 11.0);
    • you can use such a macro manually, see Procedure How to Transport a CANoe Automation Sequence Macro as a CANdela Job.
  • the CANdelaStudio job file dialog provides the predefined runtime system AutomationSequenceMacro, see [JOB-R410-AutomationSequenceMacro].
  • Example contents of an Automation Sequence Macro file (note the byte sequences):
date Fri Jul 7 10:58:15.732 am 2017
base dec  timestamps relative
internal events logged
   0.006561 DiagRequest[DoorFL] 22 01 00
   0.477000 DiagRequest[DoorFL] 22 F1 8C
  0.115000 DiagRequest[DoorFL] 22 F1 89
   0.455000 DiagRequest[DoorFL] 22 01 08
   0.030001 DiagRequest[DoorFL] 22 01 07

.NET Snippet

  • C# source code (.cs)
    • supports the full power of programming;
    • in general not restricted to diagnostic functionality
    • can be modified in source code (e.g. add ecu.Unlock in CANoe demo file "Set Variant Coding USA").
  • Creation
    • programmed manually
    • or converted from a Diagnostic Console Macro recorded in the diagnostic console (which is internally a VectorDiagnosticScript, VDS)
  • Execution
    • must be compiled before use;
    • therefore some delay on first run (drawback for use in realtime)
    • even during a running measurement
    • not via CAPL
    • not in diagnostic console, i.e. not usable in other Vector tools that support diagnostic functionality (as of CANoe 10)

Vector Diagnostic Script (VDS)

  • like .NET Snippet (see previous chapter)
    • but restricted to diagnostic functionality
  • provides more functionality than a mere Automation Sequence Macro
  • likely to be usable in other Vector tools that support diagnostic functionality

Diagnostic Console Macro

  • Interactively created in the Diagnostic Console
  • shown under "[Macros]" in Diagnostic Console
  • Replay in the Diagnostic Console
  • internally implemented as Vector Diagnostic Script (see previous chapter)
