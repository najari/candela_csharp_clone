Value Conversions

Motivation

Various CANdelaStudio objects hold numeric, string or enumeration values:

  • DTC Columns, see DTC Columns;
  • Data type based values, see Encoding [DTENC-R100];
  • Attributes, see [ATTR-R020];
  • User-defined requirement properties, see [RQ-R040] "Property type".

In several situations, such values must be converted, e.g. ...

  • when updating a diagnostic object attribute from a requirement property [RQ-R560-Attribute]
  • in document upgrade when the type of an attribute has changed
  • when replacing a data type [MENU-R475]

The following provides a central definition for these value conversions.

Types not Relevant for Value Conversions

Some values in CANdela objects have type information that is not relevant for converting values:

Value Type Information Not Relevant because...
Constant value of constant component bit length (encoding unsigned, implicit) There is no use-case that needs value conversion
Negative response code bit length (encoding unsigned, implicit) Dito (bit length assumed to be fix)
- bit length at data requirement used for data object update, not for values

Conversions

Classification

[CONV-D020 Relationship of Types]

The following relationships of two types are relevant in value conversions:

Relationship of Types Description Example
Equal equal types unsigned to unsigned of identical length
No Loss of Data types of equal size unsigned to signed, signed to unsigned
Extension from a smaller to a larger type unsigned to unsigned64, implicit conversion without loss
Extension with Loss of Precision from a smaller to a larger type, but precision may be lost unsigned 1234567890 to float 1234567936.0 (due to the float resolution, .0 does not exactly match the integer value)
Restriction from a larger to a smaller type , a subset of values may be converted (needs cast in a programming language) unsigned64 to unsigned
Unrelated between unrelated types, a subset of values may be converted enumerations with some common enum IDs

Value Conversions

[CONV-R010 Value Conversion]

So far, CANdelaStudio handles value conversions individually for the different kinds of CANdela objects (e.g. attributes vs. data types). There are only few combinations of different types for which CANdelaStudio preserves the values.

Efforts are ongoing to define and implement a uniform concept for value conversions between different types.

Field Value Conversions

[CONV-R010-FieldValueConversion] For field values (which occur only at data types), ...

  • CANdelaStudio assigns values only to identical types
    • i.e. identical field length, termination type, element type;
  • CANdelaStudio does not handle any different types as compatible.
