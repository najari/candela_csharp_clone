Description

Most diagnostic objects in CANdela have a name, a qualifier and a description.

Use-Cases

You may use a description to...

  • provide hints about the diagnostic object
  • add pictures or diagrams
  • add attachments to be processed by external applications

Description Restrictions

  • [DESC-R010] Descriptions are multi-language.
  • [DESC-R020 Character Set] A description may contain any characters of the Unicode character set.
  • [DESC-R030 Length] A description may contain 0..65535 characters).

Formatted Descriptions

[DESC-R100] Some descriptions may contain text formatting, images and attachments.

Handling in Exports:

  • Exports transfer descriptions to a specific target format.
  • If a target format cannot represent the formatting, the export represents the formatted description in an adequate way (e.g. rendering as plain text).

Occurrence

[DESC-R110] CANdelaStudio supports formatted descriptions for the following diagnostic objects:

  • ECU
  • variant
  • diagnostic class
  • diagnostic instance
  • job container

Only at these objects formatted descriptions make sense in the specification report.

Properties

[DESC-R120] Formatted descriptions can have the following formatting properties:

  • bold
  • italic
  • underline
  • font color
  • background color
  • bullet list
  • numbered list
  • image
  • file attachment

Images and Attachments

  • [DESC-R130] Images and attachments are stored in a central pool on ECU level, independent from language.
  • [DESC-R140] If an image is used in several descriptions or several languages, the single image is just referenced multiple times.

Motivation:

  • We assume most images do not have language dependent content.
  • Avoid redundancy over multiple descriptions, or multiple language versions of a description.

Display:

  • In the description field, CANdelaStudio shows...
    • [DESCUI-R100] images as a picture,
    • [DESCUI-R110] attachments as a special icon.

Formatted Descriptions in ODX

The ODX <DESC> element...

  • contains text in xhtml format:
    • top-level: paragraphs <p>, lists <ol> , <ul>, <li>
    • inline elements <br>, <i>, <b>, <u>, <sub>, <sup> (see XML schema in appendix C.2, page 411)
  • contains 0..n EXTERNAL-DOC elements
  • has a TI attribute (for multi-language information)

Formatted Descriptions in CANdela vs. ODX

[DESC-D100]

  • CANdela has...
    • font color and background color
    • images and files positioned in the text, reused across multiple languages
  • ODX has...
    • subscript and superscript
    • line-breaks within paragraphs (CANdela has just paragraphs)

Descriptions for Code Generation

  • [DESC-D200] CANdesc uses the service description (plain text) for generation of source code documentation
    • "Support description at service" (CDS-10648 6.5)
  • cf. CANdesc in the Vector Diagnostic Toolchain
