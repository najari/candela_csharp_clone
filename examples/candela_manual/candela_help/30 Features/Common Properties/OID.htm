OIDs (CDS-3862 in 5.5)

Database systems typically identify an object using a unique identifier (ID). An ID distinguishes even objects that otherwise have identical properties. To support data exchange with such systems, each CANdela object has an ObjectID (OID). This ID is also supported as an optional property by the ODX standard. OIDs may also be called "UUID" or "GUID".

ObjectID in CANdela

The CANdela data model describes diagnostic objects in templates and documents. Therefore, each diagnostic object has two string properties:

  1. the OID of the diagnostic object (in a template or in a document; “OID” = document OID).
  2. the OID of the template object on which an object in a document is based (“TemplateOID” = original OID):
    • it is empty in a template,
    • it is empty for objects created in a document,
    • it is only defined for objects in a document based on an object in a template

Operations

When CANdelaStudio creates a document from a template ("instantiate"), it moves the OID of template objects into the TemplateOID property.

For OID handling in the operation "Reference Identical Diagnostic Instances and Job Containers", see at the Diagnostic Instance Operations.

Limitations

OIDs give "identity" to a diagnostic object - they allow to identify the object even after a long sequence of modifications. This may seem desirable.

But CANdelaStudio does not bother the user with OIDs: it does not visualize or otherwise provide control over OIDs. Operations in CANdelaStudio preserve the values of diagnostic objects, not the object identity.

Therefore e.g. in operations that create copies of objects, it may be ambiguous which of the objects is the "original object" (= taking the original OID).
