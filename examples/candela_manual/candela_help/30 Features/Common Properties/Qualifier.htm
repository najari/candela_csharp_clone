Qualifier

Most diagnostic objects in CANdela have a name, a qualifier and a description.

Note: this is different from the shortcut qualifier of a service.

Use of the Qualifier

The qualifier is used e.g.

  • to uniquely identify an object within a list of objects
  • as a variable name in generated code

Generating from Names

[QUAL-R010] For a new object, CANdelaStudio automatically generates the qualifier from the name, applying the restrictions for qualifiers (e.g. it must not contain a blank).

[QUAL-R020] If you modify the name of an object, CANdelaStudio automatically updates the qualifier if the qualifier still equals the qualifier that would be generated from the name.

  • [QUAL-R020-VW] This includes a qualifier computed using the [QUAL-R200-VW5CharRule] (described below) (CDS-71416 v12). E.g. with...
    • name "New Data Object",
    • qualifier "Param_NewDataObjec",
    • ... CANdelaStudio applies modifications of the name to the qualifier.

[QUAL-R050] The concrete algorithm for generating a qualifier includes:

  • “Romanize” characters that are not in the restricted character set, e.g. replace “ä” by “ae”.
  • Optionally replace non-romanizable characters by an underscore “_”
  • Compact multiple underscores to a single one.
    • Note: AUTOSAR forbids subsequent underscores.
  • Drop a trailing underscore.
  • If the qualifier starts with a digit, prepends an underscore
  • Apply length restrictions (see the next chapters).
  • Apply options for upper-/lower-case (see below at Qualifier Generation Options).

CANdelaStudio implements few variations of this algorithm, depending on the value for "Diagnostics Based on" (manufacturer) of the document.

Qualifier Restrictions

Multi-Language

[QUAL-R110] Qualifiers are identical in all languages of the document, not multi-language.

Character set

[QUAL-R120] Restrictions for the character set of a qualifier:

  • [QUAL-R120-Chars] only 0..9, A..Z, a..z, underscore “_”
  • [QUAL-R120-Start] the first character must not be a digit 0..9
    • Motivation: allow use as a variable name in generated code.
    • Note: this differs from ODX.

Length

[QUAL-R130] Qualifier length:

  • [QUAL-R130-NonEmpty] A qualifier must not be empty.
  • [QUAL-R130-Max] A qualifier can have at most 128 characters
    • since 5.5, CDS-7946;
    • before 5.5: 64 characters;
    • cf. the maximum name length.

Note: for the qualifier length of new objects, see also the following chapter.

Qualifier Generation Options

[QUAL-R200] When CANdelaStudio computes a qualifier from a name, or re-computes a qualifier, it applies one of the following options:

FeatureID Algorithm Example for "New Data Object"
[QUAL-R200-UpperLower] Use upper-/lowercase characters of names New_Data_Object
[QUAL-R200-Upper] Use uppercase characters only NEW_DATA_OBJECT
[QUAL-R200-Lower] Use lowercase characters only new_data_object
[QUAL-R200-VW5CharRule] VW 5 Character Rule (80128) (see below) Param_NewDataObjec
  • You can specify the following options in menu File | Properties | Qualifier Generation Options [DOCUI-R700].
  • The setting may be locally overridden in the "Recreate Qualifier" dialog [RCRQ-R200] of the Qualifier Overview.

VW 5 Character Rule (CDS-38758 v11)

This option is specific for VW. When CANdelaStudio computes a qualifier from a name, it...

  • splits the name into words
  • takes the first 5 characters from each word
  • concatenates the results (no separator)
  • for some types of objects, adds a prefix, e.g.
    • "Param" for a data object
    • "DiagnServi" for the Service Shortcut Qualifier
      • CANdelaStudio always adds this prefix
      • ODX Export uses the prefix for individual services and static ODX Tables
      • For dynamic ODX Tables, ODX Export recomputes the Service Shortcut Qualifier, anyway, so the prefix does no harm.
      • See attribute Export_as_TABLE [PEnODX-R002-e]

For further details, see the VW specifications...

  • 03_20_N_VW80128-1_Autorenrichtlinie ODX_V3.1.pdf
    • section 7.3 for details,
    • table 7.3.2-1 for same examples
  • 03_21_N_VW80128-2_Autorenrichtlinie ODX Zusatz_V3.1.pdf
    • section 2.3 for the prefixes used

Fixed Qualifiers (5.0 SP2)

[QUAL-R300] You can set a qualifier to being “fixed” (CDS-5967). This protects the qualifier against un-intentional changes:

  • the qualifier will not be updated automatically if you change the name of the object
  • the Qualifier edit control in the properties dialog will be disabled:

Diagnostic Instance Property Dialog with Fixed Qualifier

You can always intentionally modify a fixed qualifier in the Qualifier Overview dialog.

Objects that Allow Fixing the Qualifier

[QUAL-R310]

  • ECU
  • Variant
  • Diagnostic instance
  • Job container
  • Job
  • Data object / Bit field
  • Data type
  • Vehicle System Group

The attribute is not relevant at diagnostic class and service (where the qualifier is not modifiable, anyway).

Create Attributes for Fixing Qualifiers

Run plug-in “Enable Fixed Qualifiers”. This will add the attributes for all objects specified above.

If the attribute does not exist, the meaning is "qualifier not fixed".

The attribute applies only to the object itself, not to child objects.

Alternative: to manually add the attributes, do the following:

  • Open the CANdela document in Expert mode.
  • If not already present, add an attribute category named “Editor” to the document.
  • Add attributes of type “Unsigned” and qualifier “FixedQualifier” to the attributes list of the objects specified above.

Attribute values:

  • 0 = "qualifier not fixed" (default)
  • any other value = "qualifier fixed"

How to Set a Qualifier to Be “Fixed”

This assumes you have created the required attributes (see above).

  • Main menu: View | Qualifier Overview. The Qualifier Overview dialog opens.
  • In column “Fixed”, select “Yes”:
