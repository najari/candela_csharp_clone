Object paths

Use cases

  • in a dialog, show the position of a diagnostic object within the document (e.g. in "References" dialog)
  • remember the position of a diagnostic object within a document and again navigate to it later
  • specify a diagnostic object to another person having the same document
  • refer to a diagnostic object within a document (e.g. from an identifying feature; as of CANdelaStudio 8.2)

Definition

The structure of an object path resembles that of an URL protocol://host/path...:

  • syntax (corresponds with URL protocol): npath, qpath, rpath, xpath, see next chapter.
  • host: (not used, like in URLs where the default “localhost” may be omitted)
  • path: starts with a top-level object of a CANdela document, e.g. a variant. An object path does not include the ECU.

The path of an object contains the objects in the document structure, starting at the ECU, down to the object.

Syntax

  • npath: a name path contains the names of objects, like npath:/C Sample
  • qpath: a qualifier path contains the language-independent qualifiers, like qpath:/C_Sample
  • rpath: a runtime path contains a path to a service, like rpath://ABS_ESP/C_Sample/DefaultSession_Start
  • (no syntax part) denoting an ODX xpath, like ODX/DIAG-LAYER-CONTAINER[SHORT-NAME='ABS_ESP']/ECU-VARIANTS/ECU-VARIANT[SHORT-NAME='C_Sample']
  • (no syntax part) denoting a qpath - if you leave out the syntax part, CANdelaStudio assumes that the path is a qpath, i.e. primarily contains qualifiers.

Path Elements

Path elements are separated by a forward slash /.

If an object contains multiple types of other objects, at this place the path to a contained object includes an "object type selector" (see below) in square brackets to the left of the name or qualifier of the contained object. The selector may be omitted if the contained object is the main type contained. E.g. in an ECU, the main contained type is the variant.

A path can contain both names and qualifiers:

  • names may be placed in double quotation marks "Present Values...";
  • qualifiers may be placed in single quotation marks 'Present_Values'.

If a name contains one of the characters that have special meaning in a path (i.e. /, [, ], double and single quotation marks), then you can "escape" that character with a reverse slash \ placed in front of the character.

Name Path (npath)

A name path will always be created based on the language in which the document has been opened.

npath Examples

  • Name path: npath:/Common Diagnostics/Start Session/Default Session
  • Path to a data type: npath://[DATATYPE]HexDump (1Byte)
  • Path to a data type which contains / in the name: npath://[DATATYPE]HexDump on\/off (1Byte)

Qualifier Path (qpath)

A qualifier path can be processed independent from the language in which the document has been opened.

Since qualifiers cannot contain special characters, no escape characters are needed for such path elements.

qpath Examples

  • qpath:/V/[DID]Braking
  • qpath:/Common_Diagnostics/Identification/ECU_Identification

ODX Path (xpath)

Use-case

Resolve ODX xpath expressions (e.g. thrown by an ASAM ODX checker) within CANdelaStudio (CDS-9744, 7.1 SP2).

Definition

Since the CANdela data model differs from ODX, CANdelaStudio cannot directly map an ODX xpath to an opened CANdela document. Therefore CANdelaStudio internally uses the ODX export to find an ODX element that matches the xpath.

There are 3 ODX versions available: 2.0.1, 2.1.0, 2.2.0. CANdelaStudio uses the ODX version from the last ODX export you executed interactively in CANdelaStudio (the info is available even after a re-start of CANdelaStudio - stored in the registry). During resolution of an xpath, CANdelaStudio writes the used ODX version to the logging.

Different ODX checkers generate different variations of xpaths (CDS-23830, 7.1 SP2). In the following xpath,

ODX/DIAG-LAYER-CONTAINER/ECU-VARIANTS/ECU-VARIANT[SHORT-NAME='SCRCM3_B30P0']/DIAG-COMMS/DIAG-SERVICE[100]

there are multiple ways to identify the ECU-VARIANT:

  • SHORT-NAME
  • ID
  • index

The xpath may optionally start with "/" (CDS-24166, 7.1 SP2) - both are accepted:

 ODX/...
/ODX/...

xpath Examples

ODX/DIAG-LAYER-CONTAINER/ECU-VARIANTS/ECU-VARIANT[SHORT-NAME='SCRCM3_B30P0']/DIAG-COMMS/DIAG-SERVICE[100]
ODX/DIAG-LAYER-CONTAINER[SHORT-NAME='ABS_ESP']/ECU-VARIANTS/ECU-VARIANT[SHORT-NAME='C_Sample']

Runtime Path (rpath)

Use-case

Start CANdelaStudio via URL (CDS-11284, 6.0) from a CANoe.DiVa report or an HTML page and navigate to a given service using a path to the service.

Definition

A runtime path has the form:

rpath://<ECU qualifier>/<Variant qualifier>/<Service Shortcut qualifier>

The "syntax" is "rpath" (according to "npath" and "qpath").

Note the two //.

The path denotes a service, ending in a service shortcut qualifier.

CANdelaStudio ignores all elements to the right of the service shortcut qualifier element of the path.

rpath Examples

rpath://ABS_ESP/BaseVariant/FaultMemory_ReadEnvironmentData
rpath://ABS_ESP/C_Sample/DefaultSession_Start

Which Objects Have a Path?

Any object with a qualifier, i.e. ECU, Variant, Diagnostic Class, Diagnostic Instance, Job Container, Service, Job, Data Object, Data Type, Default Attribute, Overridden Attribute, Attribute Category, State, State Group, Vehicle System Group etc.

No other object has a path (e.g. DTC column, conversion in data type etc.).

Command-Line Support (CDS-11284 6.0)

The CANdelaStudio command-line supports a file name argument with an optional object path, see [CLI-R100-argument].
