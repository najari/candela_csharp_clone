About this Documentation

Building Blocks

Structure

There is roughly one documentation folder for each CANdelaStudio feature (attributes, data types, DIDs, ...).

The documentation is split into the main areas...

Main Documentation Areas

  • Introduction: introduction to the Vector diagnostic toolchain, CANdelaStudio, example files...
  • Procedures: high level descriptions how to achieve typical user tasks
  • User Interface: what you see on the screen
  • Features: the concepts and data model
  • Templates: CANdela template files shipped with CANdelaStudio

Typically, a feature folder contains...

  • an introduction chapter with use-cases and an overview of the feature,
  • more detailed chapters as a feature specification (for reference).

  • The introduction chapter is the first chapter in the folder and has the same name as the feature:

    "DID" Documentation Folder with the "DID" introduction chapter

Conventions

  • This documentation contains feature specifications that answer detailed questions about a feature.
  • "CDC-xxxxx" and "CDS-xxxxx" refer to an entry in the CANdelaStudio change request database.
  • "Definition D001.0" is the definition of a term used in a feature specification.
  • "R001.0" is a requirement from a feature specification.
  • For consistency, each piece of information shall be found at one place only.
  • The documentation contains many hyperlinks,
  • ... uses bullet lists where possible,
  • ... uses FeatureIDs for a unique identification of a feature (see below).

Language

This documentation is available in English only.

Background: for CANdelaStudio 8.5, many feature details have been added to the documentation (CDS-39439). To make this possible, the German text has been dropped. So for German speaking users: read English, get more information!

FeatureIDs

This documentation describes CANdelaStudio features on specification level, with each feature identified by a FeatureID.

Example FeatureID:

[DEXT-R050-SelVariant AUTOSAR Version]

Structure of a FeatureID:

Part of FeatureID Description
DEXT Abbreviation for a high-level feature of CANdelaStudio (like DEXT export)
R050 Unique numbering within the high-level feature (arbitrary).
SelVariant Part (subtopic) of the feature (optional)
AUTOSAR Version Explanatory short text (few words, optional), shown in tooltip on hyperlinks to the FeatureID

Purpose:

  • FeatureIDs help to keep the documentation redundancy free.
    • A FeatureID defines a feature at one place in the documentation.
  • Related features refer to the FeatureID via a hyperlink shown like [DEXT-R050-SelVariant].
    • A tooltip on the hyperlink shows the explanatory short text from the FeatureID.

Searching:

  • See procedure How to Search for a FeatureID.

Title Capitalization

In this documentation, headings and captions shall be written with the usual English title capitalization.

Capitalize:

Part of Speech Example
noun man
adjective small
verb run
adverb slowly
pronoun he
subordinating conjunction if, as, because, that
(first and last word) -

Do not capitalize:

Part of Speech Example
article a, an, the
coordinating conjunction and, but, or, for, nor
preposition on, at, to, from, by, of

Special Terms Capitalization

“Special terms”:

  • where a special meaning beyond the normal English word/phrase is required
  • “highlighted” with an initial capital
  • for multiple words, each one with initial capital.

Example:

“The UDS service 19 is about reading DTCs, CANdela describes it in a Diagnostic Instance, based on Protocol Service 19. You can edit the CANdela Service in the property dialog.”

Term Meaning
service 19 service - the usual meaning in diagnostics
Protocol Service the special object in a CANdela template
Diagnostic Instance the special object in CANdela
Service the special object in a CANdela Diagnostic Instance

Chapters in "UserInterface"

  • all chapters for a topic (object list, property dialog etc.) are in the folder of the topic
  • the "CANdelaStudio Editor" folder contains general user interface features (ribbons etc.)
  • dialogs for Ribbon Tab File are in the "Document" folder
  • example topics: "Attribute", "Data Type"
