CANdelaStudio 13 SP1 (2020-05-15)

Changes

  • Sort Identifier on ECU Level (CDS-72312) See context menu of "ECU Information" and each variant, also Procedure How to Automatically Sort Diagnostic Instances
  • Preserve data objects when moving from Stored Data to Variant Coding (CDS-26665, CDC-44411) CANdelaStudio now just moves the data objects in the diagnostic instance, even if the Combined Components have different qualifiers, if source and target template have exactly one Combined Component that has semantics "data".
  • Improve Constraints Check performance (CDC-44387) Improved check of Fault Memory, saving up to 30% load time.

Identifying Features

  • CANdelaStudio < 13 cannot load 13 documents with AUTOSAR Fault Memory due to empty name (CDS-72245) Correction in Communication View.
  • Load/Save preserves "Trigger" and "Update" properties of Snapshot/Extended Data Records (CDS-72046 U010+U020) Support the convention for Additional Info in Text Tables
  • Snapshot Record Numeration Type "Calculated" not Exported to DEXT (CDS-72228) Communication View fills the attribute [SR-R023].
  • Communication View creates empty text tables (CDC-44403) For a DTC, no Snapshot record / Extended data record stored; Communication View creates a Text Table with one entry 0xFF only.

CANdelaStudio 13 (2020-02-21)

Changes

AUTOSAR

  • AUTOSAR Fault Memory (CDS-71541) Improved handling of Snapshot Records and Extended Data Records: provides detailed AUTOSAR properties, improved user interface with filters and mass operation. CANdelaStudio automatically migrates to the new data model. See AUTOSAR Fault Memory Introduction. If you would like to suppress the migration, see [MIG13-R130-No].
  • Snapshot Record Semantics (CDS-36945) Snapshot Records in the new AUTOSAR Fault Memory have the AUTOSAR properties "Trigger" [SR-R150] and "Updated" [SR-R160].
  • Snapshot Data: User-Defined Order of DIDs (CDS-69421) Snapshot Records in the new AUTOSAR Fault Memory have Snapshot Data DIDs in a user-defined order. See [SR-R240-Ordered].
  • Feature: Snapshot Records per DTC (CDS-38233) Snapshot Data DIDs in the new AUTOSAR Fault Memory can be stored / not stored individually depending on the DTC, see [SR-R300] ("checkbox feature"). Note: ODX Import of v13 Release does not yet import storage of individual Snapshot Records per DTC, see [ODXI-R300].
  • Create attributes for AUTOSAR service dependency references at Event objects (CDS-71544, CDS-71936) This saves you from manual mapping of Events and their properties in daVinci Configurator for Event data exchanged with PREEvision. See entries for Event, Operation Cycle, Indicator and Condition in the attributes list [ASR-D001]
  • Support automatic creation of the AUTOSAR reference attribute for Client/Server DID ports (CDS-72028) See [ASR-D001_ASR_SWC_DOServiceDependency_Ref].

Note for migration to AUTOSAR Fault Memory

When loading a file into CANdelaStudio for the first time, you should inspect the messages in the Output Window (you can enable the Output Window via Ribbon Tab View [MENU-R610]):

  • CANdelaStudio reports whether it migrated Snapshot Records / Extended Data Records to the new AUTOSAR conforming format of v13.

  • If the file contained the Fault Memory modelling of CANdelaStudio 8.2 (tree node "Fault Memory" below "ECU Information") with a constellation not supported by AUTOSAR, CANdelaStudio migrates to the generic modelling (Multiplexer based).

For details, see [MIG13-R130] (e.g. how to suppress the migration).

CANdelaStudio 8.5 SP2 (2016-12-16)

Note for using BCD values

Unfortunately, the meaning of BCD values in CANdelaStudio up to 8.5 has not been clear.

As a result, ...

  • editing in CANdelaStudio has been confusing, using different possible settings in the CANdelaStudio edit control

  • the BCD values have been interpreted differently in CANdelaStudio ODX export vs. other Vector tools.

8.5 SP2 fixes this and edits and stores BCD values in one unambiguous, normalized way.

After loading an older CANdela document, a BCD value will be as expected if...

  • it had been specified before 8.5 SP2 using the "BCD" or "decimal" setting in the CANdelaStudio edit control,
  • so it had shown up as expected in ODX Export.

A BCD value may be interpreted other than expected if...

  • it had been specified before 8.5 SP2 using the "hex" setting in the CANdelaStudio edit control,
  • so it had shown up as expected in the Vector tool-chain.

  • Some of these BCD values cannot be normalized. Therefore when you first open such an older file, mind the warning in the Output window:

      BCD value ... at "npath:/..." is invalid - please correct it.

For details, see the BCD Value Normalization in the CANdelaStudio online help.
