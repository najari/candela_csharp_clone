How to Describe Data for Different Snapshot Records

Situation

Note: key features of the Fault Memory are defined in the CANdela template on which the document is based.

Assumptions:

  • the template describes Snapshot Data in a Fault Memory diagnostic instance within the variant, ...
  • not in the AUTOSAR Fault Memory from CANdelaStudio 13
  • the 0x19 0x04 Protocol Service in the template defines that you can specify Snapshot Data...
    • individually for each DTC, but
    • not individually for different Snapshot Records.

Example

The Protocol Service:

0x19 0x04 Protocol Service - "rr" Iteration with one Object

  • "rr" in the positive response represents the UDS...
    • Snapshot Record Number,
    • Number of Identifiers and
    • Snapshot Data
  • the "rr" is a Multiplexer depending on the DTC
  • therefore in this example you cannot describe Snapshot Data to vary per Snapshot Record Number.
  • the "rr" is within an iteration, so this template allows for different Snapshot Record Numbers and their Snapshot Data.

0x19 0x04 Protocol Service - Positive Response Structure

The Diagnostic Instance:

19 04 Telegram with DID

The corresponding telegram table contains

  • a data object for the Snapshot Record Number,
  • a data object for the Number of Identifiers and
  • one or multiple references to a DID.

The telegram table is either the default for all DTCs, or a specific one for one individual DTC:

Selection of Default or DTC Specific Telegram Table

Solution Sketch

In order to describe different Snapshot Data per Snapshot Record Number, ...

  • insert a new second data object, called e.g. "Number of Identifiers and Data"
  • assign to it a new Multiplexer data type with the same name
  • set the Multiplexer selector to be the data type of the first data object, e.g. "Hex Dump (1 Byte)"
  • in the Multiplexer, for each Snapshot Record Number, define the Number of Identifiers and the Snapshot Data.

Step by Step

  • right click on the second data object behind "DTCSnapshotRecordNumber", select "New Data Object".
    • CANdelaStudio inserts a new data object.
  • select its "Name" cell, click again to rename it to "Number of Identifiers and Data"
  • right click on the new data object, "Assign New Data Type", "Multiplexer"
  • in the combo-box on top of the "Multiplexer" page, select "Hex Dump (1 Byte)" (i.e. the data type shown in the "Data Type" cell of the first data object)
  • in the "General" page, change the name to "Number of Identifiers and Data"
  • press "OK"
  • in the dialog "Selector Data Object for Multiplexer", confirm using the existing first data object:

Selector Data Object for Multiplexer

  • in the telegram table, select the third and all following data objects, click right mouse, "Cut"
  • on the second data object, click right mouse, "Go to Data Type",
    • CANdelaStudio navigates to the data type list and selects the data type;
  • press the [Properties...] button
  • press the [New] button
  • specify the first Snapshot Record Number
  • leave "Create separate data..." selected
  • press OK
  • in the telegram table to the right, click right mouse, "Paste"
  • repeat pressing the [New] button for all Snapshot Record Numbers required, and specify their Snapshot Data.
  • finally press OK to complete the Multiplexer data type.
    • Note: in case you did not "Cut" the "following data objects" in the step above, CANdelaStudio may complain that a data type with variable length is not allowed at the end of the telegram. If you define different Snapshot Data within the Multiplexer, the data object that refers the Multiplexer data type must be the last one in the telegram.
